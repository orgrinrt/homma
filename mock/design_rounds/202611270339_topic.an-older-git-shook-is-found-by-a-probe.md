# an-older-git-shook-is-found-by-a-probe

A review of round 202611270155 found its landing step 1 false. The round says "An older git-shook refuses
`--only` on doctor, so every member reads as not current, and the sweep reinstalls each one at every start:
noisy, never wrong." Tested on git-shook 9315c61 and 23c5ded: both take `doctor --only <name>` without a word
and answer "all good", exit 0, even with an entry edited by hand. So under an older git-shook the sweep reads a
tampered member as current, says nothing and puts nothing back.

## Decision

- Before it trusts what git-shook's doctor says of a member, the sweep and `homma hook doctor <repo>` ask it
  once more, with `--only` and a name no manifest can have. A git-shook whose doctor checks names refuses that,
  as 90c9cea does ("no manifest answers to ..."), exit 1. One that answers 0 checks no entry, whatever it says.
- Where the probe answers 0, its doctor's word is not taken: the member is read as not current and installed
  again, which writes every entry as the manifests declare it, and one line says git-shook is older than the
  doctor this needs and to install a newer one. So a tampered entry is put back at every start under an older
  git-shook, with a line saying why; nothing is read as current on an answer that checked nothing.
- The probe's name is `homma-no-such-manifest`, which homma never writes and which a manifest's `name` could
  only take by choice.
- The order of landings, step 1, says this: git-shook 90c9cea or later is what makes a current member silent;
  before it every member is installed again at every start, with that line.
