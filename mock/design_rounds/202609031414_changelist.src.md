# Source changelist: the root markers are declared in homma.toml

**Date:** 2026-09-03
**Phase:** IMPL
**Doc changelist:** `202609031410_changelist.doc.lock.md`

## `homma-api`

### `src/release.rs` (modify)

CHANGE: `Signal` is the closed vocabulary a marker maps to, `cargo`, `deno` or `content`, and deserialises from those words alone. `Markers` is the table, a map from file name to `Signal`, built by `new` over the two default rows so `Cargo.toml` and `deno.json` are present whether or not a manifest names them and a manifest naming one overrides it; `defaults` hands out the default table as a static borrow. `RepoKind` gains `Content`, and `from_signals` folds a set of signals into a kind, `None` for the empty set, `content` adding nothing beside a toolchain signal. Tests pin the defaults surviving a declared table, a signal outside the three words refusing with the word in the error, and every combination of signals folding to its kind.

### `src/lib.rs` (modify)

CHANGE: `Markers` and `Signal` are exported beside `RepoKind`.

## `homma-core`

### `src/config.rs` (modify)

CHANGE: `Config` carries `markers`, the `[markers]` table, defaulting to the two rows. `config/tests.rs` pins a bare manifest yielding the defaults, a table adding a row and overriding a default, and a wrong word refusing at parse.

### `src/release/kind.rs` (modify)

CHANGE: `detect` takes the `Markers` and folds the signals of every declared file present at the root; no declared file present is `NoManifest`, which now carries the root and the declared file list and says so in its message. Tests pin a declared content marker making a content repo, the same tree refusing under the bare defaults, a manifest beside a content marker making the manifest's kind, and a directory named like a marker counting as absent.

### `src/release/gate.rs`, `src/release/plan.rs`, `src/release/check.rs`, `src/release/run.rs` (modify)

CHANGE: `run_gate_at`, `run_gate` and `plan` take the `Markers`; `check::Inputs` and `run::Setup` carry them. Nothing else in the step table changes: a `Content` kind answers false to both `has_crate` and `has_deno`, so every step but notices is skipped. `gate_tests.rs` pins a content repo running a gate of skipped steps and passing, with nothing called, and turning red on a failing notices step when an `ante.toml` is beside the marker.

## `homma-engine`

### `src/cmd/release/mod.rs`, `src/cmd/release/gating.rs` (modify)

CHANGE: every call into kind detection, the gate, the plan and the check passes `cfg.markers`, so the hook, `check`, `plan`, `run` and `badges` all read the workspace's table.
