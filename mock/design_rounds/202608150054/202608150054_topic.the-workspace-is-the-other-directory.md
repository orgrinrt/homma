# The workspace is the other directory homma creates, and it had the opposite rule

Thirteenth review. The previous round adopted "homma creates the root, never the
path to it" and enforced it. **Homma creates two directories.** The other one
kept the opposite behaviour, and a passing test asserted it.

## The defect

`provision` creates the workspace's ancestors with `create_dir_all`. The
workspace is **required** to sit outside the containment root, so no `Root`
covers it and none can. Its only guard asks whether it is inside a git
repository, and a home directory is not one.

Reproduced twice through the built binary, both at exit 0:

```
org add paja … --workspace "$S/fakehome/.claude/hands/paja"
org up paja --root $S/root
  creates $S/fakehome/.claude/ and $S/fakehome/.claude/hands/

--workspace "../../victimhome/.claude/hands/paja"  --root $S/deep/root
  creates victimhome/, victimhome/.claude/ and victimhome/.claude/hands/
  three levels above the root
```

Both are deny item three, reached by the two spellings this branch has been
closing since round one: a relative `..` and a plainly absolute path.

## Why the parent is created at all, which is the part that matters

The call is not an oversight and deleting it is wrong. Its own comment says why:

> gix will not create the parent, and a clone into a path whose parent is
> missing fails with an error about opening data, which reads as a network
> problem and is not one. Found by running this against a real repository; the
> fake in these tests never touched a filesystem.

So one level of creation is required. What was never required is a **chain** of
it, and `create_dir_all` supplies a chain.

The fix is `create_dir`: one level, and only when its own parent already exists.
That is the same rule as the root, stated for the other directory, and it closes
both reproductions while keeping the ordinary case working, where a crew
directory sits beside others that exist.

## The test that pinned the wrong behaviour

`provisioning_creates_the_workspaces_parent_before_cloning` builds
`nested/deeper/paja`, where neither level exists, and asserts the parent was
created. It is a correct test of a rule the branch has since decided against, so
it is rewritten rather than deleted: one level is created, two are refused.

That is the useful lesson in this round. A guard being pinned says nothing about
whether the behaviour it pins is wanted. Ten tests fail if the call is deleted,
and every one of them was asserting the thing that had to change.

## The type observation, recorded rather than acted on

Every configured path in `Paths` is a `RelPath`, refused at parse time. The
workspace is a bare `String`, and it is the one configured path that reaches a
`create_dir_all`.

The obvious repair does not work: the workspace legitimately may be absolute and
may leave the root, so `RelPath` cannot express it. What it wants is a type
carrying "absolute or relative, may leave, parent must exist", and inventing that
here would be a design change on a branch that has been trying to land for
thirteen rounds. Named so the next round can take it deliberately.

## What this round does not close, stated because overstating is the pattern

**A workspace configured inside the operator's real `~/.claude` is still
accepted**, provided its parent chain exists. `create_dir` stops homma building
a path into somebody's home; it does not stop homma being pointed at one that is
already there. That is deny item three and it wants its own guard, which needs
the home directory and is a separate unit.

## Three more, from the same review

**`generate.rs` carries a live guard pinned by nothing.** Replacing its
containment check with a bare `create_dir_all` leaves all 344 tests green. Its
twin twenty lines away in `workspace.rs` is pinned. That is the third time this
exact shape has been found, and the second time in a round named for finding it.

**The design template gained a false claim in the round that removed one.** It
says a workspace never writes into a tree belonging to somebody else. Finding one
is the counterexample. Fourth consecutive round to do this.

**The PR body says every guard was checked by deleting it.** One was not, which
is how the unpinned guard above survived.
