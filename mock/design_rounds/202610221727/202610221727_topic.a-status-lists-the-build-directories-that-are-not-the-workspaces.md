# a-status-lists-the-build-directories-that-are-not-the-workspaces


Recorded in the workspace repository's `.shared/research/kaski-harness-and-lints.md`, "Round three", batch two, from op's answers of 18 October. The line, with the options it was chosen among:

> A stray build directory [between homma status and squareup; a hook refusing it; both]: both.

The intent in it: a build directory other than the workspace's one `target/` is a state the workspace reports, from two places, `homma status` and the workspace's `squareup` script, and a hook in the workspace repository refuses the build that would make one. Only the first is this repository's; the hook and the script are the workspace repository's and landed there on `scripts/build-hooks`.

The brief for this part names its content: `homma status` lists any `target/` directory other than the workspace's one, with its size. A known case to hold it against is a bench test that built into `<worktree>/mock/target/mockspace-bench-test`, fixed in mockspace #156.

Settled here without asking, because the canon is silent and the workspace's own script already decided them: what counts as a build directory (a directory called `target` holding `CACHEDIR.TAG`, `.rustc_info.json`, `debug` or `release`), how far down it looks (six levels, not into a build directory, `.git` or `node_modules`, no symlink followed), and that the human output prints the section only when there is something in it while the document always carries the list.
