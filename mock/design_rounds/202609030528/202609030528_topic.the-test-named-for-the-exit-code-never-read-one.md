# The test named for the exit code never read one

Subject: the integration test that exists to pin the command's exit code asserts
a boolean instead, so the split the last round introduced is unpinned.

## Current state

`crates/homma-engine/tests/config_exit_code_smoke.rs` opens by saying the gate
"decides from its exit code alone, so the code is the whole interface between
the two", and that these arms "assert the code rather than the wording". Its
helper returns `out.status.success()`, which is a boolean, so every arm in the
file asks whether the command was zero and none of them can tell `1` from `2`.

That was a small gap while non-zero meant one thing. Round `202609030003` made it
mean two, `1` for a command that ran and reported and `2` for one that could not
run, and the gate now branches on which. Nothing pins that. `main.rs` can go back
to `ExitCode::FAILURE` for the error arm and the whole suite stays green, while
the commit gate silently returns to telling somebody to run
`homma repo config init` over a manifest that does not parse.

The gate side of the split is pinned, at `gates.rs`, but only against a shell
stub that hardcodes `exit 2`. So both halves are asserted against each other's
assumptions and neither is asserted against the binary.

Found by a reviewer over this branch.

## The decision

The helper returns the code, and the arms assert it.

`Some(0)` where the command is expected to pass, `Some(1)` where it ran and
found the repo owing a config, and a new arm asserting `Some(2)` over a
workspace whose manifest does not parse, which is the case the whole split
exists for. `None` is a signal death and is a failure in every arm; nothing here
kills the child.

The unparseable manifest is written by the test rather than borrowed from a
fixture, because what makes it unparseable is the point: a `homma.toml` with no
`[workspace]` table, which is exactly what the previous round's own changelist
recorded as failing to parse at line 1 column 1.

## What this does not do

Nothing about the wording of any of the three cases. The messages are asserted
where they are built, and the file's own opening says that is the split.

Nothing about the parse error pointing at line 1 rather than at the missing
table. Still a defect in the manifest's diagnostics, still not this round's.

## Provenance

Derived, under the autonomous mandate, from a review finding against this
branch. No human was in the loop at the time of writing.
