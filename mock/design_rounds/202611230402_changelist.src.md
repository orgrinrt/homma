## mock/crates/homma-core

- `src/release/writes.rs`: `ReleaseForge` gains `drop_branch(root, branch, head)`; `ByClient` deletes the branch with a git push of its deletion, `ByRoute` asks `forge_route delete-branch <root> <branch> <head>`. `land` is no longer only the release's: its doc says it serves the bump into the trunk too.
- `src/release/landing.rs`: `bump_branch(repo, version)` is back as `release/<repo>-<version>`. `push_bump` takes the version: it returns at once where the remote's trunk is already at the commit, pushes the trunk, and where git's `[remote rejected]` refuses it pushes the commit as the branch, lands it with `ReleaseForge::land` (merge commit, title the bump's subject, at the commit's sha), fetches the trunk back and takes it only as a merge commit whose parents are the bump's parent and the bump and whose tree is the two merged (`ReleaseError::NotLanded` otherwise), moves the clone's trunk to it and drops the branch, best effort. A refusal with `NoPullRequest` drops the branch it pushed and stops. `set_aside` also reads the remote's trunk tip as a landed bump when it is a merge commit titled `chore: release <version>` whose second parent is a bump of that version and whose tree is that merge measured, and the clone's trunk is at the merge, the merge's first parent or the bump; the trunk is set back to the first parent and `Pending` holds the merge. `resume_bump` drops the branch of a taken merge where the remote still holds it.
- `src/release/changelog.rs`: `holds(root, version)`, whether `CHANGELOG.md` already has the heading `## <version>`, alone or with its date; `prepend` adds no block for a version whose heading the file already has, whatever the block's text and date.
- `src/release/run.rs`: `write_bump` writes only what is missing, the version and the block each, and makes no commit where the trunk already carries both; `step_bump` passes the version to `push_bump`; `NotLanded` is documented as the bump's or the release's.
- `src/release/run_dev_pr_tests.rs` (new), `run_pr_tests.rs`, `run_tests.rs` (the fake route's `delete-branch`, the module): a refused `dev` is landed through one pull request into `dev` merged as a merge commit, the branch gone, the clone's `dev` the forge's, by the route; by the client it stays refused with `NoPullRequest` and no branch beside `dev`; a pull request the route merged and reported failed, one the coordinator landed, one landed on a moved `dev` and one the forge resolved to another tree, each on a rerun; a `dev` carrying the bump and the block under any subject gets no commit, and one carrying a half gets the other alone; the old stop-at-`dev` tests are replaced by these and the reruns of `run_pr_tests.rs` stop at a pull request the route failed.
- `src/release/changelog.rs` tests: `holds` reads a heading and no prefix of one, and a block of another text and date for a version already in the file is never prepended.
