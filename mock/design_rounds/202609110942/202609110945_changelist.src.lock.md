# src changelist: workspace agent hooks that chain

Implements `202609110942_changelist.doc.lock.md`, section by section, against
`## The agent hooks` in `mock/DESIGN.md.tmpl`.

## CHANGE: `homma_api::agent_hooks` FROM absent TO the `[agent.hooks]` table
File: `mock/crates/homma-api/src/agent_hooks.rs`, `mock/crates/homma-api/src/lib.rs`

`AGENT_EVENTS` names the host's events as it names them, `AgentHook` is one row
(`matcher`, `run`, `repos`) built through `AgentHook::new` and nowhere else,
`AgentHooks` is the rows per event with an event outside `AGENT_EVENTS` refused
at load, `AgentTable` is `[agent]` holding `hooks` and nothing else, and
`InvalidAgentHooks` says why a table or a row is refused. A `run` that is
empty, absolute, climbs out with `..` or carries whitespace is refused, since
the design makes it a path under the workspace; a `repos` entry that is blank or
a path is refused; a row naming no matcher gets `*`. Unknown fields on a row or
on `[agent]` are refused.

Verification: `cargo test -p homma-api agent_hooks`, nine tests, each refusal
checked for its own reason and every event in `AGENT_EVENTS` loading.

## CHANGE: `homma_core::Config` FROM no `agent` TO `agent: homma_api::AgentTable`
File: `mock/crates/homma-core/src/config.rs`

`#[serde(default)]`, so a manifest without `[agent]` loads as before, and the
config's `deny_unknown_fields` now accepts the table rather than refusing the
file.

Verification: the homma-core suite loads every existing fixture manifest
unchanged.

## CHANGE: `aggregate::HookEntry` FROM `{ matcher, command }` TO `{ event, matcher, command }`
File: `mock/crates/homma-engine/src/cmd/aggregate.rs`, `gates.rs`

An empty `matcher` writes no `matcher` key, which is how a registration that
named none is carried. The workspace gate's entry is `PreToolUse`.

## CHANGE: ownership FROM a `<repo>--` name prefix TO `MANAGED_MARK` in the file
File: `mock/crates/homma-engine/src/cmd/aggregate.rs`, `gates.rs`, `declared.rs`

`MANAGED_MARK` is the words every file homma writes under `.claude/hooks/`
already carried or now carries, and `carries_the_mark` reads it off a comment in
the first five lines. Three places honour it:

- `clean_stale` for hooks removes a stale `<repo>--*.sh` only when it carries
  the mark (`Sweep::Marked`); the retired rule copies keep `Sweep::Everything`,
  since they predate the mark and nothing but homma ever named them that way;
- a wrapper, a declared wrapper and the workspace gate are each refused, by path
  and with a problem reported, when the file they would write is there without
  the mark;
- `merge_settings` sweeps a registration only when it is a retired shape or a
  managed name whose file is absent or marked, via
  `names_a_file_homma_did_not_write`.

The gate's own logic, what it checks and denies, is unchanged, as the doc
changelist says; its install is what now honours the collision rule every file
homma writes is under.

## CHANGE: registrations FROM `PreToolUse` only TO every event and matcher a repository gives
File: `mock/crates/homma-engine/src/cmd/aggregate.rs`

`read_settings_hooks` returns, per hook file name under `.claude/hooks/`, every
`Registration` (`event`, `matcher`, `args`) the repository's `settings.json`
gives it, a registration with no matcher included. `hook_file_named` reads the
file off a relative path, the host's project-root placeholder or an absolute
one. The `@matchers:` line still stands in where the repository gives none, and
registers under `PreToolUse`. Whatever followed the hook's path on its command
line is carried onto the wrapper's registration, and the wrapper passes `"$@"`
on, so an argument the host would have handed the hook still reaches it.

`merge_settings` sweeps and writes every event array rather than only
`PreToolUse`, and drops an entry or an event only when its own sweep emptied
it; a malformed entry, an empty one or an empty event somebody wrote is kept.

## CHANGE: `merge_settings` and its predicates FROM `aggregate.rs` TO `aggregate_settings.rs`
File: `mock/crates/homma-engine/src/cmd/aggregate_settings.rs`, `aggregate.rs`

The settings half of aggregation moves to its own file, a child module of
`aggregate` re-exported from it, so `aggregate.rs` stays under the size a file
here is meant to keep and every caller names the same paths as before.
`merge_settings`, `names_a_file_homma_did_not_write`, `is_aggregated_command`
and `is_retired_aggregated_command` move unchanged apart from what the two
changes above and below describe.

## CHANGE: which files are hooks FROM every `*.sh` TO every file the host can run
File: `mock/crates/homma-engine/src/cmd/aggregate.rs`

Every regular file under a repository's `.claude/hooks/` except hidden ones,
which are an editor's or a filesystem's. `is_executable` decides: one that is
not is reported by path. One with neither a registration nor an `@matchers:`
line is reported by path and no wrapper is written. A name not ending `.sh`
gets `.sh` on its wrapper, which is bash whatever the hook is written in. A name
that is not UTF-8 is reported. `aggregate_repo` returns `Aggregated`, the count
and the problems.

## CHANGE: narrowing FROM `$PWD` for a shell call TO the host's `cwd`
File: `mock/crates/homma-engine/src/cmd/aggregate.rs`

`TARGET_JQ` is `.tool_input.file_path // .tool_input.path // .cwd //
.tool_input.cwd // empty`: the file a file tool writes, then the directory the
host says the session is in, then one the call carries, and `$PWD` last. Both
wrapper kinds use it.

## CHANGE: `cmd::declared` FROM absent TO the manifest's own rows
File: `mock/crates/homma-engine/src/cmd/declared.rs`, `cmd/mod.rs`

`install_declared` writes `_declared--<event>--<run as a name>.sh` per row, a
second row under one event running the same script taking `--2` and so on,
each carrying the mark. A row with no `repos` hands every call on; one with
`repos` is narrowed to calls landing in them, resolved through the manifest's
own paths. A `run` naming no file, one not executable, and a repository the
manifest does not name are reported and the row not registered. A marked
`_declared--*` no row wrote this run is removed; an unmarked one stays.
`is_declared_command` lets `merge_settings` recognise the registrations.

## CHANGE: `agent regen` FROM silent drops TO a failing report
File: `mock/crates/homma-engine/src/cmd/agent.rs`

`RegenReport` gains `hooks_not_carried`, printed under its own heading. Any
problem from a repository or a row fails the run, exit `1`, without stopping the
loop, since the hooks that could be carried were. The declared rows are
installed on every run, a one-repository run included, because the merge sweeps
their registrations and writes back only what it is handed; if installing them
fails outright, `settings.json` is left as it was.

## Tests

`aggregate_chains_tests.rs`, thirteen, and `declared_tests.rs`, nine, beside the
existing aggregation suite, which is updated for the new entry shape and now
marks its planted hook executable. Negative controls, run before this was
written: with `carries_the_mark` returning true for every readable file, the
seven tests about files homma did not write fail and nothing else does; with
`.cwd` taken out of `TARGET_JQ`, the two narrowing tests fail at the shell call
inside the repository; with a registration lacking a matcher skipped, the
every-event test fails. All three restored, the three crates' suites pass except
two tests that fail the same way on `dev` without this change:
`the_readme_examples_are_real` (`homma workspace` is a launcher verb the engine
binary does not have) and `a_422_on_create_is_already_exists_only_when_the_body_says_so`,
which fails under a full parallel run and passes alone.
