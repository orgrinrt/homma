# The launcher's first round said two things that are not true of the tree

**Phase:** TOPIC

Two findings from the review of the pull request that put homma on its own
launcher. Both are about the record rather than about the code, and neither is
fixable by editing what is already locked.

## The design document still calls `homma` the command surface

`mock/DESIGN.md.tmpl` line 61 reads:

> `homma` is the command surface.

That was true until the launcher landed. It is not now: `homma` is the launcher,
a descriptor and a process entry over the shared launcher machinery, and
`homma-engine` is the command surface. The sentence is a claim about the shipped
tree and the shipped tree disagrees with it.

The previous round's doc changelist declared no document changes, on the reasoning
that the engine crate ships no per-crate design document. That is true and it is
the wrong scope: the sentence lives in the root design document, which the round
never looked at. `docs/DESIGN.md` is generated from it and is what a stranger
reads, so a public document currently asserts the wrong thing.

## The locked source changelist says the launcher publishes, and it does not

`202608242239_changelist.src.lock.md`, under `## CHANGE: homma/launcher/`, says
the package is added with `publish = true`. The shipped manifest says `false`,
flipped after the round closed, because a git dependency on an unpublished crate
cannot ship and `cargo deny` reports it as a wildcard.

A locked changelist is frozen and is meant to be the truth about what shipped, so
the correction belongs in a later round rather than in a quiet edit to the file
that made the claim. The flip is temporary: it goes back to `true` the day the
launcher machinery publishes, and that will be its own round again.

## What this round does

Fixes the sentence in the root design document, regenerates, and records the
publish flip in a source changelist so the audit trail carries it.
