# homma-what-answers-how-to-questions-from-the-tools-readmes


Op, 28 October 12:20, verbatim: "Isn’t there already a homma what tool for discovery?" and "And if the what tool doesn’t answer a question like that, well… it should".

The question that went unanswered was how to read an earlier message on a msg channel, which the readme of the `msg` tool answers (`msg <ch> show <id>`, `show --from <name> -n N`). The intent is that `homma what` answers a how-to question about a tool of the workspace from what the tool says about itself. The wording of the sketch (a readme as the source) is a vehicle.

What was checked in the tree:

- `homma what read an earlier message on a msg channel` answers with `homma msg` as the first hit and its one summary, "the messenger over channel branches", and matched `read` in a verb summary of the one command the descriptor declares. It does not say that `show` is the verb, nor print a command that reads an earlier message.
- The tool source reads `tool.toml` only: the name, the summary, the tags and each declared command with its summary. The readme beside it is not read, and the readme is where the forms are written (`msg kaski show 3f9a1c   one message whole, read or not`).
- The scripts source already reads a usage line of a header as a verb, and keeps the prose after the summary as the rest of the header, so a script's own forms can be found. A tool has no counterpart.
- The toolbox list, `tools/toolbox/tools.tsv`, is a workspace file of one workspace, and homma has no business knowing it, as `[[status.inject]]` shows. It is not a source.

The round owes:

- The tool source reads the readme beside the descriptor: the prose is the rest of the tool's text, and each usage line in a fenced block is a verb with its words, its summary and its exact command.
- Which lines count as a usage line, and what the command of one is when the tool is dispatched as `homma <name>`.
- The acceptance case: the question above finds the usage line of `show` and prints the command.

Other topics filed and open in this directory, each named so none is missed:

- `capture-answers-left-on-a-page`: out of scope; it is about `homma capture`, and `what` does not touch it.
- `how-a-provisioned-workspace-defends-its-identity-against-the-environment`: out of scope; it is about the identity a provisioned workspace commits as.
- `what-a-stranger-cannot-reach`: out of scope; it is about the published surface of the repository.
- `work-only-on-the-repos-the-instance-names`: out of scope; `what` already keeps to the instance scope for its one source that starts a process, and this round adds no source that reads outside the workspace root.
- `homma-what-finds-the-tool-that-does-a-thing`: the subject of this round; the command it asks for exists, and what this round adds is one more thing for it to read.
