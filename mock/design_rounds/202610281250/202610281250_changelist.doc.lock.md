# doc changelist

Answers the topic filed in this round, `homma-what-answers-how-to-questions-from-the-tools-readmes`, and amends the section "Finding a tool" of `mock/DESIGN.md.tmpl` that the closed round `202610271140` left. The other open topics are named in the topic file, each with the reason it needs nothing from this round.

## Current state

The section reads a tool from its `tool.toml` alone: the name, the summary, the tags and each declared command with its summary. A tool whose forms are written in its readme and not declared one by one, such as `msg`, whose channel is an argument and whose verbs follow it, is found by its one summary, and the answer cannot say which form reads an earlier message.

## Changes proposed

- Tools: the readme beside the descriptor, `README.md` in the tool's directory, is read as well. Every line in a fenced block that begins with the tool's name or the name of one of its commands is a usage line. A usage line is a verb: its name is the words after the command, its summary is the text set off by a column gap of two spaces or more (empty where there is none), and its command is the line without that text, with the tool's own name replaced by the command that dispatches it (`msg kaski show 3f9a1c` is answered as `homma msg kaski show 3f9a1c`). A line already read as a declared command is not read twice.
- Tools: the prose of the readme is kept as the rest of the tool's text, weighed as the rest of a script's header is.
- Footer: a tool whose readme cannot be read is searched by its descriptor alone, and nothing is said, since a readme is not required.
