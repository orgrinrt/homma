# What the review found on the release

**Date:** 2026-09-02
**Phase:** TOPIC
**Scope:** the source of `homma-core/src/release/` and the root `README.md`, after the round `202609022140` closed and its pull request was reviewed
**Source topics:** the review of pull request 46, and `202609022140/202609022115_topic.a-release-is-a-gated-merge-off-main.md`, which nothing here changes

## The five findings

The readme's command table does not name `release`, and the engine carries a test that reads that table against the command tree, so the suite is red on the branch. A row is added.

The jsr token travels on `deno publish`'s arguments, which is the one way that tool takes it, and on a failed publish the command line the error carries printed the token verbatim. The token is redacted out of the error, and the test that pinned the leak now pins the redaction. The module documentation said every token reached its tool through the environment, which was true of two of the three; it now says which one is the exception and why.

`deno publish` was run with `--allow-dirty`, which the design does not name and which undoes deno's own refusal to publish an uncommitted tree, in a tool whose gate refuses one. It goes.

A failure in the merge, the tag or a push inside the release left the tree on the release line. The step now aborts the merge where one is in progress and hands the tree back to the trunk before the error is reported, so a failed release leaves the branch it borrowed.

## What does not change

The design. Every fix is the code doing what the deep dive already says, so the doc changelist of this round names no template.
