# Doc changelist: the deny list's own description was the defect

## CHANGE: `mock/crates/homma-org/DESIGN.md.tmpl`

**`:77`, "So the check is by absolute path and never by name", is false.**
`starts_with` compares components byte for byte, which is by name, and two
absolute paths routinely denote one directory: a case-insensitive filesystem and
a macOS firmlink are two independent routes, both reproduced. Replaced with what
a directory is, `(dev, ino)`, and why the lexical comparison stays beside the
identity one rather than being replaced by it.

**`:138-142` is stale in the document that added the guard.** It says a workspace
pointed at a directory inside somebody's home "is still accepted" and "wants a
guard that knows where home is". The guard exists; that paragraph describes the
state before it. Rewritten to say what the deny list now reaches and what it
still does not, which is the aggregation pass.

**The scope note is added rather than implied.** `homma agent regen` does not go
through this check at all, so the deny list is currently a property of one
subcommand. The README says so and the design document did not.
