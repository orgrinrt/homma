# src changelist

The launcher's half of the round: the four settings on the descriptor, the
one command, the modules that answer it, and the tests against real
repositories. Descends from the locked doc changelist
`202609041523_changelist.doc.lock.md`. The launcher sits outside `mock/`, so
these are claims about `launcher/` and the verifications run from the repo
root.

## CHANGE: the launcher's `renki` requirement FROM `"0.0.1"` TO `renki's dev branch, with renki-config beside it`
File: `launcher/Cargo.toml`, `launcher/tests/a_publishing_crate_is_publishable.rs`
Verification: `grep -c 'git = "https://github.com/orgrinrt/renki.git", branch = "dev"' launcher/Cargo.toml` is 2; `grep -n 'FIXME: a git requirement is not publishable' launcher/Cargo.toml` returns one match; `cargo test --test a_publishing_crate_is_publishable -- --ignored` fails on `this_launcher_is_publishable` naming the git dependency, which is the catalogue being red until the renki release.

## CHANGE: `TOOL` FROM `no settings, no commands` TO `settings::SETTINGS and workspace::COMMANDS`
File: `launcher/src/lib.rs`
Verification: `grep -n 'settings: settings::SETTINGS\|commands: workspace::COMMANDS' launcher/src/lib.rs` returns two matches inside `TOOL`, and the build-time `TOOL.defect().is_none()` assertion beneath it still compiles, which `cargo build` shows.

## CHANGE: `settings` FROM `absent` TO `four user-scope rows, `Prefs` read off an `Invocation`, and the `disallowed_roots` check with the `/*` form`
File: `launcher/src/settings.rs`
Verification: `grep -c 'Setting::<' launcher/src/settings.rs` is 4 and `grep -c ', User>' launcher/src/settings.rs` is 4; `cargo test settings::` is green over three unit tests; `cargo test --test the_workspace_command_runs_where_there_is_no_workspace the_home_directory_is_refused` is green, with the plain form, the subtree form, a link to the home, an absolute entry and an empty list each asserted both ways.

## CHANGE: `workspace` FROM `absent` TO `the command, split by verb: mod.rs parses, git.rs runs git, status.rs surveys, spawn.rs clones, reap.rs removes and lists`
File: `launcher/src/workspace/mod.rs`, `launcher/src/workspace/git.rs`, `launcher/src/workspace/status.rs`, `launcher/src/workspace/spawn.rs`, `launcher/src/workspace/reap.rs`
Verification: `grep -n 'name: "workspace"' launcher/src/workspace/mod.rs` returns one match inside `COMMANDS`; `wc -l launcher/src/workspace/*.rs` shows every file under 500; `cargo test workspace::` is green over the verb parser, the url spelling and the clone-name tests; `cargo test --test the_workspace_command_runs_where_there_is_no_workspace` is green over six tests, which spawn by slug and in place, refuse before touching the disk, survey, refuse a reap on a dirty tree and on an unpushed commit, remove after a push and under `--force`, and run the built binary with no manifest above the cwd for `workspace list`, `workspace spawn`, a `--cfg` after the name, `config schema` and two refusals on stderr.

## Not changed, and why

The engine gains nothing. The org design's workspace lifecycle in
`homma-org` is a different thing and the topic file says how. The two spawn
scripts in the workspace repository and the rules that name them are the
workspace repository's to change, once this launcher is installed there.
`workspaces_root` defaults to `~/workspaces`; the value on this machine goes
in the person's file through `homma config set`, not in the source.
