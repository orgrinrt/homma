# dispatcher-review-residuals

The third and last review of the dispatcher (rounds 202611231639 and 202611231716) resolved its earlier findings
and left one should-fix and a note worth taking:

- Where several hooks answer and one gives a `permissionDecision` that is not a string, the shape check passes it,
  the fold's ranking fails on it, and an `ask` a sibling gave is lost: the run exits 1 and the call goes on
  unconfirmed, where the host running the two apart would have asked.
- A registration carrying `"args": []`, which the host's own example carries, or the cosmetic `statusMessage`, is
  refused as carrying a field the dispatcher does not carry, and fails the regen.

## Decision

- An answer whose `permissionDecision` is present and not a string is malformed, read as a `systemMessage` naming
  it, so the fold runs over the rest and an `ask` or a `deny` beside it stands.
- `"args": []` carries nothing and is let through. `statusMessage` only labels the spinner while one hook runs;
  under the dispatcher there is no one hook to label, so it is let through and not carried. Any other field is
  still refused.
