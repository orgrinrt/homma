# Src changelist: homma owns the rule corpus

## homma-api

**ADD `rule`**, the vocabulary a rule declares about itself and the reader for
it. `RuleMeta` carries `topics`, `fires`, `kind` and an optional `paths`;
`RuleKind` is `reflex` or `discipline`; `Parsed` splits a file into its meta and
its body, and splits that body at `ELABORATION_MARKER` into the card and the
elaboration.

**The reader takes `key: scalar` and `key: [a, b]` and refuses everything else
by name and line.** A YAML parser would accept nested maps, anchors, block
scalars and multi-document streams, and the generation pass can render none of
them, so each would be a file that parses and then produces something nobody
asked for. It also keeps a yaml crate out of a dependency graph that has none,
which `deny.toml` would otherwise have to carry.

**`score` matches a query term against a topic as a substring in both
directions**, so `writing` reaches `writing-style` and `readme-format` reaches
`readme`. Equality answers neither, and that is the whole failure the field
exists to prevent: a query in the question's words against a corpus written in
the answer's.

No I/O, per the crate's own rule.

## homma-org

**ADD `rules`**, the corpus. `Corpus::load` reads every `<name>.md.tmpl` under a
directory, `about` ranks by how much of a query each rule answers, `render_cards`
writes the card prefix per rule, and `render_full` puts both halves back
together for a fetch.

**Three refusals rather than skips**, each for the same reason: skipping
produces a smaller, healthier-looking corpus than the one on disk, which passes
every check and governs less than it claims. A meta that will not parse refuses
the whole load and names its file; a template naming something the meta does not
have is refused, which is what the engine's strict undefined handling buys; and
a missing directory is refused rather than read as a workspace with no rules.

**A rule's name carries no dot.** Without that guard `x.card.md.tmpl` strips to
a rule named `x.card`, which then fails to parse and refuses the corpus for a
file that was never a rule. Permanent, not migration scaffolding.

**DEP `mockspace-template`**, the engine every `mock/*.md.tmpl` already renders
through. A second templating language for this would be a second language for
rule authors to know and a second one to carry the planned extensions.

## homma-engine

**ADD `cmd::rules`** and the `Rules` command with `about` and `render`.

**An empty `about` says nothing matched the topics, not that nothing governs the
subject.** The second is a claim the search cannot support: a rule may govern it
and simply not say so, and reporting otherwise sends the caller away certain.

## What is not here

**No `budget` and no `size`.** The nutshell tool in the workspace holds those
and whether they are homma's is a separate question from whether the corpus is.
Moving them because the neighbouring half moved is the reasoning
`a-homeless-document-is-a-design-problem` rejects.

**No hook, and no refusal of a hand-edited generated card.** Both want the
corpus fully migrated first, since a gate over a half-converted corpus refuses
the commits that convert it.

## Tests

**37 across the two crates**, and the refusals are most of them, which is what a
narrow reader should produce.

One fixture defect worth recording because it invalidated a whole run: the
fixture keyed its directory on the process id, and the tests in one binary are
threads sharing one, so each test's setup deleted the others' out from under
them. Nine of eleven failed on that race rather than on anything they asserted.
