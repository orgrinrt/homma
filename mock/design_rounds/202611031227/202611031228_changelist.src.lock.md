# src changelist

Source for the doc changelist `202611031227_changelist.doc.lock.md`, round `202611031227_topic.release-roots-without-an-unmaintained-crate.md`. The roots the HTTP agents trust stay the system's, and the lock stops holding `rustls-pemfile`; the three agents of the crate (the registry requests, the GitHub client and the Forgejo client) get their roots from one place, which the correction in the topic found they needed. `Cargo.lock` and `mock/Cargo.lock` follow the manifest and drop `rustls-native-certs` 0.7.3 and `rustls-pemfile`.

CHANGE mock/crates/homma-core/Cargo.toml: `ureq` takes the `tls` and `json` features and no longer `native-certs`, and `rustls-native-certs` 0.8 is a direct dependency, so the roots are read here and the lock holds no `rustls-pemfile`
CHANGE mock/crates/homma-core/src/tls.rs: a new crate-private module with `agent_builder`, an `ureq::AgentBuilder` that carries a `rustls` client config built once per process from the roots `rustls_native_certs::load_native_certs` returns, with the `ring` provider and the TLS 1.2 and 1.3 versions `ureq` picks for itself
CHANGE mock/crates/homma-core/src/lib.rs: declares the private module `tls`
CHANGE mock/crates/homma-core/src/release/registry.rs: `agent` starts from `crate::tls::agent_builder()` where it started from `ureq::AgentBuilder::new()`, and keeps its user agent and timeout
CHANGE mock/crates/homma-core/src/forge/github.rs: the client's agent starts from `crate::tls::agent_builder()`, with the user agent and the same-host redirect policy it had
CHANGE mock/crates/homma-core/src/forge/forgejo.rs: the client's agent starts from `crate::tls::agent_builder()`, with the user agent it had
CHANGE mock/crates/homma-core/src/tls_tests.rs: a new test file, two tests over the source of the crate: `no_agent_is_built_outside_the_module_that_sets_the_roots` scans every non-test `.rs` file under `src` for `AgentBuilder::new` and expects none outside `tls.rs`, and the control `the_scan_names_a_file_that_builds_an_agent_from_nothing` plants a clean file, a bare one and a test file in a scratch directory and expects the scan to name the bare one only
CHANGE mock/crates/homma-core/src/release/registry_tls_tests.rs: no change; `a_request_trusts_the_roots_ssl_cert_file_names_and_only_those` of the closed round is the check on the new loader, and it fails with `tls_config` left out of `agent_builder` and with a root store that reads nothing, and the scan test fails with the github client's agent put back to `ureq::AgentBuilder::new()`, each run as a mutation before the lock
