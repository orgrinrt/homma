# The autofix output wants committing

**Phase:** TOPIC
**Scope:** `homma-org`, `homma`

The pre-commit hook runs rustfmt and `clippy --fix` over what is staged and
writes the result to the working tree. When that write happens during the commit
that closes a round, the reformatted lines are left uncommitted in a tree whose
phase no longer allows source edits, and the next push is refused.

Nothing is wrong with the output: an import sorted into order and four argument
lists wrapped. This round exists to land it, because reverting it only means the
next commit's autofix produces it again.

**The lesson is about ordering rather than about formatting.** A round is closed
after the tree is clean, not after the last interesting commit. The gate caught
this correctly and refusing the push was the right behaviour.
