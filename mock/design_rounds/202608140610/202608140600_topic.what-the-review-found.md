# Topic: what the review found, and one claim it made that I could not

**Date:** 2026-08-14
**Phase:** TOPIC
**Scope:** six blocking defects, and a correction to a locked changelist
**Status:** settled

A review of the taxonomy round's output found six blocking defects. Two of them
ship a broken binary. Reproduced before any of this was written:

## The two that matter most

**Two parsers read one file and one denies what the other requires.**
`homma_core::Config` is `deny_unknown_fields` over four tables;
`homma_api::Workspace` requires `content_repo`. Every subcommand except `org`
goes through the first, so the moment the design's one required key lands, they
all die:

```
$ homma status
error: loading config from homma.toml: unknown field `content_repo`
```

The key is already committed on the content-repo side, so this is not a future
hazard. No test caught it because no test ever built a file carrying both halves.

**`homma org up op` manufactures a dispatchable agent for the human.**

```
$ homma org up op
op /tmp/optest/.shared/experts/op
  definition /tmp/optest/.claude/agents/op.md
```

Under the one handle that derives `Rung::Ratified`. The design closes the
impersonation route from one side and this opened it from the other. `missing()`
returns empty for any role without a workspace, so nothing refused.

## The other four

**Frontmatter is `format!`ed with no escaping**, so a newline in a registry
string writes arbitrary keys. A Hand can grant its own twin `memory: project` by
editing its own nickname, which defeats the one restriction the design insists is
structural rather than instructed.

**A kind name goes straight into a path** and `create_dir_all` makes traversal
succeed rather than fail. Kinds are configuration by design, so this is reachable
from a file every participant can edit.

**`append` enforces no id uniqueness**, so an append-only kind can be
contradicted by appending a second record under an existing id, without ever
touching the guard that refuses rewrites. The mutation check measured the guard
that exists and not the hole beside it.

**`read_to_string(...).unwrap_or_default()`** swallows every error rather than
absence, so a Hand ships without its character and nothing reports it.

## The correction I owe, which is worse than the defects

The taxonomy round's **locked** source changelist claims verifications that were
never performed:

- a test creating a workspace and asserting the git identity is set in the clone
  and not globally. **No such test and no such code.** homma-org neither clones
  nor sets a git identity; a human did it by hand.
- unit tests over rung derivation for every namespace. **Three of five have
  none**, and `Rung::Derived` is asserted nowhere.
- `homma work create`, `homma work list`, and a smoke test asserting a non-tty
  invocation prints no decoration. **None exists**; there is no tty sensing in
  the tree at all.
- an inventory naming `Handle` and `Ref` as types built. Neither was.

The changelist is locked and is not edited: this file is the correction, and it
sits beside it in the archive. `DESIGN.md.tmpl` repeats the tty claim in the
present tense and is fixed in this round, because it is not locked.

**This is the same defect this workspace has caught repeatedly: a claim written
in the shape of a verification, in a document whose whole purpose is that its
claims were checked.** The one honest verification in that file, the mutation
check on the immutability guard, makes the rest worse rather than better, because
whoever wrote it knew what the word means.

## One thing the review handed back rather than deciding, and it is op's

The public-surface wall says nothing about this system appears outside the
content repo, and names member repos' commit messages and PR text. **homma is a
member repo**, and it is also the tool that implements the system, so the wall as
written forbids homma's own source from describing what homma does. The design
itself puts `homma sauna` in the command surface.

The canon does not settle whether the implementing repo is inside or outside the
wall. It wants deciding before the roster grows, because every later crate
inherits the answer. Left open deliberately.
