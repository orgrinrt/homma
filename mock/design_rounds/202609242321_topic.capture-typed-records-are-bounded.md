# capture-typed-records-are-bounded

The third review of the capture branch, over it and the workspace change that
makes the self-compact tool write its records, found three things wrong here.

A record takes the first matching line stamped at or after its `at`, with no
end. The tool writes the record before it types and nothing confirms the typing
arrived, so a paste that failed leaves a record that takes the person's own
`Continue` hours later. That breaks the design's own sentence that the person
typing the same words later is still the person. The fix bounds the match: a
record takes a line stamped within sixty seconds after its `at`. The tool types
within a few seconds of writing, and a queued paste drains once its escape ends
the turn, so sixty covers both with room. The two ways of being wrong are not
alike: a tool's line landing later than that is quoted as the person's, which
is visible in the file and harmless, while an unbounded match drops the
person's words where nobody sees it. So the bound is short and errs to keeping.

The one-record-one-line half of the match is untested: two records with the
same text taking one line passes the suite. A test of two records and two lines
pins it.

The project directory a transcript sits under is the workspace path with every
character that is not an ASCII letter or digit spelled `-`, and the harness
counts characters as UTF-16 units, so a character outside the basic plane is two
dashes. `store::escaped` counts it as one. The self-compact tool's spelling is
made the same in the workspace change.

The public design says the context around a message is summarised "once muisti
builds where homma runs", which is a plan in a public document. The sentence
goes, and the design says only what the file holds.
