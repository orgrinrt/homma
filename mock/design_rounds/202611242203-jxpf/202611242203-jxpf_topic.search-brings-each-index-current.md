# search-brings-each-index-current

Follows the closed rounds 202611240919, which added `homma search`, and 202611241014, which made
an index not built a line of its own. The design says how far an index is behind its files is its
owner's to say, and homma says only when each was last written. The index crate now records in
each index file the definition it was built from, and an opened index can say how far it is behind
that definition and bring itself current under it (`layer::Index::behind` and
`layer::Index::refresh`). So the owner's own measure and refresh are reachable through the crate,
with no definition held twice and no command run.

The intent: an answer is as current as the indexes can be made at the moment of the question, and
where one cannot be, its line says how far behind it is and why. Fidelity before speed: a refresh
is part of asking.

## An index brought current before it is asked

Decision: each place whose file opens is brought current through `Index::refresh` with the
embedder the verb brings, before the question is put to it, one index at a time as the question
already goes. Its line says what the refresh did: so many documents added, changed and removed,
and commits read where the index keeps a history, or that it was current. A refresh writes only
what moved; that is the index crate's.

## An index that cannot be brought current

Three cases, each a line saying how far behind the index is and why, measured by `Index::behind`
where it can be, and the index then asked as it stands:

- An index of another model than the verb's embedder. The verb brings no embedder of its own
  beyond the words, so a corpus whose vectors are another model's is not refreshed: its line says
  how many files it is behind by and that its vectors are that model's.
- A refresh refused or failed (another writer holding the file past the wait, the walk's or the
  store's error): its words, then how far behind where that can still be measured.
- A file that records no definition, written before the record was kept: how far behind is not
  known, and the line names the command that writes one.

## An index not built

Unchanged in that it is a line and not asked. Decision: the line names the command that builds
it. That is configuration, not homma's knowledge of a member's layout: two new keys under
`[search]`, `corpus_build` (default `muisti index`, run in the corpus's directory) and
`member_build` (default `cargo mock search --refresh`, run in the member's clone). The verb never
builds an index from nothing inside a question: a build is a sitting of its own.

## When the file was last written

Kept, beside how far behind: it says how old the answer's ground is where the refresh could not
run.
