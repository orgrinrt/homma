# The guard was on a path nothing writes to

The previous round added a deny check to `agent regen` and the check is on
`<workspace>/.claude`, as one string. **Every write is built below that with bare
`Path::join`, which resolves nothing.** A symlink one component down carries all
of it out, and the eighteenth review reproduced it twice at exit 0, printing
`regen: ok`:

```
$ ln -s $HOME/.claude/hooks $WS/.claude/hooks
$ ln -s $HOME/.claude/rules $WS/.claude/rules
$ homma --config $R/homma.toml agent regen --skip-cargo-mock
regen: ok
EXIT=0
```

`$HOME/.claude/rules/notko--precious.md` deleted. `$HOME/.claude/hooks/notko--precious.sh`
deleted. Two new `-rwxr-xr-x` scripts written in their place, and a third run
rewrote `settings.json` to register them.

**Eighth occurrence of the class `contained.rs` names in its own first sentence**:
a round guards a path a caller passed in, while the paths actually written to are
computed downstream and never guarded. The branch built the instrument for this
and did not use it: `Root::contain` resolves the whole path and mints a
`ContainedPath` the write functions are the only consumers of. `org up` goes
through it. `agent regen` got a hand-rolled prefix check instead.

So the next check is not "is there a guard near this write". It is **which path
does `fs::write` receive**.

## The deferred question was answered by accident, in the strictest direction

The round said it was splitting the cheap half from the hard half and deferring
the hard one. **The split was never made.** `Denied::from_env()` is the whole
home-derived list and carries `Dev/clause-dev`, so the check refuses the central
clone too, and `homma agent regen` now exits 1 on the workspace configuration that
ships:

```
error: .../Dev/clause-dev/.claude is under .../Dev/clause-dev,
       and nothing may be written there: the central clone is read, never written.
```

Four surfaces and the PR body said the opposite, and the comment above the check
predicted the consequence in the sentence denying it: "refusing it would forbid
the tool its own purpose". It did.

## Op's answer, and the derivation from it

Put to op as a blocking question. His words:

> Hand may not write. And the agent regen should run against their own clause-dev
> repo... they all start with the workspace, very same as the current
> ~/Dev/clause-dev, no? So nobody would be regenerating the "central" ones expect
> for me, who is now the "hand" owning that one.

Recorded as round 44 of the crew notes. The options he was choosing among were:
the list is for Hands and not for homma, so the check comes off; enforce it and
move the central clone's aggregation elsewhere; enforce it with an explicit
override; or teach homma who it is acting as.

**The derivation, which is mine and should be read as mine.** Deny item one is
deny item two applied to op. The central clone is **op's workspace**, and a Hand
may not write there for the same reason no participant may write into another's.
Op may, because it is his, and you do not deny somebody their own workspace.

That is exactly the two-list distinction already built for `org up`, where the
standee's own workspace is denied under the root and not to itself. So the shape
already exists and this is the second consumer of it rather than a new mechanism.

And the case barely arises, which is op's own point: every Hand's workspace **is**
a clause-dev clone of the same shape, so a Hand regenerating theirs is the
ordinary path, and the central one has exactly one owner.

## What that makes the deny list for the aggregation pass

- `~/.claude`, always. Never a workspace, never an aggregation target.
- **Every participant's workspace except the one being written into.** The
  registry knows where those are, and the one being written into is the actor's
  by definition.
- **Not `~/Dev/clause-dev` as an absolute.** It is covered by the previous item
  for every Hand, whose registry lists op with that workspace, and it is not
  denied to op, whose workspace it is.

## The other guard nothing pins

`Root::contain_under`'s re-proof. Replacing its body with `Ok(ContainedPath(base.0.join(tail)))`
leaves 384 tests passing and zero compile errors, and that mutation reverts the
method to exactly the convention it was created to replace. Its own doc argues
the case: "Callers that keep a convention correctly four times out of four are
still one careless call from the eleventh review."

Its production caller feeds `memory`, `notes` and `character`. The first two are
covered downstream by `create_dir_all`'s re-proof; `character` is not, and
`generate.rs` reads through it into the generated definition, so the mutated form
both leaves the root and skips the deny check on a read.

Eighth instance on this branch, and the file's own standard applies: defence
nothing pins is defence somebody deletes.
