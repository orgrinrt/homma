# Verify never asked whether a repo is there

Four repos in the workspace manifest were recorded under the wrong owner. Three
viola repos said `orgrinrt` and are `hiisi-digital`; the stack lint pack said
`hiisi-digital` and is `orgrinrt`. The `owner` field builds both the API path
and the clone URL, so every forge operation against those four had been 404ing
for as long as the entries had existed.

`homma verify` passed the whole time. It checks that a repo names a declared
forge and that the forge's token variable resolves. It never asks the forge
whether the repo is there, which is the one check that sees a wrong owner.

The rules table in the workspace carried the same four errors, so the two
artifacts agreed with each other and neither could catch the other. That is
what a check is for.

## Why it is a flag rather than always on

`check` is offline and pure and worth keeping so: it is one function over parsed
config, it has no fixture cost, and it runs in a test without a network. A
lookup per repo is twenty-four round trips against a manifest this size.

So `--forge` is opt-in, and the offline half is unchanged.

## The negative that is not a negative

First run of the check reported all twenty-four repos as absent from their
forge, including ones confirmed present minutes earlier. Every repo here is
private, and GitHub answers 404 for a private repo exactly as it does for one
that does not exist, so an unauthenticated lookup cannot tell them apart.

A check that is wrong by default is worse than no check, because people learn to
skip it. So where the forge has no token in the environment, the command says
that answers from it are not evidence and asks nothing. With a token, a negative
is a real finding.

## And the noise it was making

`verify` warned once per repo whose `local_path` is absent. Under the
one-workspace-per-session convention a workspace clones the repos its work
touches, so nineteen of twenty-four are absent from any given one and the
warning buried everything that meant something. It is gone; absence is the
ordinary case.
