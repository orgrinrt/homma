# Topic: what a stranger gets, and what it tells them

**Date:** 2026-08-25
**Scope:** `denied.rs`, the generated gate script and its tests, the readme and
the test that keeps it honest, and the rustdoc across the four crates.

A read of the whole repo ahead of the first release turned up five things, and
they are two shapes rather than five.

## A check that ran nothing, twice over

The generated gate script reads its input with `jq`. Both reads carry
`2>/dev/null`, so on a machine without `jq` the command line comes back empty,
the script takes its own out-of-scope branch, and every commit and every push
is allowed. The gate does not report this. It exits 0, which is what it also
does when it has looked and found nothing wrong, and there is no way to tell
the two apart from outside.

Six tests cover that script end to end. Each of them starts by asking whether
`bash` and `jq` are there and returns early if not, so on the same machine the
tests are green having run nothing. The comment on the helper says the caller
should skip, and every caller does, and the skip is silent.

So the same absence produces a gate that permits everything and a suite that
says everything is fine. Neither is a test of the missing-`jq` case, and that
case is the one worth having a test for, because it is the one where the gate
stops working.

## Documents that describe something other than what ships

The readme's command table offers `homma docs`. That is not a command: `docs`
takes a subcommand and `homma docs` alone is a usage error. `agent` is a
top-level command and is not in the table at all, though the prose below the
table talks about it.

The test that checks the readme against the cli did not catch either. It runs
each command with `--help`, and `--help` succeeds on a parent command whether
or not that command can be run on its own, so the first is invisible to it. It
also only checks that every command the readme names is one the cli takes, and
not the reverse, so the second is outside what it looks at.

The readme says tokens come out of the environment, and that nothing secret is
written into the manifest. Both true. It does not say that a manifest may also
carry `token_cmd`, an argument list homma runs to get a credential. Someone who
copies a manifest from elsewhere is running whatever that names, and the readme
they read before copying it never mentioned the key existed.

## A general tool carrying one operator's arrangements

`Denied::under_home` compiles in two locations. One is `~/.claude`, which is
where the agent harness keeps its settings, its hooks and live credentials on
any machine, and denying it is right for everyone. The other is
`~/Dev/clause-dev`, with the reason "that workspace is its owner's, not yours to
write in". Nobody else has that directory, and the reason names an owner they
have never heard of.

The capability is worth keeping and the path is not. An operator with a
directory they want homma to stay out of should be able to say so, and where
they say it is the manifest, which is the file that already decides everything
else about a workspace.

The rest of the shape is the same thing in prose. Ten comments and doc
paragraphs across the four crates justify a rule by saying "the record" forbids
it, and there is no record here to read: the reader is told an authority exists
and cannot consult it. Four more cite `U-3.1` and `U-3.2`, which name nothing
in this repository. One test message says the author is a particular person.

None of that is wrong about the code. It is all correct and none of it can be
checked by anybody who did not write it, and a rule stated in full is shorter
than a rule plus a pointer to somewhere the reader cannot go.
