## Current state

The capture paragraphs of `mock/DESIGN.md.tmpl` say what a last line with no
newline is and what a `through` the transcript does not hold does, and say
nothing of a line in the middle of the file that will not parse. The code
refuses such a line by its number, which stops a capture of a session whose
transcript has one: four lines of a long session do, each the start of an object
cut off inside a string with a complete object after it on the same line.

## Changes proposed

- The capture section gains a paragraph after the one on the last line. A line
  that does not parse whole and has a `{` from which the rest of it is one
  object is read as that object, the bytes before it are dropped, and the run
  says on stderr which line it recovered and how many bytes went. It gives the
  reason (a second writer to the harness's file, whose long lines are cut), says
  what is lost and that the notice is the trace of it, and says the recovered
  object is an ordinary line afterwards.
- The same paragraph names the two cases that stay refused by number: a line
  with no object ending it, and a line whose bytes before the object are a whole
  value, which is two lines run together and not a cut write.
- The paragraph on the tools' own record gains a sentence that a line of it that
  does not parse is refused by its number and nothing on it is recovered, with
  the reason: one writer appends one short object in one write, and a record
  skipped would leave a tool's line quoted as the person's.
- `docs/DESIGN.md` re-renders from the template through `cargo mock`.
