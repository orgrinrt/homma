# Steps verify what they write and a mark keeps the order

Follows the round `202610311636`. The third review pass found that a step edits by position and then trusts the edit: it writes a record without reading it back. The intent is unchanged, every milestone recorded with exact revisions and no tool damaging what is already recorded.

## What the review found, and what is settled

A new key was added after the last line holding an equals sign, so a value spread over several lines on the open row had the key written inside it, and a line inside a multi-line string that looked like the key was rewritten, losing the text. A value written as a literal string was replaced only up to its first space. Each wrote a record that no longer parsed, or parsed to the wrong row, and returned success, after which every step refused.

The edit stays by position, since that is what keeps every other byte, but a step now parses the text it is about to write and refuses unless it reads back as exactly the rows it started with plus the change it was asked for: the other rows unchanged and the target row holding the keys it set. A refused step writes nothing. This closes the class where the position was misjudged, whatever the shape of the value, and a multi-line value on the open row is refused rather than placed.

A literal string value is replaced whole, as a basic string is. A table header with spaces inside the brackets or a comment after it is still a `[[milestone]]` table.

`mark` with no row open appended a tip that did not contain the last tip, so the next freeze took an earlier base and its epoch covered work the closed milestone already held. The design lists a step out of order as refused, and this is one: it is refused on a sha that does not contain the last tip.

A test that counted line endings against themselves could not fail for LF, and the preservation law was sampled over single-line basic strings only. The LF case now asserts there is no carriage return, and the multi-line array, the multi-line string and the literal string are tests.
