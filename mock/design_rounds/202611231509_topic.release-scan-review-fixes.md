# release-scan-review-fixes

The first review pass over round 202611231434 (the history scan before a release) found two things in the
code and one in its test; the design is unchanged.

## What it found

- `history_refusal` hands the scan the clone's root both as its argument and as its working directory. A
  workspace whose `path` is relative resolves a repo's root relative too, so the scan is handed `x` from
  inside `x`, cannot enter it, exits 2, and a clean history is refused.
- `tests/cli_release_history.rs` runs a dry run, which moves nothing whichever side of the plan the scan
  sits on, so its "nothing moved" checks would hold with the scan moved after the release.

## Decision

- The scan is handed the root made absolute, and runs from it.
- The test also asserts that no plan was printed: the next version the plan names, `0.1.1`, is absent, so a
  scan after the plan reads red. A unit case hands the scan a relative root from another directory
  and reads a clean history.
- Left as the design says: a workspace-wide run refuses at the first flagged repo, after any repo released
  before it in name order. Scanning every repo of a sweep before any is released is a design call, filed as a
  follow-up, as is naming `history_scan` in the workspace's own manifest.
