# what-an-install-copies-where-a-seat-names-no-git-hooks-file

A workspace can keep its git hooks manifest off some of its seats, for example where the check it runs
cannot run there, and take an earlier copy out of the members at each session start. `homma hook install`
runs at each start as well. Two things are owed in the design: what the install does on such a seat, so it
does not put the manifest back each time, and when a manifest the install copies in first runs.

## Where `git_hooks` is read from

- `git_hooks` under `[paths]` is read from the manifest, `homma.toml`, and from nowhere else.
- `homma.local.toml` has no `[paths]`: the file refuses a table it does not know, and the install does not read
  it for paths.
- Any other overlay carries the agent tables only, and a table beside them is refused by name.
- So every seat of a workspace names the same file. A seat cannot name no file, or a file that is not there,
  on its own; only the manifest can, for every seat at once.

## What the install does where the named file is not there

- It registers the gate alone and says so in its line.
- It writes no workspace manifest into the member.
- A manifest of another name already in the member, one an earlier install or anything else wrote, stays as it
  was: the install neither puts it back nor takes it out. Taking it out is whoever wrote it.
- So on a seat whose manifest names a file that is not there, the install does not put the workspace's
  manifest back, whatever an earlier run left.

## When a manifest the install copies in first runs

- The workspace's manifest is registered in a member before that member's first event, or that event runs no
  new entry. An install from inside an event, the older chain entry's call, registers it while the chain that
  called it has already listed its entries, so it runs from the next event on.

## What this round does not do

- A seat naming a file of its own, or none, needs a layer that can carry `[paths]` for that seat. That is a
  round of its own.
