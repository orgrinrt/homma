# Src changelist: pin the two folds nothing asserts

**Date:** 2026-08-25
**Round:** 202608251008
**Source topic:** `202608251008_topic.what-the-deny-list-does-not-cover.md`

## CHANGE: `crates/homma-engine/tests/registry_writes_smoke.rs`

A test that the registry write refuses a place the manifest denies. This is the
`for_the_workspace` fold, and deleting that fold left the whole suite green.

The behaviour is already right, so the test passes as written. That is the
point: what was missing was never the behaviour, it was the thing that notices
when the behaviour goes.

## CHANGE: `crates/homma-engine/tests/regen_writes_smoke.rs`

Written for the same reason and it found something else. The aggregation's fold
cannot be reached at all.

The pass permits its own workspace root back after folding the list in, so an
entry naming the workspace does nothing, and everything the pass writes is
under that root, so an entry naming anywhere else is never consulted. The one
shape that is both, a path under the root that resolves out of it, is refused
first by the containment check, which does not read the list.

So the test asserts the refusal that actually happens, names the one that does
not, and says why the fold stays: it sits behind a sibling guard, and a guard
whose reachability depends on another guard holding is exactly the one to keep
for the day the first is loosened.

The registry fold above was verified the way an assertion of this kind has to
be, by deleting the fold and watching the new test go red on its own. This one
cannot be verified that way, which is the finding.
