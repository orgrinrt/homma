## CHANGE: module `cmd::tools::descriptor` FROM absent TO present
File: `mock/crates/homma-engine/src/cmd/tools/descriptor.rs`
`discover` reads `tools/*/tool.toml` under the workspace root and returns one entry for each directory
that holds one, sorted by name: the tool, or the reason its descriptor cannot be used with the directory's
name and path. A descriptor is refused for a field it has no name for, a `name` that is not the
directory's, a missing `summary`, `backend` or `source`, a command name used twice or not made of
lowercase letters, digits, `.`, `_` and `-`, and a `run` that is empty, absolute or climbs out of the tool.
Verification: the unit tests in `descriptor_tests.rs`, each run against a copy of the module with the
refusal removed.

## CHANGE: module `cmd::tools::dispatch` FROM absent TO present
File: `mock/crates/homma-engine/src/cmd/tools/dispatch.rs`
`plan` turns a tool name and the words after it into the command to run: the verb the descriptor names, else
the tool's default command with all the words, else a refusal listing the verbs. It refuses a tool that is not
promoted when asked as a subcommand, a backend that is not `local`, a descriptor that is broken (naming the
tool and the file), a `run` that is not a file or not executable. `command` builds the process, run from the
workspace root with `HOMMA_WORKSPACE` set; `exec` replaces homma with it.
Verification: the unit tests in `dispatch_tests.rs`, each run against a copy with the behaviour removed.

## CHANGE: command `tools` FROM absent TO `list`, `check` and `run`
File: `mock/crates/homma-engine/src/cmd/tools/mod.rs`, `mock/crates/homma-engine/src/cli.rs`
`homma tools` lists, `homma tools check` exits non-zero while a descriptor is broken, `homma tools run
<name> <verb> ...` runs a tool whether or not it is promoted. An unknown top level word and an unknown word
under `rules` are handed to the dispatch as external subcommands.
Verification: `mock/crates/homma-engine/tests/tools_dispatch.rs`, through the binary, over a temporary workspace
with tools that print their arguments: a promoted tool's verb, its default command, a built-in group's
verbs and the tool's together, a tool that is not promoted, a broken descriptor, an unknown name, the exit
status and the standard input passing through.

## CHANGE: test `cli_rejects_unknown_subcommand` FROM clap refusing an unknown word TO the word reaching the dispatch
File: `mock/crates/homma-engine/src/cli.rs`
An unknown top level word is an external subcommand now, since a promoted tool may be what it names, so
the test holds that it parses as one. The refusal and its wording are the dispatch's, held in
`an_unknown_name_is_refused_pointing_at_the_listing_instead_of_clap_s_words` in `tests/tools_dispatch.rs`.
Verification: the test, and the integration test through the binary.

## CHANGE: command dispatch FROM exhaustive over the built-in commands TO arms for `Tools`, `External` and `RulesOp::External`
File: `mock/crates/homma-engine/src/cmd/mod.rs`
The workspace root for a tool is the directory of the manifest path, made absolute, and the manifest is not
parsed: a tool must stay reachable while the manifest is being repaired.
Verification: `a_promoted_tool_is_a_subcommand_that_gets_the_words_after_its_name`,
`a_built_in_group_and_the_tool_of_its_name_answer_together` and `a_built_in_wins_over_a_tool_of_its_name_and_the_tool_runs_by_name`.

## Mutations

Each of these was applied to the source and reverted, and the tests named failed: the descriptor's name
check, unknown-field refusal, duplicate verb check, `run` containment check, sort and directory filter;
the dispatch's promote check, backend check, default command, verb-before-default order, executable and
file checks, working directory and `HOMMA_WORKSPACE`; the listing's built-in relation, the `check` exit
status and its listing of only the broken ones, and the merged group's refusal naming the built-in verbs.

## Known environment fact

`tests/cli_release.rs` creates repositories with `git init` and expects the branch `main`; where git's
`init.defaultBranch` is unset it creates `master` and four of its tests fail with `unknown revision main`.
They pass with `init.defaultBranch=main`, which is how the whole suite was run here.
