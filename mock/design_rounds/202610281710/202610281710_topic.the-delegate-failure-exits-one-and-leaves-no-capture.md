# the-delegate-failure-exits-one-and-leaves-no-capture

The one review pass over the fixed branch found two blockers in what the last round wrote. The delegate's failure was returned as an error, which the binary turns into exit 2, the status for a command that could not run; the design says 1, the status for a command that ran and reported. And the failure left its capture in the store with the key listed, so the same append made again once the row exists was filtered out as already recorded, reported as done, and never attached.

The design is amended: a row that cannot be written exits 1 with the reason on stderr, and the delegate takes away the capture it wrote, so the same append can be made again. A `take` keeps its capture on a failed attach, since there the capture is the record of what was left on a page and the row is only noted as not written.
