# the-second-review-of-own-lines

The second review of the own-lines branch found its first round's findings fixed and left four small things.

- `release/git.rs`: `first_parent_touching`'s doc sits above `changed_paths`, so one function has two docs and the other none.
- `subjects_touching` takes a pathspec nothing passes; it folds into `subjects` and `subjects_to`.
- The own-tag check test asserts `tag.reachable`, `tag.annotated` and `tag.pushed` on an own tag and not `tag.sha.agrees` or `tag.local`, which read the same tags. And the lock fixture names `t-p` in a dependency with no version, so taking the own lines' references out of the dependency lists is never exercised: a lock whose dependency entry carries the own line's version, as cargo writes one where two versions of a package are locked, is the case that needs it.
- Reading the commits of a line spawns a `git diff` and a parent count per commit, once per line, so a first release walks the whole history that many times over. One `git log --diff-merges=first-parent --name-only` over the range gives every commit with its paths against its first parent, a root commit's every path, in one process.
