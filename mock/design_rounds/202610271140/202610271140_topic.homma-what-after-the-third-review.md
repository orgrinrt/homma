# homma-what-after-the-third-review

A third review of the branch found what the design left unsaid or got wrong. Each is settled in this round's doc changelist, or the code is changed to meet the design.

- A tool with verbs and no default one is refused when run bare, and the answer printed it bare when no verb matched (a hit on a tag, and every related tool). The design is silent, and now says the bare command names the verbs.
- A usage line's second word was read as a verb after a column gap, so `storage.py every storage purpose` gave the verb `every`. The design said the second word; it now says set off by a single space.
- The code drops `shellcheck` lines, skips `.git`, reads `//` headers and takes an em-dash after the name; the design said none of it. The design now says it.
- A local config that does not parse widens the scope to every repository with the footer saying so, where the design said it widens nothing. The design now says what the code does.
- A root word ending in `ed` or `ing` was cut when bare and not when plural, so the two never matched. The code changes: the plural comes off first. The design says so.
- Filler was checked before stemming, so `scripts` stayed where `script` went. The code changes and the design says as it is or once stemmed.
- The tests: the prior was not tested with equal fields, one order test compared constants, several behaviours the design states had no test, and one ignore label was false. The code and the tests change.
- The commit subjects of earlier commits do not backtick `homma what`. They stay as pushed, and later ones do.

No other topic filed earlier remains open for this work.
