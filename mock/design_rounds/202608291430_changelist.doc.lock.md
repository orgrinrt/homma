# Doc changelist: the tools a workspace has and homma does not

## README.md

The manifest section is where every key is documented and is the only place
`token_cmd` is described, so it is where this goes too.

- CHANGE: after the `token_cmd` paragraph, a section for `[[status.inject]]`:
  what it is for, the two-entry example, that each runs in the workspace root in
  declaration order and its stdout becomes a block under the repos.
- CHANGE: state that `title` falls back to the program's file name and that
  `format` is an optional shell line.
- CHANGE: state the argument-list-versus-shell-line split and the anchoring rule
  (a relative path with a separator resolves against the root, a bare name is
  left for `PATH`).
- CHANGE: state that a missing or failing tool does not take the command down,
  and repeat the `token_cmd` warning, since these are programs the manifest
  picks and the reader has to know that before trusting a manifest.

It sits next to `token_cmd` rather than under `homma status` in the command list
because it is a manifest key, and a reader looking up what a manifest may carry
reads that section top to bottom.

## docs/

No change. Nothing under `docs/` documents a manifest key today, and
`token_cmd`, which is the nearest thing to this, appears in none of them.
