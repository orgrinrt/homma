# A `[what]` table that does not read fails the verb

## The defect

`homma what` reads `[what]` by opening the manifest itself and parsing it again, and a table that does not read, a misspelt `synonym = ...`, falls back to the compiled table with a line in the footer. Unknown fields are refused once the rollout order allows it, and for a table no manifest sets yet it allows it now, so the misspelt key is to be refused, not reported and passed over.

## The fix

- The verb takes the configuration the binary already loads. `Config` holds `what` raw, and the verb reads it through `WhatConfig` the way the search reads `[search]`, with an error naming `[what]` where it does not read. The manifest is not opened a second time.
- With no manifest the verb answers from the compiled table, as now. A manifest that is there and does not load is the same error every command that loads it gives.
- The gap for a `[what]` that does not read goes; nothing in the footer replaces it.
- The design's passage on the synonym table says the table that does not read fails the verb.
- The test that read the gap asserts the verb fails on the misspelt key, with the error naming `[what]`.
