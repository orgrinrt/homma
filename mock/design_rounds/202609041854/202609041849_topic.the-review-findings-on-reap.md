# the-review-findings-on-reap

A fix round, standing alone the way a defect found and fixed does. The round
`202609041520` closed with `homma workspace` on the launcher, and the review
of it found three things on `reap` that compound, four beneath them, and the
tests that would have shown each.

## What the review found

`reap` could not see a worktree. The survey counts a member by its `.git`
being a directory, a worktree's is a file, so a seat under `.worktrees/` or
one level down was invisible to the survey and to the guard, and the removal
took it with everything else. The workspace rules put every agent seat at
exactly that place.

`reap` had no destination guard. It did not ask `disallowed_roots`, did not
require the target to be a workspace at all, and with no slug took whatever
ancestor carried a `homma.toml`, then ran `remove_dir_all` on it under
`--force`. A verb that ends in a recursive removal was held to a lower bar
than the one that clones.

`reap` with no slug removed the directory the shell was standing in, printed
that it had, and left the shell where every later command fails for no
visible reason.

Beneath those: `workspaces_root` was allowed to be relative, so a destination
landed wherever the shell stood and the denied-root check resolved against
that; the give-up branch of the path resolver returned the caller's spelling
rather than the folded one it had computed for that case; a member that
failed to clone after the content repository landed left a half-made
workspace that refused its slug forever and refused its own reap; the doc
comment on the git module claimed one dependency in the commit that added
two more, and the round's topic repeats the sentence; and the empty content
repository was named ahead of the denied root, so a fresh install in the
home directory heard about a key rather than about the home directory.

## What changes

`reap` refuses, ahead of the survey and whatever `--force` says, a target
with no clone at its root, a target the settings deny, a target the cwd is
inside, and a target holding a worktree one level down or under
`.worktrees/`, each naming what to do instead. `workspaces_root` has to be
absolute or start with `~`, refused when the settings are read. The resolver's
give-up branch returns the folded path. A spawn that fails partway removes
what it made, or empties the directory it was handed, and says so. The denied
root is checked ahead of the missing key. The git module's doc says what the
launcher depends on. And a test for each, against real repositories, with a
worktree made by git itself.
