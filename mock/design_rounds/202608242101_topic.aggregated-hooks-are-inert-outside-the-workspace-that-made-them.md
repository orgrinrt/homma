# Every aggregated hook wrapper in this workspace is inert

**Date:** 2026-08-24
**Phase:** TOPIC
**Scope:** `homma` (the binary crate), `homma-core::config`

## What was measured

`homma agent regen --skip-cargo-mock` in a workspace holding two of the
manifest's repos rewrote `.claude/settings.json` from 84 hook registrations to
19. That churn is the visible part. Underneath it, a count over the 98 wrapper
scripts the workspace carries:

```
wrappers whose REPO_ROOT points inside this workspace: 0
wrappers whose REPO_ROOT points elsewhere:            98
```

Broken down by the root each one carries:

```
   5 REPO_ROOT='./homma'
   5 REPO_ROOT='./kamu'
  28 REPO_ROOT='/Users/<someone-else>/.../arvo'
  25 REPO_ROOT='/Users/<someone-else>/.../hilavitkutin'
  11 REPO_ROOT='/Users/<someone-else>/.../kolli'
  12 REPO_ROOT='/Users/<someone-else>/.../vehje'
  11 REPO_ROOT='/Users/<someone-else>/.../viola'
```

A wrapper exits 0 silently when the edited path is not under `REPO_ROOT`. So
every one of these loads, runs, matches nothing, and permits everything, and no
signal distinguishes that from a guard that ran and approved.

## Three findings, and they are separate

**F1. `Config::from_path` leaves `workspace.path` relative when the config path
it was handed is relative.** It anchors a relative `workspace.path` on
`path.parent()`, which is itself relative when `path` is. The existing test
`a_relative_workspace_path_resolves_beside_the_config_not_beside_the_caller`
asserts `is_absolute()` and never reaches this, because it passes an absolute
config path: the law is asserted over one half of its matrix.

**F2. A relative `REPO_ROOT` never matches, so F1 makes every hook of that run
inert.** The wrapper compares `REPO_ROOT` against the `tool_input.file_path`
the host supplies, which is absolute. Measured, with a control:

```
no match  root=./homma  target=/abs/ws/homma/src/x.rs
MATCH     root=./homma  target=./homma/src/x.rs
MATCH     root=/abs/ws/homma  target=/abs/ws/homma/src/x.rs
```

The ten `./homma` and `./kamu` wrappers are the ones this workspace generated
itself. They were inert from the moment they were written.

**F3. A wrapper bakes the absolute path of the workspace that generated it.**
The wrappers are tracked, so they travel to every clone, where the baked path
names a directory belonging to somebody else. Eighty-seven of the ninety-eight
are this.

F3 also explains the settings churn: `merge_settings` strips every entry naming
a known repo and re-adds only what the current run aggregated, and a repo this
workspace has not cloned aggregates nothing. Its wrapper file survives, because
`clean_stale` runs inside the per-repo pass that was skipped, so the file and
its registration disagree afterwards.

## What the wrapper should key on instead

The workspace-relative path, which is what the manifest already carries:
`repos.<name>.local_path` is relative by construction. The absolute form is a
fact about one machine and is the only part that cannot survive a clone.

A wrapper sits at a known depth, `<workspace>/.claude/hooks/<file>`, so it can
locate the workspace from its own path and needs no environment variable and no
baked prefix:

```
WS=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")/../.." && pwd)
REPO_ROOT="$WS/<local_path>"
ORIG_HOOK="$REPO_ROOT/.claude/hooks/<name>"
[ -x "$ORIG_HOOK" ] || exit 0
```

The executable check is what makes a tracked wrapper honest in a workspace that
has not cloned that repo: there is no guard to run, so it declines rather than
pretending to have approved.

That in turn settles the settings question. A registration whose wrapper cannot
find its repo costs one `[ -x ]` and is correct the moment the repo is cloned,
so entries for repos the current run did not visit are preserved rather than
swept. The cost is that a hook deleted upstream lingers as a registration in
workspaces that never clone that repo, pointing at a wrapper that exits 0. That
is the right side to err on: the alternative deletes working guards from every
workspace that happens to hold a different subset of the manifest.

## Out of scope, and recorded rather than fixed

`homma` and `homma-core` ship no design document. `mock/crates/` carries one for
`homma-api`, `homma-org` and `homma-store` only. So the aggregation mechanism,
which writes executable files into a workspace and registers them with the
host, is specified nowhere, and the contract above has no home to be written
into. Authoring two design documents is not a side effect a bug fix should
have; it is named here so it is not mistaken for an oversight.
