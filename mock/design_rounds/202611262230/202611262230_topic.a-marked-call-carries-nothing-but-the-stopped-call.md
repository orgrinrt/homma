# a-marked-call-carries-nothing-but-the-stopped-call

A found defect, fixed alone.

## The defect

A review found that the marker of a `once` row lets a call through that nothing
stopped or checked. The marked call is compared with the stopped one on the
text before the marker only, the marker is found on any line of the command,
and nothing reads what follows it. With the grep row having stopped
`grep -r foo .`, both of these pass:

- `grep -r foo . # searched-first why`, a newline, then `grep -r secret .`
- `: searched-first why; grep -r secret .`

The second grep in each runs, and no row looked at it.

## The fix

A marker counts only in one of two exact shapes:

- The `#` form: the marker is in a comment on the command's last line, the
  comment holds the marker and its reason and nothing else, and the text before
  the `#` is the stopped call exactly. The command has one line, or the stopped
  call's lines followed by the comment on the last.
- The `:` form: the whole command is `: <marker> <why>` on one line, with no
  `;`, `&`, `|`, `$(`, backtick, `<`, `>` or newline in it. It answers the
  stop and runs nothing.

A command carrying the marker in any other shape is not an answer: it is
evaluated as any call, and the stop stays. A `#` form whose text before the
comment differs from the stopped call is also not an answer.
