# how-a-provisioned-workspace-defends-its-identity-against-the-environment

Open, for a panel or for op to settle. The design does not say.

What the design says. `crates/homma-org/DESIGN.md.tmpl` requires that standing a
workspace up sets the identities in that clone's own configuration, that the
clone then reports back all four values it was given, and that the machine's
global configuration is unchanged. It gives the reason in the paragraph on the
step whose absence is invisible: the first sign is a commit landing under
whoever the machine's global configuration names. The paragraph after it adds
the committer and widens the four values to six configuration keys, because git
resolves an identity from `author.*` and `committer.*` before `user.*` and does
so across scopes, so a global `author.name` beats a local `user.name`.

What it does not say. Git resolves an identity from one more tier above every
configuration file. `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME`
and `GIT_COMMITTER_EMAIL` outrank all the configuration keys, and the
`GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>` and `GIT_CONFIG_VALUE_<n>` triple sits above the
configuration files. The design is silent on whether a provisioned workspace is
meant to hold its identity against these, and on what holding it would mean when
the process that commits is not one homma starts.

What was measured. On `dev` in a container exporting the four variables,
`crates/homma-org/tests/provisioned_commit.rs` fails: the author name read back
from the commit is `O. R. Toimela` where the registry gave `Onni Armas`. The
clone's configuration holds the right values, the read-back after provisioning
passes, and the commit still lands under the environment's identity. Both tests
in that file fail the same way. They are catalogued red, with the intended
assertions unchanged, until this is settled.

The shapes an answer could take, none preferred here:

- Provisioning installs something in the clone that sets the identity at commit
  time regardless of the environment, such as a hook, and the design says which.
- Provisioning reports the environment tier on the read-back, so the first sign
  is no longer invisible, and a commit under it is the user's own doing.
- The environment is declared out of homma's reach, and the design says so, with
  the two tests narrowed to the tiers homma owns.
- Something else the panel finds.

Whichever it is, the design gains a paragraph beside the six keys, the tests
follow it, and the `#[ignore]` on `provisioned_commit` goes or the tests change
with it.
