# An index cut by another chunker names what cuts it again

## The finding

`homma search --members` reported a member's index as not asked, with the index crate's words "the index header's chunker is `1` and the caller brought `2`", and nothing else on the line. The finding as stated holds in part.

- Why the file keeps an older chunker: a member's index is written by the member's own tool, built against the index crate at whatever its own build pins, and homma reads it with the crate homma is built against. The file keeps the chunker of the build that last wrote it until that writer opens it again; the crate's writer cuts a file of an older chunker again from nothing, so the member's own build command rewrites it. Whenever the two builds' pins move apart, one refuses what the other wrote. A reader at version 2 meeting a file cut at 1 is the case the finding saw.
- The reader refuses on open, before any refresh: `layer::open` reads the header and refuses a file of another chunker, in either direction. The line carries the refusal, so the member is not skipped in silence, but it names no way out, where a file not built names the command that builds it.
- Asking the same member today answers: the writer and homma's pin are both at chunker 2. The gap is the line, the next time the pins part.

## The fix

- A file cut by another chunker stays not asked: the question does not rewrite it. A rewrite from inside the question would cut a member's index with homma's build of the crate rather than the member's own, so the two builds would cut it in turn, and the member is to answer alone with its own tool.
- Its line says which way it is out and what moves it:
  - cut by an older chunker than homma's: the line names the `corpus_build` or `member_build` command, which cuts it again under the chunker the member's build writes with; where that build is itself older than homma's, the file stays refused after it, and the line says the chunker homma reads so the gap is seen;
  - cut by a newer chunker than homma's: the line says this build of homma reads an older chunker, and that a build of homma against the index crate's trunk reads it; the file is left as it is.
- The note follows the crate's own words on the line, as the command for a file not built does, and a file of the same chunker gets none.
- Tests plant a corpus and a member index under a chunker below and above the crate's, each asked through a place with a build command, and read the line; the failing control is the same index at the crate's own chunker, which answers with no such note.
