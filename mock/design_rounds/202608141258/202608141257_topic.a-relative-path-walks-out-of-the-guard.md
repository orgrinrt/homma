# A relative path walks out of the guard, and the fake told the test what it
# wanted to hear

**Phase:** TOPIC
**Scope:** `homma-api`, `homma-core`, `homma-org`, `homma`

Third review, third refusal, and this time **two of the findings are defects the
previous round introduced**, one of them the same deny-item-2 violation that round
was convened to prevent.

## The guard is bypassed by the ordinary invocation

`enclosing_repo` walks `parent()` upward. On a **relative** path the walk
terminates at the empty string, so it checks the process's current directory
rather than the configuration's real ancestors. Reproduced:

```
$ cd $T/outer/sub                 # inside a committed repository
$ homma --config homma.toml org up h
exit=0
$ ls -d $T/outer/sub/.git         # a repository inside a repository
$ git -C $T/outer status --porcelain
?? sub/                           # and a Hand's directories in its tree
```

The guard has exactly one test and it passes an absolute path. **A guard tested
only on the shape that cannot fail is not tested.**

## The ordinary bootstrap fails outright

A `content_repo` URI against a root that is not yet a repository, which is the
plain case of a directory, a registry, and a remote to clone from:

```
$ homma --config $T/root/homma.toml org up h
error: reading the origin of .../root: ... has no configuration file, so it is
       not a repository
exit=1
```

`GixGit::origin_url` returns `Err` where a repository is absent. The contract says
"the URL `path`'s `origin` points at, **if it has one**", and a directory that is
not a repository has none. `Err` is for a repository that cannot be read, not for
the absence of one.

**And a test asserts the opposite passes.** `standing_up_from_a_root_that_is_not_a_repository_still_works`
is green only because the fake answers `Ok(None)` where the real implementation
answers `Err`. That is setup that helps, in the exact sense
`the-test-gate.md` names: the fake was built so the assertion would hold. The
comment above the code says the right thing and the code does not do it.

## The vacuous assertion was fixed at one instance and survives at the other

The global-config check was repaired in `git_impl.rs` and the identical helper,
with the identical defect, was copied into the integration tests and left alone.
One goes red under a stripped environment; the other reports ok having compared
`[None]` to `[None]`.

**A report names an instance; the fix is the class.** That rule exists in this
workspace and this round violated it while fixing a finding.

## What else this round fixes

`remote.rs` treats five spellings of one repository as different repositories: a
port in the host, a bare `host:path` with no user, a `file://` URL, an owner
differing only in case, and `.git.git` stripped repeatedly, which is the one that
fails open rather than closed.

`org_smoke.rs` was **created over the file-size limit** by the previous round's
split, and `stand.rs` is over it too. The previous round answered that finding by
counting non-blank non-comment lines, which redefines the rule rather than meeting
it.
