# homma-org-names-types-the-core-and-api-already-hold

The commit and push gate of this repository refuses every push on `dev` as it stands: `cargo mock` reports three `single-source/type` errors, "pub enum `Finding` also defined in homma-api", "pub struct `Registry` also defined in homma-core" and "pub enum `Remote` also defined in homma-core", all in `homma-org`. The lint arrived with the mockspace trunk the gate tracks, so nothing in this repository changed to cause it, and it blocks the push of any change.

The intent of the lint, one definition per concept, is the workspace's standing tenet and is not argued with here. The smallest change that satisfies it is to give the `homma-org` types names of their own, since the concepts differ: the org crate's registry is a read over a workspace's identities, its remote is a parsed address, its finding is what one config check found.

The names are `OrgRegistry`, `ParsedRemote` and `ConfigFinding`. Only the org crate's own definitions and the places that name them change; the core's `Registry` and `Remote` and the api's `Finding` keep their names.
