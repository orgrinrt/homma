## Current state

The section `What a clone is for` describes `homma.local.toml`, `homma local init`, `show` and `set`, and says nothing about where a clone's config comes from beyond `init` writing a skeleton. Each body of work's config is written again by hand in every fresh clone.

## Changes proposed

- One paragraph after the one on `set` says that a workspace stores one config per body of work under `.shared/local/`, that `homma local install <name>` copies the named one into place and why it copies instead of linking, how declared and recorded values are kept apart without homma knowing which key is which, what install does where a file exists already (the same work, another work, a link, a file that does not parse), and what `homma local list` prints and exits with.
