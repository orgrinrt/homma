# release virtual review fixes

The review of `work/release-virtual` at `cd8fb1c` came back "merge after fixes". Each finding and what it settles:

- `docs/CORE_RELEASE.md` was not rendered from `DEEPDIVE_release.md.tmpl`; `cargo mock` renders it.
- A level taken from a pre-release made the next version past it (`0.0.5-rc.1` patch to `0.0.6`), which `is_one_step` refuses, so a sweep passed renki over. Decision: a level from a pre-release gives that pre-release's release, `0.0.5-rc.1` patch is `0.0.5`, `0.1.0-rc.1` minor is `0.1.0`, as cargo-release does. A version no single step above the last tag refuses the sweep, as a manifest off the level does, rather than passing the repo over.
- The design said a rider moves where its manifest differs, the code compares versions; the design text follows the code. The plan warns of a rider whose files changed since the last tag while its version did not.
- A rider that moves moves one step, the same `is_one_step` the primary is held to.
- `--version` names one repo's next version, so a run naming no repo refuses it.
- The primary is the member named as the repository is named in the workspace manifest, which the engine resolves, never the clone's directory name.
- A first release named outright is the manifest's version or one step above it.
- A virtual workspace with no primary is a finding of the check, `man.primary`, rather than passed over silently.
- A tag clears `tag.bump.tagged` only where it is on the release line: a tag on a `dev` commit after the bump does not.
- A commit reported by two manifest walks is one `tag.bump.tagged` finding.
