# the-clones-own-file-is-not-a-stray-and-overlays-sit-beside-the-manifest

A fifth review of the shook branches found two places where the design and the code disagree with each other or with what the file is.

## The clone's own file is read for more than its hooks

`homma.local.toml` carries the clone's `[instance]` and the other tables the clone's own reader owns, and `homma local` reads it whatever `layers` says. `hook doctor` listed it as a stray whenever `layers` did not name it, with the advice to name it or remove it. A `layers` list that replaces the default, such as `["homma.team.toml"]`, is enough to reach that, and following the advice removes the clone's identity. The file is reported on its own line instead: its hooks tables are not read because `layers` does not name it, its own tables still are, and it is not a failure and not to be removed.

## Where the overlays sit

The design says the overlays are in the workspace root. The code reads them beside the manifest, which is where `homma local` reads the clone's file, and the two only differ where the workspace path is not `.`. The design says beside the manifest.
