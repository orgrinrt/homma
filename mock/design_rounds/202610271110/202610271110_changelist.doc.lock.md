# doc changelist

Answers the topic filed in this round, `homma-what-finds-the-tool-that-does-a-thing`, and replaces the doc changelist deprecated beside it.

## Comparison to deprecated changelist

The deprecated changelist (`202610271057_changelist.doc.deprecated.md`) made a script any file with a script extension. A second review found that gives answers whose command cannot be run (a sourced library, a file without the executable bit), and test files as answers. This changelist changes:

- `mock/DESIGN.md.tmpl`, "Finding a tool", the scripts: a script can be run, being executable or starting with a shebang, whose interpreter then leads its command; a file with neither is a library and is no answer; tests are named by `_test`, `_fixture`, a `test_` prefix, a `test` runner and the `tests` and `test` directories; a program's own source under `src` or `lib` counts only where executable; a link in the scripts directory itself is a gap and not a way out.
- The same section, the footer: a local config that does not parse, a workspace with no mockspace repository and a source left out by a flag are each said in the footer.
- The same section, the mockspace listing: the limit counts the time spent reading as well as waiting.
- The same section, the acceptance set: run with every source, and a query not yet answered is kept as an ignored case with the unmet requirement reported.
