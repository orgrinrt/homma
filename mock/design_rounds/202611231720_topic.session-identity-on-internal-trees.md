# session-identity-on-internal-trees

## What is asked

Roadmap step 14 of the workspace (ticket 93b7b0ab8d0d): on an internal tree every agent commit carries an agent
identity, the author the helper that made it and the committer the coordinator responsible for it, set by
whoever starts the session; a sub-agent is its launcher's identity with a plus tag on the local part of the
address. Op, 23 November 2026, verbatim: "The author becomes whatever helper made the code ... The committer is
the responsible coord. So both have meaningful identity and name set. These NEVER leak into the public git tree";
and on the second audit's Q6: "I think it's enough to have the agent identity who launched it with a + tag as a
post fix on the first part of the email that has sub agent ID or name or whatever". clause-dev is an internal tree
(op, 23 November: "Yeah clause dev is private and we want track record going forward").

## What homma has today

The catalogue (`[org.*]`, round 202611231429) names each agent with its `git_name` and `git_email`, resolves a
handle or an alias (`catalogue::resolve`), and matches an address back to its agent with the tag stripped
(`OrgRegistry::agent_at`). Nothing turns a handle into the identity git writes, so whoever starts a session would
copy a name and an address out of `homma.toml` by hand, which is a second registry in all but name.

## Where the identity goes, and why not the environment

A session commits on both sides at once: on a member's branches under the person's identity (the public side,
until promotions stand) and in the workspace repository under its own. `GIT_AUTHOR_*` and `GIT_COMMITTER_*` are
one value for every repository the process touches, so they cannot carry both. git's own configuration can: a
global `[user]` for the person, and an `includeIf "gitdir:..."` naming the workspace repository's git directory,
which pulls in a file holding `[author]` and `[committer]`. A linked worktree has its own git directory under the
common one, so a sub-agent's worktree gets an `includeIf` of its own with the tagged author, later in the file and
so stronger. The environment variables, where set, outrank all of it; the workspace side says so and does not
pretend otherwise.

## Decided here

**homma renders the identity, from the catalogue alone.** `homma identity git-config <author> [--committer
<name>] [--tag <tag>]` prints the include file: `[author]` and `[committer]` with each name and address from the
catalogue. Without `--committer` the author commits too. Both names resolve through `catalogue::resolve`, so a
handle or an alias; the king is refused, since a person's own identity is set by git's global configuration and
is never an agent's include; an unknown name is refused naming it.

**The tag is the sub-agent's name, on the author's local part only.** The committer is the coordinator, not the
sub-agent, so it keeps its address. A tag is lowercase letters, digits and hyphens, one to forty characters, so it
survives every address parser and `normalise` strips it back to the launcher. An author with no `git_email`, or an
address with no `@`, is refused: there is nothing to tag.

**Writing it into git is the workspace's.** Which git directory is internal, where the include file sits and when
it is written (the stand-up, the sub-agent's worktree) is the workspace's tooling, which owns its trees. homma
prints the file and touches no git configuration.
