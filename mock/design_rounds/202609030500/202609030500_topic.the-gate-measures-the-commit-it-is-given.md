# The gate measures the commit it is given

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-engine/src/cmd/release/gating.rs`, `homma-engine/tests/cli_release.rs`, `homma-core/src/release/run_tests.rs`, `homma-core/src/forge/{github,github_tests}.rs`
**Source topics:** the fourteenth review of pull request 46, and `202609030445/202609030445_topic.a-members-feature-sets-run-against-that-member.md`

## The findings

`homma release gate --sha` refused any commit but the checkout's head, so the option could only confirm what a bare run measures, while the gate already knows how to measure another commit in a worktree of its own for the hook. The option resolves the commit it is given and gates that, the head in place and any other through the worktree, the way the hook does.

The design says the changelog block and the forge release body are the same block, verbatim, and the run's test asserted only that the body opened on the version heading. It compares the body to the block on the trunk.

The forge's release creation had no wire test while the status post did; the same recording server covers it, asserting the path, the credential and the three fields of the body.

The github test file crossed the size line with that; its wire tests move to a file of their own.

## What does not change

The design.
