## CHANGE: module `cmd::tools` FROM one module that reaches renki on every target TO a portable part and a unix part
File: `mock/crates/homma-engine/src/cmd/tools/mod.rs`, `host.rs`, `refused.rs`, `dispatch.rs`
`Asked`, `root`, `run_handed`, `groups` and `unix_only` are portable. `cache`, `descriptor`, `dispatch` and
the new `host`, which holds `list`, `check`, `run_tool`, `run_merged` and the report, are `cfg(unix)`.
`refused` answers the same four functions elsewhere with `unix_only`, which says renki builds on unix only.
`Asked` moves from `dispatch` to `mod.rs` so the refusing arm can name it.
Verification: `groups_tests.rs`, which holds the refusal's wording and the portable parts, built on a
target without the host; the unit tests of the host parts, now `cfg(all(test, unix))`; the whole
`homma-engine` suite.

## Non-unix build

The installed non-unix target, `wasm32-unknown-unknown`, stops in `gix-sec` before reaching this crate, so
the arm was checked on the host triple with the tools module's `cfg(unix)` renamed to a cfg that is off, in
a copy of the tree: `cargo check` of the binary and of its tests built clean with no warnings, and the
binary refused `tools`, `tools check`, `tools run x`, a group's handed word and `msg x` with the
`unix_only` message. That shows the arm compiles and answers; it does not show the rest of the engine
builds off unix, which no installed target can say.
