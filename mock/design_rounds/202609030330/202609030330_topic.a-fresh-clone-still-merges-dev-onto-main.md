# A fresh clone still merges dev onto main

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-engine/src/cmd/release/mod.rs`, `homma-engine/tests/`, `homma-core/src/release/{check,gate}.rs` and their tests, one line of `homma-core/DEEPDIVE_release.md.tmpl`
**Source topics:** the eighth review of pull request 46, and `202609030305/202609030305_topic.the-sweep-is-tested-and-both-sameset-is-per-package.md`

## The findings

The engine decides whether a repo has a working branch by resolving the local `dev`, so a fresh clone holding `origin/dev` and no local `dev` is read as a crate released off `main` alone: the merge is skipped and the tag lands on the bump commit. The design opens by saying a release is a merge of `dev` onto `main`. The working branch is looked for on the remote as well as locally, and the plan names the two branches it carries, so a dry run shows which shape it has read.

`both.sameset` paired a jsr package with an npm package by bare name, a guess at something the manifests already say: a repo ships one jsr name and one npm name, read off `deno.json` and `package.json`. The check reads those and pairs them, and a pair whose names share no segment is still a pair.

The gate's wall time was filed under the last step whatever it did, which is the notices step, skipped wherever there is no `ante.toml`, so the status line lost it. It goes on the last step that ran.

`is_adjacent` builds its candidates with `bumped`, which drops a prerelease, so a published prerelease raises `semver.gaps` at error for good. The design says only that the registry skips no number and nothing about prereleases; that is the lead designer's, filed in the workspace agenda as `homma-release-prerelease-in-the-registry-is-ops-call`, and not taken here.

The engine's smoke tests sit at 748 lines; the release ones move to their own file with the fixtures they share in a common module.

## What does not change

The design, except that the plan names its branches.
