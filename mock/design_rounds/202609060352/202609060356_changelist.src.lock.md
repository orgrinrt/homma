# Source changelist: split outside quotes, and report the cards nothing claims

## `crates/homma-api/src/frontmatter.rs` (update)

`split_outside_quotes`, a private function tracking quote state across the
scan, and `parse_list` calling it instead of `str::split(',')`.

CHANGE: a list element containing a comma inside quotes was two elements with
unbalanced quotes. Measured against the parser on this branch before the fix:
`["src/**/*.{ts,tsx}"]` parsed to `["\"src/**/*.{ts", "tsx}\""]`, and the
control case with no comma in the element parsed correctly in the same run, so
the defect is the comma rather than the quoting.

What that costs is not a parse error. `rule::paths` reads through this
function, `paths_frontmatter` writes both entries into the generated card, and
a rule whose gating the host cannot read is promoted to always loaded, so the
only sign is the always-loaded count rising by two.

The doc comment states what is guarded and what is not: no escape handling,
because the format has no escape, and an unterminated quote takes the rest of
the list as one element rather than erroring.

## `crates/homma-api/tests/frontmatter.rs` (update)

`a_list_element_holding_a_comma_stays_one_element`, three arms. The brace group
surviving as one element; two quoted elements each holding a comma still
separating, so the arm above is not passing because the split stopped
happening; and an unquoted list unchanged, which is most of the corpus.

Shown failing first: with `parse_list` reverted to the plain split, this test
fails and the other thirteen in the file pass, which is what says the file had
no arm for the case at all rather than a weak one.

## `crates/homma-org/src/rules.rs` (update)

`Corpus::unclaimed(dst)`, listing the `.md` files in the destination whose stem
is not an authored rule name, sorted. `render_cards`'s doc comment now says
what happens to a card nothing claims and why it is neither deleted nor
ignored.

CHANGE: nothing removed or reported a card whose rule was gone. The destination
is `.claude/rules`, the always-loaded corpus, so a deleted or renamed rule kept
being injected into every session.

Reported rather than removed, which is the policy `skills.rs` already carries
for a directory no authored skill claims, and the reasoning transfers exactly:
on disk a card this pass wrote last time and a document somebody put there on
purpose are the same file. The other half of the skills policy, removing what
the pass owns before rewriting it, has no analogue here, because a skill owns a
directory whose contents can go stale inside it and a rule owns one file that
is rewritten whole every pass.

## `crates/homma-engine/src/cmd/rules.rs` (update)

`RenderReport` carries `unclaimed`, and the human rendering names them under
the same wording the skills command uses. `run` calls `corpus.unclaimed(&dst)`
after rendering.

## `crates/homma-org/tests/rules_corpus.rs` (update)

`a_card_no_rule_claims_is_reported_and_left_alone`, four arms: a freshly
rendered destination reports nothing; a planted card is reported by name; it is
still on disk afterwards; a second render does not remove it either, which is
the arm that would pass vacuously if only `unclaimed` were checked; and a
`.txt` beside it is not reported, so the report is about the corpus rather than
about everything in the directory.

Shown failing first: with `unclaimed` returning empty unconditionally, this
test fails and the other sixteen pass.

## What this changelist does not touch

`skills.rs` and its tests. The policy is taken from there unchanged and stating
it a second time is how the two would start disagreeing, which is the defect
this round is repairing one tier down.
