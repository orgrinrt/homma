# Containment is relative. The deny list is absolute. Nothing checked the second.

Fourteenth review, and the first to change the question rather than move the
answer. Quoted, because the framing is the finding:

> Containment is a property *relative to a root the operator names*; deny items
> 1, 2 and 3 are *absolute* locations. Nothing in homma checks an absolute
> location anywhere.

And its verdict on what thirteen rounds achieved:

> the PR's opening line, "homma cannot write outside the workspace root", is a
> true statement about a property the record never asked for.

That is correct and it is worth sitting with. Every round so far asked whether a
write could escape a root the operator named. None asked whether the root itself
was somewhere the record forbids.

## Three shapes, all exit 0, all with containment satisfied

- **The root is a home carrying a live `.claude/`.** `org up` wrote both
  definitions and the memory symlink into it, beside a real `settings.json`.
  Every write went through `Layout` and `Root::contain`, correctly.
- **The workspace is under an existing `.claude/`.** `create_dir` made `hands`,
  gix cloned a repository into `hands/r`.
- **The root is inside an existing `.claude/`.** `Root::new` passes because the
  parent exists, `git.init` creates the root, and `.shared/hands/`,
  `.claude/agents/` and `.claude/agent-memory/` all land under it.

The previous round changed `create_dir_all` to `create_dir`, which changed how
many levels get built and did not touch this. `~/.claude` exists on every machine
that runs an agent, so the single level the new code creates is exactly the one
inside it.

## What the record actually says, read again rather than remembered

```
1  writes under ~/Dev/clause-dev
2  writes under another Hand's workspace
3  writes under ~/.claude/
```

Three absolute locations. Two are derivable from the home directory and one from
the registry, which is already in hand at the point of the check.

**This is not an ambiguity and it does not go to op.** The intent is stated
plainly and the only thing missing is a mechanism. Deriving one is the work.

## The distinction that makes it non-trivial

The record licenses `.claude/agent-memory/<name>/` **in the content repo**, which
is project scope, and denies `~/.claude`, which is user scope. Those are the same
directory name and homma has nothing that tells them apart. When the root is a
home, they are the same directory.

So the guard cannot be "refuse anything named `.claude`". It has to be "refuse
anything under the **operator's** `.claude`", which means knowing where home is,
which means the home directory becomes an input rather than an ambient fact.

## The rest of the review

A fourth guard live and pinned by nothing: the identity read-back in `provision`.
Replacing it with a discard leaves 348 green, and `ProvisionError::IdentityNotSet`
is constructed at one site, asserted by no test, with a `Display` arm that never
executes. So the previous round's claim of a systematic sweep was false, in the
round that made the claim.

The new refusal's diagnostic says only "No such file or directory (os error 2)",
with no path and no remedy, in a fix whose entire justification was that the
alternative error read as a network fault. The same defect one layer up.

`git.init` still runs before `provision`, so the new refusal leaves a `.git`
behind, against a comment three lines above saying a refusal leaves nothing
half-built. Its sibling has a test asserting exactly that; this one does not.

The design template and `git_impl.rs` still describe the longest-existing-prefix
resolution the ninth round deleted, so an implementer deriving from the design
rebuilds the bug.

Both new end-to-end tests build a home that does not exist, which is the one
configuration where the guard fires. With `.claude` present, the real case, the
same scenario succeeds.

And `if out.parent().is_some() { out.pop() }` is exactly `out.pop()`, since
`PathBuf::pop` already does nothing at the root. A guard that cannot fail, two
rounds after the round named for deleting one.
