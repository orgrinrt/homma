# The sweep is tested, and both.sameset compares per package

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-core/src/release/{check,plan}.rs` and their tests, `homma-engine/src/cmd/release/order.rs`, `homma-engine/tests/cli_smoke.rs`, one clause of `homma-core/DEEPDIVE_release.md.tmpl`
**Source topics:** the seventh review of pull request 46, and `202609030250/202609030250_topic.the-sweep-refuses-what-a-single-run-refuses.md`

## The findings

The sweep's pre-pass, which names what it passes over and refuses a manifest off the level, has no test on the command itself; the test the last round added exercised `sibling_dependency`, which had not changed, under a name promising an absence while asserting a presence. A smoke test runs the sweep over two repos, one with nothing unreleased and one with no manifest, and reads both lines; a second runs it over a manifest off the level and reads the refusal. The `order.rs` test is named for what it asserts.

`both.sameset` compared the first jsr package's versions to the first npm package's, whichever they were. The design says the check is per package that ships on both, so the versions are compared for each jsr package against the npm package of the same bare name, and the finding names the package.

The design's check section says where the ids came from, which is process rather than contract on a rendered surface. The clause goes.

Two of the review's notes are cheap and taken: `manifest_version_at` writes its scratch manifest through `write_private`, refusing a planted path rather than swallowing the error, and the off-level message no longer offers a level that makes a version below the last tag. The prerelease gap in `semver.gaps` and the wall time's step in the gate summary are noted and not taken here.

## What does not change

The design, except for the one clause.
