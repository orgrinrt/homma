# Src changelist: what a stranger gets, and what it tells them

**Date:** 2026-08-25
**Round:** 202608250858
**Source topic:** `202608250858_topic.what-a-stranger-gets.md`

## CHANGE: `mock/crates/homma-api/src/denied.rs`

`Denied::under_home` returns one entry, `~/.claude`. The second entry it
returned named a directory that exists on one machine, with a reason naming an
owner nobody else has heard of, and it goes.

The capability it stood for does not. A new `Deny` carries what the manifest's
`deny` key names, each entry a path and an optional reason, and
`Denied::denying` folds it into a list. A relative path resolves against the
manifest's own directory the way `local_path` does; a leading `~/` resolves
against the home directory; an absolute path is taken as it is.

`Denied::and` widens from `&'static str` to `impl Into<String>`, because a
reason that came out of a file is not static. Every existing call passes a
literal and is unchanged.

`Denied::for_standing_up` folds the manifest's list in, since it already takes
the workspace that carries it. A new `Denied::for_the_workspace` does the same
for the case with no standee: the home entry, every participant's workspace with
no exclusion, and the manifest's list. That is the list `org add` builds by hand
today, and building it here means the next caller cannot assemble two thirds of
it and typecheck.

Ten comments and doc paragraphs across the four crates say a rule is what "the
record" forbids. Each states the rule. Four cite `U-3.1` or `U-3.2`, which name
nothing a reader of this repository can open; each says what the requirement is.
One test message names a particular person as the author and says "the
configured identity" instead.

## CHANGE: `mock/crates/homma-api/src/config.rs`

`Workspace` gains `deny`, defaulting to empty, so the manifest key parses under
`deny_unknown_fields`.

## CHANGE: `mock/crates/homma-core/src/config.rs`

`Config` gains the same field for the same reason: two parsers read one file and
neither may reject what the other accepts.

## CHANGE: `mock/crates/homma-engine/src/cmd/gates.rs`

The generated gate script checks for `jq` before it reads anything, and denies
with the reason when it is missing. It exited 0 instead, by way of an empty
command line and its own out-of-scope branch, so a machine without `jq` had a
gate that allowed every commit and every push and said nothing.

Failing closed is the right direction for a gate, and it is also the only one
that is visible: an operator who is denied installs `jq`, and an operator who is
silently allowed learns nothing.

`run_gate` stops returning `Option`. The six tests that returned early on a
missing tool ran nothing and reported green, which is the state the suite exists
to rule out. `bash` is required outright, since a gate script is a bash script
and a machine without bash cannot run this suite meaningfully. `jq` is not:
`run_gate` takes the `PATH` to run under, so the missing-`jq` case becomes a
test of its own that asserts the deny rather than a reason to skip five others.

## CHANGE: `mock/crates/homma-engine/src/cmd/mod.rs`

`org add` calls `Denied::for_the_workspace` rather than assembling the list from
`Denied::from_env` and a loop.

## CHANGE: `mock/crates/homma-engine/src/cmd/agent.rs`

`denied_for_aggregating` folds in the manifest's `deny`.

## CHANGE: `mock/crates/homma-engine/tests/the_readme_examples_are_real.rs`

The command check resolves each command the readme names through clap's own
command tree instead of running it with `--help`. `--help` succeeds on a parent
command whether or not that command runs on its own, which is why the readme
could offer `homma docs` for as long as it did.

It also runs the other way now. Every top-level subcommand clap declares has to
appear in the readme's table, so a command added later is documented or the test
says which one is not.

A new case pins `token_cmd`: the readme has to name the key, because a manifest
that carries it runs a program of its choosing.
