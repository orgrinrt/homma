# identity-catalogue-and-lease

## What is asked

The workspace's agents get one catalogue of identities, read by homma and by nothing else directly, and an
identity is held by one session at a time. Op's answers, 23 November 2026, recorded on the workspace tickets
920a94aee4d7, 7ad3b03f1829, 9ff84a9ba61f and fd917dfa8694:

- The catalogue lives in `homma.toml`'s `[org.*]` rows: "Homma toml, one source of truth." The character files
  carry prose only.
- The hands are reused and each keeps the address its roster row gave it. A new identity gets an address of its
  own, chosen per person on `ikiuni.dev`, `eternal-stream.net` or `hiisi.digital`: "Per person, always".
- A lighter identity for helpers, the journeyman: a junior a hand's team reserves for the week. Eight of them,
  named by op.
- The coordinator offices have stable holders. Onni is the primary coordinator, Paja the tooling track, and the
  Loru coordinator is a new hand, Pikku, under Onni and in no count of slots. The other offices are named when
  their hand has a character ("Primary+tooling now").
- A sub-agent is its launcher's identity with a plus tag on the local part of the address, so a lookup by address
  strips the tag first.
- The public guard is a denylist and has to know every agent address exactly, since the hands' addresses sit on
  op's own domains and no domain pattern covers them.
- The lease: one session per identity at a time, a record per identity naming the session, the job, the time and
  an expiry, a takeover naming the holder it replaces, the history of the records being the ledger. In plain git,
  one file per identity on the workspace repository's trunk, the refused non-fast-forward push being the swap.

## What homma has today

`[org.*]` rows parse into `Identity` (role, handle, nickname, full name, domain, git and committer identity,
workspace, session, repositories). `Role` is `king`, `hand`, `expert` or `general`. `OrgRegistry` answers by
handle and by role. A handle is checked as `[a-z0-9-_]` only, so the roster's `os.si`, `säkä` and `pöllö` are
refused, and an entry carries one handle, so `pajatso` beside `paja` cannot be written. Nothing looks an address
up, nothing says who holds an office, and nothing records who is using an identity now.

## Decided here

**A journeyman is a role of its own.** It has a name and an address and is reserved by a team, so it is not
`general`, which has no persona at all; and it has no workspace of its own, so it is not a `hand`. It owns no
workspace and, until the memory ticket 228e8b157768 lands, no memory.

**An entry may carry aliases**, further handles that reach the same participant (`pajatso`, `vouti`,
`webaaja`). A handle or an alias is unique across the catalogue.

**A handle is checked as a name, not as ASCII.** It is a directory and a file name, so it may not be empty,
`.` or `..`, start with a dot, or carry a separator or a control character; letters of any script, digits, `-`,
`_` and `.` are fine. The restriction was drawn tighter than its reason, as the roster said.

**Offices are rows of their own**, `[offices.<name>]` with an optional `holder` and `counted`, in the same file.
A TOML key cannot appear twice, so one office cannot have two holders; the check refuses one handle holding two
offices, a holder missing from the catalogue, and an office named like a handle (both are pinged on the channel).
A commit carries the person, the channel addresses the office.

**Every agent address is unique across the catalogue**, compared the way the matcher compares them. An address
that two entries share would make the lookup answer one of them silently.

**The matcher** takes an address, lowercases it, strips a plus tag from its local part, and looks it up against
every entry's author and committer address, normalised the same way. The king is not an agent and is never
answered. `homma identity match <address>` prints the handle and the role and exits 1 for an address that is no
agent's; `homma identity index` writes every agent address, its handle and role, one per line, to
`[paths] identities`, for a hook that cannot afford to run homma. `agent regen` writes it too, so each instance
has it after a regen.

**The lease** is a TOML record per identity under `[paths] leases` on the trunk `[lease]` names (`remote`,
`branch`, `minutes`; `origin`, `main` and 120 by default): the handle, the session, the job, when it was taken
and when it expires, and on a takeover the session it replaced. The decision is pure and lives with the
registry: taking a free identity, renewing one's own, taking over an expired one (the replaced session is
recorded), refusing a live one held by another session unless the take names that very session as the one it
replaces, releasing one's own (the record is removed; the history keeps it). The swap is homma-core's: one file
written onto the fetched trunk tip as a commit built through the plumbing, the working tree never touched, and
pushed without force; a refused push means the trunk moved, so the lease is fetched and decided again, a bounded
number of times. `homma identity lease take|renew|release|show`.

## Review pass one, and what it changes

The first review found nothing blocking and named what the design left loose:

- An alias reached only the uniqueness check: `lease take pajatso` was refused as no handle, and an office whose
  holder was written as an alias read as a missing holder. The design says an alias reaches the same
  participant, so a name is resolved to its entry wherever one is taken: `resolve`.
- `lease show` of a mistyped name printed it free. Every verb now refuses a name the catalogue lacks.
- A length of zero minutes wrote a lease already lapsed, and a huge one overflowed the time type. A lease lasts
  from one minute to a week.
- A record that is there and cannot be read was read as free, and a record naming another handle than its file
  was accepted. Both are refused.
- `agent regen` wrote no index where the catalogue held no agent, so a removed last agent left a stale index. It
  writes an empty one.
- A landed swap whose tracking-ref update then failed reported an error for a write that landed. The tracking ref
  is a convenience; its failure is not the swap's.
- Left, and ticketed: the retry loop has no test of a trunk that moves between the read and the push, since a
  fresh fetch each try leaves no seam to move it in; a push the clone's own pre-push hook refuses is an error, not
  a move, which is what it is.
