# the-description-follows-the-tagline

## What was found

The readme pass rewrote every published package's tagline, the one line under
the title that says what the thing is, and left every manifest's description
where it was. A crate's `Cargo.toml` description is what crates.io shows
beside the name, a package's `deno.json` description is what jsr shows, and
neither had any tie to the readme that was rewritten to say the same thing
better. The question went to op with the readme pass's report.

The gate, `homma-core/DEEPDIVE_release.md.tmpl` section "The gate", is six
steps per repository kind, format, lint, tests, deny, docs and notices, each a
list of programs run and read, and nothing in it reads a readme. The release
check, section "The check", reads tags, `main`, the registries and the tree,
and nothing in it reads a description. So the two surfaces a stranger sees
first, the registry line and the readme's first line, can say two different
things about one package and nothing here says so.

The source, read after the docs: `homma-api/src/release.rs` has `Step` as a
closed set of six with `ALL`, `blocks` and `name`; `homma-core/src/release/gate.rs`
runs every step as a list of calls to a `Runner`, an empty list being a skip,
and measures numbers off the log afterwards. Nothing in the gate reads a file
of the checkout itself.

## What op ruled

From `.data/op-responses/202609031525_descriptions-toolchain-versions-and-defer-readmes.md`,
asked whether each crate's description should follow its new readme tagline
or stay as published, among [follow the taglines; stay as published; follow
only where the old one was worse]:

> Yeah should follow, and that ought to be part of the pipeline for ci.

The intent: the description is the tagline, and the pipeline holds them to
that rather than a person remembering to.

## What this round does

A seventh gate step, `description`, that blocks. For a repository whose
markers say `cargo` it reads the description `Cargo.toml` declares, under
`[package]` or under `[workspace.package]` where the root is virtual, and for
`deno` the one `deno.json` declares, and compares each with the readme's
tagline: the first paragraph of prose after the title, past the badge block
and any blank line, whitespace trimmed at both ends and nothing else, since
the tagline is what the description is meant to be and a trailing full stop
one has and the other lacks is the drift being caught. A manifest that
declares no description fails the same way, since a registry with no line
beside the name is the same absence as a wrong line. A readme with no title
or no tagline is a skip that says so, because the gate cannot compare against
nothing and the readme's own shape is another gate's business. The step runs
in the gate's process rather than as a program, being a read of two files,
and its log names both strings where they differ.

The deep dive's step table gains the row and the paragraph after it says
what the tagline is and where it is read from; the surface is unchanged.

## What was weighed and not taken

Comparing after dropping a trailing full stop, or case, or the backticks a
tagline may carry around a name: rejected, since what crates.io shows is the
description byte for byte and what the readme shows is the tagline byte for
byte, and a rule that lets them differ by a character is a rule that lets
them differ.

Reading the description off the readme and writing it into the manifest at
release time: rejected, since a release writes the version and the changelog
and nothing else into a manifest, and a description written by a tool is one
nobody read.

Putting the check in `homma release check` rather than the gate: rejected,
since op named the pipeline, and the gate is what runs on every push.
