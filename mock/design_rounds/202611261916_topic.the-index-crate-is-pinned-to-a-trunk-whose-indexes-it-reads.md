# The index crate is pinned to a trunk whose indexes it reads

## The ask

homma's lock holds the index crate at 5bf5422, 167 commits behind the crate's trunk. The trunk's chunker is at version 2 and the pinned one at 1, and the crate refuses a file whose header records a chunker newer than its own, so every index a current build of the crate wrote is reported unreadable and the search answers nothing. Move the pin to the trunk's tip, fix what the move breaks, and show the search answering over an index of today's format.

## What moves

The lock's `muisti` source moves to the trunk's tip, ef97f1b. The crate's `Embedder` trait now requires `fingerprint`, the key a cached vector is held under; homma's library code implements no embedder of its own, and its two test embedders take the crate's rule for an embedder whose vectors its own code decides: the fingerprint is the model's name. Nothing else in homma's search or layer code fails to build or fails its tests at the new pin.

## The test

A planted corpus, an index written with the header today's crate writes, chunker 2 given as a number rather than read from the crate's constant, so the test states the format a current build writes and does not move with the pin. The search answers its hit. Failing control: at the old pin the same test fails on the index's header.

## What stays

A check that refuses a pin whose index format is behind the trunk's is not built here; it is a ticket.
