# An empty declaration builds nothing and turns green

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-core/DEEPDIVE_release.md.tmpl`, `homma-core/src/release/gate.rs`, its tests
**Source topics:** the review of pull request 51, and `202609030700/202609030755_topic.a-declared-feature-set-replaces-all-features.md`

## The findings

`feature_sets = []` is a well-formed array, so the declaring arm iterates nothing, lint, tests and docs each get an empty call list, an empty list is a skipped step, and a skipped step passes. The verdict is green with three of six steps never run. A member declaring `[]` is worse: it is excluded from the workspace-wide runs and adds no run of its own, so nothing compiles it at all. An empty declaration is refused as a manifest error, beside the malformed cases already refused.

On a root that is itself a package, the old runs built that package alone; adding `--workspace --exclude` whenever a member declares sets widens them to every member. The exclusion belongs to a virtual root only, where the runs were workspace-wide already. A root package keeps building alone and a declaring member under it gets its own runs.

The tests had no fixture for `feature_sets = []` and no non-virtual workspace root, and one test re-ran two steps its own neighbours already pinned exactly.

## What does not change

Everything the last round settled about which sets run where.
