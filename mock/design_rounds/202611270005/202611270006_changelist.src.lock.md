# src changelist

Descends from `202611270005_changelist.doc.lock.md`, and through it from `202611270004_topic.a-manifest-entry-an-engine-does-not-know.md`.

## CHANGE: the manifest parse FROM strict only TO strict first, then without the unread entries
File: `mock/crates/homma-core/src/config/unread.rs`, `mock/crates/homma-core/src/config.rs`
Verification: `Config::parse` calls `unread::parse`, which returns the strict parse where it takes the manifest; otherwise it reads the raw value, takes out each entry of the top level and of `[agent]` (`GROUPS`) under which `keys()` lists no key, and parses the rest strictly, keeping the names on `Config::unread`; where nothing was unread, or the probe or the raw read fails, the first refusal is returned. The comment on `repos` says a `[repos]` table is now named as unread.

## CHANGE: the words FROM none TO `unread_advice`, `unread_note` and `unread_refusal` on `Config`
File: `mock/crates/homma-core/src/config/unread.rs`
Verification: `unread_advice` gives the `reads` pointer and the step for a rev, tag or version pin, a branch pin, or no pin; `unread_note` names the entries before it; `unread_refusal(table)` is the note and why the verb stops, only where an entry under `table.` is unread.

## CHANGE: `agent regen` FROM writing from what it read TO refusing while an `[agent]` entry is unread
File: `mock/crates/homma-engine/src/cmd/agent.rs`
Verification: `regen::regen` bails with `cfg.unread_refusal("agent")` before anything else.

## CHANGE: the status FROM no word on unread entries TO `unread` and `unread_advice` on the workspace line
File: `mock/crates/homma-engine/src/cmd/status.rs`
Verification: `WorkspaceLine` carries `unread` always and `unread_advice` where there is some; the human output prints `  not read by this engine: <entries>` and the advice under it only where an entry is unread.

## CHANGE: the tests FROM none TO the entry kept, the misspelling refused, the line kept, the words, the refusal and the status line
File: `mock/crates/homma-core/src/config/unread_tests.rs`, `mock/crates/homma-engine/src/cmd/status_unread_tests.rs`, `mock/crates/homma-engine/src/cmd/agent/regen/tests.rs`, `mock/crates/homma-engine/src/cmd/status_tests.rs`
Verification: a `[repos]` and a `[local]` table are top-level entries this engine reads no key under, so by the design they are taken out whole and named on `Config::unread`, never read in part: `a_manifest_that_still_declares_repos_is_named_as_unread_rather_than_half_read` (`tests/config_smoke.rs`) and `a_manifest_carrying_a_local_table_has_it_named_and_never_read` (`src/local_tests.rs`) assert that in place of the refusal, and the chain test of a config error refuses a misspelt `[defaults]` key in place of a `[repos]` table. Each test has a failing control; the status tests share `rendered` and `report_of`, now `pub(super)`. Taking out the second parse fails 3 tests, the `[agent]` group 2, the dot of the table prefix 1, the regen guard 1, the status line 1.
