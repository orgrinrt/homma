# tests-that-name-nothing-real-and-four-small-fixes

Extends round 202611251118-jvwb, which planted the workspace the acceptance set of `homma what`
reads. Its tests of the parsers and the ranking, and the readme tests, still carried the names of
one real tree's scripts, tools, channels and branches as their sample text. homma may be published,
and names no tree but the one a test plants.

## The sample text of the tests

Decision: every test of `cmd::what` and `cmd::ask` plants or writes what it reads under invented,
generic names: the garden of the planted workspace, a pigeon loft for the messenger readme, a
tidy-up tool for the disk. A test keeps what it checks, the header shapes, the column gap, the
fence, the verb that matched best, and changes only its words. A grep of the crate's tests for the
names of the tree homma is developed in finds none of them afterwards.

## A planted script is run with no write handle open on it

A test that writes a script and runs it can fail with `Text file busy` when another test thread
forks while the script is still open for writing in this process: the child holds the descriptor
until it calls exec. Decision: the tests write a script they will run from a child process, so no
descriptor open for writing on it exists in the test process at all. The failure is shown
deterministically by running a script while a handle on it is held open.

## The ask's cache is found for the root alone

`Cache::of_workspace` asks git for the git directory of the workspace root, and git reads
`GIT_DIR` and `GIT_WORK_TREE` from the environment before `-C`: run from a hook that exports them,
the cache, and its sweep, would be another repository's. Decision: the question is asked with both
removed, so the answer is always the root's own. The sweep test clears them for the git it runs
too, and checks the cache sits under the planted root; run with `GIT_DIR` exported at another
repository it is the control.

## The sweep leaves a write in flight alone

A cache entry is written beside its place as `.<key>.<pid>` and renamed over it. Decision: the
sweep counts and removes the entries only, never a dot file, so one ask cannot take another's write
from under it.

## A principle's render error names its template

A principle's card is named with a prefix, so an error built from the card's name named a template
that does not exist. Decision: a rule keeps the path of the template it was read from, and a
render error names that.

## Removing a frontmatter key matches a key only

`frontmatter::without_key` dropped an indented line too, so a nested key of the same name, or a
list item that reads like one, went with it. Decision: a key is an unindented line.

## The planted workspace is removed after its test

`fixture::workspace` kept its directory in a static, so every run of the test binary left one
planted workspace in the temporary directory. Decision: each test plants its own and holds it, and
the directory goes when the test ends.

## The configuration module

`homma-api`'s `config.rs` holds the workspace, the identities, the paths, the tables of search,
summary and ask, and the check for unreadable strings, past the file-size limit. Decision: a
module tree along what it holds, `config/` with `identity`, `paths`, `tables` and `unreadable`
beside the workspace in `mod.rs`, the tests beside what they test; no behaviour changes, and the
crate root's existing exports name the new places. No re-export is added for an import's sake.

## Tests

With failing controls: a script run with its handle held is busy and one written from a child is
not; the sweep test with `GIT_DIR` exported elsewhere keeps the cache under the planted root; a dot
file older than the expiry survives a sweep; a principle that fails to render names its template;
an indented key of the same name survives `without_key`; a planted workspace is gone once its
holder is dropped.
