# A guard that cannot fail, above a guard that nothing pins

Eleventh review. The class is closed for the surface this branch claims, and the
review says so. What it refuses on is worse in a way: the guard the round
advertised is a tautology, and the guard doing the actual work is pinned by
nothing.

## The tautology

Last round added, above the `symlink` call:

```
lands = AbsPath::new(link_dir.join(relative_from(link_dir, target.resolved())))
root.contain(&lands)?
```

`relative_from` expresses `to` relative to `from`. `link_dir` is resolved, so it
carries no `..` and no symlink component, so `AbsPath::new`'s lexical
normalisation recovers `to` exactly. **`lands` is `target.resolved()`,
unconditionally**, and `contain` proved that path one frame earlier in `prepare`.

Two measurements, both the reviewer's:

- Replacing the guard with `assert_eq!(lands, target.resolved())` runs the whole
  suite without tripping.
- Deleting the guard outright leaves 338 green.

The comment above it said "It is proven anyway, below, because
correct-by-construction is what ten rounds of paragraph in this crate have each
claimed." The reviewer's answer: **it is a paragraph with an `if` around it.**

That is the exact defect the workspace rule written this same session names, and
it was committed in the same session by the same agent. Worth recording rather
than quietly fixing, because a rule its own author violates immediately is
evidence about how hard the reflex is, not about the rule.

## The guard nothing pins

`root.contain(&parent)?` on the memory link's parent is **live**, not redundant:
replacing it with a bare `create_dir_all` leaves all 338 tests green while
opening a real escape.

The shape, which no test names:

```
ln -s ../outside  root/.claude                              # the parent chain leaves
ln -s root/.shared/hands/r/memory  outside/agent-memory/r   # the final link comes back
```

`contain` on the link follows its final component and passes, because the final
component points back inside. The **parent** resolves outside. Without the parent
check, homma runs `remove_file` and `symlink` outside the root and writes a body
climbing two levels above it.

So the class is closed by the parent check and by resolving both ends, and it is
closed by neither of the things the last round's changelist led with.

## A claim that was compiled and falsified

Three places say a write computed from an unchecked path does not compile. The
reviewer compiled one:

```rust
std::fs::create_dir_all(layout.root().join("unproven")).unwrap();
```

Clean build. `std::fs::*` takes `AsRef<Path>`, which `AbsPath` satisfies, and
`Layout::root()` is a public accessor handing one out, eighty lines below a
sentence saying every accessor returns a proven path.

**`Layout::root()` has no callers anywhere in the workspace.** So the route
closes by deleting it, and the narrower true statement replaces the false one:
`Root::create_dir_all` and `link_memory` take `ContainedPath`, so those cannot be
called with an unproven path.

## What the review found outside this branch, recorded so it is not lost

`cmd/aggregate.rs` and `cmd/gates.rs` write hook scripts, `settings.json` and
0755 wrappers into `<workspace>/.claude/` using bare `Path`, with no `Root`, no
`AbsPath`, and a repo name interpolated into filenames. The record licenses the
gen pass, so the surface may exist. It has no containment story at all, while the
crate next door has spent eleven rounds on one.

Out of scope here and named so it does not become round twelve by surprise.
