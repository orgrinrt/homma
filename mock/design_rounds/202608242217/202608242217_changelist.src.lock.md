# Src changelist: one client per forge, not one per repo

**Date:** 2026-08-24
**Phase:** IMPL
**Source topic:** the topic of this round
**Doc changelist:** the locked doc changelist of this round

## CHANGE: `homma/src/cmd/verify.rs`, `resolve_with` keeps its clients

MODIFY the `usable` list from forge names to forge names paired with the client
already built for them, so the per-repo loop borrows rather than constructs.

The credential probe already builds one client per forge. Keeping it is the
whole change; nothing new is constructed and one construction per repo goes
away.

## CHANGE: `homma/src/cmd/verify.rs`, a test that counts constructions

ADD a test driving `resolve_with` over a manifest with several repos on one
forge, through a factory that counts calls, asserting the count is the number of
forges in use rather than the number of repos.

Every existing test asserts findings, and the findings are identical either way,
so this is the only shape that can see the defect. Run with the per-repo
construction restored, it must fail.
