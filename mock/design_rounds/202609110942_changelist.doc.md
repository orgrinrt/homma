# doc changelist: workspace agent hooks that chain

## Current state

The design says nothing about agent hook aggregation. The one paragraph that
mentions the pass, `mock/crates/homma-org/DESIGN.md.tmpl:196`, is about where it
may write, not what it writes, so `homma agent regen` does whatever
`homma-engine/src/cmd/aggregate.rs` does, and the topic file lists what that
loses: a repository hook with no registration is written and never registered,
every event is folded into `PreToolUse`, ownership is a `<repo>--` filename
prefix, only `.sh` files count, a shell call is narrowed by the hook process's
own directory, and a workspace has no way to declare a hook of its own.

## Changes proposed

### `mock/DESIGN.md.tmpl`, new section `## The agent hooks`

Placed after the command surface's paragraphs on the git hooks, since it is the
same question asked about the other kind of hook. It says:

- what `homma agent regen` owes the hooks it carries: every one keeps running at
  the event and for the tools it was written for, and nothing homma did not
  write is replaced or removed;
- one registration per hook, and no dispatcher, because the host runs every
  registered hook for an event in parallel and runs a handler named twice once
  (`https://code.claude.com/docs/en/hooks`, fetched 2026-09-11, quoted in the
  topic file). What a dispatcher would cost is stated beside it;
- ownership by the line homma writes into every file it generates, never by
  name, with a collision refused by path and the regen exiting `1`;
- every event and matcher a repository gives a hook, the `@matchers:` line where
  it gives none, and a hook with neither reported by path with exit `1` rather
  than written and left unregistered;
- any executable file under a repository's `.claude/hooks/` is a hook, and a
  non-executable one is reported;
- `[agent.hooks]` in the manifest, one array per host event, rows carrying
  `matcher`, `run` and an optional `repos`, each written as a wrapper carrying
  the same line so declared and aggregated hooks are kept and removed by one
  rule;
- narrowing a shell call by the host's `cwd` first, then any path the call
  carries, and the process's own directory last.

The example row names a generic script and repository, since the rendered
document is public and the workspace's own guard is nobody else's business.

### What this round does not change

- The git hooks table, `[hooks]`, and how its entrypoints are written. The
  agent table sits beside it and shares nothing but the manifest.
- The mockspace bootstrap gate's logic. It already carries the line homma
  writes, so it is kept and replaced by the same rule as every other managed
  hook, and needs nothing new.
- `run` is a path rather than an argument list. The git table's `run` is a
  command string and git-shook's is an argument list; a path is narrower than
  both, because the host hands the hook its input on stdin and a declared hook
  that wants arguments ships a script, which is what git-shook asks of anything
  wanting a pipe.
