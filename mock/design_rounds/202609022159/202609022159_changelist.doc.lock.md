# Doc changelist: the shared config gate, and one status command

Two subjects, and between them they touch two templates. The rest of the doc
surface is untouched and each is accounted for below.

## mock/crates/homma-org/DESIGN.md.tmpl

A new section, `## The shared tool configs`, between `## The workspace lifecycle`
and `## Generation`.

This section is owed rather than merely wanted. `homma-org` has carried
`configs.rs` for some time, close to seven hundred lines of it, and no design
document in this repository says a word about it: no mention of the shared
configs, of `rustfmt.toml` or `deny.toml`, of the templates directory, or of the
comparison. That is code the design does not say, which is not a code change but
a design change that was never declared, and this round is where it is declared
because this round is what builds on it.

What the section states: that one canonical copy of each shared config lives in
the content repository and a repository gets that copy rather than authoring its
own; that a template says which repositories want it by the directory it sits
in, so adding one is a data act and homma is not edited; the grammar of those
directories, ecosystem and severity, joined for a template two ecosystems want;
what an ecosystem is, which is a name plus a giveaway artifact on disk; that
there is no way for a repository to write down a refusal, and why, which is that
the one that was ever written was wrong for months and nothing could check it,
while every legitimate refusal so far is derived from the repository's own state
and so is recomputed rather than remembered; that absence of a required config
is what blocks, and difference never is; that a template is satisfied by any of
the paths it names, so a pin under `mock/` counts; and that placing a config is a
deliberate act rather than something a gate does, because placing one turns
checks on and those have consequences past the file existing.

The applicability table that is currently a match on file names inside
`configs.rs` stops being described as code, because it stops being code.

## mock/DESIGN.md.tmpl

Two edits, both in the second half.

`## The command surface` gains the two commands this round adds, `homma repo
config check` and `homma repo config init`, and states what `homma status`
answers now that it covers more than the manifest. The existing sketch of the
four verb families is left exactly as it is; it describes an intended shape that
this round does not reach.

That section also gains what the gate is: a workspace-level check on the commit
and push path that refuses when a repository has not shipped a config it is
meant to have, and names the command that fixes it. Where it lives is stated,
which is the workspace hook rather than a per-repository git hook, because
mockspace owns `core.hooksPath` in every repository it manages and a second
owner of one path is a fight. The reason it reads and never writes is stated
with it, because that is the whole of why there are two commands.

A new short section, `## What a status answers`, after `## The command surface`.
It states the principle rather than the field list: the plain status covers
every population homma can report and shows, by default, only what is not in the
state it should be in, with the narrower verbs remaining the place to see a
whole population including what is fine. It names which populations are in and
says the doc surfaces are deliberately out, being a survey rather than a fault.
It states that the machine-readable document grows fields rather than being
restructured, and that it is never summarised, because a document that omitted
the healthy members would be lying about the population to the one reader that
cannot tell.

## mock/PRINCIPLES.md.tmpl

No change. The principle this round leans on hardest, that configuration is
explicit and discovery is a convenience, is already there and already says what
this needs it to say. A template declaring its own applicability by where it sits
is that principle applied, not a new one, and writing it down twice would leave
two copies to disagree.

## mock/WORKFLOW.md.tmpl

No change. Nothing about the round ceremony, the phases or the gates that run
during them moves.

## mock/crates/homma-api/DESIGN.md.tmpl

No change. The containment vocabulary this round writes through, `Root`,
`AbsPath` and `ContainedPath`, is already described and is used exactly as
described. Nothing is added to it.

## mock/crates/homma-store/DESIGN.md.tmpl

No change. Nothing here persists a record.

## mock/crates/homma-engine, mock/crates/homma-core

Neither has a `DESIGN.md.tmpl` at all, which is why the engine-side work in this
round is described in `mock/DESIGN.md.tmpl` instead. That absence is a real gap
and a larger one than this round should quietly fill: `homma-engine` is the whole
command surface, and it includes `gates.rs`, which generates a hook that already
refuses commits and pushes today and which no design document describes either.
Writing those two designs is its own round and is reported rather than started
here, because folding it in would mean designing six thousand lines of command
surface as a side effect of adding one check to it.

## README.md, docs/

No change in this changelist. `README.md` is not generated from a template here
and is read against the source changelist rather than this one; the round adds
two commands to the surface it documents, so it moves there or the round has
shipped a readme describing a smaller tool than it ships.
