# identity-review-fixes

A review of the branch that generates an agent definition from a character file (the round `202610300827`) returned four blockers and eleven lesser findings. This round fixes the class of each, and no second review follows by the instruction of the person running the session.

Correction to the earlier topic, which quoted op as saying "character.md as the existing ones" and calling the work a top priority. Neither phrase is in the capture store. The two captures that carry op's words on the place are `.data/op-responses/202610292013_profiles-identities-live-in-the-hands-place.md` and `.data/op-responses/202610292015_identities-go-in-the-hands-directory.md`, and they say, verbatim:

"I can answer: clause-dev in the same place where the other current identities are (they have real names there basically right now and are a bit stale and old concept, but the place makes sense for ours too)"

"The dir is /hands likely or related to hands since that wad the old concept that was pretty funnily close to where we endedbup anyway" and "YUP".

The intent in them is the place only: an identity lives in the hands directory, beside the older concept of the same name. The file name `character.md`, the front matter keys and everything about generation and launch are choices of the round `202610300827` and of this one, and nothing here is op's ratified word. The path is therefore the only fixed point.

The classes the review found, and the option taken for each.

Blocker 1, the design's list of command groups. The paragraph naming the groups and the pinned list disagree once `identity` exists. Fix: `identity` is a group, the paragraph and the list say so. Option rejected: leaving `identity` out of the groups, because it takes verbs and the rule in the paragraph is that every built-in that takes verbs is one.

Blocker 2, a second writer for paths the layout already guards. Options.
- a: keep the lexical paths and add checks beside them. Rejected: that is the second owner the layout was written to end.
- b: render through `Layout` (`character`, `definition`, `harness_memory`) and the layout's link routine, which resolves both ends, leaves a correct link alone and refuses anything that is not a link. Chosen. It also makes `[paths] hands` and `agents` count, since the layout reads them.

Blocker 3, the front matter reader drops the first line of the body when no blank line follows the fence. The fault is in the shared reader and the fix is one skip count, with a test whose body starts at the fence.

Blocker 4, `role` is free prose that others edit and was written into YAML unquoted. Fix: the description is written plain when that is valid YAML for it and as a double quoted scalar otherwise, in `definition_described`, so every caller gets it.

Lesser findings.
- The generated text told an identity it has a twin and notes, and carried a second top heading. A third form, `Form::Authored`, carries what an authored file needs and nothing about a twin; the body brings its own heading.
- A memory of `.shared` alone is refused (it needs a directory under it), and two characters may not name the same first memory, since the harness writes through that link and a memory has one owner.
- A render leaves a correct link in place instead of removing and recreating it, which closes the window in which the harness could create a real directory.
- Listing identities reports an unreadable character file, a name that is not a plain handle, and a regular file at the link path as what they are, and a missing hands directory is an empty list. Rendering every identity validates all of them before writing any.
- `org up` and `agents render` treat a name that has a character file with front matter as an identity: neither writes its definition nor lists it as stray.
- The launch uses the existing `exec` of the dispatcher. `HOMMA_IDENTITY` is removed: nothing reads it, and the harness already carries the agent's name.
- `Character` keeps its fields private and its memory directories are a validated type, so the checks in `parse` cannot be skipped by a struct literal.
- The tests that would pass if the behaviour broke are strengthened, and the cases the review named are added.

Left as they are, and said so. `cmd/mod.rs` and `cli.rs` were past 500 lines before this branch and the identity subcommand adds to both; moving the dispatch out is a separate round. Whether the harness accepts a role that needed quoting was not checked against the harness itself; the output is valid YAML and that is what the test pins.
