# every-index-with-no-definition-names-its-command

Follows the closed rounds 202611242203-jxpf and 202611242346-js3a. A second review of the two found
the following.

## An index of another model that records no definition

The index crate checks the model before anything else, so the refresh of an index of another model
is refused for its model, and only the measure after it finds the file records no definition. That
line then names no command, though the design says every file that records no definition names the
command that writes one. It is the likely case in practice: an index of a vector model built before
the crate recorded definitions.

Decision: the command is named wherever the crate says the file records no definition, the refresh
or the measure.

## Counts in the line

The line says `1 commits` and `1 file and 1 commits`. Decision: each count is said in its number.

## The tests of the first round

The first round's src changelist names `tests.rs` for its tests; they are in `tests_current.rs`, a
file of their own, since `tests.rs` was near the file-size limit. This round's changelist names the
file, and the test of a refresh that fails pins the outcome it gets rather than accepting either.

## The engine's summary of the verb

The engine's readme says the verb asks every index; it now brings each current first. Decision: the
summary says so.
