# regen-renders-workspace-surfaces

## What op asked

Op, 19 November, verbatim: "apparently the homma agent regen does not yet run homma rule generation so that's a thing to wire up asap too. Until then the coords and helpers might've to manually run also the rule gen step".

The intent: one `homma agent regen` leaves every rule, skill and persona a session loads current, so nobody runs `homma rules render` by hand after it.

## What the design already says

`DESIGN.md.tmpl`, the generation pass: "the sole writer of the agent configuration in every workspace it manages, **the workspace's own rules, skills and agents included**." So the wiring is owed rather than new, and it belongs to the generation pass, which `homma agent regen` is. The regen today runs `cargo mock` per member, the shared configs and the aggregate, and renders none of the workspace's own surfaces.

## Where the render lives

`homma rules render`, `homma skills render` and `homma agents render` write the three trees. At the workspace root the rules and skills trees are links into one of two slots, and the workspace's `agent-surfaces` script owns that swap: it seeds the inactive slot, has homma render into it and retargets the link in one rename, so a session never loads half a render. It also holds the render lock and the stamps the session hooks read.

Two shapes were weighed.

- homma renders the three trees itself at the end of the regen. A session reading the link mid-render would load a half-written tree, unless homma took the slot swap, the lock and the stamps over as well. That is a second copy of the script's whole job, and the script would still need it for its session hooks.
- homma runs the workspace's renderer, named by a key under `[paths]`, the way `forge_route` names the command every tag goes through. homma stays the writer, because the renderer writes through homma's own render verbs, and the swap stays with the one thing that owns it.

The second is taken. `agent_surfaces` under `[paths]` names the command, relative to the workspace root, and the regen runs it as `<command> regen` after the aggregate. Unset, the stage is skipped and says why: a workspace with no renderer has nothing to stage the render through, and the regen does not guess one.

## The loop it must not make

The renderer's own hook path runs `homma agent regen --skip-cargo-mock --skip-configs` while it holds the render lock, to write the hook wrappers. A regen that then ran the renderer would wait on the lock its parent holds and fail. So the regen gains `--skip-surfaces`, and the renderer's hook path passes it. The key and the flag land in the workspace together, after homma's side is on `dev`, so no regen runs the renderer before the renderer knows to pass the flag.

## The report

The stage is one line of the regen's report, beside the per-repo table, and a failed render fails the run like any other stage. The all-skip guard counts it as a fourth stage.
