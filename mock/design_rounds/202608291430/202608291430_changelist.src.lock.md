# Src changelist: the tools a workspace has and homma does not

## crates/homma-core/src/inject.rs

New.

CHANGE: `StatusConfig` and `Inject`, the `[[status.inject]]` schema. Both deny
unknown fields, so a manifest carrying the `process` key from the shape this
came from fails rather than having it silently dropped.

CHANGE: `Argv`, an untagged enum over a string and a list, so `tool = "foo"` and
`tool = ["foo", "bar"]` both parse and everything downstream sees a word list.

CHANGE: `Injected`, one block's result: title, text, and a failure that is
`None` when there is none. The failure is a field rather than a `Result`,
because a failing block still prints and still needs its title.

CHANGE: `settle`, which anchors a relative program path holding a separator
against the workspace root and leaves a bare name for `PATH`. Same rule as
`settle_token_commands`, different anchor, and the topic says why.

CHANGE: `run_all` and `run_one`. Runs each entry in the given directory with
stdin closed, takes stdout, trims the trailing newlines homma is about to
supply itself, and reports a missing program, a non-zero exit, a signal and an
empty argument list each as its own failure text.

CHANGE: `pipe_through`, the `format` half. Spawns `sh -c`, writes the tool's
output into it, and takes stdout. The write's error is discarded on purpose:
`head -1` closes the pipe early and the resulting `EPIPE` is the ordinary case
rather than a fault. The child's stdin handle is taken out and dropped so a
pipeline reading to end of input sees one.

CHANGE: `derive_title`, the program's file name, so the minimal entry is one key
and still labels itself.

## crates/homma-core/src/inject_tests.rs

New. 35 tests over the schema, the anchoring, the runner and the titles.

Controls, since without them the rest assert nothing: an unknown key is refused,
a bare program name is not anchored, interior lines are not touched by the
trailing trim, and a tool printing nothing is not a failure.

Six mutations were run against these and each turned one red: anchoring bare
names too, dropping the trailing trim, treating `EPIPE` as a failure, reporting
a failing format as the tool failing, formatting a signal exit as a code, and
removing `deny_unknown_fields`.

## crates/homma-core/src/config.rs

CHANGE: `Config` gains `status`, defaulted, so `deny_unknown_fields` accepts the
table and a caller has it on the config it already loaded.

CHANGE: `from_path` settles it against the workspace root, after `root` is
computed rather than beside the other two settles, which take the manifest's own
directory.

## crates/homma-core/src/lib.rs

CHANGE: the module, and `Inject` / `Injected` / `StatusConfig` re-exported.

## crates/homma-engine/src/cmd/status.rs

CHANGE: `StatusReport` gains `injected`.

CHANGE: `run` runs the injections and hands them to `build_report`, which stays
a pure function of the config. Running them inside it would make the one
function this command can be tested through spawn processes.

CHANGE: the human render prints each block after the repos: the title, then the
text indented two spaces, with a blank line left blank rather than indented into
trailing whitespace. A failed block puts its reason on the heading, so an empty
body does not read as a tool that had nothing to say.

CHANGE: eight tests over the render and the JSON document, including the control
that a report with no injections prints exactly what it printed before.

## crates/homma-engine/tests/status_carries_injected_tools.rs

New. Nine cases through the built binary, which is the only thing that can say
the halves are wired to each other rather than each working alone: the block
appears, a relative tool resolves from another directory, the tool runs in the
root, the format runs, order is declaration order, a broken tool and a missing
tool each leave the rest of the status printing, the JSON carries the blocks,
and the control that a workspace declaring none prints what it always did.

## homma.toml

No change, and it cannot have one yet. `Config` denies unknown fields, so a
`[status]` table added before this lands is a manifest the engine on `dev`
refuses outright. The wiring is a separate change in the workspace repository.
