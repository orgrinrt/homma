# the-identity-tests-split-by-tier

The two tests in `crates/homma-org/tests/provisioned_commit.rs` are each split in two, one per tier of the identity a provisioned workspace commits under. The configuration tier is the one `crates/homma-org/DESIGN.md.tmpl` settles: standing a workspace up writes six keys into the clone's own configuration, and a commit made there carries them against a hostile global configuration (`DESIGN.md.tmpl:237-249`). That test removes the four identity variables from the `git` it spawns with `without_git_identity_env`, keeps the hostile configuration file, is not ignored, and passes in a container that exports the variables. It is the only end-to-end check of the settled tier, and round `202610231413` took it away by marking both tests ignored as a whole.

The environment tier is what the design does not settle. Its test sets the four variables and the `GIT_CONFIG_COUNT` triple to hostile values with `hostile_git_identity_env`, carries `#[ignore = "catalogue: ..."]` and a `FIXME` naming the open topic `202610231408_topic.how-a-provisioned-workspace-defends-its-identity-against-the-environment.md`, and states the intended assertions unchanged. A catalogue red and a regression red are kept apart: the first is a case the design has not yet answered, the second is a settled behaviour breaking, and a single ignored test holds both and hides the second behind the first.

## The fixture

`hostile_git_identity_env` in `homma_core::testing` set one `GIT_CONFIG_COUNT` entry, `author.name`. It sets all six keys the design lists now, `user.name`, `user.email`, `author.name`, `author.email`, `committer.name` and `committer.email`, so that a defence covering part of them cannot pass unseen.
