# `join` descends, `resolve` anchors, and only one of them may leave

**Phase:** TOPIC
**Scope:** `homma-api`, `homma-org`, `homma`

Seventh review, seventh refusal, seventh instance of one class. The guard was put
on the workspace root and **the writes are not at the root**: they are at
`root.join(paths.hands)` and `root.join(paths.agents)`, and `paths` is
unvalidated configuration. Reproduced, exit 0:

```
[paths]
hands  = "../victim/stolen-hands"
agents = "../victim/stolen-agents"

$ homma org up paja
exit=0
$ ls victim/stolen-agents
paja-twin.md  paja.md
```

An absolute value does the same, because `AbsPath::join` inherited
`PathBuf::join`, which discards the receiver when the argument is absolute.

**The file claims "every path this command writes to passes through here" and
`refuse_if_nested` has one call site.** That sentence was written in the round
that shipped this.

## The distinction the code never made

Two operations were sharing one method and they have opposite requirements.

**`resolve` anchors a path the caller is entitled to put anywhere.** A workspace
legitimately lives outside the content repository, so `../out/paja` has to work,
and going up is the point. What guards it is the containment check, at runtime,
against the filesystem.

**`join` descends into a tree we own.** `.git`, `HEAD`, `objects`, a handle's
directory, a definition's filename. **Nothing joined this way has any business
leaving**, and every caller that does it today is passing a literal from the
source. The one exception was the configured paths, which is where the escape is.

So `join` stops being able to leave at all: it normalises **within the receiver**,
and `..` clamps at the receiver rather than at the filesystem root. Every existing
caller is unaffected, because none of them was trying to leave.

**And the configured paths get a type that cannot escape either**, refused when
the configuration is parsed rather than when a file lands somewhere unexpected.
Two mechanisms, and the reason for both is that six rounds of one mechanism
checked in one place have each been escaped by a path nobody checked.

## The ordering defect this also fixes

With `content_repo = "local"`, the root check passes, `git.init(root)` runs, and
*then* the workspace is checked, at which point the root is a repository and any
workspace beneath it is refused as nested. Reproduced: exit 1, **with `.git`
already created**, against the comment three lines above it saying "a refusal here
leaves nothing half-built".

A workspace under the root is refused because a workspace is a clone of the
content repository and cannot live inside it. That refusal is correct and it now
happens **before** anything is created, on the lexical relationship, rather than
after an initialisation has made it true.

## The numbers, again, and what changes

Five of five checked rows overstated. That is three consecutive rounds where the
count was wrong after the procedure was rewritten twice to stop it.

**So the counts stop being reported.** What goes in the summary is the raw output
of the mutation run, committed in the round, and the names of the tests that
failed. A name is checkable by reading it; a count I cannot explain is an
assertion, and this has been an assertion three times.
