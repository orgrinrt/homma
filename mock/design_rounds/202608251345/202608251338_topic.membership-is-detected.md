# Membership is detected, not declared

**Date:** 2026-08-25
**Phase:** TOPIC
**Scope:** `homma-core` config, and every command that enumerates from it

## The ruling

Op, 2026-08-24, verbatim:

> Yeah let's remove the repos. Initially homma was meant for a specific
> workspace that instantiates the same everywhere, but the workflow has proven
> much mroe useful as a general workspace harness instead of a static instance
> of a workspace

On what replaces it, verbatim:

> every dir under root *that has its own .git or otherwise can be detected as a
> repo* that is

So membership stops being a list somebody maintains and becomes a property of
the tree. A directory under the workspace root carrying its own `.git` is a
member. Nothing is listed anywhere.

## What the list cost

The lint pack's crate was renamed to `mockspace-extra-lints` a month before the
repository was, and the manifest went on naming the old one. Every reference in
the workspace followed the manifest rather than the tree, because the manifest
was the thing being read. Detection would have made the rename a no-op.

The same shape is available for any repo that joins, leaves, or is renamed: the
tree is right and the file is behind, and nothing says so.

## What the table carried that detection has to replace

`[repos.<name>]` has four keys and each needs an answer.

`local_path` is the directory name, which is what detection walks over. It
stops being a key at all.

`forge` and `owner` lived only here. Both are in the clone's own `origin`
remote, which is the authority anyway: a manifest that disagrees with the
remote is a manifest that is wrong. The parsing does not exist yet.
`forge/url.rs` composes a URL from an owner and a name and never reads one
back.

`public_branch` and `working_branch` are already optional overrides falling
back to `[defaults]`, and the workspace manifest sets neither on any of its
twenty-four entries. They go with the table.

## Questions this round has to answer

**Which directories count.** A `.git` directory is the plain case. A `.git`
*file* is a worktree or a submodule, and a worktree of a member is not a second
member. Whether a bare repository under the root counts.

**Where the root is.** The manifest's own directory today. Detection has to
agree with that and with what a session's workspace actually is.

**What happens when a clone has no `origin`, or one that parses to nothing.**
A freshly `git init`ed directory is a repository with no forge and no owner.
It is a member; the question is what the forge-shaped commands do with it.

**Whether the forge is inferred or defaulted.** A remote host maps to a forge
profile in `[forges]`. A host with no profile is either an error or a member
that forge commands skip.

**What `verify` becomes.** It reads `cfg.repos` today and reports what is
missing. With detection there is no list to be wrong, so what it verifies
changes rather than disappearing.

**Ordering.** `BTreeMap` gave a stable order for free. A directory walk does
not, and every command that prints a list wants one.

## What is not in scope

`content_repo` stays: it is one named repository with a specific role, not a
membership list. `deny` stays. `[forges]`, `[defaults]`, `[auth]` and `[org]`
stay.
