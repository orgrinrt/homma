# Changelist: src, membership is detected

**Round:** 202608251338 membership is detected, not declared
**Phase:** SRC
**Scope:** `homma-core` config and repo modules, and the commands that enumerate

## The answers the topic asked for

**A member is a directory one level under the workspace root whose `.git` is a
directory.** One level, because a repository nested inside a member is that
member's business and the convention is that clones are root-level siblings. A
`.git` that is a file points at another repository's object store, which is a
worktree or a submodule, and a worktree of a member is not a second member. A
bare repository is not a working clone and none of homma's commands mean
anything on one.

**The root is `workspace.path`**, after it has been anchored on the manifest's
own directory. The two are the same thing whenever the path is left at `.`,
which is every ordinary workspace, and they are not when it is set. Detecting
beside the manifest while `resolve_local_path` anchors on the root would hand
every consumer a member whose path points at a directory nobody looked in.

**A clone with no `origin`, or one whose host matches no forge profile, is
still a member.** It has no forge and no owner, and the commands that need
either say so rather than skipping it silently. A directory somebody `git
init`ed is a repository and pretending otherwise is the manifest problem again
in a new place.

**The forge is inferred from the remote host**, matched against the hosts in
`[forges]`. Never defaulted: a guess here sends a push to the wrong place.

**Ordering is by directory name**, which is what the existing `BTreeMap` gave
for free and what every command that prints a list wants.

## CHANGE: `RepoConfig` stops being deserialised and starts being derived

`mock/crates/homma-core/src/config.rs`.

The type stays, and so does `Config::repos` as a `BTreeMap<String,
RepoConfig>`, because that is the shape four commands already read and none of
them has a reason to change. What changes is where the map comes from.

`forge` and `owner` become `Option<String>`. Detection cannot always produce
them, and a `String` that is sometimes empty is the same defect as a
`declaration that is sometimes wrong: it reads as an answer.

`local_path` stays, and is the directory name.

`public_branch` and `working_branch` go. They were per-repo overrides on
`[defaults]`, no workspace set either on any entry, and there is no longer a
per-repo row to write one in.

`#[serde(skip_deserializing)]` on the field, so a manifest that still carries
`[repos]` fails rather than being half-read: `deny_unknown_fields` is what makes
that loud. Deserialising only, not both directions, because the field is still
serialised: it is what `status --output json` prints and what the template
context iterates, and a plain `skip` took both away and left the templates with
nothing to loop over.

## CHANGE: detection is its own act, not part of parsing

`mock/crates/homma-core/src/config.rs`.

`Config::parse` takes a string and has no filesystem, so it cannot detect
anything and must not pretend to. `Config::from_path` knows where the manifest
is, so it detects after parsing, from the manifest's own directory.

A caller holding a `Config` built from a string calls `detect_members` itself
with the root it means. That is one line in a test and it is honest: the
alternative is a `parse` that returns a config whose membership silently
depends on the process's working directory.

## CHANGE: read the owner and the forge off the remote

`mock/crates/homma-core/src/forge/url.rs`.

The module composes a clone URL from an owner and a name and cannot read one
back. Detection needs the other direction, so it gains one: given a URL in
either of the two spellings git actually writes, `https://host/owner/name.git`
and `git@host:owner/name.git`, return the host, the owner and the name.

Matched against `[forges]` by host, through the `host_of` that already exists,
so the two directions agree by construction rather than by two spellings of the
same rule.

`origin_url` on the git trait is what supplies the URL and already exists,
returning `None` for a repository with no origin.

## CHANGE: the commands read what detection produced

`mock/crates/homma-engine/src/cmd/{agent,archive,migrate,status,verify}.rs`.

Every one of them enumerates `cfg.repos` and keeps doing so. What moves is the
handling of a forge and an owner that may now be absent.

`verify` changes the most, because half of what it verified was that a
declaration matched the tree and there is no declaration left. What it verifies
instead: a member whose forge could not be resolved, and a forge profile
nothing detected uses.

`archive` and `migrate` gain the case where the flag is the only source. Both
took the forge and the owner from the declaration and both now take the flag
first and the remote second, and refuse with the flag named when neither
answers. A guess there is an outward act landing somewhere nobody asked for.

## CHANGE: the workspace manifest drops its table

`homma.toml`, in the content repository rather than here.

Twenty-four entries, none carrying a branch override, every one of them
reproducible from the tree. It is deleted in the same act, because
`deny_unknown_fields` means a manifest that keeps it stops parsing.

## CHANGE: the readme stops teaching the table

`README.md`, which is hand-written rather than generated and so sits outside the
doc changelist's scope.

Its manifest example carried a `[repos.notko]` block and a paragraph explaining
how `local_path` resolves. Both describe a mechanism that is gone, and a reader
following them writes a manifest that no longer parses. What replaces them says
what makes a directory a member and what a clone with no forge gets.

## Tests

Detection, over a fixture root: a plain clone is a member; a directory with no
`.git` is not; a worktree, whose `.git` is a file, is not; a nested repository
inside a member is not; ordering is by name.

The URL reader, over both spellings, with a trailing `.git` and without, plus
a URL that parses to nothing.

A clone with no origin is a member with no forge and no owner, which is the
case a declaration could never have expressed.

That the root walked is `workspace.path` and not the manifest's directory, over
a fixture where the two differ, which is the only fixture that can tell.

And the control for each: a reader that matched nothing would report a clean
empty workspace, so each is run over a root built to trip it.
