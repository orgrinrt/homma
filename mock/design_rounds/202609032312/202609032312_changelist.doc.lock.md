# Doc changelist: the status is posted once the push has landed

**Date:** 2026-09-03
**Phase:** DOC
**Source topics:** `202609032311_topic.the-status-is-posted-once-the-push-has-landed.md`

## Current state

The commit status section says a run posts its status on the sha it
measured, and the hooks section says a green run posts before the push
proceeds. A `pre-push` hook measures a commit the forge has not received,
so every hook-made post answers 422 and the status waits for a hand-run
`--post`. The hooks section also lets a tag and its commit be two tips.

No other flat topic is open on this branch.

## Changes proposed

### `homma-core/DEEPDIVE_release.md.tmpl` (modify)

The commit status section says a hook-made run cannot post from the hook,
that the hook leaves a detached poster, `homma release gate --post <sha>
--await`, which asks the forge for the commit until it is known and then
posts, giving up after ten minutes, that the forge trait grows the commit
read this needs, and that a red run leaves no poster. The hooks section says
the tips are peeled to commits and taken once each, and that a green run
leaves the poster rather than posting itself. The surface table gains the
`--await` line.

## Lock criteria

The status section no longer claims a hook-made run posts before the push
proceeds, anywhere.
