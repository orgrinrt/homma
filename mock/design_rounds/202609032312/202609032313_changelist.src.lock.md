# Source changelist: the status is posted once the push has landed

**Date:** 2026-09-03
**Phase:** IMPL
**Doc changelist:** `202609032312_changelist.doc.lock.md`

## `homma-core`

### `src/forge/trait_def.rs`, `src/forge/github.rs`, `src/forge/forgejo.rs` (modify)

CHANGE: trait `Forge` gains `commit_known(owner, name, sha) -> Result<bool, ForgeError>`,
`GET .../commits/{sha}` on GitHub and `GET .../git/commits/{sha}` on Forgejo,
404 and 422 answering `false`.
Verification: `grep -c "fn commit_known" mock/crates/homma-core/src/forge/*.rs` is 3.

### `src/release/run_tests.rs`, `src/release/status.rs` (modify)

CHANGE: the test forges answer `commit_known` with `true`.

## `homma-engine`

### `src/cli.rs`, `src/cmd/release/mod.rs` (modify)

CHANGE: `ReleaseOp::Gate` gains `--await`, requiring `--post`, threaded to
`gate_cmd` as `wait`.

### `src/cmd/release/gating.rs` (modify)

CHANGE: `gate_cmd` under `--post --await` asks the forge after the commit
every five seconds for ten minutes through `await_known` and posts once it is
known, or reports that it gave up; under `--hook` the tips are `peeled` to
commits and taken once each, a green run leaves a poster through
`leave_poster`, this binary detached in its own process group running
`poster_args`, and a red run leaves none; a plain run posts as before.
Verification: the three tests added to the module, on `peeled`,
`await_known` and `poster_args`, and `grep -c "fn leave_poster" mock/crates/homma-engine/src/cmd/release/gating.rs` is 1.

### `src/cmd/verify.rs` (modify)

CHANGE: the verify test forge answers `commit_known` as unreachable, since
verify never asks.
