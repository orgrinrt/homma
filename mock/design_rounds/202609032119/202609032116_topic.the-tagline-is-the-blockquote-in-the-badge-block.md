# the-tagline-is-the-blockquote-in-the-badge-block

## What was found

The description step landed in round `202609032021` reading the tagline as
the first paragraph of prose after the readme's title, past the badge block.
Measured against the estate, that is the wrong line. Every readme here is
shaped the same way, `readme-format.md` in the workspace's write-in-ops-voice
skill lists it: the title, a centred `<div>` holding the badge rows, and
inside that same `<div>` a blockquote carrying the tagline, then the closing
`</div>`, then the opening prose. `notko/README.md` lines 1 to 13 are the
specimen: the `>` line under the badges is what crates.io's description was
meant to match, and the paragraph after the `</div>` is the opening prose,
a different element.

The extractor skips the whole `<div>` and returns whatever prose follows it,
so on fourteen root readmes it found the tagline in none: eight skip, because
a `##` heading follows the div and the loop reads that as no prose, and six
return the opening prose or worse. On `beech`, whose title is setext, it
returned a sentence from a support section. Where the badges are not wrapped
in a `<div>` it returns the blockquote with its `> ` marker still on. A
reference-link line, `[a]: https://b`, reads as prose because the badge test
wants a `(`. The tests were green because the badged fixture was written to
the definition rather than copied from a readme, and it borrowed notko's name
while leaving out notko's blockquote.

The manifest is wrong too. `cargo_description` reads the root `Cargo.toml`'s
`[package]` or `[workspace.package]`, and homma's root is a virtual workspace
declaring neither, on purpose; the crate that reaches crates.io is
`launcher/Cargo.toml`. So the step fails homma on the root manifest saying
nothing while never reading the one that ships. The five crates under
`mock/crates/` carry `publish = false` and are nobody's registry line.

Nothing in `gate_tests.rs` names the step, so the early return in `run_step`
could go and every gate test would stay green.

## What the design has to say instead

The tagline is the blockquote under the title: the first line beginning `>`
after the first heading, wherever the badge block puts it, inside a `<div>`
or not, with the marker stripped and a wrapped quote joined. A readme with no
such line has no tagline and the step skips saying so; the opening prose is
never mistaken for it. A setext title counts as the title.

The manifests the step reads are the published ones: every `Cargo.toml` in
the tree whose `[package]` does not say `publish = false`, and every
`deno.json` with a `name`, each against the tagline of the readme beside it
where one exists and the root readme's otherwise. So homma's launcher is held
to the root readme, a workspace of several published crates each with a
readme is held crate by crate, and an unpublished engine crate is not read.
`target/` and `node_modules/` are not walked.

The gate tests gain the step: a fixture whose description differs turns the
whole run's verdict red, and one whose description matches leaves it green,
through `run_gate_at` rather than through `tagline::check` alone. The
extractor's fixtures are three of the estate's readmes copied verbatim.
