# Source changelist: permit the workspace being aggregated into

**Date:** 2026-08-24
**Phase:** SRC
**Topic:** `202608241128_topic.aggregation-denies-its-own-workspace.md`

## CHANGE: `mock/crates/homma-api/src/denied.rs`

ADD `Denied::permitting(self, path: &AbsPath) -> Self`. Drops every entry
denoting the same place as `path`, comparing both ways `check` compares, so a
firmlink spelling and a case-folded spelling are both recognised as the same
place. Mutual containment is the test, so an entry *inside* `path` is untouched.

ADD tests: the plain case, the case-folded spelling, an entry under the path
which must survive, a path under an entry which must not permit it, and the
control that a list with nothing matching is returned unchanged.

## CHANGE: `mock/crates/homma/src/cmd/agent.rs`

EDIT `denied_for_aggregating` to apply `permitting(workspace)` to the
home-derived list, so the exclusion the registry loop already performs covers
the two entries that did not come from the registry.

The doc comment above it already stated this reasoning and the code applied it
to half the list. No comment change is needed beyond naming where the exclusion
now happens.

## CHANGE: `mock/crates/homma/tests/regen_writes_smoke.rs`

EDIT `a_participant_may_aggregate_into_their_own_workspace` to put the workspace
at `<home>/Dev/clause-dev`, which is the only path the home-derived list
hard-codes and therefore the only one that reaches the branch under test, and to
assert the run succeeded and wrote a wrapper rather than asserting one sentence
is absent from stderr.

ADD the control beside it: a sibling directory under the same home is still
refused, so the permission is the workspace's own and not the whole home.
