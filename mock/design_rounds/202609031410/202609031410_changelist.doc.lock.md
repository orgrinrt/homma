# Doc changelist: the root markers are declared in homma.toml

**Date:** 2026-09-03
**Phase:** DOC
**Source topics:** `202609031408_topic.root-markers-declared-in-homma-toml.md`

## Current state

The gate section of `homma-core/DEEPDIVE_release.md.tmpl` says a repo's kind is read off two fixed file names, `Cargo.toml` and `deno.json`, that a root with neither is an error, and that the step table is per kind, headed `crate` and `deno package`.

## Changes proposed

### `homma-core/DEEPDIVE_release.md.tmpl` (modify)

The paragraph says the marker files are declared in `homma.toml` under `[markers]`, each mapped to one of three signals, `cargo`, `deno` or `content`, with the two names the binary knew as the default rows. A repo's kind is the set of signals its root carries, `content` adding no calls to any step, so a repository declared as content alone runs a gate of skipped steps bar notices and passes. A root with no declared marker stays an error. A signal outside the three words is refused at load. A mockspace repository is read as whatever its root markers say until the manifest under `mock/` is read, which stays owed. The step table is headed by the two signals that add calls.
