# the-readme-test-and-the-launchers-verbs

`the_readme_examples_are_real` is red on `dev`. The readme's command table has a
row for `homma workspace [op]`, the test reads every `homma ...` span in the
readme and runs `homma-engine <path> --help` for it, and `workspace` is not an
engine command. It is the one command the launcher answers without the engine,
from `launcher/src/workspace/mod.rs`, so that the command works where there is
no workspace yet. The engine prints `unrecognized subcommand 'workspace'` and the
test reports the readme as naming a command the cli does not take.

The readme is right and the test is asking the wrong binary. The row says so in
its own text: "The launcher's own, so it works where there is no workspace yet."

## What the fix is

Two binaries answer `homma`, and the readme documents both in one table, so the
check has two halves and each half asks the binary that answers.

- The engine test skips a span whose first word is a command the launcher
  answers. It learns which from the launcher itself, `homma::TOOL.commands`,
  through a path dev-dependency on the launcher crate, so the list cannot drift
  from what the launcher actually intercepts. A hand-written list of launcher
  verbs in the engine's test would be a second copy that goes stale the day a
  second launcher command lands.
- The engine test also asserts the engine does not list any of those names
  itself. Otherwise the skip could hide an engine command that the readme got
  wrong, which is the defect the test exists to catch.
- The launcher's own tests check the launcher's half: every command in
  `TOOL.commands` has a row in the readme's table, and every backticked form the
  row writes after `homma workspace` parses with `Ask::parse`, with a sample
  value standing in for each `<placeholder>` and each optional `[...]` group
  dropped.

The launcher already dev-depends on `homma-core` for the same reason, holding
both ends of one file in one test, so the dependency direction here has a
precedent in the other direction.

## What the design says

`mock/DESIGN.md.tmpl` is silent on this test and on the readme check generally,
so nothing in it moves. The doc changelist says so.
