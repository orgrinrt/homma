# Src changelist: three tests answered by something other than the code

## CHANGE: the merged-view test stops depending on the machine

`an_empty_configured_value_is_not_a_value` asserts a fresh clone reports `None`,
which says nothing unless a global identity exists to be wrongly reported. Under
an empty `HOME` it passes green against an implementation that reads the merged
view, which is the guarantee it is the only pin for.

It now points `GIT_CONFIG_GLOBAL` at a file naming an identity and asserts `None`
against it, which removes the machine from the answer rather than asserting the
machine is configured.

Its sibling on the write side was given a precondition two rounds ago and this
one was not, which is the write-side-only sweep one level up.

## CHANGE: the destructuring becomes a gate

Adding a field and writing `signing_key: _` beside `role: _` satisfied it with
the field unguarded, so it forced somebody to type a name once rather than to
decide anything. And its final assertion compared two identical literals forty
lines apart, which constrains neither.

The hostile entry is built as a **struct literal**, so `E0063` requires a new
field to be populated, it carries a control character, and production has to
report it or `reported == want` fails. The literal-versus-literal assertion goes.

## CHANGE: the fallback order is pinned

`author.*` is read before `user.*` deliberately, with a comment claiming it does
what git does, and reversing both left the suite green.

## CHANGE: an assertion that compares a value to itself

`assert_eq!(got.author_email, got.committer_email)` compares two halves of one
recorded value rather than either against what the registry said, and caught no
mutation.
