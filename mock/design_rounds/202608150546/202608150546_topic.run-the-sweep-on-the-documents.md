# Run the sweep on the documents

Fourth review. The engineering held: the seam test is real, the read side is
genuinely swept, and every one of the six config keys is pinned. The reviewer
says so.

What did not hold is anything written in prose, and its closing sentence is the
finding:

> what has not landed is running the sweep on the **documents**, which is where
> all three of this round's own regressions live.

## The round that fixed a long line made it longer

The previous round opened a doc phase whose stated defect was "Ninety-nine
characters in a paragraph wrapped at eighty". The commit that fixed it produced
**one hundred and fifty-one** characters, in the same paragraph, whose other
lines run 78 to 81.

Measured here rather than taken on the reviewer's word. The fix failed in the
manner it was fixing and left the defect worse than it found it, which is the
same shape as the three code regressions the previous rounds shipped, in the one
place nobody thought to apply the lesson.

## The class that was fixed one file away and never grepped

Round `202608150248` corrected `README.md`'s singular identity, calling it "a
factual claim that is wrong rather than a matter of number", and did not grep for
the class. `fix-the-class-not-the-instance-named.md` is explicit about the
remedy and it was not run.

Grepped now, and it finds **four** occurrences rather than the two the reviewer
named. Two of the four are fine and stay: `homma-api` says "a git identity",
which remains true because an identity is what it is whether or not it has two
halves. The two in `homma-org` are wrong: one enumerates "a git name and email"
as what an entry carries, and one says the clone "reports the identity's own
email" where the read-back now compares four values.

Checking all four rather than editing all four is the point. A class grep finds
candidates; it does not decide them.

## And the doc phase that should not have been declined

Round `202608150143` closed its doc phase empty, reasoning that "nothing rendered
describes the identity split yet" and that editing first would be "the design
following the code". Both halves are wrong. `homma-org/DESIGN.md.tmpl:9` **is** a
rendered description of the identity, and writing the code with no doc phase is
exactly the design following the code rather than leading it.

## Three tests answered by something other than the code

The merged-view guarantee is pinned by a test that passes green under an empty
`HOME`. Its sibling on the write side was given a precondition assert two rounds
ago and this one was not, which is the write-side-only sweep repeating one level
up.

The exhaustive destructuring is a nudge rather than a gate: adding a field and
writing `signing_key: _` beside `role: _` satisfies it with the field unguarded.
Its final assertion compares two identical literals forty lines apart, which is
`the-test-gate.md`'s "a law relating two declarations to each other constrains
neither". The reviewer's own fix is better than the test and is what lands: build
the hostile entry as a struct literal, so `E0063` forces the new field to be
populated, it carries a control character, and production has to report it.

One assertion in `provision` compares two halves of a single recorded value
against each other and catches nothing.

## And a claim in the PR body that is false for the second time

"Every guard was measured by deletion, on both sides." The ordering of
`author.*` before `user.*` in the read is deliberate, is commented as doing what
git does, and reversing it leaves the suite green. Rewriting a false absolute
into a different false absolute is not the fix.
