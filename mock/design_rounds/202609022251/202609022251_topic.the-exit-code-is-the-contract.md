# The exit code is what the gate reads, and nothing ran it

Subject: pinning the commit path's actual contract, which is a process exit
code, through the binary that produces it.

## What was missing

The gate refuses a commit by running `homma repo config check --repo <name>`
and looking at whether it exited non-zero. That exit code is the whole
interface between the two, and it was covered only in pieces: the command body
returns a reported failure, and the dispatcher threads it, and each of those is
asserted somewhere. Nothing ran the binary and looked at what the shell sees.

That gap is the shape worth naming. Every piece was tested and the thing they
compose to was not, so a wrong `Ok` in the dispatch arm would have left every
test green while the gate allowed every commit in a workspace missing every
config.

It was found by running the loop by hand against a scratch workspace: check
exits 1 and prints the repo and the missing config, `init` places it and exits
0, the re-check exits 0, and the placed bytes match the shared copy. All four
were true. None of them was written down.

## What this adds

One integration test walking that loop through the built binary, asserting the
exit codes rather than the output, because the exit code is what the gate reads
and the output is what a person reads.

The placement half is asserted by reading the file back, for the reason the
unit tests already give: a stage that reported a placement and wrote nothing
would satisfy an assertion about its own report.

## What it does not add

Nothing about the gate script, which drives the same command and is covered
where it is generated. This is about the command's own contract with any
caller.
