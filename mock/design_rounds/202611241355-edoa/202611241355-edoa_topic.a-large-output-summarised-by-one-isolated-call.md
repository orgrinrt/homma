# a-large-output-summarised-by-one-isolated-call

## The question

Some of homma's verbs print a lot by design: a search across every index, a listing over many
days. An agent reading that output pays for every line of it in its own context, when most of
what it wanted was which places answer its question and what each says. A small, cheap model can
read the output instead and hand back a short summary, provided the summary still points at the
evidence, so the reader can open the place a line names before relying on it.

## Decisions

- **One function, one verb.** The engine gets a `summary` module: a function any verb calls with
  a text and a short brief, and `homma summarise --brief <text> [<file>]`, which reads the file or
  stdin and prints what the function returns. A verb's output is a text by the time it is printed,
  so the function takes text and knows nothing of the verb that made it.
- **Off unless the workspace opts in.** `[summary]` in the manifest, `enabled = false` unless
  set, read as `SummaryConfig` like `[search]` is. With it off, or with the call failing for any
  reason, the caller gets its own output whole and one line saying why there is no summary. A
  summary is never the only way to the output.
- **The call is isolated.** It is one print-mode run of the installed `claude` command with the
  small model, no tools, safe mode (no project instructions, hooks, skills or plugins), no setting
  sources, no MCP servers but the empty set, no slash commands and no session persistence, run in a
  fresh empty directory so nothing beside it is read. Its system prompt is the compaction rules and
  the brief, replacing the default one; the content goes on stdin; the answer is read from the
  JSON result. Tried in a container on 24 November: such a call costs about 1.4k tokens over its
  own prompt and answers in about two seconds. The command and the model are keys of
  `[summary]` (`claude`, `haiku`), so a workspace may point it elsewhere. homma reads, prints and
  stores no credential: the command authenticates itself from its own environment.
- **The model is a contract.** The function is generic over a one-shot model, a trait with one
  method taking the system prompt and the content and giving back the answer or why there is none.
  The command above is its one implementation in the build; the tests give their own.
- **Budgets.** The rules and the brief stay under 15k tokens and a request under 100k, counted at
  three bytes to a token, which overcounts ordinary text and so errs toward the smaller request.
  A brief that takes the rules over their budget is not sent: the caller gets its output whole
  and the reason. Content that does not fit one request beside the rules, the brief and a reserve
  of 8k tokens for the answer is cut at line boundaries into parts that each do, a line longer
  than a part being cut itself, and each part is summarised alone; the summary is the parts'
  summaries in order, each headed with the lines it covers.
- **Locations are kept.** Every line of the content is sent with its number, and the rules ask
  for every summary line to begin with the place it summarises: the `path:line` or key the content
  itself names, or else `line <n>` of the input. The function counts the summary lines that begin
  with no place and says how many in its line, so a summary that lost its evidence says so.
- **The rules carry a version.** The compaction rules are a constant of the module, and their
  digest is their version, so a cache of summaries (the next round's) is keyed on what produced
  them.
- **`homma search --summarise` is the first caller.** It hands the printed hits to the function
  with the question as the brief, and prints the summary in place of the hits, keeping the line
  per index; with the pass off or failed it prints the hits as before and the one line. The JSON
  output carries the summary and the line as fields beside the hits.

## Not this round

The ask verb, which runs a command and answers a question over its output through this function
with a cache of summaries per chunk, is the next round. The other verbs with large output take
the pass as they need it.
