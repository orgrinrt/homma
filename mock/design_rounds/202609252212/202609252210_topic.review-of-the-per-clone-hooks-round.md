# review-of-the-per-clone-hooks-round

What a review of pull request 70 found against round `202609251911`, and which
of it moves the design and which only the code. The review read the diff
against the locked changelists and `DESIGN.md.tmpl`, and did not run anything.

## Where the code falls short of the design

The design says a registration of homma's own that the regen finds in the
shared `settings.json` "is one an earlier regen put in the shared file, and it
is swept". The sweep reuses the predicate the local file uses, and that one is
scoped to the repos this run visited, on purpose: in the local file an
unvisited repo's entry is kept so its guard comes back the moment that repo is
cloned. In the shared file there is no such reason, since nothing homma writes
belongs there at all, and the measured case the round started from is exactly
this: nine `muisti--*` registrations in the shared file of a clone without
muisti. Nothing sweeps them, and a regen scoped to one repo sweeps only that
one. The shared file wants its own predicate, homma's shape whatever the repo,
still leaving alone a file under a managed name that homma did not write.

The shared file is swept and written before the local one is read. A local
file that does not parse, or whose root or `hooks` is not an object, then
errors after the shared file has already lost homma's registrations, and the
clone is left with none, the mockspace gate among them. Both files are read and
swept before either is written, and the local one is written first, so a
failure at the second write leaves a registration twice rather than nowhere.

## Where the design says nothing and the code guesses

A persona's `name` and `description` are read line by line, since the host's
own fields may nest and the shared frontmatter reader refuses both nesting and
any key it does not know. That reader is right for rules and skills and wrong
here, so the persona reader stays its own. It misreads two things. A trailing
comment, `name: reviewer  # note`, is read into the value and then refused as
a name mismatch, which names the wrong fault. A folded or literal description,
`description: >`, is accepted and the description becomes `>`. No persona in
the corpus has either today. Both are refused by name, because reading them
properly is a YAML parser, which the shared reader's documentation already
declines to carry, and the design gains the sentence that says so. The
duplicate `unquote` goes, in favour of the shared one.
