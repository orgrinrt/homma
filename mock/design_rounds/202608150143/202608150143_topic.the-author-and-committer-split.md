# The author and committer split

Roadmap units U-3.1 and U-3.2, built together because the second is the registry
field the first needs to be worth having.

## What the record settled

Op, on Vouti's git identity, asked which name a record it writes carries:

> For the author, keep me. For the committer, use orgrinrt+vouti@ikiuni.dev, a
> tagged email on mine own so it 'just works' but helps distinguish a bit.

So one clone needs two identities at once. Git supports exactly this: `user.name`
plus `author.email` and `committer.email` as separate keys, and the two may
differ within a single repository.

`Git::set_identity` takes one name and one email, so the shape cannot express it.

## The exit test, and why it is the commit rather than the config

From the roadmap, written before this round:

> A commit made in a provisioned workspace reports author `ort@hiisi.digital`
> and committer `orgrinrt+vouti@ikiuni.dev`, read back from **the commit** rather
> than from the config, since config that never reaches a commit is the defect
> this exists to prevent.

That is not a stylistic preference. A previous round on the neighbouring branch
shipped a config write nothing read, and the guard that caught it was itself
unpinned for four more rounds. Asserting the config asserts the mechanism;
asserting the commit asserts the outcome, and only one of those is what anybody
wanted.
