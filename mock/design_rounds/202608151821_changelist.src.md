# Src changelist: route the writes, pin the re-proof, derive the list

## CHANGE: `mock/crates/homma-api/src/contained.rs`

**`Root` gains `write`, `remove_file` and `set_executable`**, each taking a
`ContainedPath` and each re-proving afterwards exactly as `create_dir_all` does.
Without them the aggregation pass has no way to write through the mechanism, so
it wrote through `std::fs` with a bare path, which is the whole of finding one.

**`contain_under`'s re-proof is pinned.** Replacing its body with
`Ok(ContainedPath(base.0.join(tail)))` left 384 tests passing and zero compile
errors, and that mutation is precisely the convention the method was created to
replace. Eighth instance on this branch of defence nothing pins, and the file's
own sentence applies: defence nothing pins is defence somebody deletes.

The test hands it a tail that escapes and asserts the refusal, which the mutated
form cannot produce.

## CHANGE: `mock/crates/homma/src/cmd/aggregate.rs`, `gates.rs`, `agent.rs`

**Every write target is proven, rather than the directory above them.** The
previous round checked `<workspace>/.claude` as one string while `ws_rules`,
`ws_hooks`, the wrapper scripts, the `0o755` calls, the `remove_file` sweep and
`settings.json` were all built below it with `Path::join`, which resolves
nothing. A symlink one component down carried all of it into the operator's own
`.claude`, deleting files there and installing executables, at exit 0 printing
`regen: ok`.

The pass takes a `Root` instead of a `&Path`. That is the mechanism this branch
exists to provide and `org up` already uses it; `agent regen` had a hand-rolled
prefix check instead.

**The deny list is derived from the registry**, by the same shape `org up` uses:
a home's own `.claude`, plus every participant's workspace **except the one being
written into**, which is the actor's by definition.

**Deny item one is not an absolute in it.** The central clone is op's workspace,
so it is denied to a Hand as another participant's and permitted to its owner.
That is op's answer, and the derivation from it is recorded in the topic file and
in the crate's design document as a derivation. The previous round refused it by
accident through `Denied::from_env`, breaking `agent regen` on the workspace
configuration that ships, while four surfaces said it had not.

**`org add` uses the registry-derived list too**, closing the same gap: it had
`Denied::from_env()`, which is two of the three locations, and the README claimed
it was checked against the same list as everything else.

## What the sweep found in this round's own work

**`Root::write`'s re-proof is unpinned**, and it is left that way deliberately
rather than overlooked. Removing it leaves the suite green, because what it
guards is the window between proving a path and writing to it, and a test cannot
plant a symlink inside that window without racing the process. `create_dir_all`
carries the same residue and states it. Recorded here so the next reader knows it
was measured rather than assumed, and so nobody deletes it believing it covered.

Every other guard in this round's surface fails a test when deleted:
`contain_under`'s re-proof, the containment on the aggregation directories, the
early refusal, and both deny-list derivations.

## Scope note, added after op redirected the arc

Op has said the real answer is operating-system level isolation: a user account
per participant, a group over the workspaces directory, and the filesystem
enforcing what a Hand may reach. That is a larger design and it is being taken up
properly rather than folded in here.

**This round is not wasted by it and is not competing with it.** Op's words are
"belts and suspenders; filesystem should handle that, but no harm in us ensuring
it too". Everything here is the second half of that: a process that has already
been confined by the operating system still benefits from refusing to write
somewhere it should not, because the refusal names the reason and the kernel's
`EACCES` does not.
