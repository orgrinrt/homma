# Named is not classified, and a fifth instance in the file being swept

Sixth review. Twenty-one mutations, twenty caught. The one that survived is the
same guard on its third attempt, and the distinction is exact enough to be worth
stating on its own.

**`E0027` requires a field to be named in the pattern. It does not require the
field to be classified.** Naming it and adding it to neither list produces
`warning: unused variable`, and this workspace has no `[lints]` table and no
`deny(unused)`, so the warning is all that happens.

Reproduced before fixing: a new field, bound in the destructure, absent from both
lists, `None` in the literal. **373 passed, one warning.**

The comment in that test says "a field can still be classified wrongly on
purpose, which is the bar, but not by omission", and the PR body says the
destructuring "requires the field to be **classified**". Both are wrong in the
same way, and this is the third round in which this guard's stated absolute has
been stronger than what it enforces.

The fix is one line and the reviewer verified it: `#[deny(unused_variables)]` on
the test turns the same mutation into a build failure.

**Scope, stated honestly.** This is a test-gate defect and not a production hole.
`unsafe_strings` derives from serialisation and does catch such a field where it
matters. What was false is the advertised compile-time guarantee, which is its
own kind of defect: a guarantee nobody can rely on is worse than none, because
the next reader stops looking.

## The sweep missed a fifth instance in the file it was editing

Two rounds ago the document sweep grepped a class and reported four candidates.
There were five. `DESIGN.md.tmpl:19` says "set the git identity in that clone's
own configuration"; its twin twenty lines later at :164 was changed by **the same
commit** from "Setting the git identity" to "Setting the identities".

One lifecycle sentence corrected and its neighbour not, in one file, by one edit.
The changelist's claim of four candidates is wrong and the CL is locked, so the
correction is recorded here.

## And a claim about rendered surfaces

The PR body says nothing else on the branch touches a rendered surface. The
branch edits `DESIGN.md.tmpl`, which renders to `docs/ORG.md`, and the round's
own doc changelist lists it as a change.

## One thing that cannot be fixed, only written down

The relocated integration test's SAFETY invariant is "this binary runs this test
and nothing else". That is true today and becomes false the moment somebody adds
a second `#[test]` to the file. Rust offers nothing that enforces it, so what the
file gets is an imperative line at the top rather than a description of the
present.
