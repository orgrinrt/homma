# SRC changelist: a relative path walks out of the guard

**Round:** the relative-path round
**Phase:** IMPL

## CHANGE: mock/crates/homma/src/cmd/mod.rs

Resolve the workspace root to an absolute path before anything reads it. The
nested-repository guard walks upward and a relative path walks up from the
process's directory instead.

## CHANGE: mock/crates/homma-core/src/repo/git_impl.rs

`origin_url` answers `None` for a directory that is not a repository, rather than
erroring. The absence of a repository is an answer; an error means one that
exists and cannot be read. Erroring made the ordinary bootstrap fail outright.

`enclosing_repo` refuses a relative path rather than walking up from the wrong
place.

## CHANGE: mock/crates/homma-org/src/provision.rs, homma/src/cmd/stand.rs

The fakes answer the way the real implementation answers. One returned `Ok(None)`
where the real one returned `Err`, which is why a test asserting the bootstrap
works was green while the bootstrap did not.

## CHANGE: mock/crates/homma-org/src/remote.rs

Five spellings of one repository compared unequal, each producing a permanent
refusal against a correct workspace: a port in the host, a bare `host:path` with
no user, a `file://` URL, and an owner differing only in case. `.git` was stripped
repeatedly, which fails open.

## CHANGE: mock/crates/homma/tests/support/mod.rs (new)

One `global_config_paths`, shared. The copy in the integration tests kept the
vacuity that was fixed in the unit tests: a report names an instance and the fix
is the class.

## CHANGE: mock/crates/homma/tests/org_smoke.rs, homma/src/cmd/stand.rs

Split. Both exceed five hundred lines. The previous round answered that finding by
counting non-blank non-comment lines, which redefines the rule rather than meeting
it.

## CHANGE: mock/crates/homma/src/cli.rs

The `--root` help still describes the defect this branch is named for as the
behaviour.
