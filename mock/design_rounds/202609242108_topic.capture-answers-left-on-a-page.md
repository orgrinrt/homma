# capture-answers-left-on-a-page

Re-filed from round `202609242046`, which did not take it.

The workspace's dashboard lets the person answer questions and leave notes on a
published page, and an agent reads those back through the page's data store.
Those words are the person's as much as a typed line is, and a capture cannot
see them: they are neither a human-origin line nor the result of an ask call.
They reach the transcript only as another tool's result, which a capture now
reads nothing of, on purpose.

Nothing is designed yet because nothing has been seen. When the first real
answer is read back through the page, its tool result in the transcript shows
the shape: which tool, which collection, and which fields hold the person's
words as against the page's own. The design names that call by tool and
collection the way an ask round is named by `AskUserQuestion`, quotes only the
person's fields, and says how an answer read twice, once per status check, is
one answer.
