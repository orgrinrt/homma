## One correction to the option, from the shaping pass

The taxonomy topic listed `homma-store` and `homma-sauna` as separate crates, one
holding "the append-only record store" and the other "channels, tasks, boards".
That is two persistence systems for one thing, and the seam is where later stages
would fight.

**A message is a record whose kind is `message`. A channel is a namespace over
records. Append-only is a property a kind declares, not a property of a separate
engine.**

This changes nothing that was decided. Correspondence stays append-only and
structural records stay mutable, which was the correction that immutability is the
correspondence system's property alone; it survives intact as a per-kind flag
rather than as a second engine. What it buys is that tasks, epochs, read cursors
and later monitoring records are the same code path with different kinds, the
relation graph runs over one store, and the single-writer property covers
everything at once instead of being re-argued when tasks arrive.

So `homma-sauna` is not a crate. sauna is a **view over the store plus a delivery
mechanism**, and it lives in the domain crate.

## The four primitives

Everything else is a view, a kind, or configuration over these.

1. **The record store.** Append and read; kinds declare attributes and mutability.
2. **The daemon.** Sole writer of the hub, sole waker, sole arbiter of exclusivity.
   Three verbs: `append`, `deliver`, `grant`.
3. **The registry.** Identity is a configuration entry, never a process.
4. **The generation pass.** Configuration plus template to definitions, settings,
   hooks and links; the sole writer of `.claude/` in any workspace.

The Monitor is not a primitive: it is an optimisation of `deliver`, since a stopped
session resumes headlessly and carries its transcript. The index is not a
primitive: it is derived. The board and the review tiers are not primitives: one is
a view and the other is prose in a generated definition.

## The layers

```
L0 contracts     types and traits, no I/O
L1 mechanism     git, forge, filesystem. things with side effects
L2 store         records and their persistence
L3 domain        registry, correspondence, work
L4 service       the daemon and its surfaces
L5 surface       what a human or an agent drives
```

`homma-core` is left alone deliberately. Its contents are a pre-mockspace split by
"is it the CLI", which the target taxonomy replaces, but restructuring seven
thousand lines of working code is its own round and mixing it into the round that
introduces the record store would put two unrelated risks in one changelist.

## What this round does not build

Named because each is licensed by something already written down rather than by
appetite.

**The Monitor wake path.** One wake path: the daemon resumes headlessly with the
digest as the prompt. Residency is an optimisation, and the measurement that made
it one is recorded.

**Twins and the exclusivity lockfile.** One Hand and one chief of staff have no
twin dispatch, and the state vocabulary exclusivity depends on is an open item.
Building it now would be building on something the design says is unmeasured.

**The index, the sigil graph, rotation, patch overlays, the terminal interface.**
Grep is adequate at day-one volume; there is no month to rotate, no correction to
overlay, and the interface is weeks of terminal emulation that nothing else may
depend on.

**Attribute types beyond `text`, `instant` and `ref`.** The type list carries a
standing caveat that it is arbitrary and possibly too limited, and the required
core carries another that it is unsettled. Kinds are configuration, so every later
type is additive. Building the full list tonight would be building on a part of
the design that says it is open.

## Porcelain and plumbing, decided now because a script will parse it tomorrow

A call with a terminal attached prints for a human and carries the digest. A call
without one, or with `--json`, prints its result and at most a one-line unread
count. The digest arrives at wake and on request.

This is a refinement of the every-call-summarises decision rather than a reversal:
it keeps the digest for the callers it was designed for, agents and op, and gives
machine callers something parseable.
