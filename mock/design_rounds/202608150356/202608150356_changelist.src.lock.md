# Src changelist: point the sweep at the read side

## CHANGE: the seam U-3.1 named gets its test

"A commit made in a **provisioned** workspace". `provision` was tested against
the fake and `GixGit` was tested directly, so the registry's committer never
travelled the whole way to a real commit. The new test runs `provision` against
`GixGit` into a real repository, with a committer that differs from the author,
and reads both back out of the commit.

It closes the read side's two holes as a side effect, which is the point: a
seam test fails for any break along it rather than for the one somebody thought
of.

## CHANGE: the read side's own tests

`GixGit::identity` fabricating the committer from the author left the suite
green, as did dropping the `user.*` fallback. Both are asserted directly as well
as through the seam, because a seam test says something broke and a unit test
says what.

## CHANGE: the list test is replaced by one tied to the field count

`the_list_of_corruptible_fields_is_the_whole_list` could not catch a field added
later: `skip_serializing_if` keeps an unpopulated `Option` out of the serialised
value, so a field nobody populates is invisible to it. It was also redundant,
since the only mutation failing it alone broke its own test-local walker.

What replaces it counts the struct's fields through a compile-time exhaustive
destructuring, so adding one to `Identity` fails to compile until it is
classified as corruptible or not.

## CHANGE: the check that fails open is marked

`unsafe_strings` skips an entry whose serialisation fails, on a check that
exists to refuse hostile strings. No current field can fail, so this is a
greppable marker naming the condition rather than a mechanism.

## CHANGE: the git version the six keys need

`author.*` and `committer.*` landed in git 2.22. On older git they are ignored
and the committer silently equals the author, with no error.
