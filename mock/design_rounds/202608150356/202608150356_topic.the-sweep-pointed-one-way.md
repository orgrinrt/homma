# The sweep was the right instrument, pointed at half the code

Third review. The pattern is now stated precisely enough to act on, and it is
the reviewer's sentence rather than mine:

> the round widens a guard, writes a test for the **motivating** case, and leaves
> the widened part untested. The deletion sweep the author ran is the right
> instrument and it was pointed at the write side only.

That is exactly what happened, twice. The previous round widened `Git::identity`
from two values to four, wrote the test for the case that motivated it, and swept
only the writes. Reproduced here before fixing: replacing both committer reads
with the author's values, so the method never reads the committer keys off disk,
leaves 368 passing.

**Third consecutive round in which a fix is unpinned in the manner it was
fixing.** The instrument was correct and its aim was not.

## What else the sweep would have caught

The `user.*` fallback in the same method. Dropping it from both author reads
leaves the suite green, and it is live behaviour with a comment explaining why it
exists.

## A test that does not do what it says, and a locked claim that repeats it

`the_list_of_corruptible_fields_is_the_whole_list` was written to fail when a
string field is added to `Identity` without reaching the list. It does not.
`skip_serializing_if` means an unpopulated `Option` never reaches the serialised
value, and both tests only see fields the test itself populates, so a new field
that nobody adds to either place is invisible to both.

Its own assertion message says otherwise, and so does the locked changelist: "A
field added later then fails loudly instead of being absorbed." That is a claim
about shipped state and it is false. The changelist stays as the audit trail;
this round is where the correction is recorded.

It is also redundant against production. The only mutation that fails it alone is
breaking its own test-local walker, which ships nowhere.

## The exit test the unit actually asked for

U-3.1 says "A commit made in a **provisioned** workspace". The test that exists
is a commit made in a directly-configured one, so the seam between `provision`
and `GixGit` is exercised by nothing: `provision` is tested against the fake,
`GixGit` is tested directly, and the registry's committer never travels the whole
way to a real commit.

That is the test worth the most here, and it is the one the unit named.

## Three smaller things

The control-character check fails open: a serialisation error skips the entry
silently, on a check that exists to refuse hostile strings. Latent, since no
current field can fail to serialise, so it wants a greppable marker rather than a
mechanism.

`author.*` and `committer.*` are git 2.22 keys. On older git they are ignored,
`user.*` carries the author, and the committer silently equals it with no error.

The README line the previous round fixed is 99 characters in a paragraph wrapped
at eighty.

## The roadmap edit, where the substance held and the procedure did not

The reviewer confirmed the factual correction independently and agrees the
three-key line was a vehicle rather than an intent, which
`intent-is-canon-vehicle-is-negotiable.md` makes replaceable.

What it objects to is that `**[built]**` was stamped in the same commit that
rewrote the Produces line it certifies against. A unit cannot fail a line
rewritten to describe the code, which is the failure `design-is-the-oracle.md`
exists to catch, and the outcome being right here is luck rather than method.

The commit is pushed and is not amended. What this round can do is say so, and
note the reviewer's other point: **a call about what the canon permits owes a
second reading**, and this one has had one expert and me.
