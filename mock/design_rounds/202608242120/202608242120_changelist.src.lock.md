# Src changelist: normalise a manifest path before it is emitted

**Date:** 2026-08-24
**Phase:** IMPL
**Source topic:** `202608242120_topic.a-curdir-component-in-a-manifest-path-breaks-the-scope-check.md`
**Doc changelist:** `202608242120_changelist.doc.lock.md`

## CHANGE: `homma/src/cmd/util.rs`, one place that drops a no-op component

ADD `pub(crate) fn relative_str(p: &Path) -> String`: the path's own components
with `CurDir` dropped, rendered with `/` separators. A path that normalises to
nothing renders as `.`, because a repo whose `local_path` is the workspace root
is a repo at the workspace root rather than a repo with no path.

ADD test `a_curdir_component_is_dropped`.

ADD test `a_path_with_nothing_to_drop_is_unchanged`: the control, so the helper
is not free to rewrite paths generally.

ADD test `a_path_that_normalises_to_nothing_is_the_current_directory`.

ADD test `an_absolute_path_keeps_its_leading_separator`: the wrapper and the
gate both branch on that separator, so losing it would silently change which
arm runs.

## CHANGE: `homma/src/cmd/aggregate.rs`, the emitted relative path is normalised

MODIFY `aggregate_repo`: renders the stripped repo path through
`util::relative_str` rather than through `to_str`.

No test lands against this call site, and that is a finding rather than an
omission. `aggregate_repo` reaches `relative_str` through `strip_prefix`, and
`Path::components` already drops a `.` unprompted, so no fixture built through
`Path` can carry one into it. Two drafts tried; both passed with the
normalisation removed, and their negative controls are what said so. The
reachable consumer is the gate's repo table, below, and the test lands there.

## CHANGE: `homma/src/cmd/gates.rs`, the gate normalises its own repo table

MODIFY `install_workspace_gate`: renders each path through `relative_str`
itself. It was the caller's job in a first draft, and a negative control showed
nothing could hold that: a caller that forgets produces a plausible-looking
table entry that never matches, and the gate then finds no repo covering any
path.

ADD test `a_manifest_path_carrying_a_curdir_component_resolves_to_the_repo`:
goes through `install_workspace_gate` with `./arvo`, reads the installed script,
and runs the resolution the script performs on the entry, with the
un-normalised form as its control.

## CHANGE: `homma-core/src/config.rs`, the anchor is absolute before it is used

Moved into this round from the previous one, which set it aside on the grounds
that nothing there depended on it. The correction appended to this round's topic
records why that was wrong.

MODIFY `Config::from_path`: resolves `path` against the working directory before
taking its parent. `Path::new("homma.toml").parent()` is `Some("")` rather than
`None`, so the existing `unwrap_or(".")` fallback never fires for the spelling an
operator actually types, and every path anchored on it stays relative.

ADD test `a_relative_config_path_still_yields_an_absolute_workspace_path`: the
half of the matrix the existing sibling test does not reach, because it passes an
absolute config path.

ADD test `a_bare_filename_config_path_is_the_case_the_fallback_never_covered`:
names the mechanism, so a later reader does not restore the fallback thinking it
handles this.

ADD test `an_absolute_config_path_is_unaffected_by_the_working_directory`: the
control.
