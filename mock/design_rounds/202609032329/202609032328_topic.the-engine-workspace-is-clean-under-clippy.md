# the-engine-workspace-is-clean-under-clippy

## What was found

The root workspace excludes `mock/`, so the gate's lint step lints the
launcher and never the engine, and the gate has been green on the trunk's
tip while `cargo clippy --workspace --all-targets` inside `mock/` is red on
its own. Thirteen findings, in four shapes.

Eight `result_large_err`, on the four private transport helpers of each
forge client: `get`, `post_json`, `patch_json` and `delete` return
`Result<ureq::Response, ureq::Error>`, and `ureq::Error` is 272 bytes,
carried by value through every call. The callers match on the error's
`Status` arm and hand the rest to `map_ureq_error`.

Two `bool_assert_comparison` in the github wire tests, `assert_eq!(x, false)`
where `assert!(!x)` says the same.

One `module_inception` in the config tests: `config/tests.rs` holds a
module named `tests` beside the two named for what they assert.

Two `doc_lazy_continuation` in the aggregator: a doc comment describing
`is_aggregated_entry` runs straight into the doc comment of
`is_aggregated_command` with no blank line, so the second sentence reads
as a continuation of the first's list.

## What changes

The transport helpers return `Box<ureq::Error>`, matched and unboxed at the
callers. The bool asserts become `assert!`. The inner module is named for
what it asserts, like its siblings. The doc comments are separated, or the
stale one goes where its function went.

No design document says anything about any of this, so no template moves.
