# Milestone rows keep what they were written with

Follows the round `202610311550`. The first review pass found five blockers, and they are taken here. The intent is the round before it and unchanged: every milestone recorded with exact revisions, nothing for a later session to infer.

## What the review found, and what is settled

The steps rewrote the whole record through the serializer, so a row written by hand, with a comment, a key in another order or a key the shape does not know, lost all three at the next step, against the design's own sentence that no tool rewrites a recorded row. The record is edited by text from now on: a new row is appended as text and a step on the open row sets only its own keys on the last table, with every other byte of the file left as it was. A key the shape does not name is never touched.

`freeze` took the first row's `base` from the newest `milestone/*` tag, which the design never said and which put a row number beside a tag of the same number. The first row has no `base` where no row is recorded, and the tag answers `base` the command and nothing else.

The test of the old row shape used a row the serializer itself produces, so it could not fail. It is replaced by a row with a comment, a reordered key and an extra key, put through each step. The command line test of `show` asserted a key that is always present, and now asserts the range's value.

`show` fills a row's missing `base` with the previous row's tip, which the design now says in its own words. The two READMEs that describe the milestone say what `freeze`, `pin` and `show` do.
