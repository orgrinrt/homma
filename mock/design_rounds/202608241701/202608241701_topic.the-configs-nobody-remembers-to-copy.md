# The configs nobody remembers to copy

**Phase:** TOPIC
**Scope:** `homma agent regen`, a new stage

Nineteen repos here are Rust. Seven have a `rustfmt.toml`, six a `deny.toml`,
eleven a `.taplo.toml`, and where a file is present it is byte-identical to
every other copy of it. So there is one canonical version of each and no
disagreement anywhere: what varies is only whether a repo got one.

That is the shape of a thing nobody remembers rather than a thing anybody
decided. A repo without a `rustfmt.toml` formats to rustfmt's defaults, which
are not ours, and the difference surfaces as a diff in somebody's unrelated
change months later. A repo without a `deny.toml` is not checking its
dependencies' licences or advisories at all.

The canonical copies now live in `.shared/configs/`, one file per template,
named exactly as it is deployed. `agent regen` already walks every repo to run
`cargo mock` and aggregate hooks, so it is the one place that sees them all and
the right place to notice.

## Three outcomes, and they are not the same severity

**Missing, and it is obvious which template applies.** Place it. A repo with a
`Cargo.toml` wants the Rust templates; that inference is safe and doing it by
hand nineteen times is how it got this way.

**Missing, and it is not obvious.** Report it and stop. The case is a template
with several variants where nothing says which the repo takes, or a template
nobody has said what to do with. Guessing is worse than asking, because a wrong
config is quieter than a missing one.

**Present and different.** Warn, and change nothing. A repo may have a reason,
and this stage cannot tell a deliberate difference from drift. Erroring here
would make the tool refuse to run over a workspace whose configs are fine,
which is how a check gets switched off.

The asymmetry is the point. Absence is a fact, and a fact can be acted on.
Difference is a question, and the answer is not in the file.

## What is not decided here

Whether placing a `rustfmt.toml` also reformats the repo it lands in. It does
not, in this stage. Op's call, recorded: the reformat is a separate commit with
a subject that says so, kept out of the one that adopts the config, so the
large diff is reviewable on its own and does not bury the adoption.
