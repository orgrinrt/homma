# Source changelist: the configs nobody remembers to copy

**Date:** 2026-08-24
**Phase:** SRC
**Topic:** `202608241701_topic.the-configs-nobody-remembers-to-copy.md`

## CHANGE: `mock/crates/homma-org/src/configs.rs`

ADD the module. It compares a repo's tool configs against the canonical copies
in `.shared/configs/` and reports what it found, placing only what is missing
and only where the template plainly applies.

ADD `Template`, a canonical config: the filename it deploys as, and the
`Applies` predicate saying which repos want it.

ADD `Applies`, currently `RustRepo` (a `Cargo.toml` at the root or under
`mock/`) and `AnyRepo`. Named rather than a closure so a template's
applicability is data a test can enumerate.

ADD `templates(dir) -> Result<Vec<Template>, TemplateError>`, reading
`.shared/configs/`. A file whose applicability is not known is not guessed at:
it becomes `Applies::Unknown` and the stage reports it for a human to place.

ADD `Finding`: `Placed`, `Matches`, `Differs`, `CannotInfer`, `Failed`. The
three the topic names plus the two mechanical ones.

ADD `ensure(root, repo_dir, templates) -> Vec<Finding>`, the stage itself.
Writes through the `Root` it is given, so a placement is contained the same way
every other generated file is.

ADD tests: a repo missing a config gets it; a repo whose copy matches is
untouched and reports `Matches`; a repo whose copy differs is **not** rewritten
and reports `Differs`; a non-Rust repo does not get the Rust templates; a
template of unknown applicability is reported rather than placed; and the
control that placing is what actually wrote the bytes, by reading them back.

## CHANGE: `mock/crates/homma-org/src/lib.rs`

ADD `pub mod configs;`.

## CHANGE: `mock/crates/homma/src/cmd/agent.rs`

EDIT `regen::run_with` to run the configs stage per repo, between `cargo mock`
and the hook aggregation, and to carry its findings into `RegenResult`.

EDIT the results table to print the per-repo config counts, and add the run's
divergence and cannot-infer findings to the summary, since a warning inside a
truncated table line is a warning nobody reads.

EDIT `Opts` with `skip_configs`, matching the two skips already there.

EDIT the comment above `denied_for_aggregating`'s call site, which describes the
workspace as "the central clone". There is no central clone; it is op's own
workspace, and the reasoning the comment records is unchanged by saying so.

## CHANGE: `mock/crates/homma/src/cli.rs`

ADD `--skip-configs` to the `agent regen` subcommand.

## CHANGE: `mock/crates/homma/tests/regen_writes_smoke.rs`

ADD the end-to-end case: a regen over a workspace whose repo lacks a config
leaves that config on disk afterwards, and a second run over the same workspace
reports it as matching rather than placing it again.

## CHANGE: `mock/crates/homma/src/cmd/agent.rs`, the skip guard

EDIT the guard that refuses `--skip-cargo-mock` with `--skip-aggregate`. It was
written when there were two stages and counts two; a third makes it refuse a run
that does real work, since comparing the configs is useful alone and is the fast
way to sweep a workspace without rebuilding anything. It now counts all three.

ADD the test: all three skips is refused, two of three still runs and reports
the configs stage.

## CHANGE: the refusal that named a central clone

EDIT `homma-api/src/denied.rs`'s reason for deny item one, from "the central
clone is read, never written" to "that workspace is its owner's, not yours to
write in", and the module comment above it. There is no central clone; the path
is op's own workspace, and it is denied for the reason every participant's is.

EDIT `homma/src/cmd/org.rs`'s generated line "The central clone is for reading"
to "Everyone else's is theirs", since that text ships into every generated agent
definition.

EDIT the three tests in `homma/tests/derived_paths_smoke.rs` that pin the
message, and their names, plus the one in `denied.rs`. A test named for a thing
that does not exist is a test nobody can place.

`mock/crates/homma-org/DESIGN.md.tmpl` carries two more mentions and is a doc
template, which this phase may not touch. A doc round follows.
