# answers-fix-first-after-review

A pr-reviewer pass over `work/console-answer-one-call` returned fix-first. The findings that change what the design says are these. A failed `--local` attach through the delegate returned success and printed nothing, and a second `registry-append` at the same `<at>` with different words was dropped by the store key. Every capture was tagged `dashboard` and read "Left on the dashboard page" whatever its source, and its title said `op` whatever `--from` said. The design says `kind` is `agenda` or `registry` where the code takes any plain name, which the console relies on by sending `ticket`. The hook execs an absolute engine path, so once that binary is replaced every `registry-append` in the workspace fails. The `answers` command is a group of verbs and the design's list of groups and the README did not name it.

The design is amended to say what the code is to do: a failed attach fails the delegate loudly, the delegate's document id carries a hash of its words, the capture says its source and speaker, `kind` is a plain name, the hook starts with a check that its engine is still an executable and declines when it is not, and `answers` is a group. The code follows, tests first.
