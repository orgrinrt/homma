# release-resume-after-a-landed-pull-request

Follow-up to round `202611160355`, from its review. Ticket `b9eeed3833e7`.

## What the review found

- A rerun bumps twice when the forge merged a pull request and the run never saw it: the route answered with a
  failure after merging, or the fetch after it failed. Nothing fetches before the bump is set aside, so the stale
  tracking ref still shows the local bump one ahead. The same on `main`: the release pull request merged, the tag
  never made, and the next plan writes a second bump and changelog block.
- `NotLanded` fires after the forge has moved the trunk or the release line, as when another merge lands between
  the push and the squash. Nothing is reset and no next step is named.
- `release/<repo>-<version>` is never deleted once the squash is checked.
- Setting a bump aside matches the `chore: release ` prefix while taking it back matches the exact subject.
- Putting a set-aside bump back drops the reset's error.

## What changes

- Before setting a bump aside the run fetches the trunk and the release line. A remote trunk whose tip is the
  bump, or carries the local bump's tree on its parent, is the bump already landed: steps 1 to 3 still run on its
  parent, and step 4 takes it without a push or a pull request. A release line with a merge of that bump on its
  first-parent history is the release merge already landed: step 5 takes it and tags it. A bump some tag already
  contains is released and is no pending bump.
- A bump is recognised by its subject read as `chore: release <version>`, the version parsed, and a single
  parent, in one place; taking it back compares the versions.
- `NotLanded` says what the forge now holds and what a rerun does with it. On the trunk the clone keeps its bump,
  and a rerun stops at `tree.pushed` until the trunk is put where the forge's is. On the release line nothing is
  tagged, and a rerun tags the forge's merge of the bump where the line's first parents hold one.
- Once the squashed bump is checked, `release/<repo>-<version>` is deleted through the route,
  `forge_route delete-branch --queue <repo root> <branch> <sha>`; `ByClient` lands no pull request and has no such
  branch. A rerun that takes a squashed bump the forge already holds deletes it the same way.
- Putting a bump back returns the reset's error.
