# A milestone is recorded where a cloud session can write it

Op, 27 October 2026, verbatim, on the job that opened this round: "You can actually run all kinds of parallel helpers here that are for things that aren't kaski source code. Tooling for example…". The intent in it is that the workspace's repeated hand steps become tools; the rest is the sentence trailing off.

The rule it applies, `the-coordinator-dispatches-lands-and-ends-its-turn`: "A step done by hand twice becomes a tool before the third time, in homma or the product's `cargo mock` tools where it is about workspaces or the canon, and in `.shared/scripts` only where nothing else needs it."

## What is wanted

The `milestone-merge` skill in the content repository carries five markers naming commands it wants, and this round designs the five as one family, `homma milestone`:

- `base <repo>` prints the base of the current milestone, which is the last one marked.
- `mark <repo> <sha>` records a milestone.
- `partition <repo> <base> <head>` splits the range into reviewable partitions by crate and by document, with the changed lines of each.
- `stand-ins <repo> <base> <head>` lists every marked stand-in the range added, with file and line.
- `branches <repo>` lists every pushed branch the trunk does not hold, with its changed lines, its conflicts against the trunk and its call.

## Where a milestone is recorded

A tag is the obvious record and it is the one that failed: the proxy of a cloud container refuses a tag push, and a helper's round tag failed to push twice on 27 October. A record has to be something a branch push carries, because a branch push is the one write a cloud session is certain to have.

Options considered:

- A tag only. Refused by the proxy where the work happens, so the record cannot be written there at all.
- A ref under a namespace of its own, `refs/milestones/*`. The proxy's handling of non-branch refs is not known, and a record that might not push is the problem over again.
- A tracked file in the repository the milestone belongs to, `.homma/milestones.toml`, one `[[milestone]]` table per mark, appended. A branch push carries it, it lands with the milestone merge it records, and it is read from the trunk by anyone with a clone.
- A file in the content repository, keyed by repository. Writable from a session, but the content repository moves by pull request, so a mark would wait on a landing that the milestone itself should not wait on.

The tracked file in the repository itself is chosen. `mark` writes the file and does not commit it; the caller commits it on a branch and pushes by name, as every other change. `mark --tag` also makes the annotated tag `milestone/<n>` locally, for the places a push of tags works; `base` reads the file first and the newest `milestone/*` tag reachable from the trunk when the file does not exist, so a repository that has only tags is still answered.

A mark refuses a sha that is not a commit, is not reachable from the trunk, or is already marked. The date in the record is the commit's own, so a mark is reproducible from the repository alone.

## What the four reports are, and are not

They are reports. None gates anything, none carries a threshold, and none exits non-zero for what it found; a gating judgement is a lint, and `a-check-lives-in-lints-or-tools` puts a report in the tools. They exit non-zero only for a refusal: an unknown repository, a sha that is no commit, a range whose base is not an ancestor of its head.

- Partition keys are the crate (the directory under a `crates/` segment of the path) and the kind, source or document, with the root's own documents under the unit `(root)`. A document is a markdown file, a `.md.tmpl`, or anything under `docs/`. Lines are added plus deleted from `git diff --numstat`, renames not followed, a binary file counted as a file with no lines.
- Stand-ins are read from added lines only. The markers are a closed vocabulary of the tool's own, named in the deep dive: `FIXME`, `TODO`, `todo!(`, `unimplemented!(`, `#[ignore`, `stand-in` and `relaxed`. A line is reported once, under the first marker it carries.
- A branch is every ref under `origin` and every local branch that the trunk's tip does not contain, except the trunk, the release line, `badges` and `HEAD`. Where a name exists as both, the remote's tip is read, since a local one may be stale. Conflicts are the files `git merge-tree --write-tree --name-only` names, which touches no tree. The call is one of `land` (no conflict), `merge-trunk` (conflicts) and `empty` (it differs from the trunk by no line).
