# user-preferences-and-the-workspace-subcommand

homma has no user-level configuration. The manifest at a workspace root says
everything about that workspace, and nothing says anything about the person
running the launcher: where their workspaces go, which repository a fresh one
is a clone of, and where one may never be made. Op, on 2026-09-04, captured at
`.data/op-responses/202609040836_home-claude-md-skills-homma-workspace.md`:
"perhaps add that to the global homma launcher as `homma spawn` or such if
not already. Or `homma workspace` which would either give status if cwd is in
workspace, or create one in place if not. Let's also intentionally add
configurability to the global userprefs config, that you'll add to homma too
through the renki abstractions, for disallowed roots, such as ~ or whatever
else, which should default to ~ at least."

The workspace design `.shared/designs/renki-configuration.md` carries the
plan: renki's descriptor declares a tool's settings, the launcher resolves
them from a flag, a variable, the repository's file, the person's file and
the default, and `homma workspace` is the first launcher command that reads
them. renki's `Tool::commands`, landed in its round `202609041506`, is the
mechanism: a command the launcher answers itself, before a root is required,
which is the whole point here, since spawning happens where there is no
`homma.toml` above the cwd and so no engine to run.

## The four keys, all user scope

`disallowed_roots`, a list of paths, defaulting to `["~"]`. Where a workspace
may never be made. A plain entry denies exactly that directory, and an entry
ending in `/*` denies everything under it, so the default refuses the home
directory itself and nothing beneath it, which is where every workspace
lives. Checked against the destination, resolved, in both forms of spawning.

`workspaces_root`, a path, defaulting to `~/workspaces`. Where `homma
workspace spawn <slug>` puts a new one. On this machine the person's file
sets it to `~/Dev/clause-work`, which is what the spawn script hard-coded.

`spawn.content_repo`, text, defaulting to empty. The git url a fresh workspace
is a clone of. The name is the manifest's own `content_repo`, at the other
scope: inside a workspace the manifest says which repository holds the
records, and before there is a workspace the person's file says which one to
clone. Empty refuses to spawn, naming the key and the command that sets it,
since a tool that clones a default repository of its author's is a tool with
its author's arrangement compiled in.

`spawn.repos`, a list of text, defaulting to `[]`. The repositories every
fresh workspace clones beside the content repository, as `owner/name` on the
same host as the content repository, or as a full git url. The command line
names more for one spawn.

## What `homma workspace` does

Bare, inside a workspace: status. The root, then the content repository and
every member directory holding a `.git` directory, one level down, each with
its branch, whether its tree is dirty, and how many commits sit on no remote.
That is the set of things `reap` refuses on, printed so somebody can see them
before it does.

Bare, outside a workspace: spawn in place. The cwd is the destination, it has
to be empty, and it is checked against `disallowed_roots` first. The content
repository is cloned into it on its working trunk, `dev` where the remote has
that branch and the remote's default otherwise, then `spawn.repos` beside it
on the same rule.

`spawn <slug> [owner/name ...] [--branch <name>]`: the same, under
`workspaces_root/<slug>`, with the extra repositories cloned too and
`--branch` switched to in every member. `reap [<slug>] [--force]`: remove a
workspace, the current one where no slug is given, refusing while any
repository in it is dirty or holds a commit on no remote, and saying which.
`list`: the directories under `workspaces_root`.

## What it is not

The org design's workspace lifecycle, in `homma-org`, stands a participant's
workspace up from a registry entry: clone, identity, memory link, generated
definition, checked against the operator's `.claude` and every other
participant's workspace. That runs inside a root, through the engine, and
knows who the workspace is for. This runs before there is a root and knows
nothing about identities; it is the session's throwaway clone, the thing
`scripts/spawn-workspace.sh` and `reap-workspace.sh` did in the workspace
repository, and those two scripts go once this lands. The manifest's `deny`
list governs where homma writes inside a workspace and stays where it is;
`disallowed_roots` governs where a workspace may be made and is the person's.

Git is reached the way the scripts reached it, as a subprocess, since the
launcher's one dependency is renki and stays so.
