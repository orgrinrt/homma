# Src changelist: the engine renames and a launcher lands beside it

**Date:** 2026-08-24
**Phase:** IMPL
**Source topic:** the topic of this round
**Doc changelist:** the locked doc changelist of this round

## CHANGE: `mock/crates/homma` becomes `mock/crates/homma-engine`

RENAME the directory, the `[package] name`, and the `[[bin]] name`. `renki` runs
the binary named by `engine_crate`, so the package name and the binary name are
one decision.

MODIFY the seven integration tests that call `Command::cargo_bin("homma")` to
name the engine binary. `mock/Cargo.toml`'s `members = ["crates/*"]` needs no
edit.

Nothing depends on this package, so the rename reaches no dependency table.

## CHANGE: `homma/Cargo.toml`, a root workspace

ADD a workspace at the repo root with the launcher as its only member, which is
the shape `mockspace` has. `mock/` stays its own workspace underneath, which is
what keeps the launcher outside the gate it is meant to plant.

## CHANGE: `homma/launcher/`, the launcher package

ADD a package named `homma`, `publish = true`, depending on `renki` by revision.
By revision rather than by branch, for the reason `cargo-mock` gives: `renki` is
unpublished at `0.0.0`, so a branch pin constrains nothing and every
`cargo update` silently moves the launcher every consumer installed.

ADD `src/lib.rs` carrying the `TOOL` descriptor and a `run_cli` that hands it to
`renki::run`, and `src/bin/homma.rs` as the two-line entry over it.

The descriptor uses `Anchor::ConfigFile` and `Hooks::NONE`. Both are claims:
the first that the config is found by walking up from anywhere, the second that
this tool needs none of what `mockspace` needed hooks for.

## CHANGE: tests

ADD a test asserting the descriptor's names against the repository they have to
match: the config file that exists, the engine crate that exists under
`mock/crates/`, and the launcher package name being this package's own. A
descriptor is a pile of string literals and nothing else checks them, so a
rename that misses one is silent until an operator hits it.

The anchor's own behaviour is not tested here and cannot be: `renki` keeps its
discovery private, so a test of it belongs in `renki`, which has one. What is
testable from this side is the end of it, and
`the_pin_the_workspace_actually_uses_parses_at_both_ends` plus the live run
recorded in the round cover that.

## CHANGE: `--dir` on the engine

ADD a global `--dir` to `homma_engine::cli::Cli`. The launcher passes it
unconditionally, resolved absolutely, so an engine that does not take it cannot
be run through the launcher at all. Every subcommand failed with
`unexpected argument '--dir' found` before this.

ADD `homma_engine::cmd::config_path`, which resolves `--config` first and
`--dir` second, and MODIFY the `org` arm to use it. That arm carried its own
copy of the computation and would have gone on reading the current directory
while every other command honoured the flag.

ADD `crates/homma-engine/tests/runs_from_anywhere.rs`, running the binary from a
decoy workspace whose config differs from the target's, so a run that ignored
the flag reports the wrong answer rather than failing. Its fourth case is the
control: without the flag the decoy is what gets read.

## CHANGE: the engine tolerates the launcher's pin

ADD five optional fields to `homma_core::Config` for the pin keys the launcher
reads from the same file. The struct is `deny_unknown_fields`, so it rejected
`homma_branch` after the launcher had just used it to select the binary doing
the rejecting. Same reason `paths` and `org` are already carried.

ADD `launcher/tests/the_pin_survives_the_engine.rs`, which is the only place
that can hold both ends: the engine must not depend on its launcher, and the
launcher treats the config as text so it stays engine agnostic.

## CHANGE: the root workspace excludes `mock`

MODIFY `homma/Cargo.toml` to exclude it. A path dependency reaching into `mock`
drags its crates in as implicit members of a root declaring no
`workspace.package`, and they then fail to inherit their edition. The test above
is the pin: without the exclusion it does not compile.
