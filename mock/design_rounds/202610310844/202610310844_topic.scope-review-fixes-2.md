# Scope review fixes 2

Follows the round `202610310833`, whose branch review found three more things, all in the fixes of the one before.

## What the second review found, and what is settled

A hook row narrowed to several repositories, one of them outside the scope, kept the in-scope ones. The fix before this dropped the whole row, so the in-scope repository lost its guard. Now only the out-of-scope names are left out, and a row whose every named repository is outside the scope is dropped, because a row with no repositories is read as applying to every call, which would widen it.

Naming a clone outside the scope says so from every command that names a clone, since the message lives in the one function that builds the "no such repository" error and `resolve_repo` calls it. The fix before this put the sentence in one command and left its siblings.

The hook run's fallback to git is for a clone outside the scope and for nothing else. It requires the clone to sit directly under the workspace root and to be a name the scope leaves out. The workspace repository itself, a clone elsewhere, and an in-scope directory that was not detected still refuse as they did.

A clone outside the scope gets no adoption check from the workspace mockspace gate, because the gate's repository table is built from the members. That follows from the scope and is now said in the design.

`Config::scope_error` is removed. It was written and read by nothing; `status` reads the local file itself and reports a broken one, so a second record of the same fact had no reader.
