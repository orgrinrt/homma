# Source changelist: a release is a gated merge off main

**Date:** 2026-09-02
**Phase:** IMPL
**Doc changelist:** `202609022140_changelist.doc.lock.md`

Written against the locked docs. `homma-core/DEEPDIVE_release.md.tmpl` is the spec every file below transcribes.

## `homma-api`

### `src/release.rs` (create), `src/lib.rs` (export it)

The vocabulary, no I/O. `Level` (`Patch`, `Minor`, `Major`) with `FromStr` and `bump(&Version) -> Version` honouring the `0.x` rule; `Version` as a plain semver triple with prerelease text, `FromStr` and `Display`, comparing by semver; `RepoKind` (`Crate`, `Deno`, `Both`); `Step` naming the six gate steps; `StepOutcome` with `passed`, `blocks`, `numbers` (a small map of text to text) and `log`; `Verdict` (`Green`, `Red`); `GateRun` with `repo`, `sha`, `ran_at`, `verdict`, `steps`, and `to_record` / `from_record` against the `gate-run` kind; `CheckSeverity` (`Warn`, `Error`, `Fatal`) and `Finding` with `id`, `severity`, `message`; `Badge` in shields' endpoint shape with `schema_version`, `label`, `message`, `color`. Every type derives `serde`.

CHANGE: add `Level`, `Version`, `RepoKind`, `Step`, `StepOutcome`, `Verdict`, `GateRun`, `CheckSeverity`, `Finding`, `Badge` as the release vocabulary; `GateRun` serialises to and from a `Record` of kind `gate-run` with the attributes the deep dive lists.

## `homma-core`

### `src/forge/trait_def.rs`, `github.rs`, `forgejo.rs` (modify)

CHANGE: `Forge` gains `set_commit_status(&self, owner, name, sha, status: &CommitStatus) -> Result<(), ForgeError>` and `CommitStatus { context, state: StatusState, description, target_url }`; GitHub posts `POST /repos/{owner}/{repo}/statuses/{sha}`, Forgejo posts the same path under its api root. The fakes in tests grow the method.

### `src/release/mod.rs` (create) and its modules

- `kind.rs`: `detect(root) -> RepoKind` from `Cargo.toml` and `deno.json` at the root. CHANGE: add.
- `sh.rs`: one `run(cwd, program, args) -> Result<Output>` over `std::process::Command` capturing stdout, stderr and status, used by every step and every git call; nothing else shells out on its own. CHANGE: add.
- `git.rs`: the git operations the release needs and `RepoOps` does not carry, each a thin call through `sh`: `head_sha`, `is_clean`, `current_branch`, `log_subjects(from, to)`, `tags()`, `tag_target`, `is_ancestor`, `merge_no_ff(into, from, message)`, `tag_annotated(name, sha, message)`, `push(remote, refspec)`, `commit_paths(paths, message)`, `write_orphan_branch(name, files)` which builds the tree with `git hash-object`, `mktree` and `commit-tree` and force-updates the ref. CHANGE: add.
- `gate.rs`: `run_gate(root, kind) -> GateRun` executing the six steps per the deep dive's table, in order, reading `[package.metadata.homma] feature_sets` for the extra test runs, refusing a dirty tree before the first step. CHANGE: add.
- `record.rs`: the `gate-run` `Kind` value, `append(store, run)`, `newest_for(store, repo, sha) -> Option<GateRun>`. CHANGE: add.
- `status.rs`: `post(forge, owner, name, run)` building the description from the numbers in table order. CHANGE: add.
- `hook.rs`: `install(root) -> Result<Installed>` writing the `pre-push` script that calls `homma release gate --hook`, refusing when `core.hooksPath` resolves outside the repo and saying it is mockspace's. CHANGE: add.
- `check.rs`: `check(root, registry) -> Vec<Finding>` with the ids the deep dive names, the blocking set at `Error` or `Fatal` and the rest at `Warn`; registry reads go through `registry.rs`. CHANGE: add.
- `registry.rs`: `published_versions(package) -> Vec<Version>` for crates.io (sparse index), jsr (`api.jsr.io`) and npm (`registry.npmjs.org`), over `ureq`. CHANGE: add.
- `version.rs`: `read(root, kind) -> Version` and `write(root, kind, &Version)` editing `Cargo.toml` (workspace package or package) and `deno.json` in place, preserving formatting. CHANGE: add.
- `changelog.rs`: `block(version, date, subjects) -> String` grouping by prefix in the fixed order with `other` last, and `prepend(root, block)` creating `CHANGELOG.md` when absent. CHANGE: add.
- `publish.rs`: `publish(root, kind, tokens)` running `cargo publish` per member in dependency order, `deno publish --token`, and the npm build and publish where the package ships there; `wait_until_served(registry, package, version)`. CHANGE: add.
- `badges.rs`: `files(run, version) -> Vec<(name, Badge)>` and `write(root, files)` through `git::write_orphan_branch("badges", ..)`. CHANGE: add.
- `plan.rs`: `plan(root, kind, level, last_tag) -> Plan` with the commits, the next version, the changelog block and the publish order. CHANGE: add.
- `run.rs`: `release(root, level, store, forge, dry_run) -> Result<Released>` in the nine steps of the deep dive, stopping at the first refusal, each step a function the tests can call alone. CHANGE: add.

### `src/lib.rs` (modify)

### `tests/release_git.rs`, `tests/release_gate.rs`, `tests/release_check.rs`, `tests/release_changelog.rs`, `tests/release_run.rs` (create)

Against real temporary repositories under `tempfile`, a fake `Forge` recording statuses, and a fake registry answering canned versions. Every test states what value would make it fail: a dirty tree refuses the gate; a red step turns the verdict red and the status `failure`; a run on the wrong sha is not found; a tag off `main` is `tag.reachable` at `Error`; a level absent refuses; the merge is a merge commit and the tag points at it; the changelog block groups in the fixed order and `other` is last; the orphan branch holds only the json and has no parent; the `0.x` major bumps the minor; the npm and jsr sets disagreeing is `both.sameset`.
