# a-nudge-is-a-declared-row-of-the-agent-table

A workspace that wants an agent stopped once before some kind of call, or told something on some event no more often than a set interval, writes a hook script for each such case today, and each script keeps its own record of what it said and when. The ask is one mechanism: the case is a declared row, and homma does the matching, the stopping, the taking of the agent's answer, the record and the log.

## Current state

- `[agent.hooks]` (homma-api `agent_hooks.rs`) declares hooks as rows of a script path per event. homma writes a wrapper per row and registers it; what the script decides is the script's own.
- `[agent]` holds that table and nothing else: `AgentTable` refuses any other key, and so does the layer reader in homma-core `layers.rs`.
- Nothing in homma stops a call once and lets it through on an answer, or says a line once per interval. A workspace doing either ships a script with its own stamp file.

## The row

`[[agent.nudges]]` in the manifest, one array, each row a nudge:

```toml
[[agent.nudges]]
name     = "search-before-grep"
tools    = "Bash|Grep"
matches  = '(^|[\s|;&(])(grep|rg)\s'
when     = "scripts/an-index-covers-the-call"
says     = "The index answers this: run the search first."
strength = "once"
answer   = "searched-first"
evidence = "scripts/a-search-ran-this-session"
ttl      = "2h"
```

- `name`: a plain slug, unique among the rows; the record and the log key on it.
- `event`: the host event, `PreToolUse` when absent, one of the events `AGENT_EVENTS` lists.
- `tools`: the host's matcher over the tool name, every tool when absent. Checked as a regular expression when the row loads.
- `matches`: a regular expression over the call's text, checked when the row loads. The text of a call carrying a `command` is that command; of any other call, its tool input as JSON. Absent, every call `tools` lets through is matched.
- `when`: a path under the workspace, checked as `run` of an agent hook is. It is handed the host's payload on stdin. Exit 0: the nudge applies, and what it printed is said after `says`. Exit 1: it does not apply. Anything else, or a program that cannot be run: the call passes in silence and the log says why.
- `says`: what the agent is told.
- `strength`: `inform`, `once` or `refuse`.
  - `inform`: the text is added to the agent's context and the call goes on. It is said again only once `ttl` has passed since it was last said in that session. This is the reminder.
  - `once`: the call is stopped with the text and the way to answer. It passes on the answer.
  - `refuse`: the call is stopped with the text, every time.
  - `once` and `refuse` stop a call, so they are refused on any event other than `PreToolUse` when the row loads.
- `answer`: for `once`, the marker that answers the stop. Absent, the same call made again within `ttl` is the answer.
- `evidence`: for `once` with an `answer`, a path under the workspace run before the answer is taken. It is handed the stopped call's payload on stdin and the reason given with the answer in `HOMMA_NUDGE_REASON`. Exit 0 takes the answer. Anything else keeps the stop, and what it printed is said with it.
- `ttl`: a duration of whole seconds, minutes or hours (`90s`, `30m`, `2h`), one hour when absent. For `inform` it is the interval; for `once` it is how long a stop waits for its answer and how long a taken answer lets the call pass.

A key the row does not know refuses the manifest, as every other table does.

## The answer

The agent answers a stop with a shell call whose command carries the marker, followed by its reason: `: searched-first the search found no symbol of that name`.

- When that command, with the marker and its reason taken out, is the stopped command itself, the call is the answer and the stopped call at once, and passes.
- Otherwise the answer is taken and the call carrying it runs as written, and the stopped call passes when it is made again within `ttl`.

The stopped call is never run in place of the call that answers it. The host runs every hook registered for an event on the call it is handed, so a call swapped in by one hook would reach no guard but that one, and every other guard would have seen only the answer. A nudge that lets through what nothing else checked turns every guard of the workspace off for whoever learns its marker. Making the call again costs its text once; skipping the guards costs what the guards are for.

## The verb

`homma agent nudge <event>` reads the host's payload on stdin and the rows for that event from every layer, finds the rows whose `tools` and `matches` take the call, and runs `when` of each that has one.

- Nothing applies: it prints nothing and exits 0.
- A stop, from the first `once` or `refuse` row that applies in the order written: it prints the host's deny for `PreToolUse` with the row's text and, for `once`, the line that answers it, the marker spelled out.
- Every `inform` row that applies and is due: it prints the text as added context, every due row's text in the order written, one notice.
- A stop and an inform both: the stop alone, since the call does not run and the inform is due again on the next call.
- It never fails the call it was handed. A row it cannot read refused the manifest at load, which `homma agent regen` already reports; a record it cannot read or write is a log line, and the call is treated as if no record existed.

## The record and the log

- The record is per session, by the payload's `session_id`, in one file under the workspace's git directory: `homma/nudges/<session>.json`. It holds, per row, when its text was last said, the call it stopped and when, and the answer taken and when. A session without an id shares one record named for that.
- The log is one file beside it, `homma/nudges.log`, one JSON line per stop, answer, refusal, evidence refused and predicate failed: the time, session, row, call text and reason. The accepted answers of a row are the list of where whatever its marker stands for fell short.
- Neither is tracked; both are the clone's, as the regen's registrations are.

## Registration

`homma agent regen` writes, for each event the rows name, one wrapper `_nudges--<Event>.sh` beside the declared ones, carrying the same line as every wrapper homma writes, so it is kept and swept by the same rule. Its matcher is the rows' `tools` joined, every tool when any row has none. It runs `homma agent nudge <Event>` from the workspace root with the payload on stdin. With no rows it writes none, so a workspace that declares no nudge sees nothing change.

The wrapper is not run through any layer that removes a line already said: the rows' own `ttl` is that rule for them, and two such rules would disagree on when a line is due.

## Where it lives

- The row is a table of `[agent]` in homma-api beside `[agent.hooks]`: both are what a workspace declares for the agent host, read from the same layers, an overlay's rows appended after the manifest's.
- The verb is under `homma agent`, the domain of the agent host.
- A later runner of hook chains for the agent host would run the wrapper as one entry of its chain; the rows and the verb do not change for it.
