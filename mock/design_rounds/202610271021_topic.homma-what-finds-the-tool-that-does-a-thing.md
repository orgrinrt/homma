# homma-what-finds-the-tool-that-does-a-thing

Op, 27 October, verbatim: "Also we need exact same treatment for helpers, as in, a rule telling them of their tools. Awareness, discoverability. Perhaps a "homma what to use for "foo"" command/tool in homma that matches appropriate and related tools by tags, some other means, fuzzily too, etc"

The intent is that an agent describes what it wants to do in its own words and one command answers with the tools that do it and the tools beside them, so a tool that exists is found rather than rebuilt or skipped. The name and the syntax are op's sketch. Finding by tags, by other signals and fuzzily is the requirement.

What exists to search, checked in the tree rather than assumed:

- `tools/<name>/tool.toml`, read already by `homma tools` through renki: a name, a summary, tags and one table per verb with its own summary.
- `.shared/scripts/**`: 137 executables with no descriptor, but almost all open with a comment block that names the script, says what it is for and shows the usage lines. The block takes four spellings (the banner form `# name - summary`, a plain sentence, a python docstring, a ts block comment).
- homma's own subcommands, held by clap.
- Skills (`Skills::load`) and rules (`Rules::about`), which answer part of this for their own corpora.
- `cargo mock tools` in a mockspace repository, which lists the builtin subcommands and the project tools there.

The round owes:

- One command, `homma what`, and its output shape: kind, the exact command, a one line summary, why it matched, related tools, and a footer that counts what a source has no descriptor for.
- The matcher: tags, names, summaries and verb summaries, and fuzzy over all of them (a misspelling, a stem, a synonym, a prefix), with a corpus weighting so a word every tool uses does not decide an answer.
- How a script gets a descriptor without a second list: the header it already has, read in place, and what a header must carry to count.
- The acceptance set, queries a helper or the coordinator types, each with the tool that must come first, every one of them a real descriptor or header in the workspace, and a query that must return nothing.
- What the command does where a source is absent (no `tools/`, no skills corpus, no mockspace repository), and how it keeps to the instance scope the open topic on scope describes.
