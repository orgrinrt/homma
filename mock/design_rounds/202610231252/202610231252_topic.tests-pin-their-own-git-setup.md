# tests-pin-their-own-git-setup

Seven tests fail on `dev` in a container that exports `GIT_AUTHOR_NAME`, `GIT_AUTHOR_EMAIL`, `GIT_COMMITTER_NAME` and `GIT_COMMITTER_EMAIL` and whose git has no `init.defaultBranch`: `a_commit_carries_the_author_and_the_committer_separately` in `homma-core`, four in `cli_release` and two in `provisioned_commit`. Nothing in the code under test is wrong. A git author environment variable outranks every config key, so a commit made by a spawned `git` carries the machine's identity and not the one the test configured, and a `git init` without `-b` makes `master` where the code under test reads `main`.

The tests are written to be independent of the machine's global config, `provisioned_commit` says so in its own comment and sets `GIT_CONFIG_GLOBAL` to a hostile file for it. The environment is the part of the machine they left open.

Each test pins its own git setup: the `git` it spawns has the four variables removed, and a repository it makes is created on `main` explicitly. The failure is shown first, on the container as it is, and the same tests pass on it afterwards with nothing set around the command.
