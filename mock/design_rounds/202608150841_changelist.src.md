# Src changelist: make naming a field mean classifying it

## CHANGE: `#[deny(unused_variables)]` on the classification test

`E0027` requires a new field to be **named** in the pattern. It does not require
it to be used, so binding it and adding it to neither list produced a warning and
a green suite, which is the escape this guard has now failed to close three
times.

Denying the warning on that function turns the same mutation into a build
failure, which is what the comment beside it claimed all along.

## CHANGE: two comments and their overstatement

The test said a field "can still be classified wrongly on purpose, which is the
bar, but not by omission". Omission was exactly what it permitted. Both the
comment and the guarantee it describes are rewritten to say what the three
mechanisms do and what each does not.

## CHANGE: the integration test's invariant becomes an instruction

"This binary runs this test and nothing else" is true today and false the moment
somebody adds a second `#[test]`. Nothing in Rust enforces it, so the file leads
with the instruction rather than describing the present.
