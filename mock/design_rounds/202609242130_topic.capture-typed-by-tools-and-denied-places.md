# capture-typed-by-tools-and-denied-places

## What the fourth review of the capture command found

Two blocking findings, both reproduced by running the built binary.

**A tool that types into the terminal is read as the person.** The workspace's
self-compact tool pastes a `/compact "Keep: ..."` line and then `Continue` into
the session's terminal. The harness marks both exactly as it marks typed input,
`origin.kind` human, and a capture of this session quoted both as the person's
remarks. Read off this session's transcript: the pair arrived at 14:23 UTC as
queued-command attachments with a human origin, the first wrapped by the harness
as `<pasted_content id="6855">`, a newline, the line, a newline and
`</pasted_content id="6855">`, the second bare. Nothing in either line tells it
from the person's own; the person pastes too, so the wrapper says nothing. Of
1,387 human-marked lines in the 80 newest transcripts, 38 are such `/compact`
lines and 202 are a bare `Continue`, some of them the person's.

The one party that knows a line was typed by a tool is the tool. The injector
already knows the session's transcript before it pastes, since it reads it to
see whether the paste was taken up. So the tool writes down what it typed, where
a capture finds it without being told: beside the transcript, as
`<session>.typed-by-tools.ndjson`, one JSON object per line typed, with `at`,
the instant just before the paste, and `text`, exactly what was typed. A capture
drops a human line whose words are a recorded `text`, bare or in one pasted
wrapper, stamped at or after the record's `at`, each record taking at most one
line, in order. The person typing `Continue` a minute later is still theirs. The
name is not a `.jsonl`, so it is never taken for a transcript.

The branch's own test asserted the defect: a `/compact` line counted as the
person's. What the person types as a slash command stays theirs; what a tool
typed for them does not.

**A capture writes wherever it is pointed.** homma refuses to write under the
harness's own `~/.claude`, inside another participant's workspace, and under
anything the manifest's `deny` names, and every command writing at a path an
operator named checks it against that list. The capture store and `--into` were
written with nothing checked: the reviewer wrote a capture into
`$HOME/.claude/agents`, and into a directory `deny` names, both by `--into` and
by `[paths] captures`. The destination goes through the same list. That list
needs the home directory, and an unknown home stops homma rather than dropping
the entry it would have derived, so a capture with no `HOME` is refused before
it writes, even for a session named by path.

## Smaller ones

- An ask the person never answered, the harness's timeout included (nine real
  results carry `afkTimeoutMs` and empty `answers`), is written as a round
  answered with nothing. A round in which no question has an answer or a note
  said nothing and is not an event.
- The design says `--since` is the floor instead of a watermark; the code, and
  the reason the previous round gave, apply both. The design moves to the code.
- `--bears-on` is written into the front matter raw, so a value holding a line
  break writes a key. One holding a line break is refused.
- The test mirror of the voice tool's reader trims with Rust's whitespace, which
  holds U+0085 and JavaScript's does not. It follows JavaScript's set, which is
  what `\s` and `trim` use.
- Pronouns and a process word remain in the transcript tests, which also run
  past 500 lines; the answer tests move to a file of their own.

## Recorded, not changed

Both canon reads agree the command may exist and sits where it should. The
second names a tension: the file's shape and its `tags` follow one workspace's
voice tool, against the design's line that nothing about the workspace homma was
born in is compiled in. The store's place is configured now; the format is the
reader's, and a second reader with another format is when it becomes data.
