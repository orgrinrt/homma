# homma-what-after-the-fourth-review

A fourth review found one place where the design promises more than its rule delivers, and a set of tests that stay green with the rule they are named for removed.

- A query of two words matched anything that held one of them, so `bake bread` and `book flight` returned answers where the design says a query about nothing the tooling does returns nothing. The design changes: a query of two words needs both, longer ones as before.
- The tests: the inverse document weighting, the kind weighting and the term coverage of a long query each had a test that passed with the rule taken out, and one test compared constants where a ranking was claimed. These are rewritten so each fails without its rule, and the code is changed only where the review found a fault: an absent `tools/` is said in the footer, and the process group of a listing is ended only when its pipe was still open after the grace.
- The commit subjects of the branch describe how it was made rather than what it does. They are reworded before the branch is handed over, which is history, not design.

No other topic filed earlier remains open for this work.
