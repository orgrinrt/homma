# Standing one up is one command

**Phase:** TOPIC
**Scope:** `homma-api`, `homma-org`, `homma`

Standing the first identity up took a command, a shell script, and two git config
calls typed by hand. That worked once and does not scale to a roster, and every
hand step is a step that gets done differently the second time.

This round closes the gap so that adding an identity and standing it up are each
one command, and so that an identity which exists on purpose without a workspace
is distinguishable from one somebody forgot to finish.

## Mapped is not incomplete, and this is the load-bearing part

A registry can hold two honest kinds of entry that currently look identical.

An entry can be **staffed**: it has a workspace on disk, a git identity, a session,
and repositories. It is somebody who works.

An entry can be **mapped**: it records that a boundary has been drawn and who owns
it, so the same ground is not carved twice by somebody arriving later. It has no
workspace and is not supposed to have one.

Today `missing()` reports a mapped entry as lacking `git_name`, `git_email` and
`workspace`, because those are exactly the fields it does not have. So a listing
of a registry holding eleven mapped entries reports eleven broken ones, and a
listing that is wrong eleven times is a listing nobody reads.

**The mark is explicit rather than inferred from an absent workspace.** Inference
is cheaper and wrong: an entry whose workspace key was mistyped or dropped would
read as a deliberate decision, which is precisely the confusion the mark exists to
remove. An entry says `staffed = false` because somebody decided that, or it says
nothing and defaults to unstaffed, and either way a missing workspace on a
`staffed = true` entry is still a gap and still reported.

**Standing up a mapped entry is refused, with the reason.** Not silently promoted.
Promotion is an edit to the registry, which is a decision somebody makes on
purpose, and doing it as a side effect of `up` would let a typo create a
workspace.

## An identity is created by a command, not by editing TOML

`homma org add` writes the entry. Hand-editing works and will keep working,
because the registry is a text file and that is a feature, but the command is
what makes the common path uniform: it refuses a duplicate handle, refuses a
handle that is not usable as a directory name, and refuses control characters
before they can reach generated frontmatter.

That last one already exists as a check at generation time. Having it at creation
time too is not duplication: one refuses to write the bad value, the other refuses
to act on a bad value that arrived some other way, and the registry is editable by
hand precisely so the second check cannot be dropped.

## Standing up owns the whole sequence

Right now `up` creates directories, links memory and generates definitions. What
it does not do is the part that was typed by hand:

- **Clone the content repository** into the workspace the entry names.
- **Set the git identity in that clone's own config**, never globally. This is the
  step whose absence is invisible until a commit lands under the wrong author, and
  it is worth an assertion rather than a comment: after standing up, that clone's
  `user.email` is the identity's, and the machine's global config is untouched.

**Cloning is skipped when the workspace already holds the content repository**, so
standing up twice remains the same answer. That property is already tested for the
directories and the memory and now has to hold for the clone too.

## Repositories arrive with the work

A workspace holds member repositories, added when work needs them rather than up
front. `homma work add <repo>` clones one into the identity's workspace on its
trunk.

The precedent is op's own and it is not about tidiness: a workspace pre-loaded
with every repository its domain might touch is a claim about what the work will
be, made before the work exists. An empty directory holding a name is a directory
pretending to be a decision.

## Also in this round

A `let second = prepare(...)` binding in `homma-org`'s idempotency test is unused
and warns. The call matters and the binding does not; the assertion below it is
what tests the property. Dropping the binding removes the warning without touching
what is checked.

## What this round does not do

It does not stand Vouti up, which is its own round because the identity carrying
op's credentials has a test nothing else has: that its records sign as `@vouti`
regardless.

It does not touch the store, channels or the daemon.
