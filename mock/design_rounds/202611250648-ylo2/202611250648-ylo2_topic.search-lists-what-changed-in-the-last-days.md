# search-lists-what-changed-in-the-last-days

Follows the closed rounds 202611240919 (`homma search`), 202611242203-jxpf to 202611250313-zuva
(each index brought current before it is asked) and 202611241355-edoa (the summarising pass). The
index crate now keeps a repository's history as sources, each commit with its day and the paths it
changed, and narrows a repository index to what changed in a window of days (`filter::Changed`),
listing what a filter keeps newest first with no words asked (`RepoIndex::newest`).

The question: a reader coming back after some days wants everything that changed since across the
workspace, the files, the commits, the state files and the tickets moved, each with where it is and
when, newest first, from the same indexes the search asks and as current as they can be made.

## How it is named and reached

Decision: a flag of `search`, `--fresh [<days>]`, three days where no number is given. It is the one
search with a filter set, so it reaches the same places in the same way and composes with every flag
already there: `--in` narrows the indexes, `--members` adds the members, `--limit` bounds the hits,
`--summarise` asks for the pass. A verb of its own would be a second entry point to the same layer,
and a named preset in the manifest would be a table to name one filter with nothing else to set.
Three days covers a weekend and the day before it.

The listing is a window and not a question, so `--fresh` takes no words. Narrowing a question to the
window across indexes needs the index crate's cross-index layer to take a filter, which it does not;
that is the crate's to add, and until it does `--fresh` with words is refused by the argument parser.

## What is listed

The window is the last `<days>` days counting today, today being the day the search runs, in UTC as
every day of the index is. Each place is found, opened and brought current exactly as a question
does, by the same code, and its line says the same: what the refresh moved, or how far behind and
why, or why it is not asked. A repository index is then listed through the index crate's own
listing over its own window filter: every file whose own day or the day of a commit that changed it
falls in the window, and every commit of the window, shown under `.git/<hash>` at its subject. A
corpus keeps no days, so what changed in it cannot be listed: it is not asked, and its line says so.
Nothing here reads git or a file: what changed is what the indexes hold.

Each hit carries its place, path, class, the last day it changed as a date, its age in days
(`today`, `1 day ago`, `<n> days ago`) and its title or first line. The hits are ordered newest
first by that day; hits of one day keep the order the places came in, and each index's own order
within it. The index crate orders one index; merging the lists of several by day is homma's only
because the crate's layer fuses questions by rank and has no listing across indexes yet, which is
the crate's to take over.

`--limit` bounds the hits as it does a question's. Its default stays ten for a question; with
`--fresh` and no `--limit` every hit of the window is listed, since the point is everything.

## Through the summarising pass

The listing is large by design, so with `--fresh` the pass runs wherever `enabled = true` under
`[summary]`, without `--summarise`. Where the pass is off the listing prints whole with no line about
the pass, unless `--summarise` asked for it, which says it is off as it does for a question. The
brief is `everything that changed in the last <days> days across the workspace's indexes: what
changed where, newest first`. It is the same pass as a question's, through the same function, so a
summary is keyed as the pass keys it, on its rules' version and the text it reads; the preset keeps
nothing of its own.

## Output

The human form prints the hits, or the summary in their place, then the line per index, as a
question does. The JSON form is the search's own, with `window`, the days, present only for a
listing, and `age` on each hit where its day is known. The exit is the search's: non-zero where no
index answered.

## Tests

Over planted places with real git histories: a repository committed to with set dates, its index
built with its history read, listed at a set day. Each test carries its failing control: a file
changed outside the window that is not listed, a corpus that is not asked, a window one day short.
