# Pin what only defence in depth is guarding

**Phase:** TOPIC
**Scope:** `homma-api`

Measuring the previous round's mutations **by test name rather than by count**
found one mechanism with nothing behind it: loosening `join` back to
`PathBuf::join` fails no test, because `RelPath` refuses such a value at the
configuration boundary first.

Defence in depth is right, and defence nothing pins is defence somebody deletes.
So `join` gets a test of its own, and `resolve` gets one asserting it may still
leave, so nobody closes that half by symmetry later.

## And the counting bug is found

Three rounds reported inflated mutation counts, and rewriting the procedure twice
did not help. The extraction was `grep -c "^test .* FAILED"`, and cargo prints a
per-binary summary reading `test result: FAILED. 4 passed; 2 failed`, which
matches that pattern. **Every count was inflated by the number of failing
binaries**, which is exactly the one-to-three overstatement the reviews measured.

The procedure was sound and the instrument was broken, which is why changing the
procedure changed nothing. **Counting by test name is self-checking**: a name can
be read and compared, a count cannot.
