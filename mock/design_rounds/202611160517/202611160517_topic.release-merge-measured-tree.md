# release-merge-measured-tree

Follow-up to round `202611160453`, from its review. Ticket `b9eeed3833e7`.

## What the review found

- A rerun tags a release merge the first run refused. The first run refuses a merge whose first parent is not
  where the release line was, something else landed there first, but the rerun looks for a merge by its second
  parent alone, finds that one and tags it, so the tag covers a tree the gate never measured.
- A failed deletion of `release/<repo>-<version>` stops the run before the tag, and the rerun, finding the
  forge's squash as the clone's tip, never deletes it.
- A bump that cannot be put back replaces the refusal that stopped the run, a blocking finding or a missing
  gate run, so that refusal is never said.

## What changes

- A release merge is taken only where its tree is the bump merged onto the release line the run saw: in step 5
  after the release pull request, and on a rerun that finds a merge of the bump on the forge. A merge of the bump
  with another tree is refused on the rerun before any pull request, nothing tagged, and stays for a human.
- A failed deletion of the squashed branch does not stop the run; the route has queued it where it could. A rerun
  whose trunk is already the forge's squash deletes the branch where the forge still holds it at a commit whose
  tree and parent the squash carries.
- A bump that cannot be put back is reported together with the refusal that stopped the run.
