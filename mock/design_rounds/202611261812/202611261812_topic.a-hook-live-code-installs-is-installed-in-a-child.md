# a-hook-live-code-installs-is-installed-in-a-child

Extends round 202611261744. A review of it found its claim wider than what it checked.

## A git hook the install writes, run by a commit

That round's changelist says no test of `homma-engine/tests`, `homma-core` or `homma-org` writes
and modes a script it runs in the test process. Its search looked at test sources, and a write in
live code called by a test is not in them. `hooks::install` writes each entrypoint and modes it in
the process that calls it, and the end-to-end test of a layer-only hook installs and then commits,
which makes git execute the entrypoint: the race the round closed for the placed answers hook.

A second look, from the other side: every live writer that marks a file executable, which is
`hooks::install`, `answers::hook::place`, `Root::set_executable` as the wrapper, gate and declared
emitters call it, and the skills copy that keeps a file's mode, and every test that reaches one.
The emitted wrappers and gates are run through `bash <path>`, which reads the file and never
executes it, so no exec can find it busy. The copied skill scripts are never run. The install is
the only other one a test executes.

Decision: the end-to-end test installs through `homma_fixture::alone`, in a child that runs only
that test, and commits in the parent, as the placed hook's test does. The changelist states the
claim as what was checked: test sources, and the live writers a test executes the output of.

## The rerun at the root of a test binary

`alone` names a test at the root of an integration test binary by its bare name, a branch no test
reached. And `passed` took any "1 passed" in the output, which a test's own printing could carry.
Decision: an integration test binary of the crate runs `alone` from its root, and `passed` reads
libtest's summary line, `test result: ok. 1 passed`.
