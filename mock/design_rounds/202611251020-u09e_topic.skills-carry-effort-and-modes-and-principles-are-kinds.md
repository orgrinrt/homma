# skills-carry-effort-and-modes-and-principles-are-kinds

`homma skills render` refuses a skill whose frontmatter carries `effort`, the host's key for the
effort of the rest of a turn, and `homma rules render` reads the rules directory only. A workspace
that wants skills raising the effort, mode skills generated from short mode files, and principle
cards kept out of its rules directory has to stage and post-process the renders itself today.

## Effort on a skill

Decision: `effort` is a known skill key, its value one of the host's words, `low`, `medium`,
`high`, `xhigh` or `max`, and any other value refused by name. It passes into the rendered skill
as written, like `model`. Unknown keys stay refused.

## Modes

A mode is one file, `<modes dir>/<type>.md.tmpl`: frontmatter `type`, `effort`, `when`, `skills`
(inline list), `tools` (inline list), `ends_turn` (`true` or `false`), then a body. Decision: homma
renders each into the skills tree as `<skill prefix><type>/SKILL.md`, its frontmatter built from
the meta (`name: <prefix><type>`, `description: mode: <type>. Use when <when>.`, `effort`), then the
body. `type` must equal the file's name, as a skill's name its directory. A body over the configured
number of characters is refused. Only `.md.tmpl` files are modes, so a settings file beside them is
not one. A mode whose skill name an authored skill already has is refused, since both would be
written to one directory.

## Principles

A principle is `<principles dir>/<name>.md.tmpl`, a rule's frontmatter and a card only. Decision:
`homma rules render` reads it as a second source of the rule corpus and writes its card as
`<card prefix><name>.md` beside the rules' cards, by the same card renderer, under the same session
binding. An elaboration marker in it is refused, and so is a first heading other than
`# <title prefix><name>`. It is not a rule to anything that compares rules with each other: it is
kept apart in the corpus, `rules about` does not answer with it, and `rules load` counts its card,
because a session loads it.

## The effort gate

Changing effort keeps the host's prompt cache only on some models and hosts; elsewhere the next
request after a change reads the whole history uncached. Decision: the gate is homma's.
`homma skills render --model <id>` keeps the `effort` keys and writes the mode skills only where
the model matches one of the configured globs, none of the configured environment variables is set,
and the base URL variable, where set, names one of the configured hosts. Without `--model`, or where
any of that fails, every `effort` line is taken out of the rendered skills' frontmatter and no mode
skill is written; one an earlier render wrote is removed, since a mode claims it.

## Configuration

Decision: one table, `[surfaces]`, with `[surfaces.modes]` (`dir`, `skill_prefix`,
`body_max_chars`), `[surfaces.principles]` (`dir`, `card_prefix`, `title_prefix`) and
`[surfaces.effort]` (`models`, `off_env`, `cache_hosts`, `base_url_env`), each with defaults and
unknown keys refused. The defaults: `.shared/modes`, `mode-`, 500; `.shared/principles`,
`principle-`, `Principle: `; the host's models known to keep the cache on an effort change, the two
variables that turn it off, its API host and its base URL variable. A missing modes or principles
directory is no modes or no principles.

## One generation path

Rules, skills, modes and principles each walked their directory, sorted their sources, rendered
through a fresh template environment, wrote with a trailing newline and listed what nothing claims,
each with its own copy. Decision: one generic path in `homma-org`, a `Kind` trait saying how a
kind's sources sit (a file per source or a directory per source) and how one is read, with `load`,
`unclaimed`, `render` and `write` over it. Rules, principles, skills and modes go through it; no
second generator. The personas' corpus has the same shape and moves onto it in a later round.

## Tests

Tests first, each with a failing control: an `effort` skill renders and a bad value is refused; a
mode renders with its built frontmatter, a long body and a mismatched type are refused, the
settings file is not a mode; a principle card is written with its prefix, its elaboration and its
wrong title refused, and it is absent from `about`; the gate keeps and strips by model, variable and
host; with the gate off an earlier mode skill is removed.
