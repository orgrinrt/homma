# Changelist: src, the six review findings

**Round:** 202608251452 the round shipped the other answer in three places
**Phase:** SRC
**Scope:** `homma-core` config and remote reading, `homma-engine` status and

## CHANGE: read a member's origin through the git trait

`crates/homma-core/src/config.rs`.

`detect_members` and `read_origin_of` take a `G: homma_api::Git` and call
`origin_url` on it. `Config::from_path` supplies `crate::repo::GixGit`, which
implements the trait over gix in this crate and was already exported.

The path is canonicalised on the way in, because the trait takes an `AbsPath`
and a relative root reaches here from a caller that built one. The directory
exists, having just been read out of the tree, so canonicalising is the answer
rather than refusing.

Best effort by design and unchanged in that: a repository whose remote cannot
be read is still a member, so the failure is an absent forge rather than an
absent member.

## CHANGE: drop the warning for a forge nothing references

`crates/homma-engine/src/cmd/verify.rs`.

The function's own comment says a declared profile nothing references is not a
gap, and that warning about it would reproduce the noise the `local_path`
warning was removed for. Twenty lines below, it warned about it. The block
goes.

## CHANGE: the branches are read from the defaults where they are used

`crates/homma-core/src/config.rs`, `crates/homma-engine/src/cmd/status.rs`,
`crates/homma-core/tests/config_smoke.rs`,
`crates/homma-engine/tests/cli_smoke.rs`.

`resolved_public_branch` and `resolved_working_branch` ignored the receiver and
handed back a field of the defaults, so no value of a member could make either
answer differently. Both go, along with the test that asserted they do what
their bodies say.

`status` reads `cfg.defaults` directly. What replaces the test is an assertion
over the status report itself: a manifest declaring `trunk` and `next` produces
a member line carrying both. That reaches through the code that builds the
line, so a per-repository override reintroduced without being wired up fails
it.

## CHANGE: name the borrow instead of re-deriving it

`crates/homma-core/src/forge/url.rs`.

`read_origin` bound the last path segment inside a `strip_suffix` call and
re-derived it in the fallback closure, defended by a comment saying
`strip_suffix` returns a shorter borrow that the closure has to rebuild. It
does not. Binding the segment first and calling `unwrap_or` on it is the same
result in two lines.

## CHANGE: pass the git through the detection call sites

`crates/homma-core/tests/membership_is_detected.rs`,
`crates/homma-core/tests/template_smoke.rs`.

Mechanical: every `detect_members` call gains `&homma_core::repo::GixGit`.
