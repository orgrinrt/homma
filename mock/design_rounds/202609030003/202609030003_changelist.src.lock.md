# Src changelist: a check that could not run says so

## crates/homma-engine/src/main.rs

The two non-zero cases are the same code today, so nothing downstream can tell
a reported failure from an error.

- CHANGE: `Err` returns `ExitCode::from(2)` rather than `ExitCode::FAILURE`,
  with the reasoning beside it: `1` is a command that ran and reported, `2` is
  one that could not run, and a caller has no other way to ask.
- KEEP: the message. `error: {e:#}` is what a person reads and it is already
  the right thing; what was missing is the half a script reads.

## crates/homma-engine/src/cmd/gates.rs, the generated gate script

The config arm reads every non-zero the same way and ends on advice that is
right for one of them.

- CHANGE: the arm splits on the code. `1` keeps the present behaviour whole,
  since that is the case its wording was written for. Any other non-zero
  becomes one problem saying the check could not run, carrying the output as
  the reason, and sets a fix naming `$WS/homma.toml` rather than
  `homma repo config init`.
- KEEP: denying in both. The reasoning is the one the missing-`jq` and
  missing-`homma` arms already carry, that a check which could not run must
  never look like one that ran and found nothing.

## crates/homma-engine/src/cmd/gates.rs, the tests

- CHANGE: `gate_denies_when_the_check_could_not_run_and_does_not_send_you_to_init`,
  stubbing a `homma` that exits `2`, asserting the refusal arrives, that it
  carries what the command printed, that it names the manifest, and that it
  does not name `repo config init`. The last assertion is the finding: the old
  arm passes every other one.
- KEEP: `gate_denies_when_a_required_config_is_missing_and_names_the_fix` as
  the control on the split. It stubs an exit `1` and still expects the init
  advice, so an implementation that dropped the advice everywhere fails it
  while satisfying the new case.

## Comparison to deprecated changelist

`202609030003_changelist.src.deprecated.md` is the same plan, and every CHANGE
and KEEP above is carried over from it word for word. Nothing about the work was
reconsidered.

What differs is only that it was locked before any of it was written. The lock
takes the round to CLOSED, which is the phase that refuses source, so the plan
sealed the window it existed to open. Unlocking deprecates the sealed copy and
this one replaces it; the source is written under this one, and it is locked
after.

## What the change was checked against

The new arm made to accept any non-zero as a reported failure, which is the
present behaviour: the new test failed on the init assertion and the exit-1 test
passed, which is the right one and only the right one. The full suite is green
either side of that mutation apart from the one test.
