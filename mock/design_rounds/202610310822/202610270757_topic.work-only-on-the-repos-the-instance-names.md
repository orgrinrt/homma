# Work only on the repos the instance names

Op, 27 October, verbatim: "A thing to add to the backlog for homma: properly respect and follow everywhere in its commands and tools and such, the local config repo scopes, so for example when we have the very few specific ones active for this project, but have more repos cloned due to cloud env quirks, it always filters out anything from anywhere and also narrows all work so useless redundant work on out of scope repos aren't done, so it's not just doing full work and hiding some results, rather, skipping unneeded work as per config".

The intent is in two parts. Every command and tool homma has reads the scope the local config gives, `repos` under `[instance]` in `homma.local.toml`, and keeps to it. And keeping to it means the work for a repo outside the scope is never done, so a command does not walk every clone and then drop the rows it was not asked for. The cloud environment is the case that brought it up, where a container holds clones of many more repos than the body of work uses, because the environment attaches them for reasons of its own.

What a round on this owes, before any code:

- An inventory of every homma command and tool that walks repos, clones, worktrees, branches or remotes, and for each one, where it reads the set of repos it works on today, and whether it reads the scope at all.
- One owner for the scope. Each command asks it for the repos in scope, rather than reading the local config itself, and none keeps a list of its own.
- What a command does when the scope is absent, as in a clone with no `homma.local.toml`, and when a repo named in the scope is not cloned.
- Tests that fail when a command does work on a repo outside the scope, measured on the work done (the repos a command opened, fetched or ran git in), not on the rows it printed, since printing the right rows after doing all the work is exactly the shape op rules out.

The kaski instance's scope today, for a worked example: `kaski`, `ikiuni`, `ikiuni-renderer`, `letkajenkka`, `clause-dev`, `mockspace`, `homma`, `renki`, `nutshell` and `git-shook`. Op's words for that scope, 23 October: "entirely forget about the repos that aren't kaski, homma, mockspace or letkajenkka. Or clause-dev of course."

## What the round found

The inventory, by where each walker takes the set of repositories it works on. Read from `cmd/` and `homma-core` on `dev` at `8588cdf`.

- `Config::detect_members` (`homma-core/src/config.rs`) walked every directory under the workspace root with a `.git`, and opened each for its `origin`. It did not read the scope. Every command that reads `cfg.repos` inherited all of them: `status` (the working tree of each member, which is a repository opened per member), `verify`, `agent regen`, `docs`, `config`, `aggregate`, `release` order, `resolve_repo` and `no_such_member`.
- `status` also walked the whole root for stray build directories and sized each (`stray_targets::collect`), clones outside the work included.
- `homma what` read the scope itself (`what::scope`, a `Vec<String>` where empty meant all) and applied it in the mockspace source after it had probed every directory for a `mockspace.toml`. A second reader of the key beside the loader.
- The other sources of `what` (scripts, tools, verbs, corpora) read the workspace's own directories, which are not repositories of the work, and are left whole.
- The capture, answers and registry stores are walks over a store and not over repositories; the scope does not apply.

## What the round settles

One owner: `homma_core::scope::Scope`, read from the local file beside the manifest. `Config::from_path` asks it before it walks, so `cfg.repos` holds only repositories in scope, and the same value is kept on the config as `cfg.scope` for the commands that walk the disk themselves (`stray_targets`, `what`). No command reads `repos` from `homma.local.toml` for itself.

The walk asks the scope on the directory name, before the directory is stat'ed for a `.git` and long before it is opened. A top-level directory that is a clone and not in scope is not entered by the stray-build walk. Directories that are not clones (`tools`, `.shared`) are walked as before.

With no `homma.local.toml`, or `repos = []`, every repository is in scope. With a file that cannot be read, every repository is in scope and the loader keeps why in `cfg.scope_error`: refusing would lock out `homma local`, which repairs the file. A name in `repos` that no clone provides is not an error; `status` prints it as in scope and not cloned.

The tests measure the work. A spy over the git trait records every path it was asked the origin of, and a clone out of scope must never appear; the same fixture with no scope must show all of them, so the first assertion can fail.
