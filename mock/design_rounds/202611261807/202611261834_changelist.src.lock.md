## CHANGE: the workspace name FROM any string TO one plain path component, refused at parse
File: `mock/crates/homma-api/src/workspace_name.rs`, `mock/crates/homma-api/src/lib.rs`, `mock/crates/homma-core/src/config.rs`, `mock/crates/homma-engine/src/cmd/status.rs`
Verification: `[workspace] name` deserializes into `WorkspaceName`, which refuses an empty name, `.` and `..`, a leading dot, a path separator and a control character; a manifest with one is refused by `Config::parse`.

## CHANGE: the role file FROM a fixed path TO `.config/<workspace name>/role`
File: `mock/crates/homma-api/src/session.rs`, `mock/crates/homma-engine/src/cmd/rules.rs`, `mock/crates/homma-engine/src/cli.rs`, `mock/crates/homma-api/tests/session.rs`, `mock/crates/homma-engine/tests/rules_session_smoke.rs`
Verification: `role_file` joins the name under `.config`, and `homma rules` reads it under the home directory. The end-to-end test reads the name from the manifest `HOMMA_TEST_MANIFEST` names and writes the role where `HOMMA_TEST_ROLE_FILE` says the setup writes it, and the role is read; with the role file derived from anything but the name, it and the api test fail. The command and the values it was run with are in the report, not here.

## CHANGE: the cloud variable FROM a constant TO `[session] cloud_var`, defaulting to the value in use
File: `mock/crates/homma-api/src/session.rs`, `mock/crates/homma-core/src/config.rs`, `mock/crates/homma-engine/src/cmd/rules.rs`, `mock/crates/homma-core/src/config/tests.rs`
Verification: `SessionConfig` refuses an unknown key; a manifest setting `cloud_var` is read by it; `homma rules` reads the variable it names, which the smoke test's planted manifest sets. A manifest without it reads the value in use, checked against `HOMMA_TEST_CLOUD_VAR` given at run time.

## CHANGE: the keychain prefix FROM a constant TO `[auth] service_prefix`, defaulting to the value in use
File: `mock/crates/homma-core/src/config.rs`, `mock/crates/homma-core/src/release/auth/store.rs`, `mock/crates/homma-core/src/release/auth/tests/store.rs`, `mock/crates/homma-engine/src/cmd/release/auth.rs`
Verification: `Keychain` carries its prefix and the store is built with `AuthConfig::service_prefix`. A manifest without the key reads the value in use, checked against `HOMMA_TEST_SERVICE_PREFIX` given at run time.

## CHANGE: the speaker of `homma answers` FROM a fixed handle TO the catalogue's king
File: `mock/crates/homma-api/src/config/mod.rs`, `mock/crates/homma-engine/src/cmd/answers/mod.rs`, `mock/crates/homma-engine/src/cli.rs`, `mock/crates/homma-engine/src/cmd/answers/tests/mod.rs`, `mock/crates/homma-engine/src/cmd/answers/tests/golden/title.txt`, `mock/crates/homma-engine/src/cmd/answers/tests/golden/capture.golden`
Verification: `Workspace::king` is the handle of the entry whose role is `king`; a page's source carries it and the title names it, or `someone` with no king; `--from` defaults to it and is required with none.

## CHANGE: the status FROM no word on the engine's keys TO `reads`
