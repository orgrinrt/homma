# Milestone steps edit by position and print their row

Follows the round `202610311626`. The second review pass found two blockers, and they are taken here. The intent is unchanged: every milestone recorded with exact revisions, and no tool touching what is already recorded.

## What the review found, and what is settled

`set` parsed the whole file and wrote the parsed document back, so a record with CRLF line endings came out with every line ending changed, recorded rows included, and a leading byte order mark was dropped. The claim that every other byte of the record stays as it was has to hold for any input, so the step is now an edit by position: the lines of the last table are found in the text, a key that is there has its value replaced in place and keeps whatever follows the value on its line, a key that is not there is added after the last key of that table, and every other byte, the file's own line ending and a leading mark included, is left alone. The lines a step adds end as the file's own lines do.

`append` refuses a record that is not written as `[[milestone]]` tables, since a table appended to an inline array breaks the file, and it passes a read error on instead of treating it as an empty file.

`freeze` and `pin` printed nothing to a person and only emitted JSON, against the design's lines for a person. Each now prints the row it wrote the way `show` prints a row, from the one function that does it. `mark` stays quiet for a person as it was before the steps, which is the one place the design's sentence is not yet kept, and is named in the report.

A pin on an open row with no recorded freeze, a row written by hand, is refused with a message that says the freeze is missing, not that nothing is open. The tests gain a freeze and a pin that take `origin`'s trunk over a stale local one, and the command line test asserts the whole epoch range.
