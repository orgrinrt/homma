# The bytes homma writes into a symlink are a path, and nothing proved them

Tenth review, tenth refusal, and the class relocated one more time. The previous
round proved every path homma *computes*. It did not prove the one homma
**writes into a file**, and the kernel follows that one too.

## The defect

`link_memory` takes two proven paths and then does this:

```
relative = relative_from(link.parent(), target)
symlink(relative, link)
```

`relative_from` is lexical and works from the paths **as written**. The link is
then created at the path **as resolved**. When a symlink in the chain makes the
real location shallower than the written one, the `..` sequence in the body
climbs further than it should and lands outside the root.

The reproduction needs one link and it is a link that is plainly contained:

```
ln -s . root/.claude
homma --config root/homma.toml org up r     # exit 0
root/agent-memory/r -> ../../.shared/hands/r/memory
```

`root/.claude` resolves to `root`, so it passes containment without argument. It
also removes one level from the real depth, and the body was computed against the
written depth.

## The part that settles it

**Run `org up` a second time and homma's own guard refuses the link homma just
created:**

```
error: preparing the workspace for `r`: …/root/.claude/agent-memory/r resolves to
…/.shared/hands/r/memory, which is outside the workspace root …/root
```

`contain` and `link_memory` disagree about the same artifact, inside one branch,
one command apart. That is not a subtle boundary case; it is the crate
contradicting itself.

And the link is git mode `120000`, committed by design, so every clone carries
the escape. One level above a Hand's root is where the other Hands' workspaces
sit, which is deny item two.

## The structural answer, and it is the reviewer's

> anything homma commits which a later `open(2)` will follow is a path, and
> `Root` should be the only thing that can produce one; a `ContainedPath`-typed
> link body would have made finding 1 a compile error rather than a tenth review.

So the body is computed between **resolved** paths rather than written ones,
which makes it correct by construction: two paths both inside the root have a
relative path between them that goes up only as far as their common ancestor,
which is at or below the root. And it is proven anyway before the `symlink`
call, because "correct by construction" is what the last nine paragraphs of this
kind claimed.

## What else the review found

**The idempotence laws are sampled over the shapes where the class cannot
arise.** Both run against a bare tempdir with no link anywhere, which is why a
crate contradicting itself is invisible at 335 green. Every symlink test on this
branch is a refusal test and none is an idempotence-under-symlink test.

**The test pinning the resolved-root guard self-skips and still passes.** It
returns early when the tempdir path is already resolved, which is every Linux
tmpfs. It ran here only because macOS has `/var -> private/var`, so on the
platform CI most likely runs, that guard is pinned by nothing.

**The design template carries the totality paragraph.** "Every path written to is
checked... The check therefore lives in one place that all of them pass through."
False, and this time in the tier that governs the code.

**The compile-fail case pins a route nobody uses.** It asserts `ContainedPath`
has no `join`. Every real derivation goes through `as_abs()`, which hands back an
`AbsPath`, which has `join`, `parent` and a full `Deref`. The four production
sites all re-prove correctly, so it is not a live escape, but the property is
convention and the test named as proving it does not reach it.

**A dead arm reading as live defence.** `resolved()` handles a `..` written in
the path, and nothing can put one there, because every constructor normalises
first. The comment describes behaviour that is unreachable, in the same file that
deleted an unreachable branch two rounds ago for the same reason.
