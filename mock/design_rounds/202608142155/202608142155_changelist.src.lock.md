# Src changelist: the link body is proven too

## CHANGE: `link_memory` computes the body between resolved paths, and proves it

The body was `relative_from(link.parent(), target)` over the paths as written,
while the link is created where those paths resolve. A link in the chain that
makes the real location shallower than the written one left the body climbing a
level too far.

Both ends are resolved first. That makes the result correct by construction, and
the argument is short enough to state: two paths both inside the root have a
relative path between them that ascends only to their common ancestor, which is
at or below the root, so it cannot leave.

It is proven anyway, before `symlink`, because correct-by-construction is exactly
what the last ten paragraphs of this kind asserted. `link_memory` takes the
`Root` for that purpose.

## CHANGE: `Root::contain_under`, so deriving a path is one call through the prover

Every derivation went through `as_abs()`, which hands back an `AbsPath` carrying
`join`, `parent` and a full `Deref`. The four production sites re-proved
correctly and the property was convention rather than a type.

`contain_under` takes a proven path and a tail and returns a proven path, so the
ordinary case never reaches the door. `as_abs` stays, documented as the unwrap
door it is, which `what-you-can-observe-is-what-you-guaranteed.md` permits when
it is declared rather than incidental.

## CHANGE: the `..` arm in `resolved` is deleted

It handled a `ParentDir` written in the path. Nothing can put one there: every
`AbsPath` constructor normalises lexically first. The doc comment described its
behaviour as live, and the measured behaviour of the whole function differs from
the kernel's for that input, so the comment was wrong twice over about something
unreachable.

A `..` inside a **link target** is still handled and still needed. That is the
reachable half and it keeps its arm and its test.

## CHANGE: tests

**Idempotence under a symlink**, at the crate and through the binary. Both
existing idempotence laws run against a bare tempdir where the class cannot
arise, which is why a crate contradicting itself sat invisible at 335 green. The
new pair stands an identity up twice into a root carrying `.claude -> .` and
asserts the second call succeeds and the link body resolves inside the root.
Committed red first.

**The unresolved-root test stops depending on the host filesystem.** It skipped
itself when the tempdir path was already resolved, which is every Linux tmpfs, so
on the platform CI most likely runs it pinned nothing while passing. It now
builds the unresolved root deliberately with a symlink, and the skip is gone.

**A differential test of `resolved` against `canonicalize`** over the link matrix
that both can answer, so a future change to the walk is measured against the
kernel rather than against its own tests.
