# Topic: adopting mockspace

**Date:** 2026-08-14
**Phase:** TOPIC
**Scope:** what changes in this repository so that mockspace governs it
**Status:** open

homma is the workspace orchestrator. Every repository it manages runs its design
work through mockspace, and homma itself does not, which means the one tool that
knows what the workspace's discipline is has never been subject to it. That is the
gap this round closes.

## What adoption actually is

Mockspace is launcher-only now. There is no `build.rs` bootstrap, no `.cargo`
alias and no proxy crate: `mock` and `cargo-mock` are installed once per machine
and a repository declares which engine it runs in a root `mockspace.toml`. So
adoption is three things and no more.

**A root `mockspace.toml`.** It names the project, the crate prefix, the mock
directory, and the engine pin. Since mockspace has cut no release, the pin tracks
its working trunk.

**Re-rooting the workspace under `mock/`.** Every sibling repository in this
workspace puts its crates at `mock/crates/` with `mock/Cargo.toml` as the Cargo
workspace, and keeps only the configuration, the licence, the readme and the
toolchain pin at the repository root. kolli, arvo, hilavitkutin and vehje are all
this shape. homma currently has `crates/` and `Cargo.toml` at the root, which is
the pre-adoption shape and the only structural difference.

**Activating the hooks**, once per clone, which points `core.hooksPath` at the
generated set.

## Why the move is a source change and belongs in a src changelist

The obvious objection to doing this through the full ceremony is that nothing
about the code changes: `git mv crates mock/crates` moves files and edits no line.

The gate disagrees, and it is right to. Mockspace reads the staged and unstaged
state of every source file, and a moved file is a modified file as far as any
consumer of the tree is concerned: paths in tooling break, the workspace manifest
resolves from a new root, and anything holding a path into `crates/` is wrong
afterwards. Treating a wholesale relocation as free because no line changed is the
same error as treating a rename as free.

So the relocation happens inside a source window like any other source change, and
this round exists to open one.

## What is deliberately not decided here

**The crate taxonomy.** homma is two crates, `homma-core` and `homma`, split
before mockspace and before the workspace had an opinion about layering. Whether
that split is right, what each crate owns, and where the layer boundaries fall is
the next round's subject, and the `layers` key in `mockspace.toml` carries a
placeholder until it answers.

Deciding taxonomy inside an adoption round would bury a real design question under
a mechanical move, and the mechanical move has to land first for the taxonomy
round to have a workspace to reason about.

## The shape of the change

- Add `mockspace.toml` at the repository root.
- `git mv crates mock/crates`, `git mv Cargo.toml mock/Cargo.toml`,
  `git mv Cargo.lock mock/Cargo.lock`.
- Copy the toolchain pin to `mock/rust-toolchain.toml`, since the Cargo workspace
  is now rooted there.
- Add the document templates the generator reads.
- Activate the hooks.

The Cargo workspace's `members = ["crates/*"]` is relative to its own manifest and
needs no edit.
