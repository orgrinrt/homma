# adoption-is-the-toml-and-the-document-keeps-its-fields


Sent back by review of the branch after round 202610270505. Two blocking
findings and four to take in the same round.

Adoption. The design says a repository has adopted mockspace when it carries a
`mockspace.toml`. The code from the earlier round called a repository adopted
when it had the toml or its mock directory, and one test pinned the code
against the design. A repository with `mock/` and no toml is mockspace's own
tree, which `mockspace-is-v1-and-v2` calls expected, and `cargo mock` answers
"no mockspace.toml found" there, so the line sending it to `homma agent regen`
named a command that cannot work. Op's coordinator ruled that adoption is the
toml, and that a mock directory without one reads as no mockspace. The design
paragraph gains that sentence, and `regen` and the commit gate follow it,
leaving a repository without the toml alone.

The same literal `mock/` was left in `regen` and in the commit gate. Both read
the directory the toml declares, as the probe now does.

The document. The design promises that the machine-readable document grows
fields and never changes shape. The earlier round removed `mock_agent_dir` and
`cargo_mock_alias` from the agent status document. Both come back, deprecated,
carrying the value of their probes, and the design says so. This sits against
`no-legacy-shims-pre-1.0`, which would delete them; the design's promise to
what reads the document is the stronger claim here and the coordinator ruled it.

The advice. A difference line said to put the shared copy back. Where a repo's
copy carries exceptions the shared one lacks, as the `deny.toml` of homma,
mockspace and muisti do, restoring would break their `cargo deny`. The line now
says restore where the difference is drift and add a variant where the copy
carries something the shared one lacks. The question of whether the webpki
exceptions belong in the shared copy is op's and stays open.

its modules move to sibling files.
