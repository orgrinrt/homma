## The findings

The deep dive lists six ids in the set a release needs green that the code and the check catalogue both report at warn: `tag.prefix`, `tag.annotated`, `tag.dupes`, `tag.local`, `reg.unpublished` and `both.sameset`. The catalogue was the port target and has all six at warn, so the design paragraph misgrouped them. Four of them are hygiene, a bare tag or a lightweight one or a fetch not run, and stay warn. Two are a release half done: the newest tag with no package published for it, and a package on jsr and npm holding different sets. Those two block, where `reg.unpublished` blocks on the newest tag and warns on older ones, since a tag from before the crate was ever published is history rather than a release nobody finished.

The gate runs `cargo clippy --all-targets --all-features -- -D warnings` as a blocking step, and the branch adds four findings under it. They go. The trunk carries thirteen more that predate the branch, so the gate refuses the tree it ships in; that is its own unit and a row in the workspace agenda.

`plan` discards `--level` where the manifest already sits above the newest tag, and the design says the level makes the version. Where the manifest disagrees with what the level makes of the last tag, the plan refuses and says both numbers.

The sibling refusal runs over every repo the workspace names, before the sweep decides which of them has anything to release, so two repos with nothing unreleased still refuse the whole run on an edge between them. The refusal is scoped to the repos the sweep will release.

The design says a repo-less run goes in dependency order; the code goes in name order and refuses on an edge, and the design says so now, the way it says the `mock/` manifest gap.

## What does not change

The check ids, the run's steps, the surface.
