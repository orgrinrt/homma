# the-unboxed-arms-each-get-a-wire-test

## What was found

The review of round `202609032329` found the source changelist claiming the
green wire tests say the status arms still match after the unboxing, while
four of the nine restructured arm groups have no wire test driving the real
client: `create_repo`'s 422 on GitHub, the one arm that moves the response
out of the boxed error and reads its body; `create_repo`'s 409 on Forgejo;
and `credential_works`' 401 and 403 on both. The arms were read against the
base one by one and hold; the claim rested on five sites out of nine.

The rewritten doc comment on `is_aggregated_command` runs to 89 columns
against the crate's 80, which rustfmt neither wraps nor reports, and names
`is_retired_aggregated_command` for one of the two shapes it owns.

The topic named the cause of the thirteen findings, the root workspace
excluding `mock/` so the gate's lint step never reaches the engine, and
nothing executable records it. That case is written as a catalogue red in
the gate's test tree, which round `202609040018` is splitting, so it lands
there rather than here.

## What changes

Each of the four arm groups gets a wire test against a loopback stub
answering by path, the stub gaining a body per route so the 422 arm's body
inspection is driven both ways. The comment is rewrapped and says what the
retired-command check owns in full.
