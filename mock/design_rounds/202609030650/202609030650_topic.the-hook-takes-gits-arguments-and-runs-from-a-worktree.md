# The hook takes git's arguments and runs from a worktree

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-engine/src/cli.rs`, `homma-engine/src/cmd/release/{mod,gating}.rs`, `homma-engine/tests/cli_release.rs`
**Source topics:** the first push through an installed hook, and `202609030640/202609030640_topic.a-hooks-path-at-the-repo-root-is-tracked.md`

## The findings

Git hands a pre-push hook the remote's name and url as two arguments, and the hook passes them on; the gate's command took the first as a repo name and refused the second as unexpected, so every push through an installed hook was refused whatever it carried. With `--hook` the two positionals are git's and the repo is the one the working directory is in.

A push from a worktree runs the hook with the worktree as its working directory, which sits beside the clones rather than under one, so the repo was not found. Where no repo contains the working directory, the clone git reports as the worktree's common directory is the repo.

## What does not change

The design and the hook script; the twenty-four installed hooks keep working as written.
