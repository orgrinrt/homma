# doc changelist

Answers `202610231736_topic.the-tool-dispatch-runs-on-renkis-host-side.md`.

## Current state

The section on the workspace's tools describes a dispatch that reads the descriptor format itself, and says in one sentence what is false: "Another backend is fetched by renki's host, so a tool with one is listed and a run of it is refused saying so". homma is renki's host, and the published renki already has the git backend, so there is no other host to fetch for it and nothing for homma to refuse. The section says too that a built-in group hands the verbs it does not know to the tool of its name, and names only `rules`, which reads as though `rules` were the one group.

## Changes proposed

- The section says the descriptor is read and checked by renki's extension api, a tool is found by its `locate` and a command built by its `command`, and lists what that refuses, so a reader knows homma holds no second reading of the format.
- The two checks that stay homma's own are named: the descriptor's name is its directory's, and a verb is named once.
- The sentence about another backend is replaced by what is true: every backend renki ships is run, a `local` tool from where its `source` names and a `git` tool from the shared cache after renki's git backend has fetched it, listing fetches nothing, and a backend renki has no row for is refused naming the ones it has.
- The environment a command is run with names `HOMMA_TOOL_ROOT` beside `HOMMA_WORKSPACE`.
- The built-in groups are named, all of them, and `tools` is said not to be one and why.
