# the-tool-dispatch-runs-on-renkis-host-side

A reviewer's findings on pull request 74, relayed to this round verbatim where they state the intent:

"It re-implements renki's host side, which homma already depends on: `launcher/Cargo.toml:51` pins `renki = "0.0.3"` and `mock/Cargo.lock` has it. The published 0.0.3 ships `renki::extension`: `Descriptor::parse`/`check`, `Registry`, `locate` with `Local` and `Git` backends, and `command`, which sets `HOMMA_WORKSPACE` and `HOMMA_TOOL_ROOT` and refuses a symlink escape. `cmd/tools/descriptor.rs` and `dispatch.rs` write a second copy."

"The design says every built-in group hands verbs it does not know to the tool of the same name; the code does it only for `rules`, so a tool named `skills` is shadowed. Make the code general (the design is the canon)."

"`DESIGN.md.tmpl:410` ('Another backend is fetched by renki's host') is false: homma is renki's host and renki already has the git backend."

The intent in them: the tool dispatch is the host half of renki's extension api and owns no second reading of a descriptor. A descriptor is parsed and checked by renki, a tool is found by renki's `locate` against the backend table renki ships, and the process is built by renki's `command`, so what renki refuses (a short `rev`, a url that git would read as a flag, a `run` that leaves the tool, a symlink that leaves it) homma refuses for the same reason and in the same words. The backend is not a thing homma restricts: a tool with the `git` backend is fetched into the shared cache and run like a local one. What stays homma's own is what renki does not say: a tool's name is its directory's, a verb is named once, the first word after the tool's name is a verb or the tool's default command, and a built-in group hands the verbs it does not know to the tool of its name. The rest of the findings' wording, the line numbers and the list of what the old tests accepted, is kept for provenance and is not an intent.

What was measured before the round: the old reading accepted a sixteen hex digit `rev` where renki wants forty or sixty-four, refused `./show` as a `run` where renki accepts it, listed a `git` source with the url `--upload-pack=x` as usable, ran `tools/esc/commands/go` symlinked to a file outside the tool, ignored `source.path` and assumed `tools/<name>`, and shadowed a tool named `skills` because the built-in group `skills` has no external subcommand.

Settled here without asking, because the canon is silent on them and the findings already decided the direction: the groups are the built-in commands that take verbs, each gets the same external subcommand `rules` has and a test holds that every one of them does; `tools` is not one, since `homma tools run <name>` is already how any tool is named; the shared cache the git backend fetches into is the cache root `renki-dirs` resolves for the namespace `homma`, which is the one the launcher keeps its own builds in: `HOMMA_CACHE`, then the XDG cache directory, then the platform default.
