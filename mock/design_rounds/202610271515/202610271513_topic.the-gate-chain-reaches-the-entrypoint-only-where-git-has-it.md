# the-gate-chain-reaches-the-entrypoint-only-where-git-has-it

An eighth review found that `homma hook doctor <repo>` reports an event as reached through mockspace's gate when the hook under `core.hooksPath` carries mockspace's marker, without reading git's own hooks directory. The gate does not run homma's entrypoint on that evidence: it chains to `<common-git-dir>/hooks/<event>` after its own checks, and exits zero where nothing executable is there. So with mockspace holding the key and the entrypoint missing, or somebody else's file in its place, the table never runs while `doctor` exits zero.

The previous round settled the same question for the case of no hooks path: an event is reached directly only when the file in git's own directory is exactly the text homma writes. The case of a hooks path that is mockspace's is the sibling and follows the same rule. The chain is reached when the hook under the path is mockspace's and the file in git's own directory is exactly homma's text. Where that file is missing the event is reported as not installed, and where it is somebody else's it is reported as another's hook that git's chain runs in place of the entrypoint, each with the same advice as the direct case.

## Left as they are

A hook under the path that is not mockspace's stays reported as foreign, and a path with nothing under it stays reported as missing: in both the chain is not run at all, so the file in git's own directory does not change the answer.

The reviewer's request for one test of `homma hook install` under git-shook followed by a real commit with no `--dir` is taken up as a test in the source changelist, not as a design change.
