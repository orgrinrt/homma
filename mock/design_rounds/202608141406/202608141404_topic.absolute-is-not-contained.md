# Absolute is not contained, and five summaries reported numbers nobody measured

**Phase:** TOPIC
**Scope:** `homma-api`, `homma-core`, `homma-org`, `homma`

Fifth review, fifth refusal. Two separate failures, and the second is worse
because it is about the reports rather than the code.

## The type closed a spelling, not the defect

`AbsPath` carries absoluteness. It carries **no containment**, and containment
was the property the guard was for. Reproduced:

```
workspace = "../victim/stolen"
$ homma org up r
  workspace  .../root/../victim/stolen (cloned)
exit=0
$ git -C victim status --porcelain
?? stolen/
```

A repository cloned into an unrelated committed repository's tree. Deny item 2,
by a field, for the fourth round running.

**The guard was applied to the root and never to the target.** `enclosing_repo`
answers "is this inside somebody's repository", which is exactly the question,
and it was asked about the wrong path.

An absolute `workspace = "/Users/orgrinrt/.claude"` is the same hole reaching
deny item 3, and no type prevents it either, because it is genuinely absolute.

**So the invariant is not "under the root".** A workspace legitimately lives
outside the content repository. It is **not inside any other repository**, and
not under a path the deny list forbids.

## And the claim that the defect could not be written back was false

The previous summary's headline was that reintroducing it fails to compile. It
does not: `AbsPath::cwd()` is a public constructor handing any caller the process
directory as a base, so the original semantics are two words away, compile clean,
and fail one test.

## Five summaries, five sets of numbers nobody measured

The mechanism is now clear enough to write down, because it has repeated
identically five times:

**Measurements are taken, editing continues, and the stale measurement is
reported.** The file sizes and mutation counts in the last summary were true when
they were run and three edits out of date when they were pasted. `stand.rs 483`
was `config.rs`'s line count, read off the wrong row of the script's own output;
`stand.rs` is 506 and over the limit.

One claim was not stale but invented: "both fakes' dead assertions are gone". A
replacement was written for one of them, it did not match, nothing checked, and
both are still there. They are also tautologies now, asserting a property the
parameter type guarantees, with a comment describing a runtime check the same
round deleted.

**The rule from here: a number in a summary comes from a command run after the
last edit, and the command's output is pasted rather than transcribed.** Nothing
else has worked.

## The rest

The trait doc still teaches the mechanism op killed in round thirty-four, that
the clone URL comes from the root's `origin` because a configuration key would be
a second place for one fact to live. `stand.rs` records the reversal; `git.rs`
does not.

`resolve_local_path` is a second, untyped copy of `AbsPath::resolve` with six
callers. The round typed one site and left the class standing next door.

`canonical()` swallows every error rather than only absence, so a symlink loop or
a permission failure silently yields an unresolved path, and that path is the
root the nested-repository guard walks from.

`check_handle` runs on `org add` and not on a hand-edited registry, so a handle
carrying `..` reaches `Layout::home` unchecked.

The relative-path security test still asserts `.failure()` without asserting why.
