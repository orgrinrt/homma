# the-status-smoke-test-pinned-the-noise


The previous round, 202610270505, stopped `homma status` listing a repository
with no mockspace as missing four directories. `tests/cli_smoke.rs`
`status_human_renders_workspace_summary` asserted that the summary contained
`github` and `notko`. The fixture is a single repository, notko, with no
mockspace, so both strings came only from the old line "notko missing mock/,
mock/agent/, .claude/, .github/instructions/, cargo-mock-alias, git-hooks".
`github` was the tail of `.github/instructions/`. The test passed on output
that was the defect, and it is red now that the defect is gone. Red on this
branch and green on `dev`, by `red-check`.

The test is changed to assert what the design now says: the summary names
neither the repository nor anything as missing, and `--full` names the
repository as having no mockspace, which is the control showing the first
assertion is not a status that never reaches the repository.
