# the-tagline-scan-stops-at-the-first-section

## What was found

The second review of the description step, on the tree round `202609032116`
left, found four things the design and the code still get wrong.

The scan for the blockquote runs to the end of the file. A readme whose
opening prose is followed by a section carrying a pull quote returns that
quote as the tagline, and a fenced console block whose first line begins
`>` is read as a quote with the closing fence swallowed as a lazy
continuation. The design says the opening prose is never taken for the
tagline, which the code keeps, and says nothing about how far the search
runs, which is why the claim is not a claim about anything. No test feeds a
readme with a later blockquote, so the path is never entered.

The manifest walk takes every `Cargo.toml` with a `[package]` not saying
`publish = false`, and a mockspace repository keeps committed research
probes under `<mock>/research/`, each a crate with a manifest, none of them
published and none saying so, because nothing was ever going to publish
them. The step reports six of mockspace's probes as manifests declaring no
description and refuses the release on that.

homma's own `launcher/Cargo.toml` description is not homma's tagline, so the
step this branch adds turns homma's own gate red the moment it lands.

`tagline.rs` is past the file-size tripwire, most of it tests.

## What the design has to say instead

The tagline is looked for between the title and the first heading after it:
the first blockquote in that span, with fenced code skipped, and nothing
below the first section is read. A readme whose opening carries no
blockquote has no tagline, whatever a later section quotes.

The manifests read are the published ones outside the audit trail: the walk
leaves `target/`, `node_modules/`, `.git/`, and any directory named
`research`, `design_rounds` or ending in `probes` unwalked, since those hold
committed evidence and closed rounds rather than anything a registry sees.

The launcher's description becomes the readme's tagline in the same change,
so the step it ships passes on the tree that ships it. The tests move to a
sibling file, the way the gate's already are.
