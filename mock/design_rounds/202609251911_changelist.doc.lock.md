# Doc changelist: generated hooks are per clone

Topic: `202609251907_topic.generated-hooks-are-per-clone.md`.

## Current state

`mock/DESIGN.md.tmpl`, the agent hooks section, says a session at the
workspace root loads `.claude/settings.json` and that `homma agent regen`
carries the members' hooks up into it. It does not say which file the regen
writes or that what it writes is one clone's, so the regen merges into the
shared, tracked `settings.json`, and a clone holding other members than the
last one to commit it drops or adds registrations for everybody.

## Op's confirmation, and the agents

Put to op before this changelist locked, as one question:

> Confirm the plan before I lock the design. (1) homma: regen writes hook
> registrations to settings.local.json, leaves your allows there alone, and
> sweeps its own old entries out of settings.json. (2) Workspace: ignore
> .claude/hooks/ and .claude/agents. (3) The 66 personas move to
> .shared/agents/ and agent-surfaces links .claude/agents to them: a symlink,
> since personas aren't templated. (4) lint-severity-reminder.sh, registered
> nowhere today and so dead, moves to .shared/scripts/hygiene/ and gets
> declared in homma.toml so it runs.

The options were: go as planned; render agents instead, like rules, through a
`homma agents render`, so they can take templating later, at more homma work;
or go as planned but delete the dead hook instead of reviving it. He chose:
render agents instead. So the personas are a third corpus beside the rules and
the skills, and this round carries it. None of the 66 carries template syntax
today, by a grep for `{{`, `{%` and `{#`, so the first render reproduces them
byte for byte. (1), (2) and (4) stand as put.

## Changes proposed

`mock/DESIGN.md.tmpl`, the agent hooks section:

- The opening sentence names both files the host loads at the root,
  `settings.json` and `settings.local.json`.
- A new paragraph after it: the regen's output is the clone's. Registrations go
  to `.claude/settings.local.json`, wrappers to `.claude/hooks/`, and a
  workspace tracks neither. `settings.json` is the shared, hand-written file and
  the regen writes nothing there; a registration of its own found there is
  swept and everything else in it kept. Nothing in `settings.local.json` that
  is not homma's is touched.

`mock/DESIGN.md.tmpl`, a new section, the agent corpus, after the skill
corpus: a persona is one file, `<name>.md.tmpl`, generated into the directory
the host reads agents from and never edited there; the declared name is the
filename or it is refused; the whole file is a template and one that does not
render is refused with its path; a generated persona whose source is gone is
reported and not deleted. The generation pass's summary names agents beside
rules and skills, and the command surface gains `homma agents`.

In the agent hooks section, everything else stands: the mark deciding what is homma's, one
registration per hook, the matchers, the manifest's `[agent.hooks]` rows and
how a call is narrowed.
