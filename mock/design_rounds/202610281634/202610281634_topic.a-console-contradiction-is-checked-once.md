# a-console-contradiction-is-checked-once

A pr-reviewer pass over branch `work/dashboard-off-where-a-console-is` found that the contradiction of a console beside a dashboard was checked at two of the paths that produce a local file and missed at the rest. `local set` refused only when the console was already in the text, so naming the console in a file holding `[tools.dashboard]` returned both tables. `local install` into an existing clone goes through `local::fill`, which had no check, so a clone keeping its old `[tools.dashboard]` gained `[tools.console] channel` beside it.

The fix is one check, `Local::check_console`, run over the text that `set`, `fill` and `parse_stored` each produce, instead of one test per path. A write that would leave the file naming a console and carrying `tools.dashboard` is refused whichever key made it so, and the error names `tools.dashboard`. The design text already promised both refusals; it is amended to say the check is over the result of every write and of the stored config.
