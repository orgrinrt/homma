# Changelist: src — the record vocabulary, the store, and the registry

**Round:** 202608140200 crate taxonomy
**Phase:** IMPL
**Scope:** three new crates and the commands that drive them

## CHANGE: create `homma-api`

The record vocabulary: `Record`, `Kind`, `AttrType`, `Attr`, `Handle`, `Ref`,
`Rung`, and the registry's configuration types.

`Rung` is derived from a `Ref` rather than stored, which is the decision that
provenance cannot disagree with itself. The derivation is a function of the
namespace and, for the registry namespace, of the role the entry carries.

Three attribute types only: `Text`, `Instant`, `Ref`. The rest are designed and
absent, because the type list carries a standing caveat that it is arbitrary and
possibly too limited, and kinds being configuration makes every later addition
additive.

**Verification:** unit tests over rung derivation for each namespace and role, and
over reference parsing for each sigil.

## CHANGE: create `homma-store`

Append and read newline-delimited records. A kind declares whether its records may
be edited; the store refuses an edit to a kind that says append-only.

**Verification:** a test appends, reads back, and asserts order; a test asserts an
edit to an append-only kind is refused and to a mutable kind is accepted.

## CHANGE: create `homma-org`

The registry over the configuration, and the workspace lifecycle: clone, set the
git identity in that clone's own config, link memory into the path the harness
expects, generate the definition.

**Verification:** a test creates a workspace in a temporary directory against a
local origin, then asserts the git identity is set in that clone and not globally,
that the memory symlink resolves and writes through to the layout path, and that
the generated definition contains the identity's handle.

The symlink test exists because the shape was established by hand and a hand check
becomes a committed test. Both the sibling and the nested forms were exercised by
hand; the nested one is what ships, so the nested one is what the test asserts.

## CHANGE: extend the command surface

`homma org list`, `homma work create`, `homma work list`. Output splits porcelain
from plumbing: with a terminal attached it prints for a human, without one it
prints its result and nothing else.

**Verification:** the CLI smoke test asserts a non-tty invocation prints no
decoration.

## What this changelist does not touch

`homma-core` keeps its forge clients and git operations unchanged. Dissolving that
pre-adoption split is its own round.
