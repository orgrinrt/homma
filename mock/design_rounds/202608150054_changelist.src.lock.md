# Src changelist: one level, not a chain

## CHANGE: `provision` creates the workspace's parent with `create_dir`

`create_dir_all` built whatever chain the configured path implied, and the
workspace is outside the containment root by requirement, so nothing covered it.
One level is genuinely required, for the reason its own comment gives, and a
chain never was.

## CHANGE: the test that pinned the chain is rewritten

`provisioning_creates_the_workspaces_parent_before_cloning` asserted two levels
of ancestor creation. It was a correct test of a rule this branch has since
decided against, so it becomes two: one level is created, and a second level is
refused rather than built.

Worth naming because it is the round's lesson: **ten tests fail when that call is
deleted, and every one was pinning the behaviour that had to change.** A guard
being pinned says nothing about whether what it pins is wanted.

## CHANGE: `generate.rs`'s containment check gets a test

Replacing it with a bare `create_dir_all` left all 344 green while its twin
twenty lines away in `workspace.rs` fails one. Third time this shape has been
found on this branch.

## What this does not close

A workspace pointed at a directory that already exists inside a home is still
accepted. `create_dir` stops homma building a path into one; it does not stop
homma being aimed at one already there. That needs a guard that knows where home
is, and it is a separate unit rather than a line here.
