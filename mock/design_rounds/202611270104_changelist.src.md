# src changelist

This changelist comes from `202611270101_changelist.doc.lock.md`, and through it from `202611270100_topic.git-hooks-are-declared-in-shook-toml.md`.

## CHANGE: the git hooks table FROM `homma_api::Hooks`, `HookEntry` and `InvalidHooks` TO gone
File: `mock/crates/homma-api/src/hooks.rs`, `mock/crates/homma-api/src/lib.rs`, `mock/crates/homma-api/Cargo.toml`
Verification:
- The module and its re-exports are removed.
- `glob`, which only that table used, leaves the dependencies.
- The layers module doc says the overlays carry the agent tables.

## CHANGE: `[paths]` FROM no key for the git hooks TO `git_hooks`, `shook.toml` by default
File: `mock/crates/homma-api/src/config/paths.rs`
Verification: `Paths::git_hooks` is a `RelPath`, and its default is `shook.toml`.

## CHANGE: the manifest parse FROM reading `[hooks]` TO taking it out unread and naming it
File: `mock/crates/homma-core/src/config/retired.rs`, `mock/crates/homma-core/src/config.rs`
Verification:
- `Config::parse` calls `retired::parse`.
  - It returns the strict parse where that takes the manifest.
  - Otherwise it reads the raw table and takes out each table in `TABLES` (`hooks`), recording a `Retired { table, file }` on `Config::retired`, then parses the rest strictly.
  - Where nothing was retired, the first refusal is returned with its line.
- `Retired::said` gives the line: `[hooks] is no longer read: the git hooks are declared in <git_hooks>`, then the move.
- The `hooks` field is gone from `Config`.

## CHANGE: the overlays FROM appending `[hooks]` TO naming a `[hooks]` they still carry as retired
File: `mock/crates/homma-core/src/layers.rs`, `mock/crates/homma-core/src/config.rs`
Verification:
- `Overlay` carries `retired` in place of `hooks`.
- `parse` takes the retired tables out of an overlay before anything else reads it.
- `apply` takes the agent table alone and returns `Applied { failed, retired }`.
- The config load extends `Config::retired` from it.
- The refusal of an overlay's unread table no longer names `[hooks]` as one an overlay holds.

## CHANGE: the git hooks install FROM entrypoints in git's own directory or a manifest from the table TO the gate and the workspace's manifest registered with git-shook
File: `mock/crates/homma-core/src/hooks/mod.rs`, `mock/crates/homma-core/src/hooks/shook.rs`, `mock/crates/homma-core/src/hooks/error.rs`, `mock/crates/homma-core/src/hooks/install.rs`, `mock/crates/homma-core/src/hooks/run.rs`, `mock/crates/homma-core/src/hooks/reach_kind.rs`
Verification:
- `install.rs`, `run.rs` and `reach_kind.rs` are removed.
- In `shook.rs`, `gate_manifest` writes `name = "homma"` with `[hooks.pre-push]` and `run = GATE`.
- `workspace_hooks` reads the workspace's manifest's `name`, taking the root's directory name where there is none. It refuses `homma` or a name that is not a plain file name as `HookError::Name`, and an unreadable toml as `HookError::Manifest`.
- `install_with` works in this order:
  1. It refuses with `HookError::NotShook` unless `holds_path`.
  2. It writes `homma.toml` and `<name>.toml` under `shook/manifests/`.
  3. It runs `git shook install --yes --only homma --only <name>` and checks that the gate's entry is registered.
  4. On a refusal it gives each manifest back as it was.
- `HookError` now lives in `error.rs`, each variant saying what to do.

## CHANGE: an older homma's leftovers FROM kept and recorded as declined TO taken away before the registration and put back on a refusal
File: `mock/crates/homma-core/src/hooks/legacy.rs`, `mock/crates/homma-core/src/hooks/shook.rs`
Verification:
- `legacy::entrypoint` is the old text byte for byte.
- `left_behind` finds it in git's own hooks directory and in git-shook's `kept/`.
- `clear` removes each copy, together with the `00-existing` entry or the declined copy that is the same text, and returns `Removed` with bytes and mode.
- `install_with` calls `clear` before registering, and `restore` on a refusal.

## CHANGE: `homma hook` FROM install, doctor and run over the table TO the verbs of the new install
File: `mock/crates/homma-engine/src/cmd/hook.rs`, `mock/crates/homma-engine/src/cli.rs`, `mock/crates/homma-engine/src/cmd/util.rs`
Verification:
- `install_cmd` finds the workspace's manifest by `git_hooks` and installs. It reports the names registered, the gate alone where the workspace has no manifest, and each leftover removed, and it reports every refusal as a line with a non-zero exit.
- `doctor_cmd` prints, failing on all but the first:
  - where the git hooks are declared;
  - each `Retired::said`;
  - the overlay survey;
  - with a repository, whether git-shook holds the hooks path and each leftover.
- `run_cmd` says on stderr to run `homma hook install <repo>`. At `GATE_EVENT` it runs `GATE` with git's arguments and stdin and takes its exit, and at any other event it runs nothing. It carries the marker of `remove_homma_hook_run_once_no_clone_carries_an_older_entrypo`.
- `out_of_scope_clone`, which only the old run used, is removed.
- The `Hook` and `HookOp` docs say the same.

## CHANGE: the status FROM no word on a retired table TO `retired` on the workspace line
File: `mock/crates/homma-engine/src/cmd/status.rs`
Verification: `WorkspaceLine` always carries `retired`, the `Retired` rows. The human output prints each `Retired::said` under the workspace line, indented by two spaces.

## CHANGE: homma's own tracked manifest FROM `homma hook run` at two events TO the release gate at `pre-push`
File: `shook.toml`
Verification: The manifest names `homma` and runs `["homma", "release", "gate", "--hook"]` at `pre-push`, and nothing else.
