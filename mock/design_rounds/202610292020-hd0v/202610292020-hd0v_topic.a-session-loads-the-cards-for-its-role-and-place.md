# a-session-loads-the-cards-for-its-role-and-place

The generation pass writes every rule card that has no `paths:` scope into every session, so a cloud helper loads the cards that only bind a coordinator, and a coordinator loads the helper's tool list. On the workspace's own corpus that is 118 cards and 107,785 bytes, about 27,000 tokens, paid before any work starts. Some cards bind one role only, and some bind nothing in a cloud container.

## What op decided

Op, 29 October, verbatim: "render rules by role, big yes. We now have the env vars to branch with."

The intent is that a session gets the cards for its role and its place and no others. The vehicle below is a proposal and replaces nothing about the intent.

## What the design says and where it is silent

The rule corpus section of `mock/DESIGN.md.tmpl` says the card is a prefix of the rule, the meta is frontmatter, and the generated tree is the always-loaded set. It is silent on who a card is for: every card with no `paths:` is written for every session. Homma declares no canon, so the design governs, and the silence is filled by this round's doc changelist, not by code.

## Decisions

The meta gains two optional keys beside `topics`, `fires`, `kind` and `paths`.

`roles` is a list of `coordinator` and `helper`. Absent means every role. The word role already names a person's standing in the organisation (`homma-org`), so the session's own is called the session role in code and prose.

`where` is `cloud` or `local`. Absent means both.

The session is read from two places, in this order of authority: an explicit `--role` and `--place` on the command, then the environment. The role is the content of `~/.config/clause-dev/role`, the file the setup script and the bootstrap write; an absent file means a local session of the person's own, which takes every role. The place is cloud when `CLAUSE_CLOUD` is exactly `1`, which is the predicate the workspace's bootstrap already uses (`bootstrap_attached.sh`), and local otherwise. A role file holding a word that is neither role is refused by name, since silently taking every role would hide a misspelt file behind a full load.

A card the session excludes is not written. A card of an authored rule that an earlier pass wrote and this session excludes is removed, because the rule claims it and the pass owns it; this is not the unclaimed case, which is still reported and left alone. `homma rules show <name>` and `rules about` still answer for every rule, so a withheld card is one command away.

The load is reported rather than guessed: `homma rules load` prints, for a session, the cards it gets with their bytes, and with `--all` the count and bytes for each role and place, so the corpus check counts what each kind of session loads.

## Why the role file and `CLAUSE_CLOUD` and not a flag per session

Both already exist and both are written once by the setup script, so a session needs nothing new to be configured. Nothing in the environment says helper or coordinator any other way.
