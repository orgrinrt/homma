# doc changelist

This changelist comes from `202611270248_topic.agent-hooks-on-one-call-per-event.md`, the round's one topic.

## CHANGE: who registers the agent hooks FROM homma, one registration per hook TO claude-shook, one per event, from a manifest homma writes
File: `mock/DESIGN.md.tmpl`
Verification: "The agent hooks" says homma registers none of the hooks itself. It writes every one as a row of `.claude/shook/manifests/homma.toml` and runs `claude-shook install` at the workspace root, which writes one registration per event into `.claude/settings.local.json`. The section says the front runs an event's entries in order as a chain on the base, each in the session's directory with the payload, only those whose matcher and `paths` take the call. It says an exit of 2 blocks and stops the chain, another failure or a timeout is named and the chain goes on, and the answers are folded as the host would fold them. The paragraph saying a dispatcher is not needed and one registration per hook is what homma writes is gone.

## CHANGE: homma's own registrations and wrappers FROM written and kept per visited member TO swept from both settings files, whichever member they name
File: `mock/DESIGN.md.tmpl`
Verification: The section says a registration homma wrote itself is swept from both files with the wrapper it ran, visited member or not. The rules on homma's namespace and the mark stay: a file under a managed name that homma did not write keeps its registration, and one homma would overwrite is refused by path. Both files are read and swept before either is written.

## CHANGE: the move FROM unconditional TO only where `claude-shook` is on `PATH`, the sweep after the install
File: `mock/DESIGN.md.tmpl`
Verification: The section says the hooks stage asks for `claude-shook` on `PATH` before writing anything and, where there is none, refuses in one line and leaves every registration, wrapper and file as it was. It says the sweep runs only after `claude-shook install` has written its registrations, and that a clone moves on the first regen after claude-shook is installed.

## CHANGE: a member's hook FROM a wrapper per hook TO a row per registration, run by `{root}`
File: `mock/DESIGN.md.tmpl`
Verification: The section says each registration of a member's hook is one row named `<repo>--<hook>`, a second at one event numbered. The row runs the registration's program words, `{root}/<repo>/.claude/hooks/<hook>` and its argument words. A program that is a line of shell, and arguments carrying a quote or a shell character, are reported by path and not carried. The sentence refusing a hook two registrations run two ways is gone, since each registration is its own row.

## CHANGE: a row's timeout FROM none TO the registration's, else 600 seconds
File: `mock/DESIGN.md.tmpl`
Verification: The section says a row takes the timeout its registration gave, else 600 seconds.

## CHANGE: the declared rows, the gate, the nudges and the git hooks' sweep FROM wrappers and registrations of their own TO rows of the one manifest
File: `mock/DESIGN.md.tmpl`
Verification: The section says a declared row is `_declared--<slug>` running `{root}/<run>` with its `repos` under `paths`. The gate is `_workspace--mockspace-gate` at `PreToolUse` for `Bash`, running the gate script still written under `.claude/hooks/`. The nudges are one `_nudges` row per event running `homma agent nudge <Event>` from the root. The git hooks' sweep is `_git-hooks` at `SessionStart` running `homma hook install` from the root. The chain order is the gate, the members, the declared rows, the nudges and the sweep. "A nudge" says the regen writes one `_nudges` row per event, with the same matcher and the same exemption from `tools/hookdedup`.

## CHANGE: the narrowing FROM each wrapper's own scope check TO the front's `paths`, by the same rules
