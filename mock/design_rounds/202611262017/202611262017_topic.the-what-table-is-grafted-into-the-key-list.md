# The what table is grafted into the key list

## The defect

The round that read a workspace's synonym groups from `[what]` grafted `WhatConfig` into `config::keys` under `what`. The round landed beside it turned `config::keys` into one returning a `Result`, and the merge of the two kept that shape, which has no graft for `what`: the status lists `what` whole as an opaque key and not `what.synonyms`, and the key list's tests fail on it.

## The fix

The graft goes back in, in the `Result` shape: `keys.graft("what", probe::<WhatConfig>()?)`. No document changes: the design already names `WhatConfig` and the derivation of the key list from the types that read the manifest.
