## mock/crates/homma-core

- `src/release/landing.rs`: `drop_landed_branch` passes the second parent of the landed merge, the bump that landed, as the head the deletion is leased on, where it passed the head the branch holds now; a branch a person pushed on past the bump is then not deleted.
- `src/release/changelog.rs`: `block_of(root, version)`, the block `CHANGELOG.md` holds under the heading of `version`, to the next block; `run.rs` `step_forge_release` makes the forge release from it where the file holds one, so the body is the file's block, as the design says, in every state the bump is not written by this run, and from the plan's block otherwise.
- `src/release/git.rs`: `delete_branch(cwd, remote, branch, head)`, the branch's deletion pushed with `--force-with-lease` on `head`.
- `src/release/writes.rs`: `ByClient::drop_branch` deletes through `git::delete_branch`, so it deletes the branch only where the remote holds it at `head`.
- `src/release/run.rs`: the words of `ReleaseError::NotLanded` say what a rerun takes for either base, a merge whose tree is the tip merged onto its first parent, and no longer say the rerun refuses the same merge.
- `src/release/run_dev_pr_tests.rs`, `run_pr_tests.rs`: a rerun with the clone at the merge (the release pull request failed after `dev` was landed) takes it with no second pull request; a merge a tag already holds is no pending bump; a branch moved past the merged bump is left on the forge and no bump is lost; the client deletes only at the head it pushed; the interloper rerun is refused for the gate run it lacks and takes the merge, with no second pull request, once the moved `dev` has a green run; the forge-resolved rerun is asserted by its error; the forge release body is the file's block where `dev` already held it, by a commit of another subject and by a pull request another landed. `run_dev_pr_tests.rs` is split in two along that line (`run_dev_resume_tests.rs`).
