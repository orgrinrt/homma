# Review findings on the release roots and clones

The first review of the branch (`pr-reviewer-senior`, round one of three, head `e3dd072`) answered merge after fixes. The sweep was clean and every test it ran passed; the findings are about a design sentence the second round made false, holes in the suite, one discarded error and one copied fixture. Each is taken here, and none is argued with, since the reviewer read the code and the changelists and the question was whether the two agree.

## The design sentence the second round contradicted

`DEEPDIVE_release.md.tmpl` in the section on what a release reaches says the three places that build an agent share the system's roots by sharing the dependency feature, and that none of them loads roots itself. The round `202611031227` took the feature out and `homma-core` now reads the roots itself, once, in the crate-private module `tls`, and the registry requests, the GitHub client and the Forgejo client all start their agent from it. That round's doc changelist said no design text moved, on the grounds that the section says nothing of the crate that reads the roots. The sentence quoted above says exactly that, so the changelist was wrong. The correction is a doc change in this round: the section says the roots are read once, in one place every agent starts from, and that a test over the crate's source names any file that builds an agent from nothing. The rendered `docs/CORE_RELEASE.md` follows.

## The scan that guards the one place

The test `no_agent_is_built_outside_the_module_that_sets_the_roots` matches only the text `AgentBuilder::new`, and the reviewer showed it stays green when the GitHub client is changed to `ureq::builder()`, which trusts only the compiled-in roots. The same holds for `ureq::agent()`, the free request functions (`ureq::get` and the others), `Agent::new()` and a renamed import of `AgentBuilder`. A file named `tls.rs` in any subdirectory is also exempt, because the exemption compares the file name and not the path.

The scan changes from a list of forbidden spellings to a list of allowed ones. Outside `src/tls.rs`, by path, the word `ureq` in code (comments are skipped) is followed by `::`, and what follows is one of the names the crate uses for types and errors (`Agent`, `Request`, `Response`, `Error`, `ErrorKind`, `Transport`, `OrAnyStatus`, `RedirectAuthHeaders`, `json`), alone or as a braced list of them. Any other path, an alias of the crate, or `Agent::new` and `Agent::from` is named. The control plants one file per spelling the reviewer listed and expects each to be named, and a clean file and a test file to be left alone. The claim stays as narrow as what is enforced: no source file outside `tls.rs` names a way to make an agent that is not on the list.

## A verb that names a repository is tested up to the lookup, and the lookup is not

`a_verb_that_names_none_but_a_directory_finds_every_clone` sets no working directory and never calls `resolve_repo`; it asserts what the loaded config holds. The refusal the ticket reported comes from `no_such_member` through `resolve_repo`, and nothing asserts that it no longer fires. `resolve_repo` reads the process's working directory, which a unit test cannot change without racing the others, so it is split in two: `resolve_repo_from` takes the directory and holds the body, and `resolve_repo` passes it the working directory. The new tests resolve `outside` by name and from a directory inside it, under the config `config_for` returns for `check`, and resolve it under the sweep's config to show the refusal still stands there.

## A discarded error

`load_native_certs` returns its errors beside its certificates, and `roots` drops them. A container whose `SSL_CERT_FILE` names a missing file ends with an empty store and every request fails as an unknown issuer, which does not say that the file was the cause. When no root parsed, the errors are written once to standard error, each with its context. The test asks through the child process with the variable naming a path that does not exist and expects the path in what the child wrote.

## The wording of the refusal, and the name of the test

The topic of the closed round asked that the request without the file fail as an unknown issuer. The library reports `invalid peer certificate` for a self-signed leaf no root vouches for, and the test asserts that refusal class and not a variant; this round records that as a departure from that topic. The positive arm uses the same certificate and the same address as the refused one, so a name mismatch or an expired certificate cannot pass both. The test's name also said "and only those", which nothing asserts: while the variable is set the system's roots are ignored by `rustls-native-certs`, and the test has no way to put a root in the system's store. The phrase is dropped from the name and the module text, and the test is `a_request_trusts_the_roots_ssl_cert_file_names`.

## A fixture written twice

`two_clones_and_a_scope_of_one` is in `config/tests.rs` of `homma-core` and in `config_tests.rs` of `homma-engine`, byte for byte. It moves to `homma_core::testing` as a function that writes the layout into a directory it is given, so neither crate's tests depend on the other's `tempfile` type, and both call it.

## Mutation evidence

Both source changelists said the changes were checked by mutation, and no record of it was committed. The mutations that hold for the code as it stands are scripted in `mock/research/202611031244_release-roots-mutants/mutants.sh` with the log of a run, so the claim can be rerun. They are: no `tls_config` on the agent, a root store that reads nothing, the GitHub client's agent built by each spelling the scan names, the errors dropped, the sweep and the named verb each forced to the other's load, and `resolve_repo_from` ignoring the directory. The claims in the earlier changelists about the `native-certs` feature cannot be rerun, since the feature is gone, and they are superseded by this table.
