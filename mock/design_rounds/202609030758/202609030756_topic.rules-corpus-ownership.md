# rules-corpus-ownership

homma takes ownership of the workspace rule corpus: the meta on each rule, the
discovery that finds a rule nobody remembers the name of, and the generation
that produces the always-loaded card from the elaboration behind it.

## Where this comes from

The corpus is injected into every session, sub-agents included, so its size is
paid before any work starts. A compaction pass took it from 521,825 bytes to
121,642, about 173k tokens to 40k, by splitting each rule into a short card that
loads always and an elaboration under `.shared/rules/` that is fetched when the
session is already in that rule's domain.

That split works and the numbers hold. What it does not have is any of the
machinery around it:

- **The card is hand-written and the elaboration is hand-written**, so the two
  drift, and nothing reports it. Six elaborations were found that no card
  pointed at, five of them by hand and the sixth by a check written afterward.
- **Finding a rule needs its name.** `rules find` greps, which answers when you
  already know the word the rule uses. A session that is about to write a README
  has no way to ask what governs that, and the rules it needs are the ones it
  will not think to look for.
- **The meta is prose.** Which moment a rule fires at, whether it is a reflex or
  a discipline, what it relates to: all of it is written in the body, so nothing
  can query it and every reader parses it again.

## The shape

**Three artifacts per rule, and one of them is generated.**

- `<name>.full.md.tmpl` in `.shared/rules/`, carrying the meta as YAML
  frontmatter and the whole reasoning as its body.
- `<name>.card.md.tmpl` beside it, the always-loaded form.
- `.claude/rules/<name>.md`, **generated from the card template** and never
  edited by hand.

**The meta is the single source and lives in the full template's frontmatter.**
Both templates render against it, so a trigger written once appears in the card
and in the elaboration without being typed twice. A second meta file would be a
second place to be wrong.

**Per-rule card templates rather than one shared card template**, because a rule
occasionally has to override the shape: the no-pull-request-body rule carries its
whole reasoning in the card on purpose, since it is one people break after having
read it, and a card that only points at the reason stops nothing. The common case
inherits a base template and adds nothing, so the per-rule file is three lines.

## The meta

Draft, to be argued in the doc changelist.

```yaml
topics: [writing, prose, readme, public]
fires: "before writing any prose a human reads"
kind: reflex
paths: ["**/*.md"]
```

- **`topics`** is what discovery matches. Several per rule, in the words a reader
  would arrive with rather than the words the rule uses, which is the failure
  `a-zero-from-a-search-is-not-an-answer` names: a query in the question's words
  finds nothing in a corpus written in the answer's.
- **`fires`** is the trigger, one line, in the words the moment arrives in. It is
  the part of a card that gets dropped and the part that makes the rest work,
  so making it a field means a card cannot be generated without one.
- **`kind`** separates a one-move reflex from a discipline whose parts interact,
  which is the distinction `writing-for-agents` already draws and which decides
  the card's shape.
- **`paths`** is the existing mechanism and stays. It fires inconsistently in
  practice, so nothing here leans on it.

**`skills` is deliberately not a field.** Which skills bear on a rule is derived
from citations in both directions at the time of asking; a hand-kept list is one
more thing to be wrong the first time a skill is renamed, and nothing would say
so.

## `homma rules about`

```
homma rules about "writing, readme, public"
```

**Answers with the rules whose topics match, ranked, each with its trigger.**
The point is that the caller does not know what it is looking for. A session
about to write a README asks the subject, not the filename, and gets back the
governing set rather than one grep hit.

**It is discovery rather than search**, so it matches on the meta rather than the
body. A body grep is what `find` already does and it answers a different
question.

## Generation

**`mockspace-template` is the engine, which homma already depends on.** It wraps
minijinja with strict undefined handling, and its `AgentRenderer` already walks a
tree of `.md.tmpl` and writes to platform-derived paths. What it does not do is
read frontmatter off the input as context, which is the one piece to add.

**The same engine rather than a second one**, so the templating a rule author
writes is the templating every `mock/*.md.tmpl` already uses, and the language
gains its planned extensions once for both.

## Skills move to `.shared/skills`

For the same reason the elaborations did: `.claude/` becomes generated output
rather than authored source. A skill is authored once as a template and rendered
per platform, which is what the agent-template machinery already does for repo
rules and does not yet do for the workspace's own.

## What this round has to settle

- The meta schema, and whether `kind` earns its place or is inferable.
- Whether the card template inherits from a base, and where that base lives.
- What happens to `tools/rules`, the nutshell CLI holding `budget`, `check`,
  `show`, `find` and `size` today. Its measurement half is not obviously homma's,
  and its reading half plainly is.
- Whether generation runs on a hook, on `homma agent regen`, or on demand, and
  what refuses when a generated card is edited by hand.
