# src changelist

Answers `202610270458_topic.the-milestone-reports-survive-what-they-read.md`, through the locked doc changelist `202610270458_changelist.doc.lock.md`.

## Current state

The source does what the first round's design said except where the review of `work/homma-milestone` at `89aedd4` found it did not, and the amended design now says the other way.

## Changes proposed

- `milestone/branches.rs`: each branch is read on its own and a git failure on it is its call, `unrelated` or `unreadable` with the reason carried in a new `reason` field. Emptiness is decided by comparing the merge's tree with the trunk's.
- `milestone/range.rs`: stand-ins are read in source files only, soft markers only inside a comment and never as `Ordering::Relaxed`, and the diffs are asked for with `--no-ext-diff` and fixed prefixes.
- `milestone/record.rs`: `--tag` makes the tag first, at the first free `milestone/<n>`, and removes it again if the record cannot be written; `base` reads the tags the trunk contains from `origin`'s branch where there is no local one.
- `milestone/mod.rs`: the `NoMilestone` hint is a constant and reads whole; `trunk_here` names the trunk as the clone holds it.
- `milestone/tests.rs` and `tests/cli_milestone.rs`: tests for each of the above, among them an orphan branch, a binary-only branch, two binary edits, a refused tag, a taken tag number, an `origin`-only clone, `diff.noprefix`, source-only stand-ins and the whole hint.
- `cmd/milestone.rs`: "1 file" where there is one, and the reason shown beside an unreadable branch.
- `cmd/util.rs` takes `resolve_repo` and `branches_for` from `cmd/release/mod.rs`, and `release` and `hook` read them from there, so the milestone command no longer reaches into the release command.
- `docs/` is regenerated: `CORE_MILESTONE.md` is new and `DESIGN.md` names the command. `.gitattributes` gains the record's append line.

The three older open topics need nothing from this round, as the doc changelist says; each stays open and none is consumed here.
