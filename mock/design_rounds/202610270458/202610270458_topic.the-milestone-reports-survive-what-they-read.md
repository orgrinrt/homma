# The milestone reports survive what they read

The coordinator's review of `work/homma-milestone` at `89aedd4` found three blockers and nine defects, and reproduced the blockers. The design the first round wrote says the reports never exit non-zero for what they found; the code does for a branch it cannot read. This round puts the design and the code back in agreement and takes the review's calls.

The calls, each with the options it chose among:

- A branch git cannot compare (no merge base, a conflict git cannot name, any other failure of the one branch) is a call of its own with the reason, and the report carries on. Options: abort the report (the first round's behaviour, refused by its own design), skip the branch silently (hides it), or call it. Called, as `unrelated` for no merge base and `unreadable` with git's words otherwise.
- `empty` is decided by the tree: the branch is empty when merging it into the trunk gives the trunk's own tree. Options: changed line count zero (calls a binary-only change empty), or the tree. The tree.
- Stand-ins. Options: restrict to source files, anchor the markers to comment and attribute syntax, drop bare `relaxed` and `stand-in`. Two of the three together: only source files are read, `FIXME`, `TODO`, `todo!(`, `unimplemented!(` and `#[ignore` count anywhere on an added line, and `stand-in` and `relaxed` count only inside a comment and never as `Ordering::Relaxed`. Research notes, documents and data stop being stand-ins, which the quality pass wants, and a comment that says an assertion was relaxed still is one.
- A mark with `--tag` makes the tag before it writes the record, and takes the next `milestone/<n>` that is free, so a refused tag leaves no mark and a rerun is not "already marked".
- `.homma/milestones.toml` only grows, so it is named in `append_only` and the append merge driver keeps both sides' marks.
- `base` and `branches` read the trunk from `origin` when there is no local branch, as `branches` already did.

The shared helpers `resolve_repo` and `branches_for` move out of the release command to where both commands read them. The three older open topics need nothing from this round.
