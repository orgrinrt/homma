# old-entrypoints-hand-on-and-the-parses-in-order

A review of round 202611270101 found two things to fix, and the merge of dev, which now carries the probe
for manifest entries an engine does not know (round 202611270005), brings a third.

## An old entrypoint runs nothing between the engine landing and the clone's reinstall

The round says of `homma hook run`, the verb an older homma's entrypoints call: "At events other than
`pre-push` it runs nothing and passes. The workspace's prose check is skipped in that window, with that line
said." An engine can change under a running session, so that window opens mid-session in any clone an older
homma installed, and a commit there passes every check but the release gate. That breaks "nothing moves for
a running workspace". A verb that passes having run nothing is the wrong way round for a guard.

Decision:

- `homma hook run <event> [<arg>...]` installs first: it does what `homma hook install` does for the clone
  it runs in, the repository git ran the hook in, which registers the gate and the workspace's manifest with
  git-shook and clears the older homma's entrypoints.
- It then hands the event to the dispatcher git-shook generated for it, `<common git dir>/shook/hooks/<event>`,
  with git's arguments and its stdin, and exits as that does. So the window closes at the first event: the
  release gate at `pre-push` and the workspace's checks at every other event run as git-shook registered
  them. An event git-shook has no dispatcher for registers nothing, and the verb passes there.
- Where the install refuses, since git-shook does not hold the hooks path, or git-shook is not installed, or
  a manifest is refused, the verb fails with the install's own words and the line that the hook did not run.
  It fails closed: a commit or a push in such a clone stops until git-shook holds the path.
- The line that the hook was written by an older homma stays, said once on stderr.

## A test names a tool of the workspace's

Two tests plant `run = "vibecheck check {paths}"` as a row of a retired `[hooks]` table. Nothing in homma names
a workspace or its tools: they plant an invented program, as dev's tests did.

## The two parses in order

The probe for entries an engine does not know (round 202611270005) and the retired tables (round 202611270101)
both wrap `Config::parse`. Decision: the retired tables come out first, then the probe runs on what is left.

- A strict parse that passes is the manifest.
- Otherwise a retired table present is taken out, its lines blanked in the text, so what follows still names
  the lines as written, and named in `retired`.
- The probe then reads the text that is left, as it reads any manifest: a manifest that carried only a retired
  table parses; one that carries an unread entry as well names both.
- So `[hooks]` keeps its own words and is never read as an unread entry, nor as a misspelling of one.
