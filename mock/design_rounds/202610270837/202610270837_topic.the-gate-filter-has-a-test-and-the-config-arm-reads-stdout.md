# the-gate-filter-has-a-test-and-the-config-arm-reads-stdout


Sent back by the seventh fresh read of the branch. The test of the gate's command filter, that a call which is not a `git commit` or `git push` is allowed, used a repository with a mock directory and no toml. Before this branch that shape was drift and would be refused, so the test held the filter. Adoption is the toml now and that shape is allowed whatever the command, so the test cannot fail. It gets a toml with a mock directory, which is drift, and the control that the same repository is refused on `git commit`.

The config arm of the gate still folds stderr into the findings it reports, the class already closed for the status read: a launcher line on stderr is listed as a problem. Findings are read from stdout and stderr is used only when the check could not run. The facts of the status read are split on a tab, which bash treats as whitespace, so an empty `mock_dir` shifts the fields and the gate refuses a repository homma answered about correctly. They are split on a separator that is not whitespace.

The launcher key list the status document must carry in its test lacks `launcher_pin`. A toml that does not parse is reported as carrying no pin, a call the code made and the design does not: it goes to the open question for the lead designer, and a gate test pins what happens today.
