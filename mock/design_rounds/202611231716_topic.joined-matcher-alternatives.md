# joined-matcher-alternatives

The regen of round 202611231639, run against the workspace's own manifest, wrote the `PreToolUse` dispatcher's
matcher as `Bash|Bash|mcp__.*|Agent|Bash|AskUserQuestion|Edit|Write|Bash|Artifact|ArtifactData`: each entry's
matcher joined whole, so a name several entries take is repeated, and a list of exact names spelled with `,`
(`Edit, Write`) would sit in a regular expression as the literal text `Edit, Write`, which takes neither tool.

## What the design says

`DESIGN.md.tmpl`, The agent hooks: "The handler's matcher is every entry's matcher joined with `|`, or every tool
where one entry takes every tool. It is wider than any one entry, which is harmless".

## Decision

Joined by alternative rather than by matcher: a list of exact names is split on `|` and `,`, a regular expression
on a `|` outside any group, class or escape, and each alternative is written once, in the order first met. That is
still every entry's matcher joined with `|`, so the design's words stand and no document changes.

## The first review of the dispatcher, the same day

A review pass over `work/hooks-lane-39` (round 202611231639 and this one) found that the fold read every event as
`PreToolUse` reads it, against a host contract recorded too thinly. Its blockers, each reproduced against the
written script: an answer that is not of the host's shape made the fold fail and drop a sibling's deny; exit 2 was
a block at every event, where `PermissionRequest` ignores it, `Stop` puts `continue` false above it and
`SessionStart` only shows its stderr; arguments were `eval`ed, so `|| true`, a redirection or an unset variable
under `set -u` broke the run and the guards after it; the first `decision` object won at `PermissionRequest`; and
the old wrappers were removed before the settings that named them were rewritten, so a settings file that did not
parse left registrations pointing at nothing. Should-fix: matchers were read against the tool name at every
event; no timer where `timeout` is missing; a large answer passed as one argument; a failure's stderr unseen when
another hook answered; plain text dropped at events that read it as context; the 60-second default replacing the
host's per-event ones; `if` and `asyncRewake` dropped; an empty regex branch dropped from the join. The host page
was read again for the per-event table (`research/202611231640_agent-hook-host-contract.md`, the section "By
event").

## Decision

- Fold only the two tool events, `PreToolUse` and `PostToolUse`, where the hooks are many and every answer is JSON
  the host folds one way: exit 2 is a deny before the call and a block after it, with its stderr the reason.
  Every other event gets one registration per entry, under its own matcher, timeout and `async`, and the
  dispatcher runs that entry alone and hands its answer on as it gave it, so the host reads it as its own.
- A lone answer at a tool event is handed on untouched. Several are each read as JSON first; a failure, a stop or a
  malformed answer becomes a `systemMessage` naming it; plain text goes to stderr. Where the fold cannot run, a
  refusal still stands as exit 2. Large answers go to `jq` as files.
- The dispatcher keeps each hook's time itself, `TERM` then `KILL`, so no `timeout` program is needed and a hook's
  own exit 124 is not read as one.
- A registration with a handler field the dispatcher does not carry, or a line of shell after its hook, is reported
  and not carried; arguments are read as the host's shell read them, an unset variable as nothing.
- The old wrappers go only after the settings are written.
- The join keeps an empty regex branch; the test reads the joined matcher the way the host does against every tool
  either entry takes.
- `[agent] timeout` stays one default, said in the design to stand in for the host's per-event ones.
- The root design is rewritten for all of it; it is a root document, so it changes in this round's source window.
  The paragraph that told the wrappers' history becomes one about the shape the regen sweeps, and the one naming
  the workspace's filter speaks of a filter in general.
