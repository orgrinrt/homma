# the-ask-cache-expires-by-last-read-and-is-capped

`homma ask` keeps a partial per chunk and an answer per question under the git directory, and
nothing ever leaves it: the cache only grows.

## Expiry

Decision: an entry expires a fixed time after it was last read. A read of a partial or an answer
that hits stamps the entry as read now; a written entry is read at the moment it is written. The
time is a setting with a default.

## The cap

Decision: the cache is capped by size. Past the cap, the least recently read entries go first,
partials and answers alike, until the cache is under it. The size is a setting with a default.

## When it runs

Decision: the sweep runs on every ask, before the question is answered, and prints nothing; an
entry it cannot read or remove is left and the ask goes on.

## Configuration

Decision: a table of its own, `[ask]`, with `cache_expire_hours`, 336 (two weeks), and
`cache_max_bytes`, 64 MiB, unknown keys refused. The ask is not the summarising pass, whose
`[summary]` table says what makes a call.

## Tests

With failing controls: an entry last read past the time is gone after a sweep and one read within
it stays; a read stamps an old entry so the sweep keeps it; over the cap the least recently read go
first and the rest stay; the table refuses an unknown key and defaults what is absent.
