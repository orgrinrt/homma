# The guard belongs on the write, not on a path somebody remembered to pass

Eighth review of this branch, eighth refusal, and the reviewer's diagnosis is the
first one that names the shape rather than a route:

> Each round guards *a path a caller passes in*; the writes are computed
> downstream from that path and are never themselves guarded. Rounds 1-7
> relocated which path gets checked; round 8 will too unless the guard is
> attached to the write.

## The reproduction

`Layout` builds every path it hands out as `root.join(paths.hands)` and never
asks the filesystem anything. `join` is lexical by design, so a symlink inside
the root defeats it: a root whose tree carries `.shared -> ../victim` takes
`homma org up` to exit 0 having created `victim/hands/<handle>`.

This is not exotic. homma itself commits a symlink for exactly this reason (the
memory link), so a content-repo clone is expected to carry them, and the write
lands under deny items one and two.

## Why seven rounds missed it

Every round was handed a reproduction, closed that route, and reported the class
closed. The path that gets checked moved seven times: the cwd default, then a
relative `--config`, then `AbsPath` without containment, then the guard moved off
the root, then `root.join` with unvalidated config. Each fix was correct about
its instance and each left the next one open, because the thing being guarded
was never the thing being written.

## What the design should be

The workspace's own rule points at it. `harness-the-type-system.md`: climb to a
type rather than restate a discipline, and make the illegal state
unrepresentable.

So a path earns the right to be written to by being proven, against the
filesystem, to resolve inside the root. `Layout` hands out only proven paths and
`prepare` accepts only proven paths, which means a write that skipped the check
does not compile rather than not being noticed.

The proof is against the filesystem rather than lexical, because lexical is
precisely what the symlink defeats.

## The second half, which is a different defect

`stand` runs `git.init(root)` before anything establishes that the workspace is
not inside another repository, so with a plain root and a workspace nested in a
different repo, `provision` refuses afterwards and a `.git` is left behind. The
lexical check added last round only covers workspace-inside-root.

## Three claims in the tree that are false and go with it

The doc comment on `stand` saying every path the command writes to passes through
one guard. It does not, and this is the second round it has survived.

The comment on the join-clamp test claiming loosening `join` fails nothing else
in the suite. Measured: two tests fail, not one.

The `is_absolute()` early return in `RelPath::new`, which is unreachable, because
the components loop already refuses a root component. Dead defence reading as
live defence is what this branch has spent eight rounds on.
