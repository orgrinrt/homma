# Src changelist: the shared config gate, and one status command

## crates/homma-org/src/configs.rs

Applicability stops being a match on file names in Rust and becomes the
directory a template sits in. The comparison gains a read-only form, because the
gate runs on a path that must not write.

- CHANGE: `Severity`, `Required` and `Suggested`, with `Required` the default a
  bare ecosystem name means.
- CHANGE: `Ecosystem`, a closed set of `Any`, `Rust`, `RustNightly`, `Deno` and
  `Node`, each with `wants(dir)` reading its giveaway off disk. `Rust` and
  `RustNightly` keep exactly the predicates that are there now, moved rather
  than rewritten.
- CHANGE: `Ecosystem::base`, answering that `RustNightly` refines `Rust` and the
  rest refine nothing. This is what keeps `NoVariantFits` expressible: a repo in
  the base set but not the refined one, missing the file, is told the shared copy
  does not fit rather than being passed over in silence.
- CHANGE: `Tag`, one ecosystem and one severity, parsed from a directory name by
  stripping a known severity suffix and requiring the remainder to be a known
  ecosystem. That ordering is what makes `rust_nightly_required` parse, since the
  ecosystem name itself contains the separator.
- CHANGE: `Template` carries `tags: Vec<Tag>` in place of `applies: Applies`, and
  an empty vector is a template nobody has said where to put.
- CHANGE: `templates` walks one level of subdirectories, reads the tags off each
  directory name, and keeps loose files at the top level as untagged.
- CHANGE: `TemplateError::Conflict`, refusing at load when one file name appears
  under two tag directories, or when one directory names an ecosystem twice.
  Neither is resolvable and guessing which was meant is how a config ends up
  somewhere nobody chose.
- CHANGE: `satisfying_paths`, the repo root then `mock/`, extracted rather than
  invented: both existing predicates already look in exactly those two places, so
  this is the rule they were both spelling out separately. Placement uses the
  first.
- CHANGE: `Finding::Missing(String, Severity)`, and `Finding::blocks`, true only
  for a missing `Required`. `Differs` does not block, `CannotInfer` does not
  block because it is a fault in the templates directory rather than in the repo,
  and `NoVariantFits` does not block because the variant that would fit has not
  been written and refusing every commit until somebody writes it punishes the
  wrong party. All three still report.
- CHANGE: `inspect`, read-only, returning findings and touching nothing.
- CHANGE: `ensure` becomes `inspect` followed by placing what came back
  `Missing`, so the two cannot disagree about what is missing.
- CHANGE: the module comment says why there is no way to write a refusal down,
  which is that a derived refusal is recomputed and a written one is remembered.

Tests, all of them beside the code as they are now:

- CHANGE: keep every existing test. They pin behaviour that does not change, and
  the ones on the nightly predicate and on difference being left alone are the
  reason those two survive the rewrite intact.
- CHANGE: `a_tag_directory_decides_who_wants_the_template`, over each ecosystem.
- CHANGE: `a_severity_suffix_is_optional_and_required_is_the_default`.
- CHANGE: `an_ecosystem_name_containing_the_separator_still_parses`, which is
  `rust_nightly_required`, with `rust_nightly` and `rust_required` as its
  controls so a pass cannot be a parser that ignores the suffix.
- CHANGE: `a_directory_naming_an_unknown_ecosystem_is_reported_not_guessed`.
- CHANGE: `one_file_under_two_tag_directories_is_refused_at_load`, and
  `one_directory_naming_an_ecosystem_twice_is_refused_at_load`.
- CHANGE: `a_config_under_mock_satisfies_the_template`, with the control that a
  repo with neither copy is missing it, so the pass is not a check that always
  says satisfied.
- CHANGE: `only_a_missing_required_config_blocks`, asserting `blocks` over every
  `Finding` variant rather than the one the fix happens to produce.
- CHANGE: `inspect_writes_nothing`, listing the repo directory before and after
  and asserting it is unchanged, including for the case that would otherwise be
  placed. Without this, a read-only claim is a comment.
- CHANGE: `ensure_and_inspect_agree_on_what_is_missing`.

## crates/homma-core/src/repo/ops.rs, crates/homma-core/src/repo/gix_impl.rs

- CHANGE: `RepoOps::hooks_path`, returning the repository's configured
  `core.hooksPath` or `None`, read through gix rather than by running git.
- CHANGE: `hooks_path_at(dir)`, opening the repository and answering `None` for
  anything that is not one or has no such setting, which is what a status probe
  over a directory that may not be a repository at all needs.

## crates/homma-engine/src/cli.rs

- CHANGE: `RepoOp::Config { op: ConfigOp }`, with `ConfigOp::Check` and
  `ConfigOp::Init`, each taking an optional `--repo` defaulting to every member,
  which is the shape `agent` already uses.
- CHANGE: `Command::Status` gains `--full`.
- CHANGE: parse tests for both, including that `--full` defaults off.

## crates/homma-engine/src/cmd/repo.rs

- CHANGE: a `config` module holding `check` and `init`. `check` reports and
  returns `Outcome::ReportedFailure` when anything blocks; `init` places what is
  missing and reports what it placed.
- CHANGE: `check` never writes. The command that places is the other one.

## crates/homma-engine/src/cmd/agent.rs

- CHANGE: `Surfaces` gains `git_hooks_path`, read through `hooks_path_at`.
- CHANGE: `roll_up` counts it, so a repo with every other surface present and no
  hooks wiring is partial rather than configured. That state is what a repo whose
  per-repo hooks are not firing at all looks like, and nothing reported it.
- CHANGE: the human rendering prints it beside the others.
- CHANGE: `a_repo_with_every_surface_but_no_hooks_wiring_is_partial`, with the
  control that the same repo with wiring is configured.

## crates/homma-engine/src/cmd/status.rs

- CHANGE: `StatusReport` gains `agent` and `configs`, and `repos` gains the
  working-tree line. Existing fields keep their names and shapes, so what reads
  the document today is unaffected.
- CHANGE: the human rendering shows only what is not in the state it should be
  in, plus a line per healthy repo, and `--full` prints every population whole.
- CHANGE: the machine-readable document is never summarised, whatever `--full`
  says, so a consumer is never handed a population with the healthy members
  quietly dropped.
- CHANGE: `json_is_never_summarised`, asserting the document carries every repo
  with `--full` off, which is the one property a human reading the terminal
  output cannot notice is broken.

## crates/homma-engine/src/cmd/gates.rs

- CHANGE: the generated script, after the bootstrap decision, asks
  `homma repo config check --repo <name>` for the repo the call came from and
  refuses when it exits non-zero, quoting what it printed and naming
  `homma repo config init --repo <name>` as the fix.
- CHANGE: it refuses when `homma` cannot be run at all, matching what the same
  script already does for a missing `jq` and for the reason argued there.
- CHANGE: the bootstrap decision keeps its own refusal, unchanged. A repo can
  fail both and should hear about both.
- CHANGE: tests driving the generated script through bash with a stub `homma` on
  `PATH`, one for a clean repo, one for a blocked one asserting the fix command
  is named, and one for a `homma` that cannot run asserting it refuses rather
  than allowing.

## crates/homma-engine/src/cmd/mod.rs

- CHANGE: dispatch for the new subcommands, threading `Outcome` so a blocking
  check exits non-zero.

## README.md

- CHANGE: the command surface gains `homma repo config check` and
  `homma repo config init`, and the status entry says it covers the other
  populations. Whatever else the read turns up is fixed in place.
