# Git hooks put back at every session start

## The ask

The git hooks reinstall themselves at every session start, and are checked through git-shook: every entry present and current. A bypass should then take deliberate trickery. A clone with a removed or edited hook has it back after a session start.

The ticket has three halves:
- homma's: a verb that puts every member's registration back and is silent where nothing is wrong;
- git-shook's: a check of one manifest's registration, entry by entry, which git-shook 90c9cea adds as `git shook doctor --only <name>`;
- mockspace's: refusing a commit or a push while the hooks are not in place. That half is mockspace's and is left to it.

## What the verb does

`homma hook install` with no repository named sweeps every member in scope. For each member it asks git-shook whether homma's two manifests are registered as they are declared now: `git shook doctor --only homma`, with `--only <name>` for the workspace's manifest where there is one. It also checks that the manifests in place are byte for byte what the install writes, and that nothing an older homma wrote is left.

- Where all of that holds, the member is current, and nothing is written or printed for it.
- Anywhere else, the install runs as it does for one repository, and says one line of what it did.
- Where git-shook does not hold the hooks path, the refusal is said, and the sweep goes on to the next member.
- The sweep exits non-zero where any member was refused, and is silent where every member was current.

So a removed entry, an entry edited by hand, a dispatcher an older git-shook wrote, a base removed or another than the one beside the front, and a manifest edited or removed are each put back by the next sweep. git-shook's doctor names each of them, and the install that follows writes it again.

`homma hook install <repo>` stays as it is: it always installs and always reports, since the operator asked for that repository.

## Who runs it

A session start runs `homma hook install`, silent unless something was put back or refused, which is what the session should hear about. Today the workspace's own session-start hook is where that call goes. The agent hooks move onto claude-shook in a later job, and then the SessionStart chain homma registers carries it as an entry of homma's own, the way the release gate is.

## The order of landings

1. git-shook at 90c9cea or later reaches every seat. An older git-shook refuses `--only` on doctor, so every member reads as not current, and the sweep reinstalls each one at every start: noisy, never wrong.
2. This engine lands.
3. The workspace's session start calls the sweep.
