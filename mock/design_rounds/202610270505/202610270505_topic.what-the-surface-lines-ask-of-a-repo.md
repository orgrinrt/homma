# what-the-surface-lines-ask-of-a-repo


Settled by the rules the workspace already has, and recorded here so the
change to `homma status` has a reason beside it.

What the status prints. At every session start `homma status` lists, under
agent surfaces, every member repo as missing `cargo-mock-alias` and
`mock/agent/`, the repos built without mockspace as missing `mock/`,
`mock/agent/`, `.claude/` and `.github/instructions/`, and under shared
configs a line for every config that differs from the shared copy. The code is
`cmd/status.rs` (`missing_surfaces`, `render_agent`) and `cmd/agent.rs`
(`probe`, `roll_up`). The design under `crates/homma-engine/` is silent on
which surfaces a repo owes, so the workspace rules stand in for it.

Each line against the rules.

`cargo-mock-alias` asks for a `.cargo/config.toml` alias. The `workspace` rule,
under "Mockspace self-initialises", says the launcher is the sole entry,
installed once per machine and invoked as `cargo mock`, and that "the `.cargo`
alias" is gone. The commit gate in `cmd/gates.rs` already reads a launcher pin
in place of the alias ("The launcher+pin model has no `[alias] mock`"). The
line asks for something the workspace retired, so the check is wrong and the
surface is removed. A repo with every rendered surface and no alias is
finished.

`mock/agent/` asks for repo-owned agent templates. The
`mockspace-builtin-rules-reach-every-repo` rule says mockspace embeds its agent
rules in its own binary and writes them into every consumer on every run, so
the directory holds only what a repo adds on top. homma and muisti have none
and render fully. The check is wrong and the surface is removed.

`mock/` is a literal. The `mockspace-workflow` rule says `<mock>` is what the
repo's `mockspace.toml` declares as `mock_dir`, and that `mock` is only the
default; sodapop declares `linux`. ikiuni keeps its `mockspace.toml` under
`mock/` rather than at the root, where the commit gate already looks. The probe
reads the declared directory from either place.

The repos with no mockspace. The `workspace` rule says notko and git-shook have
none, deliberately, and that which repos have it is `ls */mockspace.toml`. The
`mockspace-is-v1-and-v2` rule says a v1 tree with no `mockspace.toml` is
expected. A repo with neither a `mockspace.toml` nor its mock directory is not
partly configured; it has not adopted, and nothing is asked of it. The summary
stays silent on it and `--full` names it as having no mockspace. A repo with a
`mockspace.toml` and nothing rendered stays partial, so the silence cannot hide
an adopted repo.

`.claude/`, `.github/instructions/` and git hooks. These are rendered and wired
by `cargo mock`, and are gitignored, so a fresh clone lacks them until it runs.
That is a real state and stays reported. The line gains the command that ends
it, `homma agent regen`, since a line repeated every session with no next step
is read past (`mechanical-work-is-scripted-and-quiet`).

Differs from the shared copy. The shared configs README stores bytes so that
the comparison is a comparison rather than a parse, and says a repo cannot
declare itself exempt: a difference is drift, or a reason for a variant beside
the shared copy. The check stays byte for byte. The line gains the two ways out.
The differences standing today are in the report, and are not fixable from the
repos that carry them: homma and muisti `deny.toml` need the webpki root
exceptions, which belong in the shared copy or a variant of it.

Out of this round: `cmd/gates.rs` probes a literal `mock/` as well, and the
same fix applies there. It sits in a file another change is working in, so it
is named for the next round and left.
