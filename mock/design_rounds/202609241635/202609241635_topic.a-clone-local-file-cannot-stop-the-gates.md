# a clone's local file cannot stop the gates

The review of the round that brought `homma.local.toml` in found two things
wrong with how it is read and written.

## Current state

The manifest loader reads the file, and a file that does not parse fails the
load. Every homma command loads the manifest, the commit and push hooks
included, so one typo in a file nobody commits stops every gate in the
workspace until somebody finds it. The design gave the reason as a setting
silently ignored being worse than a command that refuses, and that reason is
right about the setting and wrong about the blast radius: the gates never read
the instance and have no business refusing over it.

`homma local set` writes the file with a plain write, which truncates and then
fills it. A reader landing between the two sees an empty file, and two writers
at once lose one of the updates. The publish hook is exactly a writer that runs
unattended, beside whatever else is reading the file.

## Changes proposed

The manifest loader stops reading the local file. The two commands that use it,
`status` and `local`, read it themselves. `status` reports a file it cannot
parse as a line of its own, naming the file and the parse error, and in the
document as an `instance_error` string beside a `null` instance, so the setting
is still never silently ignored and nothing else refuses over it.

`set` takes a lock beside the file for the read, edit and write, creating it
exclusively and retrying for a bounded time before refusing, and writes the
result to a temporary file in the same directory and renames it over the
original, so a reader sees the old file or the new one and never a half.
