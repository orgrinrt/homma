# Topic: the readme, ahead of the first release

**Date:** 2026-08-25
**Scope:** `README.md`, and a test that keeps its examples honest.

The launcher publishes now, so the readme's install line was still telling
people to reach for a git url and a branch. That is the thing that has to
change before anybody lands here from crates.io.

Reading it again with that in mind, three more things were wrong rather than
merely stale.

The badge block carried three of the five the convention asks for, missing
exactly the two that matter to a reader arriving from a registry.

The status section had grown into about thirty lines of implementation
narrative: which paths are proven against the filesystem, how a symlink defeats
a lexical check, what the aggregation pass writes. All of that is true and none
of it is what a status section is for. It belongs beside the code that does it.

The manifest example did not parse. It showed `[workspace] root` and a repo
`name` key, where the real schema has `[workspace] name` and `local_path`.
The command table offered `--json`, which this cli has never taken; the flag
is `--output json`.

That last pair is the reason this round carries a test rather than only prose.
A readme example that no longer parses is the first thing a new reader meets,
and nothing in the suite reached one until now.
