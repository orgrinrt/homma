## What that settles

The intent is op's and is the canon this round derives from, since `mock/canon/` does not exist yet and nothing in the design tier speaks to it. What is settled:

A release is the `dev` to `main` merge and nothing else, tagged on the merge commit, with a GitHub release carrying generated notes and a registry publish, and `homma release` is the one door all four go through. Continuous means every push is measured: a pre-push hook homma installs runs the gate on the pushed tip, on the developer's machine, refuses the push on red, writes a run record into the homma store, and posts a `homma/gate` commit status on that sha through the forge api. The trunk rulesets (`scripts/apply-rulesets.sh` in the workspace) require that status on `dev` and `main`, so the forge refuses a merge whose head was never gated here. Nothing runs on the remote. `homma release` refuses a `dev` tip without a green record and does not re-run the gate. The gate is fmt, clippy or `deno lint` and `deno check`, tests across the declared feature sets, `cargo deny` where a `deny.toml` exists, doc coverage, and `ante check`, and its numbers ride in the status description and in the run record. The registry and tag invariants (`a-release-tag-lives-on-main.md`, and the sixty checks the Python runner already encodes) are `homma release check`. Badges render from json homma writes, through shields' endpoint badge, so a badge is a number the gate measured for the commit a reader is looking at. mockspace's lints later post statuses the same way, lint by lint, configurable per trunk; that is named here and is not this round's work.
