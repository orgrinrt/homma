# The sweep refuses what a single run refuses, and a repo is not its own sibling

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-engine/src/cmd/release/{mod,order}.rs`, `homma-api/src/release.rs`
**Source topics:** the sixth review of pull request 46, and `202609030005/202609030005_topic.what-the-fifth-review-found-on-the-release.md`

## The findings

The sibling refusal hands `sibling_dependency` the whole active set, the repo's own name included, so a cargo workspace whose members include a crate named for the repo matches itself and the sweep refuses with an instruction to release the repo before itself. The design says the edge is one repo naming another. The repo's own name comes out of the slice, with a test planting the self-named member.

The sweep's pass-over arm takes every plan error as a reason to pass over, so a manifest off the level, which the previous round made a refusal in a single-repo run, is skipped without a word beyond the pass-over line. A sweep refuses on it the same way a single run does.

`homma-api/src/release.rs` sits at 622 lines with its tests inline from 473. The tests move beside it, as `git.rs`'s did.

## What does not change

The design. Both behaviours are what it already says.
