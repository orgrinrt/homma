# the-what-tests-plant-what-they-read

Carried over from round 202611251034-l741 of another branch, which this one replaces there; the decisions are the same, with the review that followed it below.

The acceptance set of `homma what` and four of its source tests read the tree the repository
happens to be cloned into: the tools, scripts, skills and rules around it. They pass or fail by the
machine, take up to a minute each where that tree is large, fail where a tool around it was renamed
or removed, and name things that are no part of this repository. A repository's tests answer for
the repository alone.

## The acceptance set

Decision: the set runs over a small workspace each test binary plants once, with neutral names:
two tools with verbs, scripts with banner headers and verbs, a sourced library, a test and a
fixture script, one skill and one rule. What each test protects decides its fate:

- a mechanism of the matcher (a script found by its summary, the verb that matched being the
  command, a misspelling found by its edit, a sourced library never offered, the footer naming what
  a kind filter left out, filler changing nothing, a query about nothing returning nothing, a query
  of only filler saying why, each answer saying where each word was found, the JSON's keys, a tool
  with verbs and no default never printed bare, the best answers naming what sits beside them) is
  kept, rewritten over the planted workspace;
- a claim about one workspace's catalogue (that its particular tool or script comes first for its
  particular query, the ignored cases of what should, the pairs the related cut is calibrated on,
  the mockspace listing of the repositories around it) is deleted: it is the workspace's to keep in
  its own tests, and the relatedness figure stays a number the design states.
- a duplicate of a test that already plants its own input (reading an earlier message off a tool's
  readme) is deleted.

## The source tests

Decision: the four that read the tree around (the verbs of one script, tests and fixtures not
being scripts, the skills and rules being read, a tool's verbs and how to run it) read the planted
workspace instead.

## Tests

With failing controls named in each kept test where its assertion is not already its own control.

## A review of the first carrying

The planted workspace first copied one real workspace's script names, headers and tools.
Decision: every name, header and summary in it is invented and generic, the acceptance test of a
tool with verbs and no default checks the hits as well as the listing, and the design names no real
tool, its example of a bare command with its verbs included.
