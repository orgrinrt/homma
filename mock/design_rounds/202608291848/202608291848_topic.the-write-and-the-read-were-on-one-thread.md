# Topic: the write and the read were on one thread

## What was found

A senior review of the `[[status.inject]]` work, over the pull request that
carries it. Its finding, in its own terms:

> `pipe_through` deadlocks on output larger than a pipe buffer.
> `stdin.write_all(input)` blocks on the calling thread while the child's stdout
> and stderr are pipes nobody drains until `wait_with_output()` runs after the
> write returns. Once the child's stdout buffer fills it stops reading stdin,
> and both sides wait.

It reproduced it against the identical function body with `format = "cat"`:

```
1 KiB  -> returned 1025 bytes
1 MiB  -> SIGKILL after 15s
```

## Why the existing tests could not see it

There are forty of them and none feeds more than a few hundred bytes.

The one that comes closest is `a_format_that_reads_none_of_its_input_neither_hangs_nor_fails`,
which pipes `seq 1 200000` through `head -1` deliberately so the write is bigger
than a pipe buffer. That case cannot reach this one: `head` closes the pipe
rather than filling it, so the write ends in `EPIPE` and returns instead of
blocking. **The comment beside it reasons carefully about exactly that, and the
both-buffers-full case is a different shape it does not mention.**

## What it costs

`homma status` hangs, with no timeout and no diagnostic, on the command the
module documentation calls the cheapest sanity check in the workspace. The three
tools this feature exists to attach are the context fill, the rule corpus and
the agenda, and the agenda alone is well past a pipe buffer.

## The shape of the fix

The write moves onto a thread of its own, detached rather than joined, so
`wait_with_output` drains stdout and stderr while it runs. Detached matters:
`stdin` drops when the closure ends, which is what closes the pipe, and joining
would put the wait back on the calling thread and reinstate the deadlock.

## What is not in scope here

The reviewer also found that an injected child has no timeout, so a tool that
reaches the network hangs the same command for a different reason. That is real
and is a separate round: it needs a policy about how long is too long, and this
one needs no policy at all.
