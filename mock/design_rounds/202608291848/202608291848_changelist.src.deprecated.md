# Src changelist: the write and the read were on one thread

## crates/homma-core/src/inject.rs

`pipe_through` writes the input from the calling thread and reads the child's
output afterwards, so both pipes can fill and neither side can move.

- CHANGE: `pipe_through` writes stdin from a `std::thread::spawn`, detached, so
  `wait_with_output` drains stdout and stderr concurrently with the write.
- CHANGE: say in the comment why it is detached rather than joined, since a join
  puts the wait back on this thread and restores the deadlock, and the closure
  ending is what drops `stdin` and closes the pipe.
- CHANGE: keep the existing `let _ =` on the write and the `EPIPE` reasoning
  beside it. That case is unchanged and is still the ordinary one.

## crates/homma-core/src/inject_tests.rs

The forty tests here never feed more than a few hundred bytes, which is why the
suite was green over a function that hangs on a megabyte.

- CHANGE: `a_format_that_reads_all_of_a_large_input_does_not_deadlock`, piping
  `seq 1 200000` through `cat`, asserting more than a megabyte comes back and
  that it starts and ends where the input did.
- CHANGE: `a_large_input_survives_a_format_that_transforms_it` as its control,
  piping the same input through `wc -l` and asserting `200000`, so a pass cannot
  be a pipeline that emitted something long without reading its input.
- CHANGE: say in the comment why `head -1` above cannot reach this case: it
  closes the pipe rather than filling it, so the write ends in `EPIPE` and
  returns.
