# A needless borrow, and a check that was read wrongly

`git_impl.rs` passes `&format!(...)` where the callee takes anything
`AsRef`, so clippy warns that the borrowed expression already implements the
required traits. The pre-commit autofix produced the correction and it arrived
after the round had closed, so the phase gate refused it and it was reverted.

**Reverting was the wrong call and the reasoning behind it was wrong twice.**
Clippy was run to decide, the output was scanned for the file, the two warnings
visible at the top were in `forgejo.rs`, and that was read as "my file is
clean". A second grep, run because the first check's own count contradicted its
label, found the warning at `git_impl.rs:136`.

So the lesson is smaller than the defect and worth writing down anyway: a check
whose output is scanned by eye is a check that reports whatever the eye reached.
The count was there in the first run and disagreed with the conclusion drawn
beside it.
