# tests-never-inherit-the-machines-git-template-dir

`hook_install_writes_one_entrypoint_per_event_and_says_how_git_reaches_them` in `homma-engine`'s `cli_release` fails on `dev` at `tests/cli_release.rs:168`, asserting "no entries, no entrypoint": a `commit-msg` file exists in the hooks directory of a repository whose table names no `commit-msg` entry.

Which side is wrong. Neither the code nor the test's intent. `homma_core::hooks::install` writes one entrypoint per key of `Hooks::events()`, the gate's `pre-push` and what the manifest declared, and the unit test in `crates/homma-core/src/hooks/install.rs` asserts `commit-msg` absent. The file is not homma's. The machine's git config sets `init.templateDir`, here to a directory holding a `commit-msg` hook (the byline guard the bootstrap installs), and `git init` copies every template into a new repository, so the test repository starts with somebody else's hook. Measured: a bare `git init` in an empty directory on this container lists `commit-msg` under `.git/hooks` before homma runs anything. The design is silent on the git environment the tests run in, as it was for the identity variables in round 202610231252. The test's intent, that an event with no entries gets no entrypoint, is the claim kept, and it is checkable only on a repository that begins with no hooks.

The class is wider than the one test. Review of the first fix, which passed `--template=` at two `git init` sites, ran the suite with a synthetic template directory whose `commit-msg` and `pre-commit` hooks `exit 1`: 1065 passed and 59 failed, against 1124 and 0 with no template directory. The failures sit in `release::{git,check,plan,run,gate,badges}`, `hooks::run`, `cmd::migrate`, `cmd::release::gating`, `containment_smoke`, `local_smoke`, `org_smoke`, `provision` and the `standing_up_*` tests, and one live exposure under the real guard is `crates/homma-core/tests/membership_is_detected.rs`, which carries its own copy of `clone_at` with a bare `git init -q`. A per-site flag leaves every site written later exposed again.

The answer: the test environment is pinned in one place. `GIT_TEMPLATE_DIR` set to an empty value outranks `init.templateDir` (measured against the real config here: `git init` then creates no hooks directory), and cargo's `[env]` table in a `.cargo/config.toml` at the repository root reaches every test process and every `git` they spawn, whether `cargo mock test` runs from the root or a member runs from its own directory. The two per-site `--template=` flags go, since the pin covers them. A test commits the class: it builds a template directory whose hooks fail, points a global config at it, and has a repository made and committed in the way every test does, inheriting the process environment; it fails without the pin and passes with it.

The pin reaches only what cargo starts. An installed `homma` is unaffected, which is the point: the production verb keeps using the user's template directory.
