# hook-install-takes-no-flag-and-regen-refuses-a-broken-layer

A review of the round `202610271153` found four things in what it shipped, and the decision is to put them right in a round of their own rather than amend the closed one.

## What the review found

1. `homma hook install --shook` is in no design document. It forces git-shook whatever `core.hooksPath` is, which takes the key from mockspace, and the design says "mockspace owns `core.hooksPath` ... and homma never contends for it" (`mock/DESIGN.md.tmpl`, the per-repository half). The topic of that round said the per-clone path works "without a flag".
2. A layer that cannot be read stops `hook install`, `hook run` and `hook doctor` reports it, but `homma agent regen` renders from the merged table too, and writes back only the rows it has. A broken `homma.local.toml` removes the clone's agent guards with no error. The release deep dive says such a layer is "an error naming the file".
3. The test `via_shook_registers_even_where_no_hooks_path_is_set_and_auto_does_not` never calls `Via::Shook`, so the forced path has no coverage.
4. The command listing in the release deep dive reads `homma hook install <repo>` alone, which the previous round recorded as not done because the template window had closed.

## What this round does

- Removes the flag and `Via`. Where `core.hooksPath` is git-shook's, `hook install` registers with it; where it is anything else, it writes the entrypoints as before. Nothing forces the other.
- Makes `agent regen` refuse, naming the file, while a layer cannot be read, the same way the hook verbs do.
- Renames the test to what it asserts.
- Puts `homma hook doctor [repo]` in the command listing of the deep dive.
