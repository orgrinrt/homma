# Topic: the design documents must name the types

**Date:** 2026-08-14
**Phase:** TOPIC
**Scope:** three public types the taxonomy round shipped without documenting
**Status:** settled by the gate

The push gate refuses three types: `Registry`, `Store` and `Error`. Each is
public, each is named nowhere in a design document, and the gate reads that as
source that exists without a design saying it should.

It is right. The taxonomy round wrote each crate's document before writing its
code and described the shapes in prose rather than by name, so the documents
describe a store and a registry without ever naming `Store` or `Registry`. That
reads fine to a person and is invisible to anything mechanical, which is exactly
the drift the gate exists to catch.

`SHAME.md.tmpl` would unblock this in one entry. It is the wrong instrument
here: a shame entry records a gap discovered while executing that is not worth
stopping for, and this is a gap in the documents themselves, found before
anything was pushed, which costs one doc round to fix properly.

So: name them, say what each is, and let the gate go green on the reason it was
raised rather than on an exemption.
