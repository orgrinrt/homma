## Current state

The capture paragraph on a line that does not parse whole says a line is read as
the object that ends it and is refused when no object ends it or when the bytes
before the object are a whole value. That lets three whole lines run together and
a whole line, a cut write and a whole line through as the last object, with the
rest dropped. The paragraph on tool results says a result is an ask round only
when it names a call to `AskUserQuestion` that an earlier line holds, so an
answer whose call was in a cut write is skipped without a word.

## Changes proposed

- The recovery sentence says what is recovered rather than what is refused: the
  bytes before the object begin with `{` and the parser reaches the end of them
  with the object it began still open. Everything else is refused by number, and
  the sentence names the cases: no object running to the end, text before the
  object that is not the start of one, and complete lines run together, two or
  three or one beside a cut write, because reading only the last would drop a
  complete record.
- The paragraph on tool results keeps the rule for a result naming another
  tool's call, which is not read whatever keys it has. It gains the result naming
  a call no earlier line holds: read as a round when its `toolUseResult` has a
  round's shape, with a note on stderr naming the line; not read, with a note
  naming the line and saying its words are not in the capture, when it has
  `questions` or `answers` and is not a round; passed without a word when it has
  neither.
- `docs/DESIGN.md` re-renders from the template through `cargo mock`.
