# shook-path-in-an-adopted-repo

The commit readiness gate in `gates.rs` counts three mockspace surfaces: the
mock directory, the launcher pin and the hooks path. Since the git-shook change
it reads a hooks path at git-shook's dispatcher directory as no surface, which
is right for a repository that never adopted mockspace. In applets and homma,
which did adopt it, mockspace's hooks reach git through that same dispatcher,
so the gate reads two surfaces of three and refuses every commit there with a
fix that cannot help. Ticket the_homma_clone_s_commit_readiness_check_says_the_hooks_key.

The fix: git-shook's path counts as the hooks surface where the repository has
the mock directory or the launcher pin, and as no surface where it has neither.
Tests: a repository with the mock directory, the pin and git-shook's path is
allowed; one with the mock directory and git-shook's path but no pin is refused
for the pin only; the existing repository with neither still reads 0.
