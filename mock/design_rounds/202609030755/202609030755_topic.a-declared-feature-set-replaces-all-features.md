# A declared feature set replaces all-features on every step

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-core/DEEPDIVE_release.md.tmpl`, `homma-core/src/release/gate.rs`, its tests
**Source topics:** the gate refusing highroller's readme push

## The findings

The gate runs `cargo clippy --all-features`, `cargo test --all-features` and `cargo doc --all-features` on every crate, and a crate whose features exclude each other refuses that build on purpose, so it is red on every push and nothing in the tree can make it green. highroller is the case: six index-width features of which one may be enabled, and a `no_std` that excludes two others, each refusal a `compile_error!` the crate wrote to say so.

`[package.metadata.homma] feature_sets` exists and shapes only the tests step, beside an all-features run that stays. So a crate declaring its sets has said which builds are legal and the gate builds an illegal one anyway.

## What changes

A crate declaring feature sets is gated on exactly those sets, on every step that builds: lint, tests and docs each run once per set, `--no-default-features --features <set>`, and no `--all-features` run happens for it. A crate declaring none keeps what it has, all features and none. In a workspace, the workspace-wide all-features runs exclude every member that declares sets, so a plain member keeps its two runs and a declaring member gets its own. The docs number reported is the first set's, since the first `Total` row is what the log is read for.

## What does not change

The shape of `feature_sets`, the `-p` runs a member's sets get on tests, and the format, deny and notices steps, which build nothing.
