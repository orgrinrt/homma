# the-ask-reads-its-input-and-runs-no-command

Follows the closed rounds `202611241445-jfkk`, which made `homma ask`, and `202611241541-y562`,
which made the call it rests on fail loudly. A review of the ask found its command run past guards
that do not hold, a chunk that can outgrow a call, a cache key missing the command that made what
it keeps, and an insertion test that checks one case and allows more change than the cut makes.

## The question

What may `homma ask` run, how large may a chunk be, and what does its cache key on?

## What is settled

- **The ask runs no command.** With `--run` the verb ran whatever no deny rule and no hook refused,
  so a session that allowed `homma` to run allowed every command through it. Its guards read the
  deny rules of two places only, never the allow rules, the project the session runs in or the
  managed settings, and matched a rule by prefix and glob, so a denied command in a subshell, after
  `eval` or `env`, in a substitution or under `bash -c` went through. Whether the ask should run a
  command at all is the person's call, asked of them. Until it is answered the ask reads what is
  piped to it on stdin, `<command> | homma ask <question>`, and the command is the caller's, under
  the session's own guards. The guard code goes, the verb's `--run` with it.
- **No chunk outgrows a call.** A line of 8 192 bytes or more was one chunk, however long, and a
  batch of one such chunk went past the request's budget. Such a line is cut into pieces of at most
  8 192 bytes, each on a character boundary, each a chunk of its own on the line's number. The cut
  is the summarising pass's own cut of a long line, one function both use.
- **The cache keys on the command that answers as well as the model.** Two configured commands
  asked for the same model can answer differently, so `[summary] command` is in the key of every
  partial and every answer.
- **The insertion test inserts at the top, in the middle and at the end** of a run with no blank
  line, and pins how many chunks change: the one the line lands in.
- **How long the cache keeps what it holds, and what expires it, is the person's call**, filed as
  the question `how_long_homma_ask_keeps_its_cached_answers_and_what_expires`.
- **A slow accept test of `homma what` is ignored with its ticket**,
  `the_asked_before_accept_test_of_homma_what_runs_over_a_minut`, until it runs in seconds.
