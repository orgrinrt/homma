# Src changelist: compare directories, refuse an unknown home, take the registry

## CHANGE: `mock/crates/homma-api/src/denied.rs`

**`check` compares `(dev, ino)` as well as components.** `starts_with` is a
component comparison and two absolute paths routinely denote one directory. A
new `under_by_identity` walks the candidate's ancestors, stats each that exists,
and compares the pair against the denied location's. The component comparison
stays beside it: a denied location that does not exist has no inode and must
still deny, which one of the existing tests asserts.

Both routes are reproduced as tests. The case-spelling one **first establishes
that the two spellings reach one inode** and skips otherwise, so it degrades to a
skip rather than a false pass on a case-sensitive filesystem. The firmlink one is
machine-dependent and is not written as a path literal; what stands in for it is
a unit test over the comparison itself, given two directories known to share an
inode by construction, which is what a hard link to a directory cannot be and a
bind mount is not portable enough to be, so it is expressed as a `(dev, ino)`
assertion on a symlinked pair that `starts_with` disagrees about.

**`from_env` is fallible.** It returned an empty list when `HOME` was absent or
relative, which disabled both home-derived items silently, and the comment above
it said that was "not a licence" while it was one. Both cases reproduced at exit
0. It now returns `Result<Self, NoHome>`, and `NoHome` says which of the two
happened and what to do.

**`Denied::for_standing_up` takes the registry and the standee**, and returns the
two lists a stand-up needs. The loop that derived deny item two lived in
`stand.rs`, was live, and was pinned by nothing: deleting it left the suite at
361 passing. `Denied::from_env()` alone type-checks wherever the full list is
required, so forgetting item two was an error nowhere. It now cannot be built
without the registry.

The two lists are separate because there are two questions. `under_root` carries
every participant's workspace including the standee's own, because a root inside
a workspace is backwards. `for_the_workspace` omits the standee's own, or the
workspace would deny itself.

**`is_empty` is deleted.** No caller, no test, and the caller it wanted was the
one that refuses an empty list, which is now `from_env` refusing instead.

## CHANGE: `mock/crates/homma/src/cmd/stand.rs`

The derivation loop is gone, replaced by `Denied::for_standing_up`. The root is
checked against `under_root` and the workspace against `for_the_workspace`, which
closes the case where a root inside the standee's own workspace passed, `git.init`
ran, and the run failed in `provision` leaving `$WS/ownroot/.git` behind. That is
the third instance on this branch of a refusal leaving something half-built, and
the first inside the guard added to close the deny list.

**A two-staffed-participant test**, which is what was missing: no test anywhere
built a registry with two, so deny item two had no coverage in the production
path at all.

## CHANGE: `mock/crates/homma-api/src/path.rs`

`if name == "." { continue; }` cannot execute. `pending` receives only
`Component::Normal`, which the parser never yields for `.`, and a link target's
`Component::CurDir` is dropped where the target is expanded. Deleting it leaves
the suite green, and it sat four lines under a paragraph calling dead defence "a
paragraph with an `if` around it".
