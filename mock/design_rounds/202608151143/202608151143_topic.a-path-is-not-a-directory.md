# A path is not a directory, and the deny list was comparing paths

The fifteenth review reproduced, end to end and at exit 0, a workspace with a
repository, both definitions and the memory link inside the operator's own
`.claude`, **with the deny list active and every containment proof satisfied**.
The whole exploit is one character:

```
$ HOME=$T/home homma --config $T/root/homma.toml org up r --root $T/home/.CLAUDE/crewroot
r .../home/.CLAUDE/crewroot/.shared/hands/r
EXIT=0
```

`Denied::check` compares with `Path::starts_with`, which compares components byte
for byte. This filesystem is case-insensitive APFS, so `~/.CLAUDE` and `~/.claude`
are one inode.

**And it needs no unusual spelling to reach.** `/Users/<user>` is a macOS
firmlink to `/System/Volumes/Data/Users/<user>`. A firmlink is not a symlink, so
neither `realpath` nor `AbsPath::resolved` collapses it, and the two spellings
name one directory with identical `(dev, ino)`.

Two independent routes to one directory means **the defect is in the comparison,
not in a missing entry**. The design document states the defect as the fix: "So
the check is by absolute path and never by name" is false, because
`starts_with` *is* by name.

## What a directory actually is

A directory is `(dev, ino)`. Everything else is a way of writing one down, and a
filesystem is free to accept several. Case folding and firmlinks are two; a bind
mount and a hard-linked directory would be others.

So the comparison walks the candidate's ancestors, stats each one that exists,
and compares `(dev, ino)` against the denied location's. The deepest existing
prefix is where the answer lives, because the leaf being checked is usually about
to be created and does not exist yet.

The lexical check stays **beside** it rather than instead of it, because a denied
location that does not exist yet has no inode to compare and must still deny.
Neither subsumes the other: lexical catches what has no identity, identity
catches what has two names.

## The absent home is a licence, and its comment says it is not

`from_env` returns an empty list when `HOME` is absent or relative, which
disables the two home-derived items outright and silently. Both reproduced at
exit 0 with the ordinary lowercase spelling. The comment two lines above says an
absent `HOME` "is not an error and is not a licence"; the effect of the entries
being absent is that the writes they forbid succeed, which is what a licence is.

**The fifteenth paragraph on this branch asserting a guard holds while it does
not**, and the first to do it about the code directly beneath itself.

So `from_env` becomes fallible. There is one caller.

## The derivation, not the list, is what nobody can be trusted to remember

Deleting the entire deny-item-two loop in `stand.rs` left the suite at 361
passing, exit 0: the eighth guard found live and unpinned on this branch, every
one of them after a review had read it.

The shape is what allows it. `Denied::from_env()` alone type-checks in every
position where the full list is required, so forgetting item two is not an error
anywhere. The fix is a constructor that takes the registry and the standee, so
the list for standing somebody up cannot be built without it.

## Two lists, because there are two questions

The standee's own workspace belongs on the list that governs the root and not on
the list that checks the workspace, which would otherwise deny itself.

That distinction is also finding six: skipping the standee made a root inside its
own workspace pass, `git.init` ran, and the run failed in `provision` having left
`$WS/ownroot/.git` behind. This branch has twice fixed "a refusal leaves nothing
half-built", and that was the third instance, inside the guard added to close the
list.

A root inside any workspace is wrong, the standee's own included, and the
workspace is required to be outside the root, so nothing derived under the root
can be under it except through a link. Which is exactly the case worth refusing.

## The dead defence

`path.rs`'s `if name == "." { continue; }` cannot execute: `pending` receives only
`Component::Normal`, which the parser never yields for `.`, and a link target's
`Component::CurDir` is dropped further down. It sits four lines under a paragraph
calling dead defence "a paragraph with an `if` around it".
