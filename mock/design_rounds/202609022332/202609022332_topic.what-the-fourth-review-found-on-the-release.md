**Date:** 2026-09-02
**Phase:** TOPIC
**Scope:** `homma-core/src/release/{check,git,kind,run_tests,publish}.rs`, `homma-engine/src/cmd/release/{mod,order}.rs`, the root `DESIGN.md.tmpl`, `homma-core/README.md.tmpl` and one paragraph of `homma-core/DEEPDIVE_release.md.tmpl`

## The findings

A workspace-wide run skipped every repo whose plan could not be made, saying nothing, and a repo with no root manifest is exactly that. Nine of the workspace's members keep their manifests under `mock/`, three of them stack repos with unreleased work. The run now prints a line naming each repo it passes over and why, and the design says what the tool reads today: the root, and a manifest under a subdirectory is not seen. That gap is a catalogued red test rather than a green one pinning the exclusion as intended.

The rendered design pointed a reader at `homma-core/DEEPDIVE_release.md`, which is nowhere; the rendered file is `docs/CORE_RELEASE.md`, and the root design and the core readme name that.

The sibling refusal read only the root `Cargo.toml`, while the publish beside it already walks the workspace members. It walks them too now, through the same member listing, so an edge declared in a member crate is seen.

`main.unreleased` cleared on any subject containing `hotpatch`, so "this is not a hotpatch" cleared it. The word has to stand as a word and not after a negation.

`git.rs` sat past the file-size line with its tests inline; they move beside it. A dead binding in a run test goes.

## What does not change

The design, except for saying plainly that the tool reads a repo from its root and names the subdirectory shape as unread, and the two path fixes.
