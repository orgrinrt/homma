# doc changelist

This changelist comes from `202611270100_topic.git-hooks-are-declared-in-shook-toml.md`, the round's one topic.

## CHANGE: the git hooks FROM declared under `[hooks]` and run by `homma hook run` TO entries of a git-shook manifest that git-shook runs
File: `mock/crates/homma-core/DEEPDIVE_release.md.tmpl`
Verification: The "Hooks" section says:
- homma declares no git hook in its config and runs no chain of them;
- a git hook is an entry of a `shook.toml` that git-shook runs on `shook`, by name order, stdin replay, `paths` selection and the first refusal;
- homma places two manifests for git-shook to register.

## CHANGE: the release gate FROM the table's built-in first `pre-push` row TO homma's own clone-local git-shook manifest `homma`
File: `mock/crates/homma-core/DEEPDIVE_release.md.tmpl`
Verification: The section shows the manifest `name = "homma"` with `[hooks.pre-push]` and `run = ["homma", "release", "gate", "--hook"]`. It also says that a workspace declaring nothing still pushes gated.

## CHANGE: the workspace's own git hooks FROM rows of `[hooks]` TO the root `shook.toml` that `git_hooks` under `[paths]` names, copied into each member
File: `mock/crates/homma-core/DEEPDIVE_release.md.tmpl`, `mock/DESIGN.md.tmpl`
Verification: The deep dive says homma reads only the file's `name`, taking the root directory's name where there is none. It says the copy goes to `shook/manifests/<name>.toml` beside `homma.toml`, and that `git shook install --yes --only homma --only <name>` registers both. It also covers three edge cases:
- a missing file registers the gate alone, and the install says so;
- a name of `homma` is refused;
- a refusal gives each manifest back as it was.

The root design gains a paragraph on `git_hooks` under `[paths]`, `shook.toml` by default.

## CHANGE: where the install runs FROM entrypoints in git's own hooks directory, or git-shook where it holds the path, TO git-shook only, refusing elsewhere

## CHANGE: the order of landings FROM unstated TO four steps checked by command
File: `mock/crates/homma-core/DEEPDIVE_release.md.tmpl`
Verification: The section lists four steps:
1. git-shook with `shook` and `paths` reaches every clone.
2. The workspace writes its root `shook.toml` and keeps `[hooks]` meanwhile.
3. This engine lands, and `homma hook install` runs per member.
4. `[hooks]` comes out once `homma --output json status | jq -e '.workspace | has("retired")'` holds in every clone and container.

## CHANGE: the overlay layers FROM described with the git hooks TO described with the agent hooks they now serve alone
