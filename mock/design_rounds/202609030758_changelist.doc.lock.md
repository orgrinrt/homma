# Doc changelist: homma owns the rule corpus

## mock/DESIGN.md.tmpl

**Two changes.**

The generation pass primitive already said it is the sole writer of the agent
configuration in every workspace homma manages. It now says the workspace's own
rules and skills are part of that. **This is a widening of an existing primitive
rather than a new one**: the pass turns configuration and templates into
generated files, and a rule card is exactly that. Reading it as new work would
have argued for a fifth primitive, which is the shape
`a-homeless-document-is-a-design-problem` rejects.

A new `## The rule corpus` section states the three artifacts, that the meta
lives once in the full template, why the meta exists at all, and that the skills
bearing on a rule are derived rather than declared. It sits above the command
surface because the surface is a view over it.

`homma rules` joins the command surface listing.

**What it does not say**: the meta's field names. Those are the source
changelist's to settle, and a design that fixes a schema before anything has
been built against it is describing an implementation it has not tried.

## README.md

No change. It describes what homma is for and the commands that exist today;
`rules` does not exist until the source changelist lands, and documenting a
command before it runs is the readme describing a release that has not happened.

**It changes in the round that builds the command**, not this one.

## docs/

No change. Nothing under it describes the agent-configuration surface, so there
is nothing for this to contradict.

## PRINCIPLES.md.tmpl, WORKFLOW.md.tmpl

No change. Neither describes what homma generates; the first is how the code is
written and the second is how a round runs.
