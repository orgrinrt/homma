# tests-plant-through-a-child-and-name-no-real-tree

Extends rounds 202611251422-cqgk and 202611251452-ojtm, which made `cmd::planted::script` the one
way a test plants a script it runs and cleared the names of a real tree from the tests of `what` and
`ask`. Three things remain of the same two classes.

## Every script a test runs is planted through a child

The hook, wrapper and dedup stand-ins of the aggregate tests, the hooks of the chains tests and the
declared-hook tests, and the stub files of the tools dispatch tests are written in the test process
and then marked executable by `aggregate::tests::make_executable`. A fork on another test thread
while one of them is open for writing carries the descriptor into its child, and running the
script then fails as busy.

Decision: each goes through `cmd::planted::script`, which writes and modes the file from a child
`sh`, and `make_executable` is removed, so a test has one way to plant a file it or the code under
test will run. The dispatch tests only plan a run and never start one; they take the same helper so
there is no second way to plant a script, not because they race. A file a test deliberately leaves
not executable is planted with its mode in the same call.

## The cache keeps asking for its directory without the caller's git variables

The unit test of `git_dir_query` shows the query removes `GIT_DIR` and `GIT_WORK_TREE`, and
nothing shows that `Cache::of_workspace` still asks through it. Decision: a test runs
`of_workspace` over a planted repository in a child of the test binary with `GIT_DIR` exported at a
second repository, and the cache is under the planted one. The test binary re-runs the one test as
its own child, the variable set only in that child, so no other test thread sees it.

Failing control: with `of_workspace` asking a plain `git rev-parse` the cache lands under the
second repository.

## Tests and fixtures name no real tree

The tests of every crate, their golden files and the samples in the design still name the
repositories, the handles, the offices and the tools of the tree homma is developed in. homma may be
published and names no tree but the one a test plants.

Decision: one round over the whole repository, since the names cross crates and a golden file
changes with its test. Each name is replaced by an invented one of the same length, chosen so that
the order of any sorted output is the order it was, so a golden file and an aligned column change
only in their words. A test keeps what it checks. Where a real crate homma depends on is named as
that dependency, in code or in a manifest, it stays; where it is used only as a sample repository
name, it is replaced. The session roles `coordinator` and `helper` are homma's own vocabulary of a
session's role and stay. A default path in live code that names a person is left for a round that
also moves the configuration relying on it, since changing a default here alone would move where a
workspace's files are read without a word.

The grep of the class, its counts before and after, and any name left with its reason are stated
in the round's changelist.

## Process traces in round topics

The topics of earlier rounds open by saying which review found what, and in what order. A topic
records a decision and why; who asked and how often is not part of it. A closed round is frozen:
its directory is history, as a pushed commit subject is, and neither is rewritten in a round.
Decision: this round and those after it state a finding as the finding, and the earlier topics are
reworded with the history when the repository is rehoused for its first public release.
