# The offline check still thought a variable was the only source

`verify` has two token checks and only one of them learned that a credential can
come from a command.

The offline one in `check` warns `forge_token_unset` whenever a profile's
`token_env` names a variable that is not set. Run against a manifest where
GitHub's credential comes from `gh auth token`, it warns about both forges while
`--forge` successfully authenticates to one of them and resolves every repo. The
report contradicts itself inside one run.

The warning is not merely noisy, it is wrong in the direction that matters. It
tells the operator that mutating operations will fail unauthorized, when the
credential is right there and works.

## What it can honestly say while staying offline

`check` is offline and pure and that is worth keeping. It cannot run the command
without giving up both.

But it does not need to. A profile declaring a `token_cmd` has named its
intended source, and the variable being unset is then the ordinary case rather
than a gap. So the offline check speaks only where `token_env` is the sole
declared source: that is a manifest saying "the credential comes from this
variable" about a variable that holds nothing, which is a real finding and
checkable without running anything.

Where a command is declared, `--forge` is what reports a command that produces
nothing, and it already names the command in the finding.
