# what-the-refresh-writes-and-skips-is-said

Follows the closed round 202611242203-jxpf, which brought each index current before `homma search`
asks it. A review of that round found the following.

## The design still says the indexes are opened read only

The section on `homma search` says the verb opens the index files read only, and that `[search]`
has four keys. The refresh now opens each file as a writer, a member's index in its own git
directory included, and the table has six keys. The module's own doc repeats the first claim, and
the root readme says the verb asks the indexes.

Decision: the design and the readme say each index is brought current, which writes it, and then
asked read only; the keys are named without a count.

## What a refresh skipped is dropped

The index crate's refresh reports what it could not read, a file skipped and why, and a definition
it found changed, as caveats. The line drops them, so an index whose refresh skipped a file says
`current` while that file is not in it.

Decision: each caveat of a refresh is a note on the index's line, as the caveats of its answer are.

## A file with no definition and its command

The topic of the round before says the line of an index whose file records no definition names the
command that writes one; the design did not carry it, and the code says it as `built again by`,
which reads as if the index were rebuilt. Decision: the design says it, and the line says the
command writes one.

## Tests the round did not have

That a question leaves an index not built still not there; a refresh that fails, its words on the
line; a repository's index refreshed and measured, not only a corpus's; and the command named on a
line whose file records no definition.
