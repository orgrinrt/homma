# Containment is a property of the filesystem, not of a path

**Phase:** TOPIC
**Scope:** `homma-api`, `homma-core`, `homma-org`, `homma`

Sixth review, sixth refusal, and the sixth instance of one class. The review's
own diagnosis is the round:

> Each round takes the reproduction it was handed as the specification, closes
> that path, and reports the class closed. Here the guard was *relocated* from
> root to target, which closed the demonstrated route and opened finding 1 by
> removing the check from the path that still writes.
>
> Containment is a property of `(path, filesystem)`, and it is being computed
> from the path alone.

Both halves are right and the second is the mechanism.

## The route that reopened

The previous round moved the guard from the root to the workspace. **The root is
where `prepare` and `write_definitions` write**, so moving the check off it put
the original defect back, one function over. Reproduced:

```
config in victim/sub/, content_repo a URI, victim a committed repository
$ homma org up paja
  definition .../victim/sub/.claude/agents/paja.md
exit=0
$ git -C victim status --porcelain
?? sub/
```

`.shared/hands/paja/`, both definitions and the memory symlink, in a tree that is
not ours. The guard was never on that path, because the round treated the
reproduction it was given as the specification.

## Two of the three reported routes did not reproduce, and one of those is worse
## than if it had

The review named three. Only the first reproduces as constructed here.

**The symlink route exited 1**, and for the wrong reason: the guard walked
lexical parents, found the workspace root among them, and refused because it
believed the root enclosed the target. A correct refusal from an incorrect
computation. Rearranged so no lexical ancestor is a repository, the same
computation lets it through, so the finding is real and its reproduction was not
faithful. **A guard that answers correctly by accident is not a guard**, and the
distinction is worth writing down because it is invisible in a pass or fail.

**The bare-repository route exited 1** in the construction tried here. Not
dismissed: `at.join(".git").exists()` genuinely cannot see a bare repository, so
the mechanism the review describes is present in the code even where this
construction did not reach it.

## What the round does

**One checked constructor, and the check asks the filesystem.**

The path is canonicalised as far as it exists before anything walks it, so a
symlink cannot hide an ancestor and `..` cannot invent one. A directory counts as
a repository when it has a `.git` **or** when it is itself bare, which is a `HEAD`
beside `objects` and `refs`.

**Every path that writes is checked, not the one a reproduction pointed at.**
That is the root and the workspace, because both are written to, and the check
runs from one place so a third writer cannot be added without meeting it.

## And the numbers were wrong again

Seven of nine mutation rows overstated, and one claimed two failing tests where
the answer is zero: **the root's symlink resolution is unpinned entirely.**

The measurement procedure was rewritten last round specifically to stop this, and
the rewrite did not work, because the mutations were run before the commit's
autofix landed and the results were carried across it. The procedure that will
work is narrower: **a number is produced by a command and pasted from that
command's output in the same act.** Not re-typed, not carried, not summarised.
