## What the python does

`.shared/scripts/release/auth` keeps three publish tokens (crates-io, jsr, npm) in the macOS keychain, service
`hiisi-release-<name>`, account `publish`, expiry in the item's comment, and leaves github to `gh`. Verbs: none
(check all, walk through what needs work), `status`, `fix <name>`, `forget <name>`, `expiry <name> <date>`,
`token <name>`, `npmrc`, `env`, `diagnose <name>`. Two rules: nothing is stored before the registry accepts it,
and every check calls the registry with the token held. crates.io 401 is a rejection, 403 is a publish-scoped
token and fine. Expiry: past is invalid, two weeks or less is expiring.

## The traceback

`auth status` on Linux prints `publish credentials` and then a `FileNotFoundError` for `security`: the keychain
reader runs a program the machine does not have, and nothing catches it.

## Decisions (from the brief, op away)

- `homma release auth` with the same verbs. A store the machine cannot read is a reason on each line, never a
  crash; the status still renders all four.
- The store is a trait. On macOS the keychain through `security`; elsewhere the store homma already reads
  secrets from, the registry's `token_env` in `[registries.<key>]`, read-only, with writes refused by a named
  reason. Never its `token_cmd`, which the workspace points at this very verb.
- The npmrc's place is a key, `[auth] npmrc`, defaulting under the cache directory.
