# third-review-fixes-the-kept-entry-and-the-strays

A third review of the git-shook work found three places where the shipped code does not do what the design already says. Nothing in the design changes; the code is brought to it.

## The kept copy of the entrypoint

The deep dive says the registry holds one entry per event, and that registering removes the entrypoint homma wrote. git-shook adopts a hook already in the hooks directory by copying it into `kept/<event>` and writing a `00-existing` entry that runs the copy. Registering removes the original only, so when the entrypoint was homma's own, `00-existing` still runs it and the event runs the table twice. Registering also removes the `00-existing` entry and the kept copy for an event when the kept copy is byte for byte what homma writes, and nothing else.

## Every `homma.*.toml` the survey names

The design says `hook doctor` names every `homma.*.toml` in the root that nothing reads. The survey only looked at names with a plain middle, so a copy such as `homma.local.old.toml`, the case the design itself gives, was neither read nor reported. The survey lists every file shaped `homma.<anything>.toml` that is not the manifest and not named in `layers`.

## An unreadable layer is found by reading it

`hook doctor` decided that a file had failed by looking for its name inside the error strings, so an error whose cause quoted another layer hid that layer's `read` line. It asks the reader about the file instead.

## Left as they are

Commit subjects of the earlier rounds that narrate the review that produced them are pushed, and rewording them rewrites history on a branch the coordinator has not landed. They are named in the report for the coordinator to settle when landing.
