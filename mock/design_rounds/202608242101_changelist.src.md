# Src changelist: aggregated hooks find their own workspace

**Date:** 2026-08-24
**Phase:** IMPL
**Source topic:** `202608242101_topic.aggregated-hooks-are-inert-outside-the-workspace-that-made-them.md`
**Doc changelist:** `202608242101_changelist.doc.lock.md`

## NOT IN THIS ROUND: `homma-core/src/config.rs`

The topic's F1, a relative config path leaving `workspace.path` relative, was
found independently by a reviewer against the open `feat/a-forge-token-can-come-from-a-command`
branch, with a sharper mechanism than the topic states: `Path::new("homma.toml").parent()`
returns `Some("")` rather than `None`, so the `unwrap_or(".")` fallback in
`from_path` never fires and the join leaves the path relative. That branch also
carries a second consumer of the same anchoring, so the fix lands there rather
than being written twice in two places that would then conflict.

Nothing in this round depends on it. A wrapper that locates its own workspace
does not read `workspace.path` at all, which is most of why that shape is the
right one.

## CHANGE: `homma/src/cmd/aggregate.rs`, a wrapper locates its own workspace

MODIFY `wrapper_script`: takes the repo's workspace-relative path and the hook's
repo-relative path in place of two absolute paths. The emitted script derives
the workspace from its own location, resolves an absolute entry unchanged for a
repo declared outside the workspace, and declines when the hook it fronts is not
executable.

MODIFY `aggregate_repo`: derives the workspace-relative repo path by stripping
the workspace root, falling back to the absolute path for a repo declared
outside the workspace, which remains correct for the workspace that generated it
and is the only shape available there.

MODIFY `aggregate_hooks`: takes `repo_rel_path: &str` in place of
`repo_abs_path: &Path`, and registers the hook as
`"${CLAUDE_PROJECT_DIR}"/.claude/hooks/<name>` rather than as the absolute path
this run wrote to. The host substitutes the project root regardless of the
working directory the hook runs in, which is what makes one tracked
`settings.json` name each clone's own wrappers.

MODIFY `merge_settings`: takes `visited: &[&str]` alongside `known_repos`. An
entry is swept when it names a repo this run aggregated; an entry naming a
declared repo this workspace has not cloned is preserved.

MODIFY `is_aggregated_command`: recognises the current `<repo>--` shape only.

ADD `is_legacy_aggregated_command`: the retired bash aggregator's
`imports/<repo>/` shape, swept on the full manifest rather than on the visited
set, since nothing writes it any more and no clone makes it work again.

ADD test helpers `make_executable` and `run_wrapper` / `run_wrapper_output`.

RENAME test `wrapper_script_contains_scope_check_and_handoff` to
`a_wrapper_carries_no_absolute_path_and_finds_its_workspace_from_its_own_location`,
and rewrite it: it now walks every emitted line and refuses any assignment of a
path starting at the filesystem root.

ADD test `a_wrapper_matches_a_path_under_its_repo_and_declines_one_outside`: runs
the emitted script under bash against a real temporary workspace, both arms,
with the real hook writing a marker so the hand-off is observed rather than
inferred from an exit code that is 0 either way.

ADD test `a_wrapper_declines_when_the_repo_is_not_cloned_here`: targets a path
inside the absent repo, which is the only target that separates the two arms.

ADD test `a_relative_repo_root_never_matches_the_absolute_path_the_host_supplies`:
pins why the old shape was inert under a relative manifest path, with two
controls.

ADD test `merge_settings_keeps_entries_for_a_known_repo_this_run_did_not_visit`,
carrying its own control: the visited repo's stale entry is still replaced in the
same run.

ADD test `merge_settings_sweeps_the_legacy_shape_for_any_known_repo_visited_or_not`,
with a hand-authored entry as the control.

MODIFY tests `legacy_imports_path_detected_as_aggregated`,
`legacy_imports_at_path_start_detected_as_aggregated` and
`imports_substring_not_at_path_boundary_not_detected`: they address
`is_legacy_aggregated_command`, and the first also asserts that the current-shape
check does not claim the legacy form, so the two predicates are not silently one.

MODIFY test `aggregate_repo_end_to_end_against_synthetic_workspace`: asserts the
emitted wrapper and the registered command carry no path naming the workspace
that generated them.

MODIFY the four existing `merge_settings` tests: they pass the visited set.

## CHANGE: `homma/src/cmd/gates.rs`, the workspace gate does the same

MODIFY `install_workspace_gate`: registers
`"${CLAUDE_PROJECT_DIR}"/.claude/hooks/_workspace--mockspace-gate.sh` rather than
the absolute path it wrote to. Its `repos` argument becomes workspace-relative
pairs.

MODIFY `gate_script`: derives the workspace from its own location and joins each
relative repo-table entry to it, leaving an absolute entry alone.

MODIFY test `install_writes_executable_script_and_returns_entry`: relative repo
paths, and it refuses any occurrence of the generating workspace's path in
either the command or the script body.

ADD test `a_relative_repo_entry_resolves_against_the_workspace_the_gate_sits_in`,
with the absolute arm as its control.

## CHANGE: `homma/src/cmd/agent.rs`, regen reports which repos it visited

MODIFY the aggregation loop: collects the repos whose hooks were aggregated and
passes that set to `merge_settings`.

MODIFY the gate call site: passes the manifest's own `local_path` rather than the
absolute path this run resolved.
