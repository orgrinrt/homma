# Src changelist: the deny list, enforced

## CHANGE: `homma-api::denied`, the absolute locations

Containment answers whether a path stays inside a root the operator named. It
cannot answer whether that root is somewhere the record forbids, because a home
directory contains itself perfectly, and thirteen rounds asked only the first
question.

Two entries derive from the home directory and one from the registry. The home
is a parameter rather than read where it is needed, so a test hands over a
tempdir and exercises the real path rather than a variant of it.

The check is by absolute path and never by name, because
`.claude/agent-memory/<name>/` inside the content repository is licensed while
`~/.claude` is denied, and those are the same word.

## CHANGE: `Root` carries the deny list, and `Root::new` takes it

**Not a second check a caller performs**, because a caller that must remember one
is a caller that forgets it. Checking the root and the workspace was the first
attempt and it was not enough: with the root set to a home, every derived path
passed containment and landed in `~/.claude` anyway.

So it lives where containment lives, in the one funnel every proven path goes
through, and `Layout::new` takes it too. There is no default: the default would
be the empty list, which is the answer that silently reintroduces the defect.

## CHANGE: the identity read-back gets its test

A fourth live guard pinned by nothing. `ProvisionError::IdentityNotSet` was
constructed at one site, asserted by no test, with a `Display` arm that never
ran, in code whose own comment says it exists because a write that never reached
disk survived a round.

## CHANGE: the parent refusal says which directory and what to do

It said "No such file or directory (os error 2)" with no path and no remedy, in a
fix whose whole justification was that the alternative error read as a network
fault. The same defect one layer up, and its sibling `Root::new` had the good
message to copy.

## CHANGE: the parent refusal leaves nothing behind

`git.init` ran before it, so a refusal left a `.git` in the root, against a
comment three lines above saying a refusal leaves nothing half-built. Its sibling
has a test asserting that; this now has one too.

## CHANGE: a condition that cannot be false is deleted

`if out.parent().is_some() { out.pop() }` is exactly `out.pop()`, since
`PathBuf::pop` already does nothing at the root. Deleting the condition fails
nothing, and here that is a proof rather than a coverage gap.

## CHANGE: the `.claude`-present variants

Both end-to-end tests from the previous round build a home that does not exist,
which is the one configuration where the parent guard fires and therefore the one
that hid all of this. The real case has `.claude` there already.
