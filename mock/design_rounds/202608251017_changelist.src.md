# Src changelist: anchor the deny entries at load

**Date:** 2026-08-25
**Round:** 202608251017
**Source topic:** `202608251017_topic.one-anchor-for-a-relative-deny.md`

## CHANGE: `crates/homma-core/src/config.rs`

`from_path` anchors every relative `deny` entry against the manifest's own
directory, beside where it already anchors `workspace.path` and the token
commands, off the same `beside` those two share.

Nothing relative survives the load, so the base a later caller passes cannot
disagree with the documented one. The argument keeps its meaning for a config
parsed from a string, where the caller is the only thing that knows.

A `~/` entry is left alone here. Its anchor is the home rather than the
manifest, `denying` resolves it and drops it when there is no home, and doing
that twice in two places is how the two come to disagree.

## CHANGE: `crates/homma-engine/src/cmd/agent.rs`

A comment at `denied_for_aggregating`, saying that the workspace root it passes
as the base now decides nothing, and why the two anchors coincided until they
did not.

## CHANGE: `crates/homma-core/src/config/tests.rs`

The three test modules move out of `config.rs`, which the new tests carried past
the file-size limit. The seam is that they are the only part of the file that is
not the schema.

Four tests added there. A relative entry lands beside the manifest rather than
beside the working directory; the same entry with `workspace.path` pointed
elsewhere still lands beside the manifest, which is the case that diverged; a
`~/` entry and an absolute one come through untouched, so the home resolution
stays where it is; and settling twice against different directories lands in the
same place.
