# Src changelist: a test that keeps the readme's examples honest

**Date:** 2026-08-25
**Round:** 202608250741
**Doc changelist:** `202608250741_changelist.doc.lock.md`

Two of the readme's errors were of a kind prose review does not catch reliably:
a manifest example that no longer parses, and a flag that does not exist. Both
are checkable, and neither was checked by anything in the suite.

## CHANGE: `crates/homma-engine/tests/the_readme_examples_are_real.rs`

New file. Three tests, reading `README.md` through `include_str!`.

`the_manifest_example_parses_as_a_manifest` pulls the readme's single toml
block and parses it as `homma_core::config::Config`. Parsing alone would pass
over an empty block, so it then asserts the workspace name, the forge key and
the repo entry survived, which is the vacuity guard. It asserts the block count
is one, so a second toml block added later fails loudly rather than being
skipped past.

`every_command_the_readme_names_is_one_the_cli_takes` collects every
`` `homma <cmd>` `` the readme spells and runs each as `<cmd> --help` against
the built binary. A count floor guards against the extraction silently finding
nothing at all.

`the_readme_names_the_output_flag_the_cli_actually_has` pins the correction the
round is partly for: the readme may not offer `--json`, must name
`--output json`, and that flag has to still parse.

Each was watched failing before being kept.
