# SRC changelist: 202608242017

## CHANGE: `mock/crates/homma-core/src/forge/trait_def.rs`

ADD `Forge::credential_works(&self) -> Result<bool, ForgeError>`.

Answers whether the forge accepts the credential this client carries. `Ok(false)`
is the forge rejecting it; anything leaving the question unanswered is an error,
because that is not evidence either way.

WHY: a negative from `repo_exists` is evidence only when the asker could have
seen a positive. Both forges answer `404` for a private repo the credential
cannot see, identically to one that is not there, so a missing, expired, revoked
or under-scoped token turns every private repo into a false absence. Checking
that a token is set covers only the first of those four.

## CHANGE: `mock/crates/homma-core/src/forge/github.rs`

ADD the `credential_works` impl: `GET {api}/user`, `401` false, `403` true, any
other failure an error.

SET `redirect_auth_headers(RedirectAuthHeaders::SameHost)` on the agent.

WHY: GitHub answers `301` for a renamed repo, to `/repositories/{id}` on the
same host. `ureq` drops `Authorization` on redirects by default, so the followed
request arrives anonymous and a private repo answers `404`, which `repo_exists`
maps to `Ok(false)`. `SameHost` keeps the header where the redirect stays on the
issuing host and drops it where it does not.

ADD `redirect_tests`: a local stub answering `301` to a path that is `200` with
a credential and `404` without one. Two tests, the second being the control that
the stub discriminates on the header at all.

## CHANGE: `mock/crates/homma-core/src/forge/forgejo.rs`

ADD the same `credential_works` impl.

## CHANGE: `mock/crates/homma-core/tests/forge_smoke.rs`

ADD `credential_works` to `MockForge`, returning `Ok(true)`. No test here is
about credentials.

## CHANGE: `mock/crates/homma/src/cmd/verify.rs`

SPLIT `resolve_on_their_forges` into a thin wrapper and `resolve_with`, which
takes a client factory.

WHY: the two branches that matter, a repo reported absent and a credential the
forge rejects, were reachable only against the live API because the client was
built inline. That is the defect underneath the missing tests rather than a
testing convenience.

CHANGE the token loop to run over forges some repo actually references, and to
probe the credential before asking about any repo. Three findings replace one:
`forge_answers_are_not_evidence` for no token, `forge_credential_rejected` for a
token the forge refuses, `forge_unreachable` for a forge that could not be
asked. Each names a different thing to go and fix.

WHY the used-forge filter: this workspace declares a `codeberg` profile that no
repo names, so the old loop warned about a forge nothing was going to ask about.
Same noise the `local_path` warning was removed for, on another axis.

ADD `tests`: a `Stub` forge and seven cases covering absent, present, rejected,
unreachable, no token, empty token, and the unused profile. The present case is
the control on the absent one.

## CHANGE: `mock/crates/homma/tests/cli_smoke.rs`

CHANGE `verify_does_not_reach_a_forge_unless_asked_to` to assert on the finding
kind rather than on a repo name. The name was satisfied by three findings with
three different meanings, so it proved only that `--forge` reached something.

ADD the missing half to the empty-token arm of
`verify_will_not_claim_a_repo_is_absent_from_a_forge_it_cannot_authenticate_to`:
it asserted the warning appears and not that the repo goes unmentioned, which
is the half that matters, on the subtler of the two cases.
