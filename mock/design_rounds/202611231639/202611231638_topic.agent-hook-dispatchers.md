# agent-hook-dispatchers

The regen registers one handler per hook and matcher, each a wrapper of its own. In the workspace clone the
coordinator measured, `.claude/settings.local.json` held 179 `PreToolUse` groups; this clone holds 81, with 8
`PostToolUse`, 6 `Stop` and 2 `PreCompact`. None carries a timeout, `async` or an `if`, and the timeout each
repository's own `settings.json` gives its hooks (kaski's give 60 seconds) is dropped on the way up.

## What the design says now

The root `DESIGN.md.tmpl`, The agent hooks: "The host runs every hook registered for an event, in parallel,
and runs a handler named twice only once. So the dispatcher git needs, one program at an event fanning out to
many, is not needed here, and one registration per hook is what homma writes. A dispatcher would put a homma
process in front of every tool call and serialise hooks the host already runs side by side, to buy an order
nothing here depends on."

## What that misses

What one registration per hook costs is a process per hook per call, whether or not the call is any of that
hook's business. A shell call in this clone matches 49 handlers: six for each of seven repositories (their
`check-message` is registered for every tool), the workspace gate and six declared rows. Each is a bash process
running `jq` three times to learn where the call lands before it declines, so a shell call starts about 49
shells and 147 `jq` processes and most of them say nothing. The two objections hold only of the dispatcher they
name. One that is a homma process puts the engine in front of every call, and homma is a launcher that builds
the engine for a new pin on its first run, which takes minutes. One that runs hooks one after another
serialises them. A dispatcher that is a shell script, reads the payload once, runs only the hooks the call lands
in and runs those side by side has neither cost.

The host contract this rests on is in `research/202611231640_agent-hook-host-contract.md`: hooks at one event
run in parallel, a deny beats an ask beats an allow, exit 2 is a deny with stderr the reason, every
`additionalContext` reaches the session, an `async` hook cannot block and its `additionalContext` and
`systemMessage` arrive on the next turn, and `if` takes one permission rule per handler.

## Decision

- One dispatcher script, written by the regen with the same line as every file it writes, run once per event
  it has entries for, and once more for the entries that are `async`. So an event gets at most two groups.
- The entries are a table the regen writes beside it: for each hook its event, matcher, the file it runs, the
  program it runs it with and its arguments, the repositories it is narrowed to, its timeout, whether it is
  `async`, and where it came from (a member, the manifest's rows, the workspace gate).
- The dispatcher reads the payload and the table with one `jq`, keeps the entries whose event, mode and matcher
  take the call, narrows each by where the call lands exactly as the wrappers did, runs what is left side by side,
  each under its timeout, and folds their answers into one: any exit 2 is the answer, with every other hook's
  `additionalContext` kept in its reason; otherwise the decisions fold by the host's precedence, every
  `additionalContext` and `systemMessage` is kept, and a hook that failed some other way is named on stderr.
- The wrappers are retired, every one, with their registrations. The workspace gate stays a file of its own and
  becomes an entry.
- The notice filter (`tools/hookdedup/hookdedup run`) runs once around the dispatcher rather than once per
  hook, and it becomes a key, `[agent] filter`, rather than a path homma knows.
- A row in `[agent.hooks]` may say `timeout` and `async`; `[agent] timeout` is the default for every entry that
  says none. A member's hook keeps the timeout its repository gave it.
- The group's matcher is every entry's matcher joined, or every tool where one takes every tool. It only spares
  the host a process where nothing could match; the dispatcher matches each entry exactly.
- `if` is not used. It takes one rule per handler and cannot say where a shell call lands, which is the narrowing
  every member's hook needs.
