# Topic: what the deny list does not cover, and what nothing pins

**Date:** 2026-08-25

A review of the readme against the code found two things, and they are the same
thing seen from either end.

## The prose says the list is total and it is not

The readme calls `deny` "the places homma may not write", with no exception,
and a refusal says "nothing may be written there". `agent regen` writes into
the workspace root regardless, because the constructor that builds its list
permits that root after folding every entry in.

That permission is deliberate and the reasoning sits beside it: an operator can
deny a place and then ask homma to aggregate into it, and refusing would break
the command they asked for. The reasoning is real and the sentence describing
it is missing. So the prose claims a guarantee wider than the mechanism, which
is the defect rather than the permission.

Whether the permission itself is right is a separate question and not this
round's. An explicit entry is a deliberate act and a permission is a default,
so there is an argument for letting the entry win. There is also an argument
that denying the root denies homma its own operation, which an operator would
meet as a tool that silently does nothing. Both are real, it changes the
behaviour of a tool about to be published, and it is filed rather than decided
here.

## Two of the three folds are pinned by nothing

`for_the_workspace` and `denied_for_aggregating` both fold the manifest list
in, and deleting either fold leaves the whole suite green. Only
`for_standing_up` is pinned.

This is the module's own recorded history repeating one constructor over: its
doc says, of the entry it used to carry, that it was live and pinned by nothing
and that deleting it left everything passing. The fix that removed that entry
introduced two more places with the same property.

The behaviour works. `org add` does refuse a registry write in a denied place,
and that refusal is reachable today. What is missing is the test, and a
mechanism nothing asserts is a mechanism the next edit removes for free.

## One smaller thing

`~/` expands in a `deny` entry and not in `workspace.path`, where it makes a
directory literally named `~`. The readme teaches the tilde in the deny block
without saying where it stops working.
