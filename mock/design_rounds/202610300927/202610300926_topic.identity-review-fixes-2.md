# identity-review-fixes-2

A second review of the branch that generates an agent definition from a character file returned blockers and lesser findings against the state left by the round `202610300858`. This round fixes the class of each. Another review follows, as the person running the session asked.

Blocker 1, `org up` refuses an authored character only after it has provisioned. The refusal in `write_definitions` comes after the clone, the git init and the memory link, so a refused stand-up leaves a half-made workspace. Fix: one predicate says whether a file is an authored character, `identities` and `write_definitions` both use it, and `stand_up` asks it before the first thing it creates. Option rejected: moving the whole of `write_definitions` earlier, because the definition needs the layout, which needs the provisioned root.

Blocker 2, a render that fails halfway. `render` loads and checks every identity, then writes one at a time, so a real directory at the second identity's link slot fails after the first was written. Fix: every link slot is checked before the first write, and each link is made before its definition, so a refusal leaves nothing partly done. Option rejected: rolling back, because a rollback is a second writer that can itself fail.

Blocker 3, a configured `[paths] hands` makes the default memory fail the `.shared` check, since the default was derived from the configured place. Fix: the default memory is always `.shared/hands/<name>/memory`, a fixed vocabulary of the character format and not of the layout. `Layout::default_memory` is removed. Option rejected: relaxing the `.shared` check to allow the configured place, because the rule that a memory lives under `.shared` is what keeps a character from pointing the harness's writes anywhere else.

Blocker 4, a commit body that names the review it came from. The repository is public. It is reworded, and the step is waiting on the coordinator.

Blocker 5, tests. Added: the `write_definitions` refusal, a failure in the write phase, a configured `hands`, stronger laws for the YAML scalar writer, and the smoke test asserting the message that reports a broken character. The claim in `characters.rs` that a struct literal cannot skip the checks is a type-level statement a runtime test cannot show, so it is dropped from the test and kept in the type's own documentation.

Blocker 6, the organisation design says the definition is generated from a registry entry plus a shared template plus a hand-written fragment. That describes the personas. This round adds the character format, the rule that a memory lives under `.shared`, the rule that a memory has one owner, and the rule that a persona may not share an identity's name.

Lesser findings, taken together.
- Two memory directories that contain one another (`.shared/hands/coord` and `.shared/hands/coord/memory`) are refused, since a write through one lands in the other.
- The YAML scalar writer writes plain only what cannot be read back as anything else: it starts with an ASCII letter, holds only letters, digits, spaces and a few punctuation marks, and is not a reserved word of either YAML version. Everything else is double quoted. This closes `0x1F`, `.inf`, dates, `Y`, and a raw control character.
- A handle may not start with `-`, so it cannot be read as an option by `launch`.
- `agents render` does not fail on an unrelated broken character. It uses a lenient list of names for the collision and stray checks and reports a broken one as a warning.
- The scalar writer moves to its own file, which brings `generate.rs` under the 500 line tripwire.

Reported rather than changed. The two branches (this one and the clause-dev one) must land together, because clause-dev's trunk still has block form lists that the reader here does not take. The `role` key means a registry role in the registry and a free description in a character. Whether an identity is a row of the registry is a question for op and is filed as one; the earlier topic defers it and nothing here decides it.

Correction to the lesser findings above, appended when the source was written: `agents render` does not warn about a broken character it has no business reading. It uses the names that are claimed (a directory whose character opens with a frontmatter fence) and says nothing else, and `identity render` is the command that reports what is wrong with one. The render module of the character is split into its own file for the same line count reason as the scalar writer.
