# Src changelist: answer for a directory that is not there yet

## CHANGE: `mock/crates/homma-api/src/denied.rs`

**The component comparison becomes case-insensitive**, replacing `starts_with`.
`under_by_identity` answers nothing about a location with no inode, so for a
denied place that does not exist yet the component comparison was the only arm
running, and that is the comparison folding defeats. All three deny items were
reproduced being written into on exactly that condition, and the control that
isolates it is the same command with the directory pre-created, which refuses.

The question a deny list is actually asked is whether two paths **could** denote
one directory, and where one of them cannot be consulted the honest answer is
conservative. So it over-refuses on a case-sensitive filesystem, deliberately and
legibly: an operator wanting `~/Dev/CLAUSE-DEV` distinct from `~/Dev/clause-dev`
is refused and told why.

The identity comparison stays, because a firmlink shares no components at all.

**Unicode normalisation is the residual and carries a `FIXME`.** APFS folds NFD
against NFC as well as case, the standard library has no normalisation, every
current entry is ASCII, and a registry-derived entry need not be.

**The module header said the record's list is three absolute locations.** It has
seven; three are locations. Corrected, with where the other four live.

**The sentence that was false when it was written** is gone: "A location with no
identity is caught by the component comparison beside this." It was not, and the
paragraph asserting the pair was total was asserting it about the exact hole.

## CHANGE: `mock/crates/homma/src/cmd/registry.rs`

`append_entry` writes two files at an operator-supplied path with no deny check,
so `--config $HOME/.claude/homma.toml org add intruder` exited 0 having rewritten
a registry inside `~/.claude`. It takes the deny list and refuses, before the
temporary file rather than after it.

## CHANGE: `mock/crates/homma/src/cmd/org.rs`

The caller builds the list and hands it over. It cannot use
`Denied::for_standing_up`, which needs a standee; `org add` is not standing
anybody up and the registry it is about to write is the one that would name the
workspaces.

## CHANGE: `mock/crates/homma/tests/derived_paths_smoke.rs`

**Every end-to-end deny test pre-created the denied directory**, and exactly one
test anywhere entered the absent path, using the identical spelling. So the suite
sampled the region where the identity comparison works and never named the region
where it does not.

Four tests, each with the denied place **absent**, one per deny item plus the
half-built case:

- the central clone absent, workspace spelled `Dev/CLAUSE-DEV`;
- a home with no `.claude` yet, workspace spelled `.CLAUDE`;
- a participant declared but not yet stood up, another's workspace inside it
  under a folded spelling, which is the ordinary case rather than a contrivance;
- `--root $HOME/Dev/CLAUSE-DEV` with the central clone absent, asserting nothing
  exists afterwards. That refusal previously fired **after** `git.init` had
  created the directory and `provision` had cloned into it, because the guard
  only started answering once the write had made the directory exist.

Each is written to establish that the two spellings reach one directory **once
the directory exists**, and to skip otherwise, so it degrades on a case-sensitive
filesystem rather than passing for the wrong reason.

## CHANGE: `mock/crates/homma/tests/registry_writes_smoke.rs`

New. The `org add` refusal, end to end, asserting the registry is not written and
no temporary file is left behind.
