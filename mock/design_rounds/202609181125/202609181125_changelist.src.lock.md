# src changelist: what a carried hook is handed

## CHANGE: `mock/crates/homma-engine/src/cmd/aggregate_wrapper.rs`

- `one_runner` takes the runners a hook's registrations name and answers the one
  program, or the problem to report. Two ways is refused as before, moved here
  from `aggregate.rs`. A runner whose first word is an assignment, or which
  carries `&`, `;`, `|`, `(`, `)`, a backtick, `<`, `>` or `$(`, is refused as a
  line of shell.
- `LANDS_IN_SH`: a file path that climbs with `..` lands everywhere. The comment
  over `lands_in` no longer calls an over-fire free.
- `wrapper_script`'s rustdoc says the hook runs in the directory the host ran the
  wrapper in, and why. The source already did; nothing in the emitted script
  changes for it.

## CHANGE: `mock/crates/homma-engine/src/cmd/aggregate.rs`

The two-runner check becomes a call to `one_runner`. `BTreeSet` is no longer
imported. 494 lines.

## CHANGE: `mock/crates/homma-engine/src/cmd/aggregate_wrapper_tests.rs`

`a_relative_repo_root_never_matches_the_absolute_path_the_host_supplies` is
deleted: it ran a `case` the test wrote and no homma code. `run_payload` and
`planted` are `pub(super)` for the file below.

## CHANGE: `mock/crates/homma-engine/src/cmd/aggregate_wrapper_handoff_tests.rs`

New, three arms. The hook records `pwd -P` and runs at the session's directory,
the root and inside the repository both. A climbing file path fires, the same
sibling without the climb and a name holding `..` do not. `one_runner` refuses
eight shell lines and keeps `bash`, `env A=1 node`, `node --flag=x` and none.

## CHANGE: `mock/crates/homma-engine/src/cmd/aggregate_registration_tests.rs`

`a_hook_run_through_a_line_of_shell_is_reported_and_not_carried`, at regen,
with the hook beside it run through `bash` carried as the control.

Verified: 208 pass, 1 ignored, in the engine's unit tests. With the shell check
and the climb both broken, exactly the three new arms that read them go red and
the other 47 aggregate tests stay green.
