# A member's feature sets run against that member

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-core/src/release/gate.rs` and its tests, `homma-api/src/release.rs`, `homma-engine/src/cmd/release/mod.rs`
**Source topics:** the thirteenth review of pull request 46, and `202609030425/202609030425_topic.the-hook-gates-every-tip-and-versions-compare-as-semver.md`

## The findings

The last round had the feature sets walk the workspace members and stop at the first that declared any, which was a call of the agent's on a question the design does not answer: it says the sets come from the crate's own manifest and says nothing about a workspace of several. Under that sentence a member's manifest is the crate's, so each member's sets are run against that member, `-p <member>`, beside the two workspace-wide runs every crate gets. A root that is itself a package keeps what it had: its sets stand in for the plain no-features run. Nothing is dropped and nothing is inherited, and the reading is filed for the lead designer to ratify or replace.

Two files crossed the size line with the last round: the engine's release command, whose gate arm moves to a module of its own, and the api's release types, whose version type moves to a module of its own with the same public path.

The design.
