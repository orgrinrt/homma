# release-refuses-a-flagged-history

Workspace ticket 0d8ea254ba15. Op, 23 November 2026: every release or publication from a poisoned history
needs a full rehouse. A history that carries an agent's byline, a tool trailer or a tool's advert is public
the moment its tag and release are, and a release made from it publishes what cannot be withdrawn.

## What the design says

`DEEPDIVE_release.md.tmpl`, The run, lists the steps a run takes and the order it stops in. Nothing in it
reads the commit messages, tag messages or author identities of the history being released. The check reads
the tree and the branches; it carries no attribution scan.

## Where the scan lives

The workspace already has the one scanner: a script that reads a repository's whole history (trailers,
identities, adverts in messages, tag messages, and the forge's pull request bodies) and exits 0 clean,
1 contaminated, 2 when it could not scan. Its patterns are the attribution engine's, and the workspace's
policy is that no byline is permitted. homma keeps no copy of either: what a byline is belongs to that
engine, and which ones a workspace permits belongs to the workspace.

So homma names no scanner. The workspace manifest names one under `[paths]`, as it names `forge_route`, and
homma runs it.

## Decision

- `[paths] history_scan` in the workspace manifest: a path under the workspace root to a command taking one
  argument, the clone's root. Unset, a release scans nothing, as a release tags with git where
  `forge_route` is unset. Named and not there, the run refuses before anything, as for `forge_route`.
- `homma release run` runs it over each repo it would release, before step 1 and before any registry is
  asked, and with `--dry-run` too, since a plan of a release that cannot be made says nothing. Exit 0 goes
  on. Anything else refuses that repo's release, nothing moved, with what the scanner printed, and names
  the remedy: rehousing the repository onto a clean history (`forge-rehouse`), a human decision. A scan
  that could not run is a refusal too, since a scan that did not happen reads the same as a clean one.
- The publish to crates.io is step 8 of the same run, so it is held by the same refusal. `release check`
  is left as it is in this round: it runs on every gate and reports at warn, and a whole-history scan
  there is a separate decision, filed as a follow-up.
