## Comparison to deprecated changelist

`202610091700_changelist.src.deprecated.md` carried the same changes and the
same verification. It was deprecated because the doc changelist it implemented
named a cause for the cut lines, a second writer and lines of megabytes, that the
transcript does not show, and the source repeated it. This one differs in three
places and keeps the rest as it was.

- The module documentation of `capture::cut` and `capture::transcript`, the
  comment of the tests in `tests/cut.rs` and the comment of the pinning test in
  `tests/typed.rs` stop naming a cause. They describe a write left cut off with
  the next line written straight after it.
- The binary-level test is renamed from
  `a_transcript_line_cut_by_a_second_writer_is_recovered_and_said_so` to
  `a_transcript_line_left_cut_off_is_recovered_and_said_so`.
- The reason `typed` keeps refusing is the consequence of skipping a record, a
  tool's line quoted as the person's, and not that its writer cannot be cut.

The code behaves as it did: the reader, the notice and the refusals are the same
and no test changed what it asserts.

## CHANGE: module `cmd::capture::cut` FROM absent TO present
File: `mock/crates/homma-engine/src/cmd/capture/cut.rs`
Holds `ending`, which takes a line that did not parse whole and returns the
object that ends it with the count of bytes before it, and `Recovered`, a line's
number and that count, which prints as the notice. `ending` tries each `{` after
the first byte from the left, takes the first from which the rest of the line is
one object, and returns nothing when none is, or when the bytes before it parse
as a whole value.
Verification: the tests under `src/cmd/capture/tests/cut.rs`.

## CHANGE: `capture::transcript::read` FROM refusing every line that is not JSON TO reading the object that ends one
File: `mock/crates/homma-engine/src/cmd/capture/transcript.rs`
A line that does not parse whole goes to `cut::ending`. Where it returns an
object, that object is the line from there on, and `Transcript::recovered` gains
the line's number and the bytes dropped. Where it returns nothing, the line is
refused by its number as before, with the parser's own message. The module
documentation says so.
Verification: `a_line_cut_short_then_whole_is_read_as_the_whole_line`,
`the_recovered_object_is_read_as_an_ordinary_line`,
`a_line_with_no_whole_object_ending_it_is_still_refused_by_number`,
`two_whole_lines_run_together_are_refused_by_number` and
`every_recovered_line_is_reported_by_number_and_bytes` under
`src/cmd/capture/tests/cut.rs`, and the existing
`a_malformed_line_of_a_read_shape_is_refused_by_number`, which stays as it was.

## CHANGE: `capture::run` FROM silent about the lines it read TO writing a warning to stderr for each recovered line
File: `mock/crates/homma-engine/src/cmd/capture/mod.rs`
The warnings go to stderr before anything is written, so they appear whether
the run then writes a capture, finds nothing new, or is refused. The report on
stdout is unchanged.
Verification: `a_transcript_line_left_cut_off_is_recovered_and_said_so` in
`mock/crates/homma-engine/tests/capture_smoke.rs`, over the binary.

## NO CHANGE: `capture::typed`
File: `mock/crates/homma-engine/src/cmd/capture/typed.rs`
The tools' record keeps refusing a line that does not parse, for the reason in
the topic's correction. A test pins it so the recovery is not carried across
later because the two readers look alike.
Verification: `a_record_cut_short_is_refused_where_the_transcript_recovers` in
`src/cmd/capture/tests/typed.rs`.

## CHANGE: `docs/DESIGN.md`
Re-renders from the template through `cargo mock`; the template changed in the
doc changelist and this round adds nothing to it.

new tests failed three of them with the error the real session gave,
