## Current state

The "Hooks" section of the release deep dive says the install reports how git
reaches the entrypoints once, for the install as a whole, and calls the chain
case "where the path is mockspace's", which the source read off the path's
spelling. mockspace's chain exists for three events only, so an entrypoint
for any other is reported as reached and is not. The section says stdin is
captured once and does not say for which events git hands one over.

No other flat topic is open on this branch.

## Changes proposed

### `homma-core/DEEPDIVE_release.md.tmpl` (modify)

The install's reach is stated per event: for each entrypoint written, git
reads it directly, or the hook git will run under `core.hooksPath` is
mockspace's, read off that file's own first lines, and chains to it, or
nothing there reaches it, with one unreached event making the exit non-zero.
Stdin is captured for the events git documents as supplying one, and named.
The claim that nothing is written where anything refuses is kept as what the
pre-check guarantees, and no more.
