# An index of another extraction is said as one of another chunker

## The defect

A review of the round that names what moves an index cut by another chunker found it keyed on one field. A repository index whose recorded extraction differs from the one homma's build of the index crate reads is refused on open the same way, `Error::Header` with the field `extraction` from the repository reader, and its line still carries only the crate's words. The direction was also read against the crate's constant rather than the value the refusal itself says the reader brought.

## The fix

- The note covers every format field the reader refuses a file over, the chunker and the extraction, and reads which way the file is out from the refusal's own `stored` and `brought`. The helper is named for what it covers, a file of another format.
- The words stay as they are, with the field named: an older file names its build command, which writes it again, and the version homma reads; a newer one says this build of homma reads an older version and that a build against the index crate's trunk reads it.
- A value that does not read as a version, on either side, gets no direction and no note beyond the crate's words.
- Tests: the chunker's three stay; the same three for the extraction, an older and a newer one planted in a repository index and its control at the crate's own; and the older chunker asked through a repository index, the member's own kind of file, not only a corpus store. The planting writes the recorded value into the file, so the tests take the database driver the index crate is built on as a test dependency.
- Outside this round, a ticket: on the index crate's work not yet on its trunk, the chunker's number differs by a feature rather than by a version, so older and newer would misname a feature mismatch and the older case's command would rebuild into the same refusal.
