# Doc changelist: what the review of the per-clone hooks round found

Topic: `202609252210_topic.review-of-the-per-clone-hooks-round.md`.

## Current state

`mock/DESIGN.md.tmpl` says a registration of homma's found in the shared
`settings.json` is swept, and does not say whether that holds for a member the
clone does not hold, nor in what order the two settings files are read and
written. Of the agent corpus it says the name a persona declares is its
filename, and nothing about how the frontmatter is read.

## CHANGE: the agent hooks section FROM "it is swept" TO swept whichever member it names, both files read and swept before either is written, the local one first
File: `mock/DESIGN.md.tmpl`

A registration homma finds in the shared file is homma's whatever repo it
names, because nothing homma writes belongs in that file at all. The keeping
of an unvisited repo's registration is the local file's, where it brings a
guard back the moment the repo is cloned. The order of the reads and writes is
stated because the other order leaves a clone with no registrations when the
local file does not parse.

## CHANGE: the agent corpus section FROM silent on the frontmatter TO the host's, written out as it was, with only `name` and `description` read, one line each
File: `mock/DESIGN.md.tmpl`

A folded or literal value, or a trailing comment, on either key is refused. The
shared frontmatter reader cannot serve a persona, since it refuses nesting and
unknown keys and the host's schema has both, and a full YAML reader is what
its own documentation declines.
