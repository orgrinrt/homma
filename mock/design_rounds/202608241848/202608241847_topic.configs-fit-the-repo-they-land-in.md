# The configs stage has to fit the repo it is landing in

Review of the configs stage found two things it does not know, and both are the
same shape: the stage decides where a config goes from the config's name alone,
and a name is not enough.

## The shared rustfmt.toml only works on nightly

Measured: `rustfmt +stable --check` against the shared copy warns 49 times that
"unstable features are only available in nightly", out of 76 options set. So
most of what the file says does not exist on stable at all, and a stable repo
given it formats to rustfmt's defaults while printing a wall of warnings.

`Applies::RustRepo` covers any repo with a Cargo manifest, which includes renki,
the one Rust repo in the workspace that pins nothing. Placing it there would be
worse than placing nothing.

Two ways out. A predicate on the toolchain, so the file goes where it works; or
a stable subset written as a `_stable` variant, so both kinds get a config. The
first is available now and the second is somebody writing a file that does not
exist yet, so the stage takes the first and reports the second as owed.

That report matters. Silently skipping renki leaves the only Rust repo in the
workspace without a formatting config and nothing saying so, which is the exact
failure the stage was written to stop.

## The manifest names one particular clone

`homma.toml` carried `path = "/Users/orgrinrt/Dev/clause-dev"`, absolute, and
every repo's local path resolves against it. So the stage run from any other
workspace resolves each repo into that one, and the stage writes files.

The file is tracked, so it is the same file in every workspace, and it named
one. A relative path anchored on the file's own directory is what a tracked
manifest can say: the config sits at the workspace root by definition.

## And then the list can be complete

The manifest listed twelve repos where the workspace has twenty-four, because a
repo the manifest names and a workspace has not cloned was reported as a
failure, and without `--continue-on-error` it stopped the run. Under the
one-session-one-workspace convention a workspace clones the repos its work
touches, so absence is the ordinary case rather than a fault.

With that fixed the manifest can name every repo, which is what makes a repo
joining the workspace visible to the stage at all.
