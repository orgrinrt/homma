# A credential lives where whatever minted it put it

Every forge profile names an environment variable and reads its token from
there. That works and it puts the whole problem on the operator: something has
to export the variable before homma runs, in every shell, on every machine, and
a variable exported in one terminal is not set in the next one.

The credentials themselves are not in environment variables. They are in a
keychain, in a password manager, or inside whichever tool minted them. The one
thing all of those have in common is that **something can be run to print one**.

## What the content repo already does

The workspace's release tooling holds publish credentials and answers for them:

```
auth token <name>      print one token, for a publish script to consume
```

It prints the secret on stdout and exits 1 with a message on stderr when
nothing is stored. That is exactly the shape a configuration key can call.

Its store is generic. One keychain item per name, under a service built from
the name, so nothing about it is specific to the four registries it currently
lists.

## It deliberately does not hold the github one

`auth token github` refuses, and the tool says why in its own header:

> Credentials a cli owns stay where that cli put them; `npm login` and
> `gh auth login` are called and nothing is copied out, because two copies of
> one secret is two things to expire.

That settles the design rather than complicating it. A forge credential is
asked of whoever owns it: `gh auth token` for GitHub, which works today and
needs nothing minted, and `auth token <name>` for anything the operator minted
themselves. Neither is privileged over the other, because a command is a
command.

## Shape

A workspace-level default with the forge's own name substituted in, so one line
serves every profile:

```toml
[auth]
token_cmd = [".shared/scripts/release/auth", "token", "{forge}"]

[forges.github]
token_cmd = ["gh", "auth", "token"]
```

Four things follow from what the thing is, rather than from taste.

**An argument list, never a shell string.** A placeholder substituted into a
shell command is something that can be quoted out of, and nothing here needs a
pipeline.

**The variable still wins.** It is the deliberate override, it is what a
continuous-integration runner sets, and a command reading a keychain cannot
answer on a machine with no session to unlock it. An empty variable counts as
unset, because that is how a shell says "not this one" and how a runner renders
a secret it does not hold.

**A relative program path is anchored to the workspace root**, the way
`local_path` already is. homma is meant to run from inside a member clone,
where a path relative to the working directory names nothing. A bare program
name is left alone so `PATH` finds it, which is what keeps the `gh` line
working with no configuration at all.

**The substitution happens once, at load.** Otherwise every offline command
spawns processes it has no use for. `status` is offline and stays offline.

## What it costs

A command in a manifest is a program the manifest runs. This is the operator's
own manifest, describing their own workspace, so that is not a new authority;
it is the same authority `local_path` already carries. Worth stating rather
than discovering.
