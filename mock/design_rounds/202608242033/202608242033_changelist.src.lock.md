# SRC changelist: 202608242033

## CHANGE: `mock/crates/homma-core/src/config.rs`

ADD `AuthConfig { token_cmd: Option<Vec<String>> }` and `Config.auth`.

ADD `ForgeConfig.token_cmd: Option<Vec<String>>`.

ADD `Config::settle_token_commands(&mut self, config_dir)`, called from
`from_path` beside the existing `workspace.path` anchoring. Inherits the
workspace default into any forge naming none, substitutes `{forge}` with the
profile key and `{host}` with the host of its `api_url`, and anchors a relative
program path carrying a separator against the config's own directory.

WHY at load: an offline command must not spawn anything. `status` and `verify`
without `--forge` never ask a forge for anything, and a lazy resolution at the
point of use would put a subprocess behind both. Pure, so it is checkable
without running any of it.

WHY a bare name is left alone: `gh` has to stay `gh` or the one case needing no
configuration at all stops working.

ADD `token_command_tests`, seven cases. Two forges in the fixture, because one
cannot distinguish a working substitution from a constant. Controls on the
anchoring (a bare name), on the default (a manifest naming no command gets
none) and on idempotence.

## CHANGE: `mock/crates/homma-core/src/forge/token.rs` (new)

ADD `resolve(&ForgeConfig) -> Option<String>`: the variable when it names one
and that one is not empty, else the command's first line of stdout.

WHY the first line: a tool that prints a token may print a newline after it and
several print a notice under it. A trailing newline inside an `Authorization`
header is rejected for a reason nobody can see.

WHY silent on failure: a missing command, a non-zero exit and empty output all
leave the client anonymous, which the caller already reports as the credential
problem it is. Printing here would put a diagnostic in the middle of whatever
the operator's actual command was producing.

ADD `token_tests`, nine cases, including the precedence control that runs the
same config both with and without the variable set.

## CHANGE: `mock/crates/homma-core/src/forge/github.rs`, `forgejo.rs`

CHANGE `new` to call `token::resolve` instead of reading the variable
themselves. The two had identical private copies of that read.

## CHANGE: `mock/crates/homma/src/cmd/verify.rs`

CHANGE `has_a_token` to ask `token::resolve`, so a forge configured entirely
through a command is not reported as tokenless and its operator sent to set a
variable the manifest never named.

ADD `where_it_looked`, so the finding names the sources that were tried rather
than asserting a credential is missing and leaving the reader to guess where it
was looked for.

## CHANGE: `mock/crates/homma/tests/cli_smoke.rs`

ADD two end-to-end cases: a forge whose credential comes only from a command
gets as far as using it, and one whose command produces nothing is reported
with the command named. The second is the first's control.
