# A failed push of main leaves no merge behind

**Date:** 2026-09-03
**Phase:** TOPIC
**Scope:** `homma-core/src/release/{run,git}.rs` and their tests, `homma-engine/src/cmd/release/mod.rs`, `homma-engine/tests/cli_release.rs`, `homma-api/src/release_tests.rs`
**Source topics:** the ninth review of pull request 46, and `202609030330/202609030330_topic.a-fresh-clone-still-merges-dev-onto-main.md`

## The findings

Where the merge of `dev` onto `main` succeeds and the push of `main` is refused, the tree is switched back to `dev` and the merge is left on the local `main`, since a completed merge cannot be aborted. The next run then refuses on `main.unreleased`, naming the wrong cause. The release line is reset to the commit it held before the merge, and the test on the refused push asserts it.

`git ls-remote` runs with no bound while the registry client gives up after fifteen seconds, so a check against an unreachable remote sits for as long as the network does. The call carries git's low-speed limit and time, so it gives up in the same order of time.

The design says the plan prints the branches it carries, and `release plan` does while `release run --dry-run` does not. The run's plan step prints the same line.

A doc comment left behind by the smoke-test move sits on the wrong test and goes; a test named for any bump exercises one level and is named for it.

## What does not change

The design. All four are the code brought to it.
