# SRC changelist: standing one up is one command

**Round:** 202608140910
**Phase:** IMPL

## CHANGE: mock/crates/homma-api/src/config.rs

Add `staffed` to `Identity`, defaulting false, and **replace `missing()` with
`standing()`** returning a four-way answer rather than a list of gaps.

```
NoWorkspace          the role owns no workspace at all
Mapped               a boundary recorded, no workspace by design
Incomplete(fields)   meant to have a workspace, these are absent
Staffed              ready
```

`missing()` cannot express the distinction, because a mapped entry lacks exactly
the fields an unfinished one lacks, so its empty-or-not answer conflates them. It
is deleted rather than kept alongside: two functions answering one question drift,
and there is no released version to keep compatible with.

Tests: a mapped Hand reports `Mapped` and not a gap list; a staffed Hand missing
its email reports `Incomplete` naming it; a King reports `NoWorkspace`; and
`staffed` defaults false so an entry that says nothing is mapped rather than
broken.

## CHANGE: mock/crates/homma-org/src/workspace.rs

Add `clone_content_repo`, which clones the content repository into an identity's
workspace and **is a no-op when the workspace already holds it**, so standing up
twice stays the same answer.

Add `set_git_identity`, writing the name and email into **that clone's own
configuration**. Not the global one, which is the failure mode this exists to
prevent and which is invisible until a commit lands under the wrong author.

Drop the unused `second` binding in the idempotency test. The call is what
matters and the assertion below it is what tests the property.

Tests: cloning into a workspace that already has the repository leaves its
contents alone; the identity lands in the clone's config and the surrounding
environment's configuration is not consulted or written.

## CHANGE: mock/crates/homma-org/Cargo.toml

Depend on `homma-core` for its git operations. Downward, L3 on L1.

## CHANGE: mock/crates/homma-org/src/lib.rs

Re-export what the new surface adds.

## CHANGE: mock/crates/homma/src/cmd/org.rs

`stand_up` refuses a mapped identity, naming that it is mapped rather than
reporting missing fields, so the message says what is true.

`add` writes a new entry: refusing a duplicate handle, a handle that is not usable
as a directory name, and a control character in any field before it can reach
generated frontmatter. The last check exists at generation time already; having it
at creation time as well is not duplication, because the registry stays
hand-editable and the second check is what covers a value that arrived some other
way.

Tests: standing up a mapped identity is refused and leaves nothing behind; adding
a duplicate handle is refused; adding a handle carrying a path separator is
refused.

## CHANGE: mock/crates/homma/src/cli.rs

`org add` takes the handle, role and the fields a role needs. `work add` clones a
member repository into an identity's workspace.
