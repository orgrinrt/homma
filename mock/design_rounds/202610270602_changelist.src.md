Answers `202610270601_topic.the-refusal-arms-are-entered-by-tests.md`, through the locked doc changelist `202610270601_changelist.doc.lock.md`.

## Current state

The source classifies git's refusals as the deep dive now lists them, but `merged` mixed the git call with the classification, so its refusal arms could not be entered without a repository git fails on, and the `Refused` arm of `read` was entered by no test. Several assertions in the range tests could not fail: the comment case for `Ordering::Relaxed`, the `unimplemented!(` marker, the rename flags of both diffs, and a guard on the continuation anchor that never changed a result.

## Changes proposed

- `milestone/branches.rs`: the classification of `git merge-tree`'s exit and streams is `classify`, a pure function, and `merged` calls it.
- `milestone/range.rs`: the continuation anchor drops its guard on empty text, which changed no result.
- `milestone/tests/branches.rs`: `classify` is tested with 0 with a tree, 1 with a tree and files, 1 with no tree, 1 with a first line that is not a tree, 128, no exit, an exit 2 with a tree, and a 64-digit tree.
- `milestone/tests/range.rs`: a comment naming `Ordering::Relaxed`, a positive `unimplemented!(`, and a renamed file read as a deletion and an addition by both reports.
- `tests/cli_milestone.rs`: the `git` shim fails a named subcommand, and a case fails `merge-tree`, asserting the call, the lines and the reason through the binary.
- `docs/` is regenerated.

The three older open topics need nothing from this round, as the doc changelist says; each stays open and none is consumed here.
