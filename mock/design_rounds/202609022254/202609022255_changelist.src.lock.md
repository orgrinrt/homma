# Source changelist: what the second review found on the release

**Date:** 2026-09-02
**Phase:** IMPL
**Doc changelist:** `202609022254_changelist.doc.lock.md`

## `homma-core`

### `src/release/publish.rs`, `publish_tests.rs` (modify)

CHANGE: `publish_npm` writes the user config to `homma-npmrc-<pid>-<nanos>` under the temp directory, and `write_private` opens it with `create_new`, so an existing path, a symlink included, is a refusal and never a write; the module doc names npm's file beside jsr's arguments as the two tokens that leave the environment. The mode test also plants a symlink and a world-readable file at the path and asserts each is refused with the target untouched.

## `homma-engine`

### `src/cmd/release/record.rs` (modify)

CHANGE: `newest(store, repo)` returns the newest run recorded for the repo on any sha, beside `newest_for`, with a test that the newest of three shas comes back and another repo's does not.

### `src/cmd/release/mod.rs` (modify)

CHANGE: `badges_cmd` reads `record::newest` rather than a run on the release line's tip, and its report names the sha the run measured. `release_order(cfg)` is the function behind the multi-repo release, still name order, carrying the dependency-order gap as an ignored red test in `tests/cli_smoke.rs` that plants two crates where the alphabetically later one is the dependency.

### `tests/cli_smoke.rs` (modify)

CHANGE: `homma release badges` on a planted `dev`/`main` repo with a green run recorded on the trunk's tip writes the badges branch to a bare origin, and with no run at all reports that.
