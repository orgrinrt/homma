# a-content-repo-s-gate-summary-says-so

## What was found

The review of the root-markers round: a content repository's gate skips every
step, and `GateRun::summary` skips every skipped step, so the summary is the
empty string. `homma release gate` prints a blank line for it, and the
`homma/gate` status it posts carries a green verdict with a description that
says nothing. The trunk rulesets require that status, so on a content repo the
required check is satisfied by a run that ran nothing, and the operator sees
nothing at the point of use saying so.

The design ratified the run itself: a repository whose markers say only
`content` runs a gate of skipped steps and passes. What it did not say is what
that run looks like when it is reported, and a blank line is not a report.

## What changes

The summary names what happened when nothing ran. A run in which every step
was skipped summarises as `nothing to run` with the reason the design already
gives, that the repository's markers say only content; a run in which some
steps ran keeps the summary it has, the names of the steps that ran, and says
nothing about the skipped ones, as before. The status description carries the
same words, since it is built from the summary.

The kind is not in the record today, and adding it is not this round's: the
sentence is derived from the steps alone, all skipped meaning nothing ran, and
the design's own account of when that happens is what the sentence says.
