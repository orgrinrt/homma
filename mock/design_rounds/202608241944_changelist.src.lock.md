# Source changelist: verify can ask the forge

## CHANGE: crates/homma/src/cli.rs

MODIFY `Command::Verify` from a unit variant to one carrying `forge: bool`,
behind `--forge`. Its doc comment says what the flag costs and what it is the
only check for.

## CHANGE: crates/homma/src/cmd/verify.rs

REMOVE the `repo_path_missing` finding. A workspace clones the repos its work
touches, so an absent `local_path` is the ordinary case and warning per repo
buried everything else.

ADD `resolve_on_their_forges`, which asks each forge whether the repo is there
under the owner and name the manifest gives it. Separate from `check`, which
stays offline and pure.

ADD `has_a_token`. Where a forge has no token in the environment, the command
reports that its answers are not evidence and asks nothing about its repos: a
private repo and an absent one are the same 404, and every repo here is
private. An empty variable counts as no token.

## CHANGE: crates/homma/src/cmd/mod.rs

MODIFY the dispatch arm for the new variant.

## CHANGE: crates/homma/tests/cli_smoke.rs

ADD `verify_says_nothing_about_a_repo_this_workspace_has_not_cloned`.

ADD `verify_will_not_claim_a_repo_is_absent_from_a_forge_it_cannot_authenticate_to`,
covering both the unset and the empty-string case, the second being what a bare
`is_some()` would have got wrong.

MODIFY `verify_does_not_reach_a_forge_unless_asked_to` to carry a token, so
both halves are about the flag rather than about the fixture. Its first shape
passed without one and stopped meaning anything the moment the token gate
landed, which the run caught.
