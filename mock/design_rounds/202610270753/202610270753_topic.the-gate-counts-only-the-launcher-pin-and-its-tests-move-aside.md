# the-gate-counts-only-the-launcher-pin-and-its-tests-move-aside


Sent back by the fifth fresh read of the branch. The gate still accepts the legacy `[alias] mock` entry in `.cargo/config.toml` as the config surface beside the launcher pin. The status probe for the alias was deleted last round under the rule on legacy shims before 1.0, and the gate's acceptance is the sibling left behind: it also lets a toml with an alias and no pin pass, though `cargo mock` refuses to run without a pin. The gate counts the pin only.

A deny for a missing pin sent the reader to `homma agent regen`, whose `cargo mock` stage refuses without a pin. The advice for that case is to add the pin to `mockspace.toml`.

The pin awk's table-header guard has no test: reverting it leaves every gate test green. The status end of the root-wins lookup has no test either. The `run_with` rustdoc was changed last round to an order the code does not run: the stages are `cargo mock`, the shared configs, the aggregate, and the settings merge after the loop; the comment on that last step also says stage 3, which collides with the aggregate's. The design sentence about the dropped fields reads as history and is restated as what the document carries. The gate's inline test module has grown the file past 1300 lines, and moves beside it as the agent tests did.

Left for the coordinator and the lead designer, not this round: whether the gate should ask homma for the toml's values instead of reading them in awk, and which set of surfaces the gate checks against the status's set.

The same read found that the gate still reads `mockspace.toml` in awk while the status reads it with the toml crate, and that they disagree on valid files: a top-level nested array whose element line begins with `[`, ahead of `mock_dir`, stops the awk and sends it to the default directory. Two rounds of patching the awk toward the parser have not closed it, and the design says the gate asks homma so the rule exists once. The coordinator ruled that the gate asks `homma agent status --repo <name> --output json` for the toml's facts and holds no reader of its own, failing closed where homma is missing. The status document gains `launcher_pin`, whether the toml carries a `mockspace_*` pin at its top level, since the gate counts it and nothing else reads it. The gate's tests run it against a stub `homma` that answers from a fixture the real probe wrote.

The set of surfaces the gate counts differs from the status's. The coordinator ruled that neither is changed here and that the design records it as an open question for the lead designer, naming both sets.
