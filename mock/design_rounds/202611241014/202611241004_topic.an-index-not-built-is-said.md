# an-index-not-built-is-said

Follows the closed round 202611240919, which added `homma search`. A review of its source found the
following.

## A member asked for and not there

`discover::places` leaves out an opted-in member whose index file is missing, and one whose clone is
not there at all, so the answer says nothing about them. The design says an index absent is a line
saying so under an answer from the rest.

Decision: every opted-in member is a place. One whose index file is missing is asked, and the index
crate's open reports it as not built. One whose clone is not there is a place that is not asked,
with the reason, since there is no git directory to find its index under.

## A corpus config that names its index badly

`own_index` follows whatever `corpus.index` a corpus config names, an absolute path or one climbing
out with `..` included, and a config that does not read as TOML falls back to the default index with
nothing said.

Decision: an index path that leaves the content repository is refused, and the corpus is a place not
asked, with the reason. A config that does not read is a note on its line, and its index is the
default.

## The build without the index crate

The engine's manifest and the design say a build that cannot reach the index crate turns the
`search` feature off. That is not so: cargo resolves an optional git dependency whether the feature
is on or not, so a build that cannot fetch it fails at resolution either way. The dependency stays
in the engine and the feature stays on by default; the feature only leaves the verb and its code
out of the build. homma is publishable only once the index crate is reachable by a public build.

## Tests the round did not have

The `--members` flag of one run turning the members on over the manifest's default; `[search]`
refusing an unknown key and a value of the wrong type.

## The rendered documents

`docs/DESIGN.md`, `docs/API.md` and the root `README.md` were not rendered after the template edits.
This round renders them.
