# release a virtual workspace

Ticket 5c963fc9dcb5. `homma release run renki --level patch --dry-run` refuses on four findings and `homma release plan renki` fails with `Cargo.toml: no version`. renki's root `Cargo.toml` is a virtual workspace, `members = ["mock/crates/*"]`, with no `[package]` and no `[workspace.package] version`; its three crates are versioned on their own: `renki` at `0.0.5-rc.2` on `dev`, `renki-config` and `renki-dirs` at `0.0.2`.

## What renki's history shows

One tag per release, bare, named by the version of the crate that carries the repo's name: `0.0.1` to `0.0.4`, then `0.0.5-rc.1` on the merge of `dev` into `main`. The other two crates have no tag of their own. They move by a hand bump on `dev` and ride in the release that carries the bump: `renki-config` and `renki-dirs` reached `0.0.1` in the merge tagged `0.0.3` and `0.0.2` in the merge tagged `0.0.4`, and the `CHANGELOG.md` block of that release names the move. crates.io holds `renki` `0.0.1` to `0.0.5-rc.1` and the other two at `0.0.1` and `0.0.2`. `0.0.5-rc.1` was cut by hand (`28a0fde chore: release 0.0.5-rc.1`), since a level cannot name a pre-release.

## The four findings

- `reg.unpublished` for `renki-config` and `renki-dirs` at `0.0.5-rc.1`: the check reads every tag as a version of every crate. Wrong for a workspace whose crates move apart.
- `semver.gaps` `0.0.4` to `0.0.5-rc.1`: adjacency was "a level bumps one into the other", and no level makes a pre-release, nor a pre-release's own release. A pre-release of a legal next version is no gap, and neither is a later pre-release or the release of the same version.
- `tag.bump.tagged` on `23b9b71`, which bumped the root manifest `0.0.0` to `0.0.1` in August while renki was one crate; the `0.0.1` tag was made later, on `4a78543`, a commit on `main` that carries `0.0.1` too. The check's intent is that no version reaches the release line without being released, a bump with no tag being a release half done. `0.0.1` was released and tagged, only not on the bump commit, and no tag can be moved there now. A check bug: a bump is tagged when a version tag names the version it bumps to; a tag naming the version on some other commit than one carrying it is `man.version.matches`, which already exists.
- `homma release plan` failing is `version::read` asking the root for a version a virtual workspace does not have.

## What changes

- A virtual workspace (a root `[workspace]` with no `[package]` and no `[workspace.package] version`) releases as a set of crates. The primary is the member named as the repo's directory, else the one publishable member; anything else refuses with the names.
- The primary's version is the release's: the level or an explicit version makes its next version from its last tag, the bump writes its manifest, the tag is named by it in the repo's convention, as renki's tags are.
- Every other publishable member rides: its version is its manifest's. It moves where its manifest at the head differs from its manifest at the last tag, and then it publishes and the block names the move; otherwise it stays and does not publish. It has no tag of its own; its version is tagged by the release tag on the commit that bumped it on `main`, as renki's history has it.
- The check judges each crate against its own versions and registry: the primary against the tags as before, every other crate by its bump commits on `main` carrying a release tag, its published versions each matching a tagged bump, and its version at the newest tag being published.
- `--version <X.Y.Z[-pre]>` beside `--level`, exactly one of the two: an explicit next version, for a pre-release no level makes. It must lie above the last tag with no gap; the manifest may already carry it, as renki's does.
