# doc changelist

The root design document gains the launcher's own command and the person's
settings file. It descends from the workspace design
`.shared/designs/renki-configuration.md`, section "homma's user preferences,
and `disallowed_roots`", from renki's round `202609041506` which is the
mechanism, and from the topic file
`202609041520_topic.user-preferences-and-the-workspace-subcommand.md`.

## What lands

- `mock/DESIGN.md.tmpl`, under "The command surface": two paragraphs. `homma
  workspace` is the launcher's, runs where there is no engine, and does status,
  in-place spawn, `spawn <slug>`, `reap` and `list`; it is the session's
  throwaway clone and not the org design's per-identity lifecycle, which stays
  in the engine. The four user-scope keys the descriptor declares, with their
  defaults and why `spawn.content_repo` has none, and that the manifest's
  `deny` list is a different question.
- `README.md` at the repo root, hand-written: two rows in the command table,
  `homma workspace` and `homma config`, and a paragraph on the settings file.

## Claims the source changelist will carry

The four `Setting` rows on the launcher's `Tool`; `Tool::commands` with the
one `workspace` command; the module that answers it, split by verb; the
`disallowed_roots` check with the `/*` form; git as a subprocess; and the
tests, which build real repositories in temporary directories the way the
scripts' suite did.
