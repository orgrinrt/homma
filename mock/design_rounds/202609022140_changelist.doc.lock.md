# Doc changelist: a release is a gated merge off main

**Date:** 2026-09-02
**Phase:** DOC
**Source topics:** `202609022115_topic.a-release-is-a-gated-merge-off-main.md`, `202609022130_topic.the-three-calls-on-the-release-shape.md`

Every flat topic in `design_rounds/` is one of those two, and both are consumed here.

## Current state

No design document mentions a release, a tag, a version, a registry, a changelog or a badge. `homma-core` and `homma-engine` carry no `README.md.tmpl` and no `DESIGN.md.tmpl` at all, so the command surface and the mechanism layer are described nowhere but in source. The root `DESIGN.md.tmpl` lists what spans repositories and names four primitives; releasing spans repositories and is not among them.

## Changes proposed

### `mock/crates/homma-core/README.md.tmpl` (create)

Three to six lines: the mechanism layer, git, forge and filesystem, the things with side effects; now also the gate that measures a commit and the release that moves one.

### `mock/crates/homma-core/DEEPDIVE_release.md.tmpl` (create)

The spec for the whole of it, one document, sections in this order:

1. What a release is: the four acts, the `dev` to `main` merge, the annotated tag on the merge commit, the GitHub release, the registry publish, and that nothing is released off `dev`. The carve-out for a hotpatch that is not worth a version.
2. The gate: the steps in order (fmt, lint, tests, deny, doc coverage, ante), how a repo's kind is detected (a `Cargo.toml` or a `deno.json` at the root), what each step runs per kind, what blocks and what only reports, and the numbers a run produces.
3. The run record: the `gate-run` kind the workspace declares, its attributes (repo, sha, ran at, verdict, the numbers as text), append-only, and that `homma release run` reads the record for the `dev` tip and never re-runs the gate.
4. The commit status: `homma/gate` posted on the gated sha through the forge, success or failure, the description carrying the numbers, and the trunk rulesets requiring it on `dev` and `main`. That the remote runs nothing and only checks that something ran here.
5. The hook: a `pre-push` homma installs into a repo's hooks directory, running the gate on every pushed tip and refusing the push on red. Where the repo already routes `core.hooksPath` to mockspace's durable hooks, the hook is not installed and the gap is named (see BACKLOG).
6. The check: the invariants a repo must hold before anything moves, the tag on `main`, `main` holding nothing unreleased, the manifest version matching the tag, published versions ascending, no gap in the sequence, every tag published and every published version tagged. The set is the one `.shared/scripts/release/patchworks/CHECKS.md` encodes, named here by id so the port is checkable.
7. The run: `--level` required, the plan printed first (the commits since the last tag with their prefixes, the version it becomes, what publishes where), then bump, changelog block, merge with a merge commit, annotated tag, GitHub release with the same block as body, publish in dependency order, badge json to the `badges` branch. What refuses: no green record on the tip, a check failing, a level missing.
8. The changelog: `CHANGELOG.md` on `main`, newest first, one block per release, grouped by prefix, never trimmed.
9. Badges: the orphan `badges` branch, one json per measured thing in shields' endpoint shape, and the url a readme carries.
10. Credentials: the forge token through the configured `token_cmd`, the registry tokens through the same tool.
11. The command surface: `homma release check`, `gate`, `plan`, `run`, `badges`, `hook`, with their flags.

### `mock/crates/homma-core/BACKLOG.md.tmpl` (create)

Three items, unbackticked: the mockspace hook chaining (a repo whose hooks path is mockspace's gets the gate through mockspace's pre-push delegating to homma, not built here); the daemon re-running the slow half of the gate after a push and appending a second record; mockspace's own lints posting per-lint statuses the rulesets can require, lint by lint, per trunk.

### `mock/crates/homma-engine/README.md.tmpl` (create)

Three to six lines: the surface a human or an agent drives, the binary, every command family named including `release`.

### `mock/DESIGN.md.tmpl` (update, root, not gated)

Under the paragraph on what homma must be, one sentence that releasing is workspace work and homma drives it; under what exists, one sentence naming the release surface in `homma-engine` and its mechanism in `homma-core`.

## What is not changed

`homma-api/DESIGN.md.tmpl`, `homma-store/DESIGN.md.tmpl`, `homma-org/DESIGN.md.tmpl`. The record kind is configuration and needs no new attribute type: a number rides as text.
