## mock/crates/homma-core

- `src/release/writes.rs`, new: `ReleaseForge`, the two forge writes of a release, `tag` and `release`; `ByClient` tags with git in the clone, pushes the tag and makes the release through `Forge::create_release`; `ByRoute` asks the workspace's `forge_route` for both through the release's `Runner`, `tag <root> <tag> <sha> <message>` and `release <root> <tag>` with `FR_NOTES`, and a failure of every route is `ReleaseError::Route` in its words.
- `src/release/mod.rs`: the `writes` module.
- `src/release/run.rs`: `Setup::forge` is a `&dyn ReleaseForge` in place of the forge client, `owner`, `name` and `forge_route`; step 6 asks it for the tag and step 7 for the release, with no branch on an optional path; `step_hold_tag` fetches the tag into the clone after step 6 and refuses with the new `ReleaseError::TagElsewhere` where it names another commit than the one tagged; `ask_route` and `root_arg` move into `ByRoute`.
- `src/release/git.rs`: `fetch_tag`, the one tag from the remote into the clone, refusing to overwrite a local tag on another commit.
- `src/release/run_tests.rs`: the fixture gives its origin; `client` builds the `ByClient` the existing tests release through; the `Routed` fake makes the tag in the fixture's origin with a message of its own, as the Worker does, refuses one the origin holds, or answers done and makes none. Tests: `a_configured_forge_route_makes_the_tag_and_the_release_and_the_clone_holds_the_tag` (replaces the test that asserted the tag absent from the clone), `a_second_release_through_the_route_from_the_same_clone_plans_the_next_version`, `a_tag_the_remote_holds_on_another_commit_refuses_the_release`, `a_route_that_answers_done_and_made_no_tag_stops_the_release`, and `a_forge_route_that_fails_every_way_stops_the_release_with_its_words` kept. Shown red: with `step_hold_tag` not called, the first four fail; with the commit check removed from it, the third fails.

## mock/crates/homma-engine

- `src/cmd/release/mod.rs`: `forge_for` also gives the forge's kind; `route_for` takes the route for a GitHub repo alone, and `release_forge` builds `ByRoute` where it does and `ByClient` otherwise; `forge_route_of` reads the manifest once per run, before any repo, and is an error where the manifest does not read as a workspace's, `None` only where it names no route.
- `src/cmd/release/gating.rs`: takes the client and owner from `forge_for` as before.
- `src/cmd/release/route_tests.rs`, new: the route from the manifest's directory, none where unnamed, an error for a manifest that does not parse and for one that is not there, and the route taken for GitHub alone. Shown red: with the manifest's failure read as no route the third fails; with the route taken for Forgejo too the fourth fails.
