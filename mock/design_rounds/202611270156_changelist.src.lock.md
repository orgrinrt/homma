# src changelist

This changelist comes from `202611270155_changelist.doc.lock.md`, and through it from `202611270155_topic.git-hooks-put-back-at-every-session-start.md`.

## CHANGE: whether a registration is current FROM unasked TO `registration`, which also asks git-shook's doctor
File: `mock/crates/homma-core/src/hooks/shook.rs`, `mock/crates/homma-core/src/hooks/mod.rs`
Verification:
- `registration(root, workspace, on_path)` refuses with `HookError::NotShook` where git-shook does not hold the path.
- Otherwise it gives one line for each manifest in place that is not byte for byte what `install` writes, and one for each leftover of `legacy::left_behind`.
- It runs `git shook doctor --only homma [--only <name>]`, and where that fails, adds each of its lines prefixed `git shook doctor:`.
- An empty list is current.
- `register` and `registration` share `run_git` for the `PATH` with `on_path` ahead.

## CHANGE: `homma hook install` FROM one named repository TO an optional one, the sweep where there is none
File: `mock/crates/homma-engine/src/cli.rs`, `mock/crates/homma-engine/src/cmd/hook.rs`
Verification:
- `HookOp::Install` takes `repo: Option<String>`.
- With one named, `install_cmd` installs and reports as before through `install_one`.
- With none, `sweep` goes over `cfg.repos`:
  - it installs where `registration` is not empty, or where git-shook does not hold the path, the latter giving the refusal line;
  - it skips a current member;
  - it fails where any install refused;
  - with every member current and human output, it returns without printing anything.

## CHANGE: `homma hook doctor <repo>` FROM the hooks path and leftovers TO those and git-shook's lines too
File: `mock/crates/homma-engine/src/cmd/hook.rs`
Verification: Where git-shook holds the path, the doctor adds each `git shook doctor:` line of `registration` with what puts it back, and fails for it.

## CHANGE: the tests FROM the install alone TO the registration and the sweep
File: `mock/crates/homma-core/src/hooks/shook/tests.rs`, `mock/crates/homma-engine/tests/hook_smoke.rs`
Verification:
- The fake git-shook answers `doctor` from a `doctor-says` file.
- The core tests cover three cases:
  - a fresh install is current, and git-shook was asked of both names;
  - an edited manifest, a leftover and a line from git-shook's doctor are each not current;
  - a path git-shook does not hold is the refusal.
- The smoke tests cover the refusal in a sweep and the silent sweep over no members.
- With `GIT_SHOOK`, a smoke test covers a sweep putting back a removed and a hand-edited entry, and staying silent otherwise.
