# a-console-turns-the-dashboard-off

Op, 28 October 09:02, verbatim:

> And we need to clearly make the tooling respect the fact that we don't keep dashboard here. It has to disable and disallow any dashboard shit, because we have the console here as its replacement. The project homma config should reflect that

His answer at 09:06 to how wide the ban goes, from three options (any clone whose config names a console; kaski only; remove the dashboard everywhere): "Any clone with a console".

The intent is that in a clone whose local config names a console, nothing about the claude.ai dashboard runs, prompts, reports or publishes, and the config says so. Other clones keep their pages. The rest of the wording above is kept for provenance.

## What homma owns of it

Homma holds a tool's settings untyped, so it does not know what a dashboard is, and it has no business learning. Three small things are homma's, because they are about the local file and the status line and not about any one tool.

A local file names a console when `[tools.console]` carries a non-empty `channel`. That is a fact about the file's shape, readable without knowing the tool, and the workspace's tools ask homma for it through the parsed file.

`homma local set` refuses to write under `tools.dashboard` into such a file. A hook that records a publish would otherwise put the page's address back into a clone that has none, and the tool reading the file would have two answers to whether it keeps a dashboard.

`homma local install` refuses a stored config that names a console and also carries a `tools.dashboard` table. The stored file is what a fresh clone starts from, so a stored file holding both would hand every new clone the contradiction.

## The status line

A tool that is told to stay silent prints nothing, and until now `homma status` still printed its heading with nothing under it. A clone that turns the dashboard off therefore still showed a `dashboard:` line, empty. An injected block whose text is empty and which did not fail is left out of the text render. The failed block keeps its heading, and the json document keeps every block, so a script reading it loses nothing.

## What stays elsewhere

The tool that builds and publishes the page, its refusal in a console clone, the hook that denies the Artifact tool the page, and the console's own hand-off live in the workspace repository, in the keep-the-dashboard skill, and are not homma's.

## Decisions

Naming a channel is what makes the table a console, so a console table without one is not one and the dashboard is back. Existing installed copies are not rewritten by homma: `install --replace` writes the console form where a clone still holds the old table.
