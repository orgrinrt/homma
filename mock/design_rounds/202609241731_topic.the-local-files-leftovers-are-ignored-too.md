# the local file's leftovers are ignored too

`homma local set` writes under a lock file, `homma.local.toml.lock`, and through
a temporary file, `homma.local.toml.<pid>.tmp`, both beside the file. A writer
that dies between taking the lock and renaming leaves one or both behind, and
`init` ignores only `/homma.local.toml`, so what is left shows in `git status`
as untracked and is one `git add -A` from being committed. The review of the
round that added `local` named it.

So `init` also adds `/homma.local.toml.*`, and adds it where a `.gitignore`
already names the file itself but not the leftovers, which is every clone set
up before this. The pattern is anchored and names only what sits beside the
file, so nothing else in the tree is ignored by it.

The same review found the test pinning where the file is looked for, beside the
manifest and never at `workspace.path`, deleted with nothing in its place when
the lookup moved out of the config loader. The lookup is `manifest_dir` now,
and a test on it goes back.
