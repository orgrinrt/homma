# the-paths-table-refuses-a-key-it-does-not-read

# The paths table refuses a key it does not read

## The ask

`[paths]` is read by `Paths`, which takes defaults and does not refuse an unknown key, so a misspelt key, or one meant for some other program, reads as nothing and the path homma uses is its default, silently. Every other table of the manifest refuses an unknown key. `[paths]` should too.

## The constraint

A manifest in use sets keys under `[paths]` that homma never reads: the workspace's own scripts read them from the manifest, and one of them is read as well by another program deployed apart from the scripts. A homma that refuses them stops every verb for that workspace, in every clone and container whose engine is that new. So the manifest has to lose them first, and the manifest is not homma's to change; it changes on its owner's schedule, and one of its keys waits on that other program.

## The order

1. Landing A (this round): `Paths` keeps the keys it does not read, by name, as `Paths::unread`, and `homma status` names them under the workspace line, `  not read under [paths]: <key> <key>`, and in the document as `workspace.unread_paths`. Nothing is refused and nothing moves for a running workspace; a manifest with no such key prints nothing new.
2. The workspace moves each key its scripts own to the scripts' own settings, and the one another program reads once that program reads it there. Its owner checks by command, in each clone and container, that nothing is listed: `homma --output json status | jq -e '.workspace.unread_paths == []'`.
3. Landing B (a later round, on word that step 2 is done everywhere): `Paths` refuses an unknown key like every other table, and `unread` and the status line go.

Options weighed:
- Refuse now: stops the workspace's verbs the moment the engine updates. Ruled out.
- Refuse with a list of keys allowed through: names a workspace's keys in homma, which homma may not do, and is an exemption.
- Warn on stderr at every load: every verb's output grows a line, and an agent reading output pays for it on every call; a status line is read where the workspace is checked.
- Keep the unread keys and report them (taken): the warning is where the workspace's state is reported, and it gives the check by command that the refusal waits on.

## How the keys are kept

`#[serde(flatten)]` of a map of the remaining keys beside the named fields: serde gives every key no field takes to the map, so what the struct does not read is caught by the same parse that reads the rest, with no second parse and no list of names. The map is never written back: `Paths` serialises without it.

## The keys are found by the key probe, not by flatten

The flatten above is not taken. It turns `Paths` into a map for every reader of its shape, the key probe of the status key list included, which would then list `paths.*` in place of its keys. The unread keys are instead the keys of the raw `[paths]` table that `keys_of::<Paths>()` does not list: the probe names every field `Paths` reads, so no list of names is kept beside the struct, and a field added to `Paths` stops being reported with no other edit. They are kept on `Workspace` as `Workspace::paths_unread`, set by `Workspace::parse` from the table it already read, not on `Paths`; the order above reads `Workspace::paths_unread` wherever it says `Paths::unread`. This round's source waits for the probe to be on the trunk and builds on it.
