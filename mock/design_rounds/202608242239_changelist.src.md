# Src changelist: the engine renames and a launcher lands beside it

**Date:** 2026-08-24
**Phase:** IMPL
**Source topic:** the topic of this round
**Doc changelist:** the locked doc changelist of this round

## CHANGE: `mock/crates/homma` becomes `mock/crates/homma-engine`

RENAME the directory, the `[package] name`, and the `[[bin]] name`. `renki` runs
the binary named by `engine_crate`, so the package name and the binary name are
one decision.

MODIFY the seven integration tests that call `Command::cargo_bin("homma")` to
name the engine binary. `mock/Cargo.toml`'s `members = ["crates/*"]` needs no
edit.

Nothing depends on this package, so the rename reaches no dependency table.

## CHANGE: `homma/Cargo.toml`, a root workspace

ADD a workspace at the repo root with the launcher as its only member, which is
the shape `mockspace` has. `mock/` stays its own workspace underneath, which is
what keeps the launcher outside the gate it is meant to plant.

## CHANGE: `homma/launcher/`, the launcher package

ADD a package named `homma`, `publish = true`, depending on `renki` by revision.
By revision rather than by branch, for the reason `cargo-mock` gives: `renki` is
unpublished at `0.0.0`, so a branch pin constrains nothing and every
`cargo update` silently moves the launcher every consumer installed.

ADD `src/lib.rs` carrying the `TOOL` descriptor and a `run_cli` that hands it to
`renki::run`, and `src/bin/homma.rs` as the two-line entry over it.

The descriptor uses `Anchor::ConfigFile` and `Hooks::NONE`. Both are claims:
the first that the config is found by walking up from anywhere, the second that
this tool needs none of what `mockspace` needed hooks for.

## CHANGE: tests

ADD a test asserting the descriptor's names against the repository they have to
match: the config file that exists, the engine crate that exists under
`mock/crates/`, and the launcher package name being this package's own. A
descriptor is a pile of string literals and nothing else checks them, so a
rename that misses one is silent until an operator hits it.

ADD a test that the anchor finds the config from inside a member clone, which is
the behaviour the variant was chosen for and the thing that does not work today.
