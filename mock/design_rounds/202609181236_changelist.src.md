# src changelist: a stub forge reads the body it answers

Carries `202609181236_topic.a-stub-forge-answers-before-the-body-arrives.md`.

## CHANGE: fn `status_by_path` FROM answering after the headers TO answering after the body
File: `mock/crates/homma-core/src/forge/github_wire_tests.rs`
File: `mock/crates/homma-core/src/forge/forgejo_wire_tests.rs`
Verification: both stubs take `Content-Length` off the headers and `read_exact`
that many bytes before writing the response, as the recording stubs in the same
files already did. The forgejo stub's doc no longer says its arms need no body
read. Before the change, the github create test went red on two of three
consecutive runs and the forgejo one in a full suite run; after it, both ran
thirty times in a row with no red run.

## CHANGE: test `the_stub_reads_a_large_body_before_it_answers` FROM absent TO one per stub
File: `mock/crates/homma-core/src/forge/github_wire_tests.rs`
File: `mock/crates/homma-core/src/forge/forgejo_wire_tests.rs`
Verification: a raw `POST` with a four mebibyte body against each stub, asserting
the write completes and the answer is the route's status. `cargo test -p
homma-core the_stub_reads_a_large_body` from `mock/`, two passing. Negative
control, run by hand and reverted: with the github stub's `read_exact` removed
the test went red on five runs of five with `BrokenPipe`, so the race the create
tests lost sometimes is one this test loses every time.

## Not changed

`renamed_private_repo` serves `GET`s with no body, so it has nothing to leave
unread.
