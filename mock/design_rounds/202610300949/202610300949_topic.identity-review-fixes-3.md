# identity-review-fixes-3

A third review of the branch that generates an agent definition from a character file returned a verdict of do not merge. It is the last review the flow allows, so this round fixes what is checkable in the code and the design text, and the rest is handed back with the verdict.

Handed back and not decided here. The review's strongest point is that a second source of who exists, beside the registry, is what the one-owner tenets tell a design to rethink. That is the question already filed for op (is an identity a row of the registry), and the coordinator's standing answer for this branch is to finish as built, which keeps every later answer open. Also handed back: a sibling identity whose character broke after it was rendered is not seen by the owner check; the auto memory a coordinator session installs and the identity's own memory directory can both be written by one session; `identity render` can take over a registry hand whose character gained a frontmatter fence; what a session writes under `.shared/hands/<name>/memory` is landed by no tool; the console's own edit of a personality lives in kaski and cannot be called from a test here; and no test reads the quoted scalar back through a YAML reader, since the crate has none.

Fixed, by class.

- A claim in the design and the code that disagreed. The design said nothing else is added to the body. The definition adds the standing discipline, the memory instruction and a memories section after the authored body. The design now says so, and says the body itself is composed verbatim.
- A claim of totality with a hole. A render checked the link and definition slots and not the memory directory they point to, so a regular file there failed after the first identity was written. The memory directory joins the slots checked first.
- A memory owner the render cannot see. An identity naming a memory under another name's home in the hands place, which is where a registry hand keeps its own, is refused: below `.shared/hands/` a memory sits under the identity's own name or elsewhere in `.shared`.
- A claim that no path is built by hand. The default memory is fixed by the character format and not derived from the configured hands place, so the module says that instead.
- The name is written as a scalar like the description, since a handle may be `true` or a number.
- A launch that cannot find its definition. The harness reads `.claude/agents`; a configured agents place writes elsewhere, so a launch refuses it and names the place.
- An environment variable naming the program a launch runs. `HOMMA_CLAUDE` is named in the design as a test seam of the launch, with the default `claude`.
- Tests. One test asserted against its own constant and cannot fail; it is deleted. Three assertions threw away the reason a render failed and now name it. The identity tests are split over two files to stay under the size tripwire.

The commit text in the range already pushed carries the review round and a message about a reword that did not happen; the coordinator lands the branch as one squash with a message of its own, and no history is rewritten.
