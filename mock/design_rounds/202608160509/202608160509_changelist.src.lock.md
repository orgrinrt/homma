# Src changelist: the test imports, the proving door, and the kind check

Five changes across three crates. The first four landed in commits made while the
phase was `TOPIC` and are recorded here because they had no changelist of their
own; the fifth and the formatting fix are this round's own work.

## CHANGE: `mod tests` in `gates.rs` FROM `no use items` TO `use std::fs; use std::path::Path;`

File: `mock/crates/homma/src/cmd/gates.rs:253`

The module reached both through `use super::*` and lost them when the previous
round removed them from the parent. Restored inside the test module, where the
uses are, so a later autofix on the non-test half cannot orphan them again.

Verification: `cargo check --tests -p homma` succeeds. Reverting the file to
`5968ffb` makes it fail with thirteen errors while `cargo check -p homma` still
succeeds, which is the asymmetry that hid it.

## CHANGE: definition writes in `generate.rs` FROM `fs::write` TO `root.write`

File: `mock/crates/homma-org/src/generate.rs:158,162`

Both paths are already `ContainedPath`, so containment was proven; what was
skipped is `Root::write`'s post-write `reprove`, which is the whole reason the
door exists.

Verification: `grep -n 'fs::write' mock/crates/homma-org/src/generate.rs` returns
nothing. `use std::fs` stays live via the read at line 147.

## CHANGE: `Store::read` FROM `unvalidated kind` TO `Self::check_kind_name(kind)?`

File: `mock/crates/homma-store/src/lib.rs:157`

A read escapes the root exactly as a write does. `append` validated and `read`
did not, so a kind naming a path outside the root was readable, and then
rewritable through `replace`.

Verification: `read_refuses_a_traversing_kind_rather_than_opening_a_file_outside_the_root`.
Removing the guard makes it fail; it passes with the guard, and its control reads
an ordinary kind first so the refusal is about traversal rather than absence.

## CHANGE: `Store::rewrite` FROM `unvalidated kind` TO `Self::check_kind_name(kind)?`

File: `mock/crates/homma-store/src/lib.rs:204`

Its one caller now validates twice over, which is the point: a guard held in a
different method survives exactly until a second caller appears.

Verification: `rewrite_refuses_a_traversing_kind_without_help_from_its_caller`.
Removing the guard makes the call return `Ok` and a file is genuinely written
outside the store root, which the test asserts against.

## CHANGE: `check_kind_name` FROM `six clauses` TO `five clauses`

File: `mock/crates/homma-store/src/lib.rs:113`

`kind.split(['/', '\\']).any(|c| c == "..")` could never decide anything. `||`
short-circuits, so reaching it means the name holds no separator, so `split`
yields one component, so the clause reduces to `kind == ".."`, which is the next
clause. Removed, with a comment saying why the scan is absent so it is not added
back as missing rigour.

Verification: `cargo test -p homma-store` is green, twelve tests, including both
traversal tests above.

## Not changed, and named so the class grep is on the record

`homma-store` is reached by nothing: no other `Cargo.toml` names it and no source
references `homma_store`. Its guards are still correct and stay. Whether the crate
should be in this branch at all is a scope question for its owner, not a reviewer's
to settle by deletion.

`workspace.rs:247` and `provision.rs:177` bypass their doors in the same class as
the `generate.rs` fix above. Both carry deliberate justifications in place and
both sit in the already-reviewed part of the branch, so neither is touched here.
