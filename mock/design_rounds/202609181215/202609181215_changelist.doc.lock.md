# doc changelist: the design names both of the launcher's commands

## Current state

`mock/DESIGN.md.tmpl`, in the section listing the command families, opens the
paragraph on `homma workspace` with "One command is the launcher's rather than
the engine's". `homma config` is answered before the engine as well, by renki for
any tool carrying settings, and the paragraph after says `homma config` reads and
writes the settings file without saying which binary answers it.

## Changes proposed

That opening says two commands, names `homma config` as the second, and gives
the reason it is the launcher's: the engine is what is being configured and may
not build. The rest of the paragraph on `homma workspace` is unchanged.

Nothing else in the design moves. The other findings of the topic are about the
two test files, and the design has no statement about either binary's suite for
them to disagree with; the src changelist carries those claims.
