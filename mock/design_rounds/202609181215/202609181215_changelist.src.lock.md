# src changelist: the readme's launcher spans are checked by the binary that answers them

Carries the topic `202609181214_topic.what-the-review-of-the-readme-test-found.md`,
every section of it. The doc changelist beside this one carries the design
sentence; everything here is to the two test files.

## CHANGE: fn `row_for` FROM a bare prefix match TO a match ending at a space or a backtick
File: `launcher/tests/the_readme_names_the_launchers_commands.rs`
Verification: `a_prefix_of_a_commands_name_finds_no_row` passes, asserting
`row_for("work")` and `row_for("con")` find nothing while `row_for("workspace")`
finds the row.

## CHANGE: the `config` row FROM checked for existence only TO checked verb by verb against the binary
File: `launcher/tests/the_readme_names_the_launchers_commands.rs`
Verification: three tests, run with `cargo test -p homma --test
the_readme_names_the_launchers_commands`, seven passing.
`the_config_row_names_exactly_the_verbs_the_launcher_takes` reads the verb list
out of bare `homma config`'s refusal and asserts the row names that set and no
other. `every_verb_the_config_row_names_runs` runs each verb the row names on a
settings directory under a temporary directory, named through
`homma::TOOL.config_env()` and run from inside it, `get` over every declared key
and `set` over every key at its own default, and panics on a verb it has no
arguments for. `a_config_verb_the_launcher_does_not_take_is_refused` is the
control: `frob`, `get` with no key, `get` with an undeclared key and `set` with
no value each fail.

Negative control, run by hand and reverted: the row's `edit` written without
backticks turned `the_config_row_names_exactly_the_verbs_the_launcher_takes`
red with "the readme's `config` row and the binary disagree on the verbs", and
nothing else.

## CHANGE: the engine's third check FROM restating its own filter TO asserting the handoff
File: `mock/crates/homma-engine/tests/the_readme_examples_are_real.rs`
Verification: `only_the_launchers_commands_are_left_to_the_launcher` now asserts
every span the engine drops is one `the_launchers_row_writes` accepts: a form
starting with a verb the launcher's row for that command writes, or no verb at
all. `a_span_the_launchers_row_does_not_write_is_reported` is its control, over
`homma workspace frob`, `homma config frob`, `homma work spawn` and a command with
no row. `cargo test -p homma-engine --test the_readme_examples_are_real` from
`mock/`, nine passing.

Negative control, run by hand and reverted: the readme's prose `homma config
schema` rewritten as `homma config frob` turned the handoff red naming that span,
which is the case the review said neither suite read.

## CHANGE: `mock/Cargo.lock` `tempfile` FROM `getrandom 0.3.4` TO `getrandom 0.4.3`
File: `mock/Cargo.lock`
Verification: the previous round's dev-dependency on the launcher brings `renki`
into the engine's graph, and with it `getrandom 0.4`; `tempfile`'s range takes
either, so cargo unified on the one already present. Kept as resolved rather than
edited back by hand, which would be selecting one side of a resolution.

## Not changed here, and where it went

The word `config` and renki's condition for answering it stay written in both
test files under their `FIXME:` markers. The fix is renki exporting
`config::query::SUBCOMMAND` and `is_the_config_query`, filed as an agenda row in
the workspace so the markers point at something.
