# hooks-declared-not-installed

homma declares its two hooks in a `shook.toml` now, which is the tracked half
of the answer: a manifest says what homma wants run at an event, and
`git shook install` registers it beside whatever else the repository declares
rather than instead of it. That leaves three things in homma itself that were
written when homma was the only tool installing anything.

## `homma hook install` writes a file nothing will run

The entrypoints go into the common git directory's `hooks/`, which is the one
place every chain used to reach: git reads it directly where no hooks path is
set, and mockspace's durable gate runs the repository's own hook there after
its own checks. Where git-shook owns the hooks path, neither holds. Its
dispatcher runs the entries under `<git-dir>/shook/entries/<event>/` and
nothing under it reaches `.git/hooks/`, so the file homma wrote sits there
inert and the install reports it as written.

`reach` already has a vocabulary for this and it does not fit: it reports
`Foreign`, whose message says git will not run the entrypoint until that tool
chains to the repository's own hooks. git-shook does not chain and is not going
to; it registers what a manifest declares. So the honest report is a fourth
kind, one that names git-shook and says the manifest is the way in.

## The adoption gate counts a hooks path that is not mockspace's

`homma agent gates` writes a pre-commit gate that decides whether a repository
has half-adopted mockspace, by counting three surfaces: a `mock/` directory, a
launcher pin, and `core.hooksPath` being set. Zero of three is a repository
that never opted in and three of three is one with nothing to say; anything
between is drift, and the gate refuses the commit.

`core.hooksPath` being set was evidence of mockspace when mockspace was the
only thing that set it. git-shook sets it too, in a repository that may never
have heard of mockspace, and that repository then counts one of three and every
commit in it is refused with an instruction to run `homma agent regen`, which
cannot help because there is nothing wrong.

Measured on git-shook's own clone: no `mock/`, no pin, `core.hooksPath` at
`<git-dir>/shook/hooks`, and the gate refusing an ordinary commit.

The surface the gate is actually asking about is whether mockspace's hooks
fire, so a hooks path pointing at git-shook's dispatcher directory answers no
and should count as no.

## The manifest's comment says something homma does not do

The `shook.toml` this round lands beside says homma takes `core.hooksPath` to
install its hooks. It does not, and has not: `hooks_dir` asks git for the
common git directory and appends `hooks/`, with a doc comment saying never the
`core.hooksPath`, and `the_hooks_dir_is_the_common_git_dir_whatever_the_hooks_path_says`
pins it. The real reason to declare the hooks in a manifest is not that homma
takes the path; it is that three tools each writing one file into one hooks
directory can only ever leave the last one's, and homma's own `Reach` is the
machinery that exists because of it.
