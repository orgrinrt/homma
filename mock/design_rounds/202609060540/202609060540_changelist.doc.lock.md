# doc changelist

Two documents, both because git-shook now sets `core.hooksPath` in
repositories homma also has a hand in.

## `mock/DESIGN.md.tmpl`

CHANGE: the gate paragraph says what incomplete means, and says that a
`core.hooksPath` pointing at git-shook's dispatcher directory is not one of
mockspace's surfaces.

The paragraph described the gate's refusal without describing what it counts,
so the surface list lived only in the generated script. It counted the hooks
path being set as evidence of mockspace, which held while mockspace was the
only thing that set it, and a repository with a git-shook dispatcher and no
mockspace at all now reads as half-adopted.

## `mock/crates/homma-core/DEEPDIVE_release.md.tmpl`

CHANGE: the install's report gains git-shook as a case of its own, apart from
a foreign hook waiting to be chained to.

`Foreign` says git will not run the entrypoint until that tool chains to the
repository's own hooks. git-shook does not chain and does not need to: it runs
what the manifests declare. The report for that path names the manifest
instead, which is what a reader can act on.

Neither document's other claims move. The install still writes into git's own
hooks directory, mockspace still owns the path where mockspace is what set it,
and the chaining case is unchanged.
