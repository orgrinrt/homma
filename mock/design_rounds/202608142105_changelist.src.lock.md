# Src changelist: resolve links the way the kernel does

## CHANGE: `AbsPath::resolved` walks and re-anchors instead of canonicalising a prefix

The old shape found the longest prefix for which `Path::exists()` answered true,
canonicalised that, and appended the rest as written. Two defects in one:
`exists()` follows a link, so a dangling one reads as absent; and `canonicalize`
fails on a dangling link, so the fallback returns the path unresolved.

The new shape walks components from the root. Each prefix is examined with
`symlink_metadata`, which reports a dangling link as the link it is. A link is
read with `read_link` and its target pushed back onto the pending components,
absolute targets restarting at the root and relative ones continuing from where
the link sat. A hop counter refuses a cycle rather than looping.

`..` is handled during the walk rather than only lexically, because a link target
may carry one and it applies to wherever the link landed.

## CHANGE: `ContainedPath` no longer dereferences to `Path`

`Deref` handed every consumer `Path::join` and `Path::parent` on a proven path,
neither of which preserves the proof, and an absolute argument to `join` replaces
the receiver outright. A proof that any caller can void by accident is not a
proof. `as_path`, `as_abs` and `AsRef<Path>` remain, none of which produces a new
path.

## CHANGE: `link_memory` takes proven paths

It performed `remove_file` and `symlink` on two `&Path`, against the module's own
claim that an unproven write no longer compiles.

## CHANGE: `stand` resolves both sides of the nesting comparison

The comment said both sides were resolved and one was raw. On a machine where the
root's own path passes through a link, the comparison answered false for a
workspace that was inside the root. Inert today because a caller upstream
canonicalises first, and nothing pinned that.

## CHANGE: two files made rustfmt-clean

`generate.rs`, whose import order this branch disturbed, and `output.rs`, which
was already unclean on the trunk and is fixed here rather than left as a
permanent false signal in `cargo fmt --check`.

## CHANGE: tests

The dangling-symlink case, at the type and through the binary, written and
watched fail before the fix. Both existing symlink tests instantiated only the
shape where the target exists, which is a sampled law, so each gains its
counterpart rather than being replaced.

A test that `ContainedPath` does not expose a path-producing method, which is a
compile-fail case rather than a runtime one.
