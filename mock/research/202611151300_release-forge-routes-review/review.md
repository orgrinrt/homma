# Review: the two branches that take a release to the forge from a cloud container

Reviewed on 2026-11-15 against `origin/dev` at `aabfae4`: `work/release-through-forge-route` at `65efe47` (round 202611151139) and `work/tooling-track-release-in-a-cloud-container` at `29dd774` (rounds 202611030733, 202611031227, 202611031246, 202611051449, 202611051500, 202611051503). Both answer how a release reaches the forge from a container whose proxy refuses a tag push and `gh release` with HTTP 403.

Canon gate: homma's `mockspace.toml` declares no `canon_paths`, so the release design (`DEEPDIVE_release.md.tmpl`) stands in for the canon, and op's words quoted verbatim in `202611151138_topic.release-tags-through-forge-route.md` carry the intent: every release gets its annotated tag and its forge release, from a cloud session too, through the workspace's one chain of routes. Branch 1 aligns with that intent and with the workspace rule `a-tag-a-release-and-a-branch-deletion-go-through-forge-route`. This is a first read; a second independent read is owed.

## Findings

1. `mock/crates/homma-core/src/release/run.rs:241` with `plan.rs:143` [correctness]: when `gh` or the console Worker wins inside `forge-route`, the tag exists on the remote and not in the clone. `plan::last_tag` reads `git tag --list` locally only, and nothing in the release fetches (`git::fetch`, `git.rs:432`, has no caller outside tests). The next `homma release run` from that clone plans from the tag before, takes the manifest's version as already bumped, plans the version just released again, prepends a second changelog block, pushes the bump, merges `main`, and then the route refuses a tag the remote holds on another commit: a half release made by the fix for half releases. After the route succeeds, fetch the tag into the clone (`refs/tags/<tag>:refs/tags/<tag>`) and refuse when its target is not `sha`.
2. `mock/crates/homma-core/src/release/run_tests.rs:534` [tests]: `assert!(git::tag_target(f.root(), "v0.1.1").is_err(), "git made the tag itself")` pins finding 1 as intended behaviour. The `Routed` fake answers success and makes no tag anywhere, so the state a real route leaves is never entered: setup that helps. Make the fake write the tag into the fixture's `origin` as the Worker would, assert the clone holds it on `tag_sha` afterwards, and add a second release in a row from the same clone. This is the test-gate failure that makes the verdict MERGE AFTER FIXES rather than CLEAR.
3. `mock/crates/homma-engine/src/cmd/release/mod.rs:315` [correctness]: `forge_route_of` is applied to every repo of the loop, while `forge_for(cfg, r)` two lines up picks GitHub or Forgejo per repo. `forge-route` reaches GitHub alone (`gh`, git, `forge-write` to GitHub) and derives the slug from the clone's origin, so a Forgejo repo's tag and release would be asked of GitHub under a slug taken from a Forgejo URL, and `setup.owner`/`setup.name` are ignored. The route belongs behind the `Forge` contract, as an implementation chosen in `forge_for` for GitHub repos (a tag method beside `create_release`), which also removes the `Option<&Path>` branch from `run.rs:241` and `run.rs:306` (`harness-the-type-system`: a trait object over a runtime match on an optional path).
4. `mock/crates/homma-engine/src/cmd/release/mod.rs:518` [correctness]: `crate::cmd::org::load(&manifest).ok()?` turns an unreadable or unparsable manifest into "no route", which falls back to the git tag push: the exact 403 path in a container, reached after `main` was pushed. A manifest that cannot be read as a workspace is an error; only an absent key is `None`.
5. `.shared/scripts/remote/forge-write:86` with `forge-route.sh:148` [spec, workspace side]: the Worker's release body carries owner, repo and tag and no notes, so `FR_NOTES` reaches only the `gh` route. In a cloud container, which has no `gh`, the release is made with an empty body, and because a release that exists is taken as done, a rerun never fills it. `DEEPDIVE_release.md.tmpl` step 7 still promises the changelog block as the body; the topic's "for the route that takes a body" names the gap and closes nothing. Owed: a workspace ticket for the Worker and `forge-write` to take the notes.
6. `mock/design_rounds/202611151139/202611151140_changelist.src.lock.md:18` and `mock/crates/homma-core/BACKLOG.md.tmpl:21` [drift]: the cited ticket `homma_release_check_names_no_version_tag_that_has_no_forge_r` is not in kaski's registry on `origin/dev` (`git grep` returns nothing; the same grep finds `workspace_worktree_sparse_checkout_lacks_scripts_the_pre`). File it before landing. `release-cadence` calls a tag with no forge release a release half done, and `homma release check` names none.
7. `mock/DESIGN.md.tmpl:105` [naming]: the doc changelist puts `forge_route` with the manifest's `[paths]`, and the diff instead appends an unwrapped 200-character sentence to the release paragraph; the `[paths]` text near `docs/DESIGN.md:234` does not list the key. It also says "the GitHub release", which is true only after finding 3.
