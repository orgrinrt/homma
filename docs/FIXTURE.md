# homma-fixture

What a test needs to stage the world outside the code under test. Taken only as a
dev-dependency, published nowhere, and depending on nothing of homma's, so the tests of
any crate at any layer may take it.

## A script a test runs

A test runner that runs tests as threads of one process forks from every thread. A script
this process writes is open for writing while it is written, and a fork on another thread
in that moment carries the descriptor into its child until the child's exec, so running
the script then fails as busy. `script` writes the file, creating its directory, and gives
it its mode, all in a child `sh`, so the script is never open for writing in the test
process at all. Every test that writes a script and then runs it plants it this way.

## A test alone in a child

Some states belong to one test only: an environment variable the code reads, a file
written by the code under test that the test then executes. Set in the test process, the
first leaks to every other test thread, and the second is the busy race again. `alone`
is the command that runs one test of the current test binary by itself in a child, given
the test's module path and name, and `passed` checks that the child ran exactly that one
test and it passed. The test tells the two runs apart by a variable only the child is
given.
